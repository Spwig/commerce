---
title: APIトークン
---

APIトークンは、外部サービスや統合がストアと通信できるようにするためのセキュアなキーです。第三者のサービスやツールがストアのデータにアクセスしたり、アクションをトリガーしたりする必要がある場合、各リクエストにAPIトークンを送信して、ストアがリクエストが承認されていることを確認します。APIトークンセクションから、トークンを作成し、管理し、ストアのどの部分にアクセスできるかを正確に指定できます。

## APIトークンが必要になるとき

通常、以下のような状況でAPIトークンを作成する必要があります。

- 外部サービスや自動化ツールを接続し、ストアに読み取りまたは書き込みが必要な場合
- インバウンドコールを認証する必要があるホックリスナを設定する場合
- ご自分のインストール用のSpwigヘルプシステムを構成する場合
- SpwigのAPIを使用してカスタム統合を構築する場合
- Spwigストアと他のシステムの間でデータを同期する場合

各統合には独自のトークンを持つ必要があります。これにより、あるサービスのアクセスを無効にしても、他のサービスに影響を与えることなく管理できます。

## トークンの種類

トークンを作成する際、その目的を示すタイプを選択します。このタイプは、あなたの参照のためにあり、各トークンが何をするかを把握するのに役立ちます。

| タイプ | 目的 |
|------|---------|
| **ヘルプシステム** | Spwigヘルプドキュメンテーションシステムで使用されます |
| **外部統合** | 第三者サービス、自動化ツール（例: Zapier）、またはデータ同期ツール |
| **ホック** | ホックリスナーやエンドポイントの認証に使用されます |
| **カスタム** | 上記のカテゴリに該当しない他の目的 |
| **インスタンス同期** | Spwigインストール間または外部Spwigサービス間の同期 |

## APIスコープ: トークンがアクセスできる範囲を制御する

すべてのトークンには、**APIスコープ**セクションがあり、ストア内でトークンが呼び出せる正確な部分を決定します。トークンがすべてにアクセスできる権限を持つ代わりに、統合が実際に必要とするレベルで、1つずつアクセス権を付与します。

**スコープが選択されていないトークンは、APIにアクセスできません**。他の条件が満たされている場合でも、これは有効でアクティブなトークンであってもです。

これは新しいトークンのデフォルト設定であり、アクセス権を明示的に付与するまで、統合は動作しません。

各スコープに対して、以下の3つのアクセスレベルのいずれかを選択します。

| アクセスレベル | 許可内容 |
|----------------|-----------|
| **アクセス不可** | このエリアの任意のエンドポイントを呼び出すことはできません |
| **読み取り** | このエリアからデータを取得することはできますが、変更することはできません |
| **読み取り & 書き込み** | このエリアからデータを取得し、また作成、更新、または削除することもできます |

スコープは、管理画面のエリアに合わせてグループ化されています。

| グループ | スコープ | 読み取り & 書き込み可能？ | アクセス対象 |
|---------|---------|:---:|-------------------|
| 分析 | **販売分析** | 読み取りのみ | 販売ダッシュボード、KPI、商品/顧客/カテゴリ分析、比較およびエクスポート |
| 分析 | **ウェブ分析** | 読み取りのみ | 訪問者およびトラフィック分析：概要、トレンド、上位ページ、地理およびリファララー |
| カタログ | **商品** | はい | 商品、バリエーション、画像、在庫調整および属性の割り当て |
| カタログ | **カテゴリ** | はい | 商品カテゴリ、画像およびバナーを含む |
| カタログ | **ブランド** | はい | 商品ブランド |
| カタログ | **属性** | はい | 商品属性の定義 |
| カタログ | **在庫** | はい | 在庫ダッシュボード、在庫速度、在庫の移動、再注文の提案および在庫設定 |
| 注文 | **注文** | はい | 注文、注文ノート、ステータス/追跡の更新、キャンセル、返金および注文書 |
| 顧客 | **顧客メッセージ** | はい | コンタクトフォームからの顧客メッセージおよび注文ノート、ステータス更新および返信を含む |
| 店舗 & 設定 | **店舗設定** | はい | 店舗設定、利用可能な言語およびブランド（名前、色、ロゴ） |
| ユーザー & アクセス | **スタッフ & ロール** | はい | スタッフアカウント、招待、ロールおよび権限カタログ |

**分析**の2つのスコープは常に読み取り専用です — レポートデータには「書き込み」の概念がありませんので、選択肢は**アクセス不可**または**読み取り**のみです。

![APIスコープ選択ダイアログ、AnalyticsおよびCatalogスコープグループの上にアクセスに関する注意事項が表示されている](/static/core/admin/img/help/api-tokens/api-token-scope-picker.webp)

スコープ選択ダイアログの下部には、**"このトークンがアクセスできる内容:"** という読み取り専用のサマリが表示され、あなたが割り当てたすべてのスコープとそのレベルが一覧表示されます。これにより、pickerをデコードすることなく、トークンのアクセス権を一目で確認できます。

!["このトークンがアクセスできる内容:" というサマリで、割り当てられた各スコープとその読み取りまたは読み取り＆書き込みレベルが表示されている](/static/core/admin/img/help/api-tokens/api-token-scope-summary.webp)

### トークンが実際に使用する権限

トークンのスコープは、それが行えることができる *上限* を示していますが、トークンは、それを作成したスタッフメンバーの現実世界での権限を引き継ぎます:

- トークンは、作成したスタッフがスーパーユーザーであっても、**スーパーユーザー**の権限で動作することは決してありません。
- スコープでの **読み取り＆書き込み** は、作成したスタッフのロールがその領域への書き込みアクセスを許可している場合にのみ機能します。たとえば、製品に対してみなし表示のみのロールを持つスタッフが「製品: 読み取り＆書き込み」のトークンを作成した場合、そのトークンはそれでも読み取りのみが可能になります。ロールはスコープの上に追加のゲートとして機能します。
- トークンを作成したスタッフが削除されたり、アカウントが非アクティブ化されたりした場合、トークンはスコープに関係なく、直ちにAPIアクセスを失います — これ以上、許可されたユーザーがいないためです。

このため、トークンのスコープを厳密に設定する最も安全な方法は、トークンを作成する際、すでにトークンに与えたいアクセス権と一致するロールを持つスタッフとしてログインしているときに作成することです。

## APIトークンの作成

1.

**設定 > APIトークン** に移動します
2.

**+ APIトークンの追加** をクリックします
3.

トークンの目的を明確に示す **名前** を入力します（例: `Zapier製品同期` または `ヘルプシステムAPI`）
4.

適切な **トークンタイプ** を選択します
5.

統合に関する詳細情報を含む **説明** を任意で追加します
6.

**APIスコープ** で、統合が必要な各領域に対して **アクセスなし**、**読み取り**、または **読み取り＆書き込み** を選択し、他のすべてのスコープは **アクセスなし** に残します
7.

すべてのマークダウン形式、画像パス、コードブロック、および技術用語を保持してください。

必要に応じて **Active** のステータス、**Expiry Date**、および **Allowed IPs** を設定してください（下記を参照）
8.

**Save** をクリックしてください

保存後、トークンの完全な値は詳細ページに表示されます。**すぐにコピーしてください** — リストビューではセキュリティのためトークンがマスキングされて表示され、このページを離れる後は再び完全な値を取得することはできません。

## Token value security

Spwig は、新しいトークンを保存した直後にのみ、トークンの完全な値を表示します。その後、リストビューではマスキングされたバージョン（例: `spw_••••••••••••••••••••3f8a`）のみが表示されます。

トークンの値を紛失した場合、それを復元することはできません。古いトークンを削除し、新しいトークンを作成した後、それを使用していた統合を更新する必要があります。

**メール、チャットメッセージ、またはソースコードでトークン値を共有しないでください**。パスワードのように扱ってください。

## Setting an expiry date

**Expires At** フィールドは、トークンが自動的に停止する日時を設定します。期限のないトークンの場合は、このフィールドを空のままにしてください。

有効期限の設定は次のケースで役立ちます:

- 一定の終了日を持つ一時的な統合
- 第三者に与えるトークンで、自動的にアクセスを削除したい場合
- 高権限の統合に追加のセキュリティ層を提供する

トークンが期限切れになると、そのトークンを使用したリクエストは拒否されます。アクセスを延長するには、**Expires At** の日時を更新するか、代替のトークンを作成してください。

## Restricting to specific IP addresses

**Allowed IPs** フィールドは、IP アドレスのリストを受け入れます。リストが空でない場合、トークンはそのリストに含まれるアドレスからのみリクエストを処理します。

たとえば、アナリティクスツールが `203.0.113.42` のサーバーで実行されている場合、そのIPを追加すると、他の場所からトークンが漏洩した場合でも、誤って使用されることはできません。

**Allowed IPs** を空のままにすると、すべてのIPアドレスからのリクエストが許可されます。

**有効期限とIP制限はスコープとは独立してチェックされます。** 有効期限切れまたは許可リストにないトークンは、そのスコープが考慮される前に拒否されます。また、スコープが広範囲に設定されているトークンであっても、有効期限切れになったり、未記載のIPから呼び出された moment に拒否されます。

## トークンを使用してAPIを呼び出す

統合は、`Authorization` ヘッダーにトークンを送信してSpwigの管理APIに認証します:

```
Authorization: Bearer <your-token-value>
```

すべての管理APIエンドポイントは`/api/admin/...`の下に存在します。統合を構築している開発者がどのエンドポイントを呼び出すかを決定します。あなたが商売人として行うべきことは、トークンの**APIスコープ**がこれらのエンドポイントをカバーしていることを確認することです。リクエストが権限エラーで拒否された場合、最初に確認すべきことは、トークンが正しいスコープが正しいアクセスレベルで割り当てられているかです。

### 例: ウェブトラフィック分析を読み取る

Spwigは`GET /api/admin/analytics/traffic/`というエンドポイントを公開しており、これはあなたのストアの訪問者とトラフィック分析を返します。訪問回数とユニーク訪問者、時間ごとの傾向、上位ページ、訪問者の地理、リファラースポークスの概要が含まれます。レポートツールやダッシュボードがこのデータを読み取れるようにするには:

1. その統合用のトークンを作成する（または既存のトークンを編集する）
2. **APIスコープ**で**ウェブ分析**を**読み取り**に設定する
3. トークンを保存し、統合に提供する

**ウェブ分析**は読み取り専用のスコープであるため、「読み取り & 書き込み」オプションは選べません。統合は分析データのみを取得でき、ストアの設定を変更することはできません。

## トークンの使用状況を監視する

トークン一覧は以下を表示します:

- **使用回数** — トークンが使用された総回数
- **最後に使用された時刻** — トークンがリクエストのために最後に使用された時刻

これらのフィールドは、使用されていないトークン（失効の候補）を特定し、予期しないアクティビティを検出するのに役立ちます。使用回数の急激な増加は、意図した統合以外の誰かがトークンを使用している可能性を示唆しています。

## トークンを失効する

トークンを削除せずにすぐに使用を停止するには:

1.

トークン名をクリックします
2.

**有効**を外します
3.

保存

トークンは参照のためにリストに残りますが、その後のリクエストでは拒否されます。問題の調査中に一時的に統合を停止する必要がある場合にこれは役立ちます。

トークンを永久に削除するには:

1. リストからそのチェックボックスを選択します
2. アクションメニューから **選択したAPIトークンを削除** を選択します
3. 削除を確認します

削除されたトークンは復元できません。統合がまだアクセスを必要とする場合は、新しいトークンを作成し、統合の設定を更新してください。

## 例: Zapier統合の設定

**シナリオ:** 店舗をZapierに接続して注文通知を自動化したい場合です。

| フィールド | 値 |
|-------|-------|
| 名前 | `Zapier Order Automation` |
| トークンタイプ | 外部統合 |
| 説明 | Zapierが新しい注文を読み取り、通知をトリガーするために使用されます |
| APIスコープ | **注文**: 読み取り & 書き込み |
| 有効 | はい |
| 有効期限 | *(空欄のままにします)* |
| 允許IPアドレス | *(空欄のままにします — Zapierは動的IPを使用します)* |

**注文**スコープのみが割り当てられているため、このトークンが漏洩したとしても、商品、顧客メッセージ、スタッフアカウント、または店舗の他の部分にアクセスすることはできません。保存後、トークンの完全な値をコピーし、ZapierのSpwig統合設定に貼り付けてください。

## ヒント

すべてのマークダウンの書式、画像のパス、コードブロック、および技術用語を保持してください。

- すべてのトークンに明確で具体的な名前を付ける — ブラウザのトラブルシューティングを数カ月後に行う場合、`Shopify Sync v2` は `Token 3` よりもはるかに役に立つ
- 1つの統合ごとに1つのトークンを作成する — 統合が侵害された場合、他のトークンに影響を与えることなくそのトークンのみを無効にできる
- **統合が実際に必要なスコープのみを付与する** — レポートツールは Sales Analytics または Web Analytics への読み取りアクセスのみが必要であり、Products または Staff & Roles への読み取りと書き込みは不要である
- 第三者にトークンを渡す前に、変更フォーム上の **"This token can access:"** のサマリを確認する — これは、意図しないアクセスを付与していないかを確認する最も速い方法である
- 書き込みアクセスは、作成者スタッフの役割にも依存していることを覚えておく — スコープが Read & Write でも、書き込みがまだ失敗している場合は、そのユーザーの役割権限も確認する必要がある
- 一時的なプロジェクトや一時的な統合で使用するトークンには有効期限を設定する — これにより、忘れられたトークンが無期限に有効なままになるリスクを低減できる
- 数か月に一度、トークンリストを確認し、**Last Used** 日が予期せぬほど古いトークンを無効にする — これらはもはや実行されていない統合に属している可能性がある
- トークンが漏洩した可能性がある場合は、直ちに無効にし、代替トークンを作成し、影響を受けた統合を更新した後でアクセスを再び有効にする
