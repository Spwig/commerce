---
title: 付款設定
---

付款服務商將您的商店連接到付款網關，讓您可以在結帳時接受信用卡、數位錢包和其他付款方式。Spwig 支援同時使用多個服務商，為您的客戶提供靈活的付款選項。

![付款服務商](/static/core/admin/img/help/payment-setup/payment-dashboard.webp)

## 可用服務商

| 服務商 | 說明 |
|----------|-------------|
| **Stripe** | 信用卡、Apple Pay、Google Pay 和 135+ 種貨幣 |
| **PayPal** | PayPal 帳戶餘額、信用卡/借記卡以及後付選項 |
| **Airwallex** | 為跨境電商優化的多幣種付款 |
| **Square** | 支援現場和線上付款，並整合 POS 系統 |
| **Revolut** | 快速的歐洲付款，具競爭力的外匯匯率 |

## 連接服務商

前往 **設定 > 付款服務商**，並點擊 **連接服務商** 以啟動設定向導。

### 第 1 步：選擇服務商

從可用的付款服務商中選擇。每張卡片顯示服務商支援的功能和地區。

### 第 2 步：設定說明

查看特定服務商的設定指南。這包括：
- 如何在服務商處建立帳戶（如果您還沒有帳戶）
- 如何在服務商的儀表板中找到您的 API 權限憑證
- 任何前提條件（例如企業驗證）

### 第 3 步：輸入憑證

輸入您的 API 權限憑證：
- **API 金鑰 / 密碼** — 從服務商的儀表板取得的驗證憑證
- **結帳模式** — 選擇客戶如何與付款表單互動：

| 模式 | 說明 |
|------|-------------|
| **Hosted** | 將客戶導向服務商的付款頁面（例如 Stripe Checkout）。最簡單的設定，PCI 合規性由服務商處理。 |
| **Integrated** | 將付款表單直接嵌入您的結帳頁面。體驗無縫，但需要服務商的 JavaScript SDK。 |

- **測試環境 / 真實環境** — 從測試環境開始進行測試，準備好後切換到真實環境

### 第 4 步：測試連線

點擊 **測試連線** 以驗證您的憑證是否有效。向導會檢查：
- API 金鑰驗證
- 帳戶權限
- Webhook 端點的可訪問性

### 第 5 步：設定並儲存

完成提供者的設定：
- **啟用** — 啟用或停用提供者
- **預設提供者** — 設為結帳時的主要付款方式
- **顯示名稱** — 在結帳時顯示給客戶的名稱
- **排序順序** — 控制提供者在結帳時出現的順序（數字較小的會先出現）

## 支付儀表板

前往 **設定 > 支付儀表板** 以查看您的支付活動概覽：

### 需要處理的動作

頂部的警示卡片突出顯示需要關注的問題：
- **失敗交易** — 無法處理的付款
- **待處理的捕獲** — 已授權但尚未捕獲的付款
- **連線錯誤** — 存在連線問題的提供者

### 收入分析

- **收入圖表** — 隨時間顯示付款量的視覺化分類，按天、週或月分組
- **效能指標** — 總收入、成功率、平均交易價值和退款率
- **提供者比較** — 每個連接提供者的效能卡片並排顯示

### 交易細分

- **狀態分佈** — 已完成、待處理、失敗和退款的交易數量
- **付款方式組合** — 顧客最常使用的付款方式（信用卡、PayPal、數位錢包）

## 管理付款方式

每個提供者支援不同的付款方式。您可以根據國家啟用或停用特定的付款方式：

1. 前往提供者的設定頁面
2. 滾動到 **付款方式** 區段
3. 啟用或停用個別方式
4. 使用國家層級的控制來限制特定市場的付款方式

當您在一個地區某種付款方式很受歡迎，但在其他地區卻不然時，這很有用（例如荷蘭的 iDEAL、比利時的 Bancontact）。

## Webhooks

Webhooks 可以讓您的商店與支付提供商實時同步。

它們處理以下事件：
- 支付完成或失敗
- 退款處理
- 爭議和退單開啟
- 訂閱續訂

### 自動設置

當您連接提供商時，Spwig 會自動向提供商註冊一個 Webhook 端點。Webhook URL 會顯示在提供商的配置頁面上供參考。

### Webhook 監控

每個進來的 Webhook 都會記錄以下信息：
- **事件類型**（例如，payment_intent.succeeded）
- **時間戳**和處理狀態
- **負載**用於調試

如果 Webhook 無法處理，會記錄為錯誤，以便您進行調查。

## 使用多個提供商

您可以同時連接多個支付提供商：

- **默認提供商** — 在結帳時默認選擇的提供商。在提供商的配置中標記一個提供商為默認。
- **排序順序** — 控制結帳時的顯示順序。客戶可以看到所有活動的提供商，並可以選擇他們偏好的一個。
- **故障轉移** — 如果某個提供商出現停機，客戶仍然可以使用替代提供商進行支付。

## 小技巧

- 從 **Stripe** 或 **PayPal** 開始 — 它們覆蓋了最廣泛的支付方式和地區。
- 使用 **沙盒/測試模式** 來處理測試交易，再上線。每個提供商的文檔中都有測試信用卡號。
- 啟用 **多個提供商**，以便在某個提供商出現問題時，客戶有備用的支付選項。
- 為您偏好的提供商設置 **較低的排序順序**，使其在結帳時首先顯示。
- 每週監控支付儀表板，以及早發現失敗的交易和連接問題。
- 保持您的 API 凭證安全 — 它們以加密形式存儲在數據庫中，但永遠不要與他人共享。
