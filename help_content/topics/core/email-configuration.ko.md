---
title: 이메일 구성
---

이메일 구성은 스토어가 전자상거래 이메일을 전송하는 방식을 제어합니다. 주문 확인, 배송 알림, 비밀번호 재설정 등이 포함됩니다. Spwig은 내장된 SMTP 서버를 포함하고 있으며, 더 높은 전달률을 위해 외부 이메일 공급자를 지원합니다.

![이메일 계정](/static/core/admin/img/help/email-configuration/email-accounts.webp)

## 사용 가능한 공급자

| 공급자 | 설명 |
|----------|-------------|
| **내장된 SMTP** | Spwig에 포함된 무료, 자체 호스팅 이메일 서버입니다. 자동 DKIM 서명이 가능합니다. |
| **Gmail API** | OAuth 인증을 사용하여 Gmail 또는 Google Workspace 계정을 통해 이메일을 보냅니다. |
| **일반 SMTP** | SendGrid, Mailgun, Amazon SES 또는 자체 메일 서버를 포함한 모든 SMTP 서버에 연결합니다. |

## 이메일 설정하기

**설정 > 이메일 계정**으로 이동하여 설정 마법사를 시작하려면 **이메일 계정 추가**를 클릭하십시오.

### 단계 1: 공급자 선택

이메일 공급자를 선택하십시오. 내장된 SMTP 서버는 시작하기 가장 쉬운 옵션입니다. 외부 계정이 필요 없습니다.

### 단계 2: 인증 정보 구성

선택한 공급자의 인증 정보를 입력하십시오:

- **내장된 SMTP** — 인증 정보가 필요 없습니다. 서버는 Spwig 설치와 함께 실행됩니다.
- **Gmail API** — Google OAuth를 통해 인증하십시오. Google 계정으로 로그인하라는 안내가 표시됩니다.
- **일반 SMTP** — SMTP 서버 주소, 포트, 사용자 이름 및 비밀번호를 입력하십시오.

### 단계 3: 발신자 구성

 outgoing 이메일의 발신자 정체성을 설정하십시오:

- **보내는 사람 이메일** — "보내는 사람" 필드에 표시되는 이메일 주소 (예: orders@yourstore.com)
- **보내는 사람 이름** — 이메일 주소 옆에 표시되는 이름 (예: "Your Store Name")
- **답장 이메일** — 고객이 답장을 보낼 주소 (보내는 사람 주소와 다를 수 있음)

### 단계 4: DNS 검증

도메인의 이메일 인증 기록을 검증하십시오. 마법사는 세 가지 DNS 기록을 확인합니다.

| 레cord | 목적 |
|--------|---------|
| **SPF** | 도메인을 대신하여 이메일을 전송할 수 있도록 서버를 승인합니다 |
| **DKIM** | 이메일이 변조되지 않았음을 증명하기 위해 디지털로 서명합니다 |
| **DMARC** | 수신 서버가 SPF/DKIM 검사를 통과하지 못한 이메일을 어떻게 처리해야 하는지 지시합니다 |

각 레cord에 대해, 마법사는 다음을 보여줍니다:
- **현재 상태** — 레cord가 올바르게 구성되었는지 여부
- **필요한 값** — 도메인 등록업체에서 추가해야 하는 정확한 DNS 레cord
- **확산 상태** — 최근 변경 사항이 적용되었는지 여부 (DNS 변경 사항은 최대 48시간이 걸릴 수 있습니다)

내장된 SMTP 서버는 자동으로 도메인용 DKIM 키를 생성합니다.

### 단계 5: 테스트 이메일 전송

모든 것이 작동하는지 확인하기 위해 테스트 이메일을 전송합니다:
1. 수신자 이메일 주소를 입력하십시오
2. **테스트 전송**을 클릭하십시오
3. 테스트 메시지가 포함된 수신 캐비닛을 확인하십시오
4. 스팸 경고 없이 이메일이 도착하는지 확인하십시오

### 단계 6: 저장 및 활성화

구성 정보를 저장하고 계정을 활성화하십시오. 기본 이메일 계정이 되어야 할 경우 **기본**으로 표시하십시오.

## 이메일 템플릿

Spwig은 모든 거래 이벤트용 30개 이상의 이메일 템플릿을 제공합니다. **설정 > 이메일 템플릿**으로 이동하여 관리하십시오.

### 템플릿 유형

템플릿은 다음을 포함한 모든 스토어 이벤트를 커버합니다:
- **주문 라이프사이클** — 확인, 처리, 발송, 배송 완료, 취소
- **결제** — 영수증, 환불 확인, 실패한 결제
- **고객 계정** — 환영, 비밀번호 재설정, 이메일 인증
- **선물 카드** — 전달, 잔액 알림
- **배송** — 추적 업데이트, 배송 확인
- **디지털 제품** — 다운로드 링크, 라이선스 키
- **마케팅** — 장바구니 이탈 복구, 리뷰 요청

### 템플릿 맞춤 설정

1. 템플릿 목록으로 이동하십시오
2. 편집할 템플릿을 클릭하십시오
3. 제목 줄, 헤더, 본문 콘텐츠, 푸터를 수정하십시오
4. 동적 콘텐츠를 위한 템플릿 변수 (예: `{{ order.number }}`, `{{ customer.name }}`)를 사용하십시오
5. 저장하기 전에 이메일 미리보기를 수행하십시오

### 다국언 지원

모든 마크다운 포맷, 이미지 경로, 코드 블록, 기술 용어를 보존하십시오.

이메일 템플릿은 여러 언어를 지원합니다:
- 각 템플릿은 스토어의 모든 활성 언어에 대한 번역을 가질 수 있습니다
- 시스템은 고객이 선호하는 언어로 이메일을 전송합니다
- **언어 폴백 체인** — 번역이 사용할 수 없는 경우, 시스템은 스토어의 기본 언어로 폴백합니다
- **AI 번역** 기능을 사용하여 템플릿을 다른 언어로 자동으로 번역하세요

### 템플릿 복제

시스템 템플릿의 사용자 정의 버전을 생성하려면:
1. 수정하려는 템플릿을 엽니다
2. **템플릿 복제**를 클릭합니다
3. 복제된 버전을 편집합니다
4. 복제본은 원래 시스템 템플릿보다 우선합니다

## 이메일 대기열

**설정 > 이메일 대기열**에서 발신 이메일을 모니터링합니다:

- **대기 중** — 전송을 기다리는 이메일
- **전송 중** — 현재 전송 중인 이메일
- **전송됨** — 성공적으로 전달된 이메일
- **실패** — 전달할 수 없는 이메일 (오류 세부 정보 포함)
- **바운스** — 수신자의 메일 서버에 의해 거부된 이메일

이메일을 클릭하여 수신자, 제목, 전송 시간 및 전달 상태를 포함한 전체 세부 정보를 확인합니다.

## 전달 추적

이메일 참여도를 추적합니다:
- **열림** — 이메일을 연 수신자의 수
- **클릭** — 이메일 내 링크 클릭
- **바운스** — 하드 바운스 및 소프트 바운스 추적
- **신고** — 수신자의 스팸 신고

## 여러 계정

여러 이메일 계정을 구성할 수 있습니다:
- **기본 계정** — 별도로 지정되지 않는 한 모든 발신 이메일에 사용됩니다
- **폴백** — 기본 계정이 실패하면 이메일이 재시도 대기열에 추가됩니다
- 다양한 용도(예: 거래용 이메일, 마케팅용 이메일)에 다른 계정을 사용하세요

## 이메일 전달 모드

**설정 > 스토어 설정**으로 이동하여 스토어가 발신 이메일을 처리하는 방식을 제어합니다. 이러한 설정은 개발 및 테스트 중에 유용합니다.

| 모드 | 설명 |
|------|-------------|
| **라이브** | 이메일이 실제 수신자에게 정상적으로 전송됩니다 |
| **중지** | 이메일이 대기열에 보관되며, 다시 라이브로 전환할 때까지 전송되지 않습니다 |
| **로그만** | 이메일이 아웃바운드에 기록되지만 결코 전송되지 않습니다 |

### 테스트 리디렉션 이메일

모든 발송 이메일을 가로채서 단일 주소로 리디렉션하도록 **테스트 리디렉션 이메일** 주소를 설정하십시오. 설정이 완료되면 실제 수신자와 관계없이 모든 이메일이 해당 주소로 전송됩니다. 이 기능은 실제 고객에게 실수로 이메일을 보내지 않고 이메일 템플릿을 테스트하는 데 유용합니다. 실제 수신자에게 이메일을 보내려면 비워 두세요.

### 사전 모드 이메일 허용 목록

사전 또는 개발 모드에서, 허용된 주소 목록에만 이메일 전송을 제한할 수 있습니다. 허용 목록에 있는 주소로만 이메일이 전송됩니다. 다른 모든 이메일은 로깅되지만 결코 전송되지 않습니다. 관리자 이메일은 항상 자동으로 포함됩니다. 최대 10개의 주소를 추가할 수 있습니다.

## 팁

- 빠른 설정을 위해 **내장된 SMTP** 서버를 사용하십시오. 필요에 따라 외부 공급사로 전환하십시오.
- 항상 **SPF, DKIM, DMARC** 레코드를 구성하십시오. 이들 없이는 이메일이 스팸 폴더에 들어갈 가능성이 훨씬 높습니다.
- 구성 변경 후 **테스트 이메일**을 보내서 전달이 제대로 되는지 확인하십시오.
- 이메일 대기열을 정기적으로 모니터링하여 **실패** 또는 **반송**된 이메일을 확인하십시오. 이는 전달 문제를 나타냅니다.
- **프로페셔널한 발신 주소**(예: orders@yourstore.com)를 사용하되, 스팸으로 간주되지 않도록 무료 이메일 주소 대신 사용하십시오.
- 템플릿을 간결하게 유지하십시오. 트랜잭셔널 이메일은 정보를 빠르게 전달해야 하며, 마케팅 뉴스레터가 되어서는 안 됩니다.
