---
title: โทเค็น API
---

โทเค็น API เป็นกุญแจที่ปลอดภัยซึ่งอนุญาตให้บริการภายนอกและระบบการผสานรวมสามารถสื่อสารกับร้านค้าของคุณได้ เมื่อบริการภายนอกหรือเครื่องมืออื่น ๆ ต้องการเข้าถึงข้อมูลของร้านค้าของคุณหรือกระตุ้นการดำเนินการ มันจะส่งโทเค็น API ไปพร้อมกับคำขอทุกครั้ง เพื่อให้ร้านค้าของคุณสามารถตรวจสอบว่าคำขอได้รับการอนุญาตแล้ว คุณสามารถสร้างและจัดการโทเค็นทั้งหมด รวมถึงส่วนที่โทเค็นสามารถเข้าถึงได้ในร้านค้าของคุณได้จากส่วน API Tokens ในแดชบอร์ดผู้ดูแลระบบของคุณ

## กรณีที่คุณต้องใช้โทเค็น API

คุณมักจะต้องสร้างโทเค็น API เมื่อ:

- เชื่อมต่อกับบริการภายนอกหรือเครื่องมืออัตโนมัติที่ต้องการอ่านหรือเขียนข้อมูลในร้านค้าของคุณ
- ตั้งค่าตัวรับเวิร์กฮุคที่ต้องการตรวจสอบการเรียกเข้าที่มาถึง
- ตั้งค่าระบบช่วยเหลือ Spwig สำหรับการติดตั้งของคุณ
- สร้างการผสานรวมแบบกำหนดเองโดยใช้ API ของ Spwig
- สังเคราะห์ข้อมูลระหว่างร้านค้า Spwig ของคุณกับระบบอื่น

แต่ละการผสานรวมควรจะมีโทเค็นของตัวเอง เพื่อให้คุณสามารถยกเลิกการเข้าถึงสำหรับบริการหนึ่ง ๆ โดยไม่กระทบต่ออีกบริการที่เหลือ

## ประเภทของโทเค็น

เมื่อคุณสร้างโทเค็น คุณจะเลือกประเภทที่อธิบายวัตถุประสงค์ของมัน ประเภทนี้เป็นเพียงข้อมูลอ้างอิงสำหรับคุณ และช่วยให้คุณติดตามว่าโทเค็นแต่ละตัวทำอะไรได้

| ประเภท | วัตถุประสงค์ |
|--------|-------------|
| **ระบบช่วยเหลือ** | ใช้โดยระบบเอกสารช่วยเหลือ Spwig |
| **การผสานรวมภายนอก** | บริการภายนอก เครื่องมืออัตโนมัติ (เช่น Zapier) หรือเครื่องมือซิงค์ข้อมูล |
| **เวิร์กฮุค** | การตรวจสอบสำหรับตัวรับเวิร์กฮุคหรือปลายทาง |
| **แบบกำหนดเอง** | วัตถุประสงค์อื่นใดที่ไม่ตรงกับประเภทข้างต้น |
| **การซิงค์อินสแตนซ์** | การซิงค์ระหว่างการติดตั้ง Spwig หรือบริการ Spwig ภายนอก |

## API scopes: การควบคุมสิ่งที่โทเค็นสามารถเข้าถึงได้

โทเค็นแต่ละตัวยังมีส่วน **API Scopes** ที่กำหนดว่าโทเค็นสามารถเข้าถึงส่วนใดของร้านค้าของคุณได้โดยตรง แทนที่จะให้โทเค็นเข้าถึงทุกสิ่งโดยไม่มีข้อจำกัด คุณจะอนุญาตให้เข้าถึงแต่ละพื้นที่ทีละส่วน และในระดับที่การผสานรวมที่ต้องการจริง ๆ

**โทเค็นที่ไม่ได้เลือก scope ใด ๆ จะไม่สามารถเข้าถึง API ใด ๆ ได้** แม้ว่าโทเค็นนั้นจะยังคงใช้งานได้อยู่และมีความถูกต้อง

นี่คือค่าเริ่มต้นสำหรับโทเคนใหม่ ดังนั้นการผสานระบบจะไม่ทำงานจนกว่าคุณจะอนุญาตให้โทเคนนั้นเข้าถึงข้อมูลโดยเจตนา

สำหรับแต่ละ scope คุณสามารถเลือกระดับการเข้าถึงได้สามระดับ:

| ระดับการเข้าถึง | สิ่งที่อนุญาตให้ทำ |
|----------------|-------------------|
| **ไม่มีสิทธิ์เข้าถึง** | โทเคนนี้ไม่สามารถเรียกใช้ endpoint ใด ๆ ในพื้นที่นี้ได้ |
| **อ่านข้อมูล** | โทเคนนี้สามารถดึงข้อมูลจากพื้นที่นี้ได้ แต่ไม่สามารถเปลี่ยนแปลงอะไรได้ |
| **อ่านและเขียน** | โทเคนนี้สามารถดึงข้อมูลและสร้าง แก้ไข หรือลบข้อมูลได้ |

scope ถูกจัดกลุ่มเพื่อให้ตรงกับพื้นที่ต่าง ๆ ในแดชบอร์ดผู้ดูแลระบบของคุณ:

| กลุ่ม | Scope | มีสิทธิ์อ่านและเขียน? | อนุญาตให้เข้าถึง |
|-------|-------|:---:|-------------------|
| การวิเคราะห์ | **การวิเคราะห์ยอดขาย** | อ่านเท่านั้น | แดชบอร์ดยอดขาย, KPI, การวิเคราะห์ผลิตภัณฑ์/ลูกค้า/หมวดหมู่, การเปรียบเทียบ และการส่งออก |
| การวิเคราะห์ | **การวิเคราะห์เว็บไซต์** | อ่านเท่านั้น | การวิเคราะห์ผู้เยี่ยมชมและปริมาณการเข้าชม: ภาพรวม, แนวโน้ม, หน้าที่ได้รับการเข้าชมมากที่สุด, ภูมิศาสตร์ และแหล่งที่มา |
| แคตตาล็อก | **ผลิตภัณฑ์** | ใช่ | ผลิตภัณฑ์, ตัวแปร, รูปภาพ, การปรับปรุงสต็อก และการกำหนดค่าคุณสมบัติ |
| แคตตาล็อก | **หมวดหมู่** | ใช่ | หมวดหมู่ผลิตภัณฑ์ รวมถึงรูปภาพและแบนเนอร์ |
| แคตตาล็อก | **แบรนด์** | ใช่ | แบรนด์ผลิตภัณฑ์ |
| แคตตาล็อก | **คุณสมบัติ** | ใช่ | การกำหนดค่าคุณสมบัติของผลิตภัณฑ์ |
| แคตตาล็อก | **สต็อก** | ใช่ | แดชบอร์ดสต็อก, ความเร็วสต็อก, การเคลื่อนไหว, การแนะนำการสั่งซื้อใหม่ และการตั้งค่าสต็อก |
| คำสั่งซื้อ | **คำสั่งซื้อ** | ใช่ | คำสั่งซื้อ, หมายเหตุคำสั่งซื้อ, การอัปเดตสถานะ/การติดตาม, การยกเลิก, การคืนเงิน และเอกสารคำสั่งซื้อ |
| ลูกค้า | **ข้อความลูกค้า** | ใช่ | ข้อความจากฟอร์มติดต่อและหมายเหตุคำสั่งซื้อ รวมถึงการอัปเดตสถานะและการตอบกลับ |
| ร้านค้าและตั้งค่า | **ตั้งค่าร้านค้า** | ใช่ | ตั้งค่าร้านค้า, ภาษาที่ใช้ได้ และการกำหนดค่าแบรนด์ (ชื่อ, สี, โลโก้) |
| ผู้ใช้และสิทธิ์ | **พนักงานและบทบาท** | ใช่ | บัญชีพนักงาน, การเชิญ, บทบาท และแคตตาล็อกสิทธิ์ |

scope **การวิเคราะห์** สอง scope นี้จะมีสิทธิ์อ่านเท่านั้นเสมอ — ข้อมูลการรายงานไม่มีแนวคิดเรื่องการเขียน ดังนั้นตัวเลือกจะแสดงเฉพาะ **ไม่มีสิทธิ์เข้าถึง** หรือ **อ่านข้อมูล** เท่านั้นสำหรับ scope นี้

[![The API Scopes picker, with an access note above the Analytics and Catalog scope groups](/static/core/admin/img/help/api-tokens/api-token-scope-picker.webp)](https://example.com)

ด้านล่างของตัวเลือกขอบเขต (scope picker) จะมีรายการ **"This token can access:"** ที่แสดงข้อมูลแบบอ่านได้เท่านั้น ซึ่งจะแสดงขอบเขตทุกอย่างที่คุณอนุญาตและระดับของแต่ละขอบเขต เพื่อให้คุณสามารถตรวจสอบสิทธิ์ของโทเคนได้อย่างรวดเร็วโดยไม่จำเป็นต้องถอดรหัสตัวเลือกขอบเขต

[![The "This token can access" summary listing each granted scope and its Read or Read & Write level](/static/core/admin/img/help/api-tokens/api-token-scope-summary.webp)](https://example.com)

### สิทธิ์ที่โทเคนใช้จริง

ขอบเขตของโทเคนอธิบายถึง *ขีดจำกัด* ของสิ่งที่มันสามารถทำได้ — แต่โทเคนยังคงสืบทอดสิทธิ์จริงในโลกของพนักงานที่สร้างมันด้วย:

- โทเคนจะไม่สามารถทำสิ่งต่าง ๆ ด้วย **สิทธิ์ผู้ใช้หลัก (superuser)** ได้เลย แม้ว่าพนักงานที่สร้างมันจะเป็นผู้ใช้หลัก
- **การอ่านและการเขียน** บนขอบเขตจะทำงานได้ก็ต่อเมื่อบทบาทของพนักงานที่สร้างโทเคนอนุญาตให้เขียนในพื้นที่นั้น หากบทบาทของพนักงานนั้นเป็นเพียงการดูเท่านั้นสำหรับสินค้า เช่น โทเคนที่สร้างด้วย "สินค้า: อ่านและการเขียน" จะสามารถอ่านได้เพียงอย่างเดียว — บทบาทจะทำหน้าที่เป็นประตูที่สองเหนือขอบเขต
- หากพนักงานที่สร้างโทเคนถูกลบหรือบัญชีถูกปิดใช้งาน โทเคนจะสูญเสียการเข้าถึง API ทันที ไม่ว่าโทเคนนั้นจะมีขอบเขตใดก็ตาม — ไม่มีผู้ใช้ที่ได้รับอนุญาตให้โทเคนทำแทนอีกต่อไป

นี่หมายความว่าวิธีที่ปลอดภัยที่สุดในการกำหนดขอบเขตของโทเคนคือการสร้างมันขณะที่คุณล็อกอินเป็นพนักงานที่มีบทบาทตรงกับสิทธิ์ที่คุณต้องการให้โทเคนมี

## การสร้างโทเคน API

1.

ไปที่ **Settings > API Tokens**
2.

คลิก **+ Add API Token**
3.

ใส่ **Name** ที่ชัดเจนว่าโทเคนนี้ใช้สำหรับอะไร (เช่น `Zapier Product Sync` หรือ `Help System API`)
4.

เลือก **Token Type** ที่เหมาะสม
5.

เพิ่ม **Description** ที่มีรายละเอียดเพิ่มเติมเกี่ยวกับการผสานระบบ (integration) ได้ (ไม่จำเป็นต้องทำ)
6.

ใน **API Scopes** เลือก **No access**, **Read**, หรือ **Read & Write** สำหรับแต่ละพื้นที่ที่การผสานระบบต้องการ — ทิ้งขอบเขตอื่น ๆ ไว้ที่ **No access**
7.

รักษาการจัดรูปแบบมาร์กดาวน์ ชื่อเส้นทางรูปภาพ บล็อกโค้ด และคำศัพท์ทางเทคนิคไว้ทั้งหมด

ตั้งค่าสถานะ **Active**, **วันหมดอายุ**, และ **IP ที่อนุญาต** ตามที่จำเป็น (ดูข้อมูลเพิ่มเติมด้านล่าง)
8.

คลิก **Save**

หลังจากบันทึกแล้ว ค่าโทเคนทั้งหมดจะแสดงบนหน้ารายละเอียด คัดลอกมันทันที — โทเคนจะถูกบังไว้ในรูปแบบรายการเพื่อความปลอดภัย และไม่สามารถเรียกคืนค่าทั้งหมดได้อีกครั้งหลังจากที่คุณออกจากหน้านี้

## ความปลอดภัยของค่าโทเคน

Spwig จะแสดงค่าโทเคนทั้งหมดเพียงครั้งเดียว: ทันทีหลังจากที่คุณบันทึกโทเคนใหม่ หลังจากนั้น รายการจะแสดงเฉพาะรูปแบบที่ถูกบังไว้เท่านั้น (เช่น `spw_••••••••••••••••••••3f8a`)

หากคุณสูญเสียค่าโทเคน คุณจะไม่สามารถกู้คืนมันได้ คุณจะต้องลบโทเคนเก่าและสร้างโทเคนใหม่ แล้วอัปเดตการผสานที่ใช้โทเคนนั้น

**อย่าแชร์ค่าโทเคนผ่านอีเมล ข้อความแชท หรือโค้ด** ให้ปฏิบัติกับมันเหมือนกับรหัสผ่าน

## การตั้งค่าวันหมดอายุ

ฟิลด์ **Expires At** ตั้งค่าวันและเวลาที่โทเคนจะหยุดทำงานโดยอัตโนมัติ ปล่อยว่างไว้หากโทเคนไม่ควรหมดอายุ

การตั้งค่าวันหมดอายุมีประโยชน์ในกรณีต่อไปนี้:

- การผสานชั่วคราวที่มีวันสิ้นสุดที่กำหนดไว้
- โทเคนที่ให้กับบุคคลที่สามที่คุณต้องการให้การเข้าถึงถูกยกเลิกโดยอัตโนมัติ
- เพิ่มชั้นความปลอดภัยเพิ่มเติมสำหรับการผสานที่มีสิทธิ์สูง

เมื่อโทเคนหมดอายุ การร้องขอที่ใช้โทเคนนั้นจะถูกปฏิเสธ คุณสามารถขยายการเข้าถึงได้โดยการอัปเดตวันหมดอายุในฟิลด์ **Expires At** หรือสร้างโทเคนทดแทน

## การจำกัดให้ใช้งานเฉพาะที่อยู่ IP ที่กำหนด

ฟิลด์ **Allowed IPs** รับรายการที่อยู่ IP เมื่อรายการไม่ว่างเปล่า โทเคนจะทำงานได้ก็ต่อเมื่อคำขอมาจากที่อยู่เหล่านั้นเท่านั้น

ตัวอย่างเช่น หากเครื่องมือวิเคราะห์ของคุณทำงานบนเซิร์ฟเวอร์ที่ `203.0.113.42` การเพิ่มที่อยู่ IP นี้หมายความว่าโทเคนจะไม่ถูกใช้ผิดจากสถานที่อื่น ๆ แม้จะถูกหลบหลีก

ปล่อยฟิลด์ **Allowed IPs** ว่างไว้เพื่ออนุญาตให้คำขอมาจากที่อยู่ IP ใด ๆ

**การหมดอายุและการจำกัด IP ถูกตรวจสอบอย่างอิสระจาก Scopes** โทเคนที่หมดอายุหรือไม่ได้อยู่ในรายการอนุญาตจะถูกปฏิเสธก่อนที่จะพิจารณา Scopes ของมันเลย และโทเคนที่มี Scopes ที่กว้างขวางก็ยังถูกปฏิเสธทันทีที่มันหมดอายุหรือถูกเรียกจาก IP ที่ไม่ได้ระบุไว้

## การเรียกใช้ API โดยใช้โทเคน

การผสานระบบจะยืนยันตัวตนกับ API ผู้ดูแลระบบของ Spwig โดยการส่งโทเคนในหัวข้อ `Authorization`:

```
Authorization: Bearer <your-token-value>
```

ทุกจุดปลายของ API ผู้ดูแลระบบอยู่ภายใต้ `/api/admin/...` ผู้พัฒนาที่สร้างการผสานระบบของคุณจะตัดสินใจว่าจะเรียกใช้จุดปลายใด — หน้าที่ของคุณในฐานะผู้ขายคือการตรวจสอบให้แน่ใจว่าโทเคน **API Scopes** ครอบคลุมจุดปลายเหล่านั้น หากคำขอถูกปฏิเสธด้วยข้อผิดพลาดเกี่ยวกับสิทธิ์ อย่างแรกที่ควรตรวจสอบคือโทเคนนั้นได้รับสิทธิ์ใน Scope ที่ถูกต้องในระดับการเข้าถึงที่เหมาะสมหรือไม่

### ตัวอย่าง: การอ่านข้อมูลการวิเคราะห์การเข้าชมเว็บไซต์

Spwig เปิดเผยจุดปลาย `GET /api/admin/analytics/traffic/` ที่คืนค่าการวิเคราะห์การเข้าชมและข้อมูลการจราจรสำหรับร้านค้าของคุณ — ภาพรวมของการเข้าชมและผู้เข้าชมที่ไม่ซ้ำกัน แนวโน้มตามเวลา หน้าเว็บยอดนิยม ภูมิศาสตร์ของผู้เข้าชม และแหล่งที่มาของผู้อ้างอิง ในการให้เครื่องมือรายงานหรือแดชบอร์ดสามารถอ่านข้อมูลนี้ได้:

1. สร้างโทเคน (หรือแก้ไขโทเคนที่มีอยู่) สำหรับการผสานระบบดังกล่าว
2. ใน **API Scopes** ตั้งค่า **Web Analytics** เป็น **Read**
3. บันทึกโทเคนและให้โทเคนนั้นกับการผสานระบบ

เนื่องจาก **Web Analytics** เป็น Scope ที่อ่านเท่านั้น จึงไม่มีตัวเลือก "Read & Write" ให้เลือก — การผสานระบบสามารถดึงข้อมูลการวิเคราะห์เท่านั้น ไม่สามารถเปลี่ยนการตั้งค่าร้านค้าของคุณได้เลย

## การตรวจสอบการใช้โทเคน

รายการโทเคนแสดง:

- **Usage Count** — จำนวนครั้งทั้งหมดที่โทเคนถูกใช้งาน
- **Last Used** — เมื่อโทเคนถูกใช้ล่าสุดเพื่อทำคำขอ

ฟิลด์เหล่านี้ช่วยให้คุณระบุโทเคนที่ไม่ได้ใช้งาน (เป็นตัวเลือกที่เหมาะสมสำหรับการยกเลิก) และสังเกตกิจกรรมที่ไม่คาดคิด ความเพิ่มขึ้นอย่างกะทันหันในจำนวนการใช้งานอาจบ่งบอกว่าโทเคนถูกใช้โดยบุคคลอื่นนอกเหนือจากการผสานระบบตามที่ตั้งใจไว้

## การยกเลิกโทเคน

เพื่อหยุดโทเคนจากการทำงานทันทีโดยไม่ต้องลบมัน:

1.

คลิกที่ชื่อโทเคน
2.

ยกเลิกการเลือก **Active**
3.

บันทึก

โทเคนจะยังคงอยู่ในรายการของคุณเพื่อใช้อ้างอิง แต่จะถูกปฏิเสธสำหรับคำขอใด ๆ ที่ตามมา นี่เป็นประโยชน์เมื่อคุณต้องการระงับการผสานรวมชั่วคราวขณะสืบสวนปัญหา

เพื่อลบโทเคนออกอย่างถาวร:

1. เลือกช่องถูกต้องในรายการ
2. เลือก **Delete selected API tokens** จากเมนูการดำเนินการ
3. ยืนยันการลบ

เมื่อได้รับการลบ โทเคนจะไม่สามารถกู้คืนได้ หากการผสานรวมยังต้องการการเข้าถึง ให้สร้างโทเคนใหม่และอัปเดตการตั้งค่าการผสานรวม

## ตัวอย่าง: การตั้งค่าการผสานรวม Zapier

**สถานการณ์:** คุณต้องการเชื่อมต่อร้านค้าของคุณกับ Zapier เพื่ออัตโนมัติการแจ้งเตือนคำสั่งซื้อ

| Field | Value |
|-------|-------|
| Name | `Zapier Order Automation` |
| Token Type | External Integration |
| Description | Used by Zapier to read new orders and trigger notifications |
| API Scopes | **Orders**: Read & Write |
| Active | Yes |
| Expires At | *(ปล่อยว่าง)* |
| Allowed IPs | *(ปล่อยว่าง — Zapier ใช้ IP แบบไดนามิก)* |

อนุญาตเฉพาะ **Orders** scope ดังนั้นแม้โทเคนนี้จะถูกเปิดเผยในอนาคต มันก็ไม่สามารถเข้าถึงสินค้า ข้อความลูกค้า บัญชีพนักงาน หรือส่วนอื่น ๆ ของร้านค้าของคุณได้ หลังจากบันทึก ให้คัดลอกค่าโทเคนทั้งหมดและวางไว้ในการตั้งค่าการผสานรวม Spwig ของ Zapier

## เคล็ดลับ

รักษาการจัดรูปแบบมาร์กดาวน์ ชื่อเส้นทางภาพ บล็อกโค้ด และคำศัพท์ทางเทคนิคไว้ทั้งหมด

- ให้แต่ละ token มีชื่อที่ชัดเจนและเฉพาะเจาะจง — `Shopify Sync v2` มีประโยชน์มากกว่า `Token 3` มากเมื่อคุณกำลังแก้ไขปัญาในภายหลัง
- สร้าง token หนึ่งต่อการผสาน (integration) — หากการผสานถูกบุกรุก คุณสามารถยกเลิก token นั้นเพียงตัวเดียวโดยไม่กระทบต่อ token อื่นๆ
- **อนุญาตเฉพาะ scope ที่การผสานต้องการจริงๆ** — เครื่องมือรายงานเพียงแค่ต้องการสิทธิ์การอ่านข้อมูลจาก Sales Analytics หรือ Web Analytics เท่านั้น ไม่ใช่สิทธิ์การอ่านและเขียนข้อมูลใน Products หรือ Staff & Roles
