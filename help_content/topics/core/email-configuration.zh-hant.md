---
title: 電子郵件設定
---

電子郵件設定控制您的商店如何發送交易性電子郵件——訂單確認、出貨通知、密碼重設等。Spwig 內建 SMTP 伺服器，並支援外部電子郵件供應商以提高送達率。

![電子郵件帳戶](/static/core/admin/img/help/email-configuration/email-accounts.webp)

## 可用供應商

| 供應商 | 說明 |
|----------|-------------|
| **內建 SMTP** | 隨 Spwig 提供的免費自架電子郵件伺服器。自動 DKIM 簽章。 |
| **Gmail API** | 使用 OAuth 驗證，透過您的 Gmail 或 Google Workspace 帳戶發送。 |
| **通用 SMTP** | 連接任何 SMTP 伺服器（SendGrid、Mailgun、Amazon SES 或您自己的郵件伺服器）。 |

## 設定電子郵件

前往 **設定 > 電子郵件帳戶**，並點擊 **新增電子郵件帳戶** 以啟動設定精靈。

### 步驟 1：選擇供應商

選擇您的電子郵件供應商。內建 SMTP 伺服器是最簡單的入門選項——它不需要外部帳戶。

### 步驟 2：設定憑證

輸入您所選供應商的憑證：

- **內建 SMTP** — 不需要憑證。伺服器運行在您的 Spwig 安裝環境上。
- **Gmail API** — 透過 Google OAuth 進行驗證。您將被重定向以使用您的 Google 帳戶登入。
- **通用 SMTP** — 輸入 SMTP 伺服器地址、埠號、使用者名稱和密碼。

### 步驟 3：寄件人設定

設定外發電子郵件的寄件人身份：

- **寄件人電子郵件** — 顯示在「寄件人」欄位的電子郵件地址（例如：orders@yourstore.com）
- **寄件人名稱** — 顯示在電子郵件地址旁邊的名稱（例如：「您的商店名稱」）
- **回覆至電子郵件** — 客戶回覆的目的地（可以與寄件人地址不同）

### 步驟 4：DNS 驗證

驗證您網域的電子郵件驗證記錄。精靈會檢查三個 DNS 記錄：

| 記錄 | 用途 |
|--------|---------|
| **SPF** | 授權您的伺服器代表您的網域發送電子郵件 |
| **DKIM** | 對電子郵件進行數位簽章，以證明其未被篡改 |
| **DMARC** | 告知接收伺服器應如何處理未通過 SPF/DKIM 檢查的電子郵件 |

對於每條記錄，嚮導會顯示：
- **目前狀態** — 記錄是否已正確配置
- **所需值** — 需在您的網域註冊商處添加的準確 DNS 記錄
- **傳播狀態** — 最近的變更是否已生效（DNS 變更可能需要長達 48 小時）

內建的 SMTP 伺服器會自動為您的網域生成 DKIM 金鑰。

### 步驟 5：發送測試郵件

發送一封測試郵件以驗證一切運作正常：
1. 輸入收件人電子郵件地址
2. 點擊 **發送測試**
3. 檢查您的收件匣以查看測試訊息
4. 驗證郵件到達時沒有垃圾郵件警告

### 步驟 6：儲存並啟用

儲存配置並將帳戶設為啟用狀態。如果它應作為主要電子郵件帳戶，請將其標記為 **預設**。

## 電子郵件範本

Spwig 包含 30 多個用於所有交易事件的電子郵件範本。前往 **設定 > 電子郵件範本** 進行管理。

### 範本類型

範本涵蓋所有商店事件，包括：
- **訂單生命週期** — 確認、處理中、已出貨、已送達、已取消
- **付款** — 收據、退款確認、付款失敗
- **客戶帳戶** — 歡迎、密碼重設、電子郵件驗證
- **禮券** — 交付、餘額通知
- **運送** — 追蹤更新、送達確認
- **數位產品** — 下載連結、授權金鑰
- **行銷** — 遺失購物車挽回、評論請求

### 自訂範本

1. 前往範本列表
2. 點擊範本進行編輯
3. 修改主旨、標頭、正文內容和頁尾
4. 使用範本變數（例如，`{{ order.number }}`、`{{ customer.name }}`）進行動態內容
5. 儲存前預覽電子郵件

### 多語言支援

保留所有 markdown 格式、圖片路徑、程式碼區塊和技術術語。

電子郵件模板支援多種語言：
- 每個模板可以為您商店的所有活躍語言提供翻譯
- 系統會以客戶首選語言發送電子郵件
- **語言回退鏈** — 如果沒有可用的翻譯，系統會回退到商店的預設語言
- 使用 **AI 翻譯** 功能自動將模板翻譯成其他語言

### 複製模板

要建立系統模板的自定義版本：
1. 開啟您要修改的模板
2. 點擊 **複製模板**
3. 編輯複製的版本
4. 複製版優先於原始系統模板

## 電子郵件佇列

在 **Settings > Email Queue** 監控出站電子郵件：

- **已排程** — 等待發送的電子郵件
- **正在發送** — 正在傳輸中的電子郵件
- **已發送** — 成功交付的電子郵件
- **失敗** — 未能交付（包含錯誤細節）
- **退件** — 被收件人郵件伺服器拒絕

點擊任何電子郵件以查看其完整細節，包括收件人、主旨、發送時間和交付狀態。

## 郵件交付追蹤

追蹤電子郵件互動：
- **開啟** — 多少收件人打開了電子郵件
- **點擊** — 電子郵件中的連結點擊
- **退件** — 硬體和軟體退件追蹤
- **投訴** — 收件人提出的垃圾郵件投訴

## 多個帳戶

您可以設定多個電子郵件帳戶：
- **預設帳戶** — 用於所有出站電子郵件，除非被覆蓋
- **備用** — 如果預設帳戶失敗，電子郵件會排程重試
- 使用不同的帳戶用於不同用途（例如，一個用於交易電子郵件，另一個用於營銷）

## 電子郵件交付模式

導覽至 **Settings > Store Settings** 來控制您的商店如何處理出站電子郵件。這些設定在開發和測試期間非常有用。

保留所有 markdown 格式、圖片路徑、程式碼區塊和技術術語。

| 模式 | 說明 |
|------|-------------|
| **Live** | 電子郵件正常發送給實際收件人 |
| **Paused** | 電子郵件保留在佇列中，直到您切換回 Live 模式才會發送 |
| **Log Only** | 電子郵件記錄在寄件箱中，但永遠不會發送 |

### 測試重定向電子郵件

設定一個 **Test Redirect Email** 地址，以攔截所有外發電子郵件並將其重定向到單一地址。設定後，所有電子郵件——無論實際收件人為何——都會發送到該地址。這對於測試電子郵件範本而不會意外發送給實際客戶非常有用。留空則會將電子郵件發送給實際收件人。

### 沙盒電子郵件白名單

在沙盒或開發模式下，您可以將電子郵件發送限制在已核准地址的白名單中。只有發送到白名單上地址的電子郵件才會被發送。所有其他電子郵件僅記錄但永遠不會發送。管理員電子郵件會自動包含在內。您最多可以新增 10 個地址。

## 提示

- 從 **Built-in SMTP** 伺服器開始以快速設定，如果需要更高的發送量或更好的可達性，再切換到外部供應商。
- 務必設定 **SPF、DKIM 和 DMARC** 記錄——沒有這些記錄，電子郵件更容易進入垃圾郵件資料夾。
- 在任何設定變更後發送一封 **測試電子郵件**，以驗證發送是否正常運作。
- 定期監控電子郵件佇列中的 **failed** 或 **bounced** 電子郵件——這些表示可達性問題。
- 使用 **專業發件人地址**（例如 orders@yourstore.com），而不是免費電子郵件地址，以獲得更好的信任度和可達性。
- 保持範本簡潔——交易型電子郵件應快速傳遞資訊，而不是行銷電子報。
