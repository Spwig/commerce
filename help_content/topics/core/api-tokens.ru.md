---
title: Токены API
---

Токены API — это безопасные ключи, которые позволяют внешним службам и интеграциям общаться со вашим магазином. Когда сторонняя служба или инструмент нуждается в доступе к данным вашего магазина или в выполнении действий, она отправляет токен API с каждым запросом, чтобы ваш магазин мог проверить, авторизован ли запрос. Вы создаете и управляете всеми токенами, включая те части вашего магазина, к которым они могут получить доступ, в разделе Токены API в вашем административном панели.

## Когда вам нужен токен API

Вы обычно будете создавать токен API, когда:

- Подключаете внешнюю службу или инструмент автоматизации, который должен читать или записывать в ваш магазин
- Настраиваете получатель веб-хука, который должен аутентифицировать входящие вызовы
- Настраиваете Систему помощи Spwig для вашей установки
- Создаете пользовательскую интеграцию с использованием API Spwig
- Синхронизируете данные между вашим магазином Spwig и другой системой

Каждая интеграция должна иметь свой собственный токен, чтобы вы могли отозвать доступ для одной службы, не влияя на другие.

## Типы токенов

При создании токена вы выбираете тип, который описывает его назначение. Тип предназначен для вашей ссылки и помогает вам отслеживать, что делает каждый токен.

| Тип | Назначение |
|------|---------|
| **Система помощи** | Используется системой помощи Spwig |
| **Внешняя интеграция** | Сторонние службы, инструменты автоматизации (например, Zapier) или инструменты синхронизации данных |
| **Веб-хук** | Аутентификация для получателей веб-хуков или конечных точек |
| **Пользовательский** | Любой другой цели, которая не подходит в вышеуказанные категории |
| **Синхронизация экземпляра** | Синхронизация между установками Spwig или внешними службами Spwig |

## API-области: контроль того, к чему может получить доступ токен

Каждый токен также имеет раздел **API-области**, который определяет, какие именно части вашего магазина он может вызывать. Вместо того чтобы токен имел общий доступ ко всему, вы предоставляете доступ по одному участку за раз — и на уровне, который действительно нужен интеграции.

**Токен без выбранных областей не может получить доступ к любому API**, даже если он иначе активен и действителен. Это значение по умолчанию для нового токена, поэтому интеграция не будет работать, пока вы не предоставите ей доступ специально.

Для каждой области вы выбираете один из трех уровней доступа:

| Уровень доступа | Что он позволяет |
|--------------|-----------------|
| **Нет доступа** | Токен не может вызывать никаких конечных точек в этой области |
| **Только чтение** | Токен может извлекать данные из этой области, но не может ничего менять |
| **Чтение и запись** | Токен может извлекать данные и также создавать, обновлять или удалять их |

Области группируются, чтобы соответствовать областям вашего административного панели:

| Группа | Область | Доступ на чтение и запись? | Предоставляет доступ к |
|-------|-------|:---:|-------------------|
| Анализ | **Аналитика продаж** | Только чтение | Панели мониторинга продаж, KPI, аналитика продуктов/покупателей/категорий, сравнения и экспорта |
| Анализ | **Веб-аналитика** | Только чтение | Анализ посетителей и трафика: обзор, тренды, популярные страницы, география и источники |
| Каталог | **Продукты** | Да | Продукты, варианты, изображения, корректировки запасов и назначение атрибутов |
| Каталог | **Категории** | Да | Категории продуктов, включая изображения и баннеры |
| Каталог | **Бренды** | Да | Бренды продуктов |
| Каталог | **Атрибуты** | Да | Определения атрибутов продуктов |
| Каталог | **Запасы** | Да | Панели запасов, скорость запасов, перемещения, рекомендации по заказу и настройки запасов |
| Заказы | **Заказы** | Да | Заказы, заметки к заказам, обновления статуса/отслеживания, отмены, возвраты и документы заказов |
| Покупатели | **Сообщения покупателей** | Да | Сообщения покупателей из форм обратной связи и заметки к заказам, включая обновления статуса и ответы |
| Магазин и настройки | **Настройки магазина** | Да | Настройки магазина, доступные языки и брендинг (название, цвета, логотип) |
| Пользователи и доступ | **Сотрудники и роли** | Да | Аккаунты сотрудников, приглашения, роли и каталог разрешений |

Две области **Анализ** всегда только для чтения — данные отчетов не имеют понятия «запись», поэтому в выпадающем списке доступны только **Нет доступа** или **Только чтение**.

### Какие разрешения на самом деле использует токен

Области действия токена описывают *предел* того, что он может делать — но токен также наследует реальные разрешения сотрудника, который его создал:

- Токен никогда не может действовать с **superuser**-правами, даже если создавший его сотрудник является суперпользователем.
- **Read & Write** в области действия работает только в том случае, если роль создавшего токен сотрудника также разрешает запись в эту область. Если их роль только для просмотра, например, Products, то токен, который они создают с "Products: Read & Write", всё равно может только читать — роль выступает как вторая преграда поверх области действия.
- Если сотрудник, создавший токен, удален или его аккаунт деактивирован, токен сразу теряет доступ к API, независимо от его областей действия — больше нет разрешенного пользователя, от имени которого он может действовать.

Это означает, что самый безопасный способ ограничить область действия токена — создать его, войдя в систему как сотрудник, чья роль уже соответствует доступу, который вы хотите предоставить токену.

## Создание токена API

1. Перейдите в **Settings > API Tokens**
2. Нажмите **+ Add API Token**
3. Введите **Name**, который ясно описывает, для чего предназначен токен (например, `Zapier Product Sync` или `Help System API`)
4. Выберите подходящий **Token Type**
5. Дополнительно добавьте **Description** с дополнительной информацией об интеграции
6. В **API Scopes** выберите **No access**, **Read** или **Read & Write** для каждой области, необходимой для интеграции — оставьте все остальные области действия на **No access**
7. Настройте статус **Active**, **Expiry Date** и **Allowed IPs** по мере необходимости (см. ниже)
8. Нажмите **Save**

После сохранения полное значение токена отображается на странице деталей. **Скопируйте его немедленно** — токен маскируется в представлении списка для обеспечения безопасности и не может быть снова полностью извлечен после того, как вы покинете эту страницу.

## Безопасность значения токена

Spwig показывает полное значение токена только один раз: сразу после того, как вы сохранили новый токен. После этого в представлении списка отображается только маскированная версия (например, `spw_••••••••••••••••••••3f8a`).

Если вы потеряете значение токена, его невозможно восстановить. Вам нужно будет удалить старый токен и создать новый, а затем обновить интеграцию, которая его использовала.

**Никогда не делитесь значениями токенов по электронной почте, в сообщениях в чате или в исходном коде.** Обрабатывайте их как пароли.

## Установка даты истечения срока действия

Поле **Expires At** задает дату и время, после которых токен автоматически перестанет работать. Оставьте его пустым для токенов, которые не должны истекать.

Даты истечения срока действия полезны для:

- Временных интеграций с фиксированной датой окончания
- Токенов, предоставленных третьим лицам, где вы хотите автоматически удалить доступ
- Добавления дополнительного уровня безопасности для интеграций с высокими привилегиями

Когда токен истекает, запросы, использующие его, отвергаются. Вы можете продлить доступ, обновив дату **Expires At** или создав заменяющий токен.

## Ограничение доступа по конкретным IP-адресам

Поле **Allowed IPs** принимает список IP-адресов. Когда список не пуст, токен работает только тогда, когда запрос поступает с одного из этих адресов.

Например, если ваш инструмент аналитики работает на сервере с IP-адресом `203.0.113.42`, добавление этого IP означает, что токен не может быть использован из любого другого места, даже если он утечет.

Оставьте **Allowed IPs** пустым, чтобы разрешить запросы с любого IP-адреса.

**Срок действия и ограничения по IP проверяются независимо от областей действия.** Истёкший или не включённый в список разрешённых токен будет отклонён до того, как будут рассмотрены его области действия, и токен с широкими областями действия всё равно будет отклонён в тот момент, когда истечёт его срок действия или его будут использовать с IP-адреса, не указанного в списке.

## Вызов API с использованием токена

Интеграции аутентифицируются в API администратора Spwig, отправляя токен в заголовке `Authorization`:

```
Authorization: Bearer <your-token-value>
```

Каждый конечный пункт API администратора находится под `/api/admin/...`. Разработчик, создающий вашу интеграцию, решает, какие конечные точки вызывать — ваша задача в качестве продавца — убедиться, что **области действия API** токена охватывают эти конечные точки. Если запрос отклонён с ошибкой разрешений, первым делом проверьте, был ли токен предоставлен с правильной областью действия на нужном уровне доступа.

### Пример: чтение аналитики трафика

Spwig предоставляет конечную точку `GET /api/admin/analytics/traffic/`, которая возвращает аналитику посещений и трафика вашего магазина — обзор посещений и уникальных посетителей, тенденции со временем, популярные страницы, география посетителей и источники переходов. Чтобы разрешить инструменту отчётов или панели приборов считывать эти данные:

1. Создайте токен (или отредактируйте существующий) для этой интеграции
2. В **API Scopes** установите **Web Analytics** в **Read**
3. Сохраните токен и предоставьте его интеграции

Поскольку **Web Analytics** — это область действия только для чтения, нет опции «Read & Write» — интеграция может только получать аналитические данные, никогда не изменяя конфигурацию вашего магазина.

## Отслеживание использования токена

Список токенов показывает:

- **Usage Count** — общее количество раз, когда токен был использован
- **Last Used** — когда токен последний раз использовался для выполнения запроса

Эти поля помогают определить неиспользуемые токены (кандидаты на отзыв) и обнаружить неожиданную активность. Резкий скачок счёта использования может указывать на то, что токен используется кем-то другим, кроме предназначенной интеграции.

## Отзыв токена

Чтобы немедленно остановить использование токена без его удаления:

1. Нажмите на имя токена
2. Снимите флажок **Active**
3. Сохраните

Токен остаётся в вашем списке для справки, но будет отклонён при любых последующих запросах. Это полезно, когда вам нужно временно приостановить интеграцию во время расследования проблемы.

Чтобы полностью удалить токен:

1. Выберите его флажок в списке
2. Выберите **Delete selected API tokens** в меню действий
3. Подтвердите удаление

После удаления токен невозможно восстановить. Если интеграции всё ещё требуется доступ, создайте новый токен и обновите конфигурацию интеграции.

## Пример: настройка интеграции Zapier

**Сценарий:** Вы хотите подключить свой магазин к Zapier для автоматизации уведомлений о заказах.

| Field | Value |
|-------|-------|
| Name | `Zapier Order Automation` |
| Token Type | External Integration |
| Description | Used by Zapier to read new orders and trigger notifications |
| API Scopes | **Orders**: Read & Write |
| Active | Yes |
| Expires At | *(оставьте пустым)* |
| Allowed IPs | *(оставьте пустым — Zapier использует динамические IP-адреса)* |

Только область действия **Orders** предоставляется, поэтому даже если этот токен когда-либо был раскрыт, он не мог бы взаимодействовать с товарами, сообщениями клиентов, учётными записями сотрудников или любыми другими частями вашего магазина. После сохранения скопируйте полное значение токена и вставьте его в настройки интеграции Spwig в Zapier.

## Советы

Сохраните всю разметку Markdown, пути к изображениям, блоки кода и технические термины.

- Дайте каждому токену понятное и конкретное название — `Shopify Sync v2` намного полезнее, чем `Token 3`, когда вы будете решать проблемы спустя месяцы
- Создавайте один токен на каждую интеграцию — если интеграция скомпрометирована, вы можете отозвать только этот токен, не нарушая другие
- **Предоставляйте только те разрешения, которые действительно нужны интеграции** — инструмент для отчетов нуждается только в праве чтения для Sales Analytics или Web Analytics, а не в праве чтения и записи для Products или Staff & Roles
- Проверьте **сводку "This token can access:"** на форме изменения перед передачей токена третьей стороне — это самый быстрый способ убедиться, что вы не предоставили больше, чем планировали
- Помните, что права на запись также зависят от роли самого сотрудника, создавшего токен — если разрешение показывает Read & Write, но записи всё ещё не работают, проверьте разрешения пользователя
- Установите срок действия для токенов, используемых в одноразовых проектах или временных интеграциях — это снижает риск забытых токенов, которые остаются активными вечно
- Проверяйте список токенов каждые несколько месяцев и деактивируйте те токены, у которых дата **Last Used** неожиданно старая, так как они могут принадлежать интеграциям, которые больше не работают
- Если вы подозреваете, что токен был скомпрометирован, немедленно деактивируйте его, создайте замену и обновите затронутую интеграцию перед тем, как снова включить доступ
