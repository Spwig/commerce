---
title: 収益の寄与
---

収益の寄与は、カスタマーが購入する直前にクリックした最後のリンクだけでなく、そのカスタマーをその場に導いたすべてのチャネルが実際にどのくらい貢献したのかを示します。たとえば、カスタマーがソーシャルメディアで共有したブログ記事を読み、1週間後にはグーグル検索から戻り、最後にメールマガジンのリンクをクリックして購入した場合、この3つのタッチがすべてその販売に寄与したということになります。このダッシュボードでは、あなたが選ぶモデルを使用してすべての寄与を評価するため、"最後のクリックが勝つ"という考え方ではなく、実際にマーケティングがどのように機能しているのかを把握できます。

![収益の寄与ダッシュボード: トランスアクションモデルのスイッチャー、KPIストリップの「正規収益に一致する」ラベル、チャネル別の収益、収益の時間にわたる推移、カスタマージャーニーのフロー、キャンペーン一覧表](/static/core/admin/img/help/revenue-attribution/dashboard-overview.webp)

## どこで見つけるか

サイドバーの**インサイト > 収益の寄与**に移動してください。インサイトは製品の上に配置された専用メニューグループであり、収益の寄与は注文やカスタマーレポートとは別の場所にあります。

インサイトは**インサイトと分析**の権限カテゴリによって制限されています。サイドバーに表示されていない場合は、ストアの管理者にその権限を付与してもらう必要があります。スタッフの役割と権限を管理する方法については、[スタッフの役割と権限](/help/staff-roles)を参照してください。

## マルチタッチの寄与を理解する

多くの店舗では、注文がどこから来たのかという単一の答えがあるかのように考えています。現実には、カスタマーは初回訪問で購入しないことがほとんどです。別の方法であなたを発見し、別の方法で戻り、3度目の訪問で購入するのです。数日または数週間かけて複数回訪問する場合もあります。これらの訪問のそれぞれが**タッチ**であり、メールのリンク、検索結果、ソーシャルポスト、アフィリエイトリンクなど、どこから来たのかを示すシグナルを含んでいます。

**マルチタッチの寄与** は、最終的な販売に対してどのタッチがどれだけの寄与をしたのかを認識し、最後のクリックにすべての信用を割り当てることなく、それぞれのタッチにどれだけの信用があるのかを決定することを意味します。

これは、最後のクリックによるレポートがシステム的におこなうため、ブログやオーガニック検索での存在、ソーシャル投稿などの早期の発見作業を行うチャネルを過小評価してしまうため、重要です。

## どの寄与モデルを選ぶか

ダッシュボード上部のモデルスイッチャーは、ページで最も重要なコントロールです。どのモデルでもクリックすると、ダッシュボード上のすべての数値—KPIストリップ、チャネルバー、チャート、キャンペーンテーブル—が即座に再評価され、それに応じた信用を与えるようになります。これはライブプレビューです: ここでモデルを切り替えると、既存の収益に対する見方を変えるだけで、レコードを再処理したり、ストアの保存されたデフォルトモデルを変えたりすることはありません。

![「再評価はライブで・再処理はしない」の表示付きの寄与モデルスイッチャー—最後のタッチ、最初のタッチ、線形、タイムデカイとポジション40/20/40](/static/core/admin/img/help/revenue-attribution/model-switcher.webp)

| Model | 何をしますか | 向いているのは？ |
|-------|---------------|----------|
| **最後のタッチ** | 注文に至るまでのすべてのチャネルの中で、最後のチャネルに完全なクレジットを割り当て、以前のタッチは無視します（「ディレクト」アクセスのみは、最後の本格的なソースに優先してスキップされます）| 収益を報告する際の素早く、馴染みのあるビュー — ほとんどの基本的なアナリティクスツールが収益を報告する方法 |
| **最初のタッチ** | カスタマーをあなたのストアに訪れた最初のチャネルに完全なクレジットを割り当てます | 新規カスタマーやファネル上部の成長を運ぶものが何かを理解する |
| **Linear** | 旅程内のすべてのタッチにクレジットを均等に割り当てます | どのチャネルも優遇したくない場合のバランスの取れた、意見のないビュー |
| **Time decay** | 注文に近いタッチに多くのクレジットを割り当て、より後ろのタッチには少ないクレジットを割り当てます | 考え込む時間が短いキャンペーンで、最近のアピールが最も重要な場合 |
| **Position 40/20/40** | 最初のタッチに40％、最後のタッチに40％、残りの20％を間のすべてに分けて割り当てます | 「誰が私たちを発見したか」や「誰が取引を完了したか」を認識しつつ、旅程の中間部分にもクレジットを割り当てること |

モデルに正しいものはありません — それぞれが異なる質問に答えます。一般的なアプローチは、**最初のタッチ**をチェックして、何が新規カスタマーディスカバーを運んでいるかを確認し、**最後のタッチ**または**Position 40/20/40**をチェックして、転換を運んでいるものが何かを確認し、どちらかを選んで他のものを無視するのではなく、両方のビューを一緒に使用することです。

## KPIストリップの読み方

モデルスイッチャーの下には、4つの数値が表示され、選択された期間とモデルが示されます:

- **割り当てられた収益** — 現在のモデルですべてのチャネルに割り当てられた収益の合計。

これは、選択された期間における実際の正規収益と一致する場合、**正規収益と一致**のバッジが表示されます — つまり、モデルが実際の収益をチャネル間で分割しているだけで、それを発明したり、失くしたりしていないということです。
- **注文数** — 選択された日付範囲に該当する注文数。
- **1注文あたりの平均タッチ数** — 注文1つあたりの記録されたタッチの平均数。

すべてのマーケドフォーマット、画像パス、コードブロック、技術用語を保持してください。

1未満の数値は、お客様のカスタマージャーニーの多くが単一の訪問にとどまらないことを示しており、それがまさにマルチタッチの属性が重要となる理由です。
- **リーディングチャネル** — 選択したモデルで現在、属性付き収益の最大シェアを占めているチャネルで、そのシェアパーセンテージと収益。

## チャネル別収益

**チャネル別収益**カードには、属性付き収益によってサイズが決まる各チャネル用の水平バーが表示されます。属性モデルを切り替えると、バーがスムーズに順位順に並び替わることに注目してください。これは同じ元の収益ですが、別のルールで再分割されているため、**最後のタッチ**で強めに表示されるチャネルが、**最初のタッチ**ではサポート役に過ぎない場合、順位が数段下がる可能性があります。

## 時間を通じた収益

**時間を通じた収益**チャートでは、選択した範囲の各日でチャネルごとに属性付き収益が積み重ねられ、各チャネルがどれだけ価値があるかだけでなく、いつ貢献しているのかも確認できます。これは、シーズンごとのパターンを特定したり、キャンペーンの影響が予想通りの日に届いたか確認したり、チャネルの貢献度が期間を通じて増加または減少しているかをチェックするのに役立ちます。

## 実際の顧客の訪問経路

**実際の顧客の訪問経路**パネルは、最初にカスタマーを引きつけたチャネル（左）から、注文が完了した際のチャネル（右）へのジャーニーを示すフローチャートです。太いリibbonは、その経路を通じて収益がどれだけ流れているかを示しています。これは、たとえば、オーガニック検索からメールへの太いリボンがあれば、検索が人々を引きつけているが、メールマーケティングが購入に至らしめていることがわかります。

![インフルエンスレンズが選択されたカスタマージャーニーフローのチャートで、左側にファーストタッチチャネルが表示され、各注文がコンバートされたチャネルに流れています](/static/core/admin/img/help/revenue-attribution/journey-flow-sankey.webp)

チャート上部の**属性付き** / **インフルエンス**トグルを使用してレンズを切り替えてください:

- **Attributed** は、選択したモデルに応じて注文ごとの収益を分割し、合計が100%のAttributed Revenueになるようにします。これはダッシュボード上の他の場所に表示されている数値と同じものです。
- **Influenced** は、注文が最後のクリックではなく、その注文の*完全な*価値でどのチャネルにも影響を与えたものを*すべて*のチャネルに与えます。1注文につき1回ずつカウントされます。

これは意図的につきあわせが100%にならないようにしています。あるチャネルが他のチャネルの完全な収益を「影響を与えた」としている可能性があるためです。

これは、最後のクリックによる報告で隠されている、ブログ記事やソーシャルシェアなど、最終訪問でクリックしなかったにもかかわらず興味を持たせたチャネルの影響力を明らかにするためです。

## キャンペーン

**キャンペーン**テーブルでは、タグ付けされたキャンペーンごとの収益、注文、平均注文価格（AOV）が表示されます。これは、キャンペーン名が付与されたリンクやコード、キャンペーンタグ付きのクーポンコード（[クーポンキャンペーンのアイデア](/help/voucher-campaign-ideas)を参照）を含む、あなたのタグ付けされたキャンペーンすべてについてのものです。これは、個別のプロモーション、インフルエンサーコード、マーケティングプッシュのパフォーマンスを比較するためのもので、それがどのチャネルで行われたかにかかわらず、互いに比較できます。

## 日付範囲とデータのエクスポート

右上にある日付範囲セレクターを使用して、**直近7日間**、**直近14日間**、**直近30日間**、**直近90日間**、**月間累計**に切り替えてください。ダッシュボード全体が新しい期間用に更新されます。

**CSVエクスポート**をクリックして、現在選択しているモデルと日付範囲のチャネル別内訳をダウンロードしてください。これは、数値をスプレッドシートに引き出すのにも役立ち、パートナーエージェンシーと共有するのにも便利です。

## トーチの記録方法

Spwigは、訪問者が認識可能なソースシグナルをもってあなたのストアに到着したときに自動的にトーチをキャプチャし、あなたのストアのクッキーバナーで**アナリティクス**の承認を提供したときのみです（承認バナーを実行していない場合、ストアの独自のポリシーに従ってデフォルトでトラッキングが有効になります）。これは、あなたのストアフロントの他のアナリティクスと同様のプライバシーの基準で収益の属性を維持するためです。

いくつかのソースは自動的にタグ付けされ、設定は必要ありません:

| チャンネル | どのように特定されるか |
|---------|----------------------|
| **メール** | マーケティングメール内のリンク（注文や配送メールを含まない） |
| **オーガニック / 有料検索** | 検索エンジンのリファラー、または有料キャンペーンを示す`utm_medium`値 |
| **オーガニック / 有料ソーシャル** | ソーシャルネットワークのリファラー、またはソーシャルな`utm_medium`値 |
| **アフィリエイト** | アフィリエイトプログラムを通じて生成されたリンク |
| **友人を紹介** | 顧客紹介プログラムを通じて生成されたリンク |
| **キャンペーン** | 任意のリンクやコードにキャンペーンタグが付いていること、キャンペーンタグ付きのクーポンコードを含む |
| **外部リンク** | 他のウェブサイトからのインバウンドリンクで、他のチャネルに分類されていないもの |
| **直接** | ソースのシグナルが存在しない — 訪問者がアドレスを入力した、ブックマークを使用した、またはリファラーのないアプリから到着した |

接続されたソーシャルアカウントに自動共有されたブログ投稿は自動的にタグ付けされるため、それらが生成するトラフィックが適切なソーシャルチャネルに表示され、DirectやExternal Linkに失われるのを防ぎます。

手動でリンクをタグ付けすることもでき、Spwigが自動でタグ付けしないチャネルであれば、印刷物、パートナーのニュースレター、または他のあらゆるチャネルに対して、標準の`utm_source`、`utm_medium`、`utm_campaign`パラメータを使用して、ストアへのURLに任意のリンクを設定できます。

## 注意するべき制限事項

- **アトリビューションはブラウザに基づき、人ではなく、です。** 顧客がスマートフォンでリサーチし、ラップトップで購入した場合、トラッキングにおいては2つの異なるジャーニーとして扱われます — さまざまなデバイス間でのアクティビティをリンクする方法はありません。

これは、別のデバイスで以前のタッチが行われた場合に「すべき」だったクレジットがDirectに振り分けられることを意味します。
- **Directは、トラッキングされていない収益が振り分けられる場所です。** Directの割合が高かっても、利用者がURLを記憶から入力しているわけではないことを必ずしも示しません。これは、顧客が以前に別のデバイスでタッチを行ったことや、タグが付けられていないリンクを使用したことを意味する場合もあります。
- **同意が拒否された場合は、タッチが記録されません。** クッキーのバナーで分析の同意を拒否した訪問者はトラッキングされず、その注文は通常、Directとして表示されます。これは、他のチャネルから来ている場合でもです。

## トipp

- 結論を出す前に1つのモデルだけでなく複数のモデルを確認してください。**Last touch** で弱く見えるチャネルが、**First touch** では最も強力な発見の手段になる場合があります。
- **Direct** が収益の大きな割合を占めている場合は、マーケティングリンクの多くを `utm_source` / `utm_medium` / `utm_campaign` でタグ付けしていないか確認してください。タグが付けられていないトラフィックは、他の場所に振り分けられません。
- オーガニック検索やブログコンテンツなど、最後のクリックを獲得することがほとんどないが、一貫してジャーニーを開始するチャネルの投資継続を検討する際には、ジャーニーのフロー図の **Influenced** レンズを使用してください。
- 時間が経つにつれて **Avg. touches / order** を比較してください。数値が増えるのは通常、顧客が決定に時間がかかっていることを意味し、フォローアップメールやリターゲティングのタイミングを計るうえで有用なシグナルです。
- **Export CSV** をクリックする際、現在選択されているモデルが反映されるため、再度モデルを切り替える前に、報告対象のモデルと期間のCSVをエクスポートしてください。
