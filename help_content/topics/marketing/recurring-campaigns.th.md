title: แคมเปญซ้ำ
---

ฟีเจอร์ **แคมเปญซ้ำ** ใน Campaign Studio ช่วยให้คุณตั้งค่าจดหมายข่าวได้ครั้งเดียว — เช่น สรุปสินค้ารายสัปดาห์ หรือสรุปบล็อกประจำเดือน — แล้วให้ Spwig ส่งโดยอัตโนมัติตามตารางเวลาแบบซ้ำ แทนที่คุณจะต้องสร้างและส่งแคมเปญใหม่ด้วยตนเองทุกครั้ง

## แบบส่งครั้งเดียว vs. แบบซ้ำ

ทุกแคมเปญใน Campaign Studio จะมี **ประเภทแคมเปญ**:

| ประเภท | พฤติกรรม |
|------|-----------|
| **Broadcast** | ส่งครั้งเดียว — ทันที หรือตามวันที่และเวลาที่กำหนดไว้ครั้งเดียว ใช้สำหรับอีเมลประกาศครั้งเดียว, โปรโมชัน หรือการเปิดตัวสินค้า |
| **Recurring** | ทำหน้าที่เป็นเทมเพลตที่ส่งตามตารางเวลาแบบซ้ำ แต่ละครั้งที่จะส่งจะเป็นสำเนาใหม่ที่มีวันที่เรียกว่า **occurrence** — ตัวเทมเพลตเองจะไม่ "ส่ง" โดยตรง |

เพื่อเปลี่ยนแคมเปญให้เป็นแบบซ้ำ ให้เปิดแคมเปญใน **Campaign Studio > Campaigns** แล้วตั้งค่า **ประเภทแคมเปญ** เป็น **Recurring** จากนั้นบันทึก เมื่อเปิดแคมเปญอีกครั้ง ส่วน **Schedule** จะปรากฏขึ้น — ส่วนนี้จะแสดงเฉพาะสำหรับแคมเปญแบบซ้ำเท่านั้น

![ตั้งค่าประเภทแคมเปญเป็น Recurring](/static/core/admin/img/help/recurring-campaigns/campaign-type-selector.webp)

## การตั้งค่าตารางเวลา

เมื่อแคมเปญเป็นแบบซ้ำแล้ว ส่วน **Schedule** จะควบคุมเวลาในการส่ง:

| ฟิลด์ | คำอธิบาย |
|-------|-------------|
| **Active** | เปิดหรือปิดการซ้ำโดยไม่ลบตารางเวลา |
| **Cadence** | **รายวัน**, **รายสัปดาห์**, หรือ **รายเดือน** |
| **Interval** | ส่งทุก N หน่วยของ cadence — เช่น interval `2` กับ cadence **รายสัปดาห์** หมายถึงทุก 2 สัปดาห์ |
| **Weekday** | วันใดที่จะส่งสำหรับ cadence รายสัปดาห์ (`0` = วันจันทร์ … `6` = วันอาทิตย์) |
| **Day of month** | วันใดที่จะส่งสำหรับ cadence รายเดือน (`1`–`28`, เพื่อให้ทุกเดือนมีวันนั้น) |
| **Send time** | เวลาของวันที่แคมเปญจะถูกส่ง |
| **Timezone** | ชื่อ timezone แบบ IANA เช่น `Europe/London` หรือ `America/New_York` — เวลาในการส่งจะถูกตีความในโซนนี้ ไม่ใช่โซนของเซิร์ฟเวอร์ |

[Weekly schedule section on a recurring campaign](/static/core/admin/img/help/recurring-campaigns/schedule-section.webp)

เมื่อคุณบันทึกตารางเวลาที่ใช้งานอยู่ ระบบจะ **ตั้งค่าการแจ้งเตือน** — Spwig จะคำนวณเวลาที่จะเกิดขึ้นถัดไปและแสดงใน **Next run at** คุณไม่จำเป็นต้องเริ่มการส่งด้วยตัวคุณเอง; งานพื้นหลังจะตรวจสอบตารางเวลาที่ถึงเวลาและส่งเมื่อถึงเวลาที่กำหนด ค่าของ **Last run at** และ **Occurrences sent** จะอัปเดตโดยอัตโนมัติหลังจากการส่งแต่ละครั้ง ทำให้คุณสามารถตรวจสอบได้ว่าตารางเวลาทำงานอยู่จริง

## นโยบายไม่มีเนื้อหาใหม่



การส่งข่าวสารแบบซ้ำๆ มักมีเนื้อหาที่เปลี่ยนแปลงได้ ซึ่งมักจะเป็น **บล็อกโพสต์บล็อก** (หรือ **กริดสินค้า**) ที่ตั้งค่าเป็น **New since last send** ในตัวสร้างรูปแบบ ซึ่งจะดึงโพสต์ที่เผยแพร่หรือสินค้าที่เพิ่มเข้ามาตั้งแต่การส่งครั้งก่อนเท่านั้น นี่คือคำถามที่ชัดเจน: เกิดอะไรขึ้นถ้าการส่งตามตารางเกิดขึ้นและไม่มีเนื้อหาใหม่ให้แสดง?

Spwig ตอบคำถามนี้ด้วย **นโยบายไม่มีเนื้อหาใหม่** ของตารางเวลา:

| นโยบาย | สิ่งที่เกิดขึ้น | เหมาะกับ | 
|--------|---------------|----------|
| **ข้ามการส่งนี้** *(ค่าเริ่มต้น)* | การส่งในครั้งนั้นจะถูกข้ามไปทั้งหมด — ไม่มีการส่งอีเมลใด ๆ ตารางเวลาจะเดินหน้าต่อไปยังรอบถัดไปทันที | สรุปบทความบล็อกหรือสินค้า เพื่อให้ผู้รับไม่ได้รับอีเมลที่ซ้ำกับสิ่งที่พวกเขาเคยเห็นแล้ว |
| **ส่งอยู่ดี (ละเว้นบล็อกที่ว่างเปล่า)** | อีเมลจะถูกส่งตามตารางเวลาไม่ว่าจะเกิดอะไรขึ้น บล็อกใดก็ตามที่ไม่มีเนื้อหาใหม่ — เช่น บล็อก "บทความใหม่ตั้งแต่การส่งครั้งก่อน" ที่ว่างเปล่า — จะไม่แสดงเนื้อหาใด ๆ ในตำแหน่งนั้น | นิตยสารข่าวที่มีเนื้อหาอื่น ๆ ที่น่าส่งอยู่เสมอ (ข้อความต้อนรับ ส่วนเนื้อหาถาวร หรือบล็อกไดนามิกหลายส่วน) แม้บล็อกหนึ่งบล็อกจะว่างเปล่า |
| **รอและส่งล่าช้า** | การส่งจะถูกเลื่อนออกไป Spwig จะตรวจสอบเนื้อหาใหม่ทุกวัน จนครบ **ช่วงเวลาการรอ (วัน)** หากมีเนื้อหาใหม่ปรากฏในช่วงเวลานั้น การส่งจะเกิดขึ้นล่าช้า; หากครบกำหนดเวลาโดยไม่มีสิ่งใหม่ การส่งในครั้งนั้นจะถูกยกเลิกและตารางเวลาจะเดินหน้าต่อไปยังรอบถัดไป | รอบการส่งที่คุณต้องการปกป้อง (เช่น ส่ง *บางสิ่ง* ในที่สุดเสมอ) โดยไม่ส่งฉบับว่างเปล่าทันทีเมื่อไม่มีสิ่งใหม่ให้เผยแพร่ในสัปดาห์นั้น |

เฉพาะแคมเปญที่ใช้เนื้อหาแบบ delta-aware — บล็อกบทความหรือกริดสินค้าที่ตั้งค่าเป็น **ใหม่ตั้งแต่การส่งครั้งก่อน** — เท่านั้นที่จะกระตุ้นการตรวจสอบนี้ แคมเปญซ้ำที่ไม่มีบล็อกดังกล่าวจะถือว่ามีความสดใหม่เสมอและจะส่งตามตารางเวลาตามปกติ

**ช่วงเวลาการรอ (วัน)** ใช้กับนโยบาย **รอและส่งล่าช้า** เท่านั้น — กำหนดจำนวนวันที่ Spwig จะลองใหม่ก่อนจะยกเลิกการส่งในครั้งนั้น

## การทดสอบ A/B สำหรับแต่ละครั้ง

นิตยสารข่าวแบบซ้ำเป็นสถานที่ที่เหมาะสำหรับการทดสอบ A/B **หัวข้ออีเมล** — คุณส่งตามรอบเวลาปกติไปยังกลุ่มเป้าหมายเดียวกัน ดังนั้นคุณสามารถเรียนรู้ต่อไปว่าถ้อยคำใดดึงดูดการเปิดอ่านมากขึ้น Spwig สามารถทำการทดสอบ A/B หัวข้ออีเมลใหม่สำหรับ **ทุกการส่ง** โดยอัตโนมัติ

ตั้งค่าในส่วน **ตารางเวลา**:

1.

ใน **หัวข้อการทดสอบ A/B** ให้ใส่ **สองถึงสี่** หัวข้อ หนึ่งหัวข้อต่อหนึ่งบรรทัด

เว้นว่างไว้เพื่อส่งการเกิดเหตุการณ์ตามปกติพร้อมกับหัวข้อของเทมเพลตเอง
2.

ตั้งค่า **สัดส่วนการทดสอบ A/B** — ส่วนหนึ่งของกลุ่มผู้รับของแต่ละการเกิดเหตุการณ์ที่ใช้ทดสอบ แบ่งออกเป็นส่วนเท่าๆ กันสำหรับหัวข้อต่างๆ

ส่วนที่เหลือคือกลุ่มที่ไม่ได้ทดสอบซึ่งจะได้รับหัวข้อที่ชนะ
3.

เลือก **ตัวชี้วัดผู้ชนะ A/B** (อัตราการเปิดหรืออัตราการคลิก) **ช่วงเวลาการทดสอบ A/B (ชั่วโมง)** เพื่อรวบรวมผลลัพธ์ก่อนตัดสิน และว่าจะ **ส่งผู้ชนะโดยอัตโนมัติ** ไปยังกลุ่มที่ไม่ได้ทดสอบหรือไม่

หลังจากนั้น ทุกครั้งที่กำหนดการเกิดเหตุการณ์ หัวข้อการส่งจะถูกแบ่งออกเป็นส่วนย่อย แต่ละหัวข้อจะถูกส่งไปยังกลุ่มย่อย รอช่วงเวลาการทดสอบ แล้วเลือกหัวข้อที่ชนะและส่งไปยังผู้รับทั้งหมด — คุณไม่ต้องทำอะไรเพิ่มเติมเลย แต่ละการเกิดเหตุการณ์จะเป็นการทดสอบที่สมบูรณ์แบบแยกต่างหาก คุณจึงได้ผลการวิเคราะห์ใหม่ทุกครั้งที่ส่ง และสามารถดูว่าหัวข้อใดชนะไปในช่วงสัปดาห์ต่อๆ ไปได้ ผลลัพธ์ของแต่ละการเกิดเหตุการณ์จะแสดงอยู่ภายใต้ **ประวัติการเกิดเหตุการณ์** ด้านล่าง ซึ่งเชื่อมต่อกับหน้าผลลัพธ์โดยตรงที่มีอัตราการเปิดและคลิกของแต่ละรูปแบบ ผู้ชนะ และความมั่นใจของ Spwig (ดู [การทดสอบ A/B](ab-testing) เพื่อดูวิธีอ่านผลลัพธ์เหล่านี้)

มีสิ่งที่ควรรู้สองอย่าง:

- **การทดสอบ A/B ที่นี่มีเพียงหัวข้อเท่านั้น** หากต้องการเปรียบเทียบรูปแบบที่แตกต่างกันทั้งหมด ให้ใช้การทดสอบ A/B เป็นการเฉพาะสำหรับการเผยแพร่แบบหนึ่งครั้ง — ผู้ช่วยสร้างแบบสอบถามทั้งหมดนี้สำหรับการส่งแบบเป็นชุดเท่านั้น
- หากกลุ่มผู้รับของแต่ละการเกิดเหตุการณ์มีขนาด **เล็กเกินไปที่จะแบ่งออกเป็นรูปแบบต่างๆ** Spwig จะส่งการเกิดเหตุการณ์นั้นเป็นแบบอีเมลข่าวสารตามปกติโดยไม่แจ้งให้ทราบ — ช่วงเวลาที่มีการส่งน้อยก็ไม่ได้หมายความว่าจะต้องไม่ส่ง

## ประวัติการเกิดเหตุการณ์

ทุกครั้งที่แคมเปญที่ซ้ำแล้วซ้ำอีกส่งจริง Spwig จะสร้าง **การเกิดเหตุการณ์** ที่มีวันที่แน่นอน — บันทึกแคมเปญที่แท้จริงและอิสระที่มีหัวข้อของตัวเอง ผู้รับ และสถิติการส่ง (ส่งสำเร็จ ล้มเหลว ข้ามไว้ จำนวนการเปิด จำนวนการคลิก) การเกิดเหตุการณ์นี้จะถูกเรียกชื่อตามเทมเพลตพร้อมกับวันที่ส่งที่แนบมา เช่น "Weekly Blog Digest — 2026-08-19"

หน้าแก้ไขแคมเปญซ้ำจะแสดงรายการ **ประวัติการเกิด** — การเกิดล่าสุดแต่ละรายการจะลิงก์ไปยังบันทึกแคมเปญของเหตุการณ์นั้นโดยเฉพาะ เพื่อให้คุณสามารถตรวจสอบได้ชัดเจนว่ามีการส่งอะไรไปบ้างและผลลัพธ์เป็นอย่างไร

![รายการประวัติการเกิดในแคมเปญซ้ำ](/static/core/admin/img/help/recurring-campaigns/occurrence-history.webp)

## เคล็ดลับ

- จับคู่แคมเปญซ้ำกับบล็อก **Blog Posts** ที่ตั้งค่าเป็น **New since last send** เพื่อสร้างสรุป "โพสต์ใหม่ในสัปดาห์นี้" ที่ดูแลตัวเองได้ — คุณเขียนโพสต์ และ Spwig จัดการการส่งอีเมล
- เริ่มต้นด้วย **Skip this send** สำหรับสรุปเนื้อหา เป็นค่าเริ่มต้นที่ปลอดภัยที่สุด: ผู้สมัครรับข้อมูลจะไม่ได้รับเนื้อหาซ้ำจากครั้งก่อน
- เปลี่ยนเป็น **Send anyway** เฉพาะเมื่อเทมเพลตของคุณมีเนื้อหาอื่นที่มีคุณค่าเพียงพอที่จะส่งได้แม้ว่าบล็อกไดนามิกจะว่างเปล่า
- ใช้ **Hold and send late** เมื่อการพลาดจังหวะการส่งเป็นครั้งคราวไม่เป็นไร แต่การพลาดติดต่อกันหลายสัปดาห์ไม่โอเค — ตั้งค่าช่วงเวลาพักให้ตรงกับระยะเวลาช่องว่างที่คุณยอมรับได้
- ตรวจสอบ **Next run at** หลังจากบันทึกตารางเวลา เพื่อยืนยันว่าตรงกับวันที่และเวลาที่คุณคาดหวัง โดยเฉพาะเมื่อทำงานข้ามเขตเวลา
- ทบทวน **ประวัติการเกิด** เป็นประจำ — เทมเพลตที่ข้ามการส่งซ้ำๆ เป็นสัญญาณว่าแหล่งข้อมูลไดนามิกของคุณ (เช่น บล็อก) เงียบไป
