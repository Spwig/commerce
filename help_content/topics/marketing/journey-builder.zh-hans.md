**旅程构建器** 是一个可视化的拖放画布，用于设计 [旅程](/help/triggered-journeys) 的具体行为——包括发送哪些邮件、邮件之间的等待时间，以及不同的订阅者是否应遵循不同的路径。您无需填写表单，而是将流程构建为流程图：在画布上连接各个方框，您可以重新排列、分支并一目了然地预览。

## 打开构建器

每个旅程都有自己独立的构建器画布。您可以通过两种方式访问：

- 创建新旅程——在设置页面中填写其**名称**、**触发器**和受众，然后点击**保存**——即可直接进入构建器，立即开始设计。
- 打开现有旅程的设置页面，然后点击顶部的**设计旅程**。

构建器是一个全屏工作区，包含三个区域：左侧是步骤类型的**调色板**，中间是**画布**，右侧是选择某项后出现的**步骤设置**面板。

![显示带有是/否分支的欢迎系列的旅程构建器画布](/static/core/admin/img/help/journey-builder/journey-builder-canvas.webp)

在画布顶部，页眉会重复显示旅程的**触发器**和**受众**（如果未设置细分，则显示为“所有订阅者”），以便您始终清楚自己正在为谁设计，而无需离开构建器。

使用 **返回** 按钮返回旅程的设置页面。

## 步骤类型

从左侧面板中拖拽一个步骤到画布上，或点击面板中的项目以自动放置。共有四种步骤类型可用：

| 步骤 | 功能说明 |
|------|--------------|
| **发送邮件** | 向订阅者发送您的其中一项营销活动。 |
| **等待** | 在继续之前暂停设定的小时数或天数。 |
| **分支** | 根据订阅者是否属于您选择的细分群体，将路径分为两条 —— **是** 或 **否**。 |
| **退出** | 结束该订阅者的旅程。 |

每个旅程都以一个单独的 **入口** 步骤开始，该步骤在您首次打开构建器时自动创建。它显示旅程的触发条件，且无法删除 —— 它只是订阅者进入流程的起点。

## 连接步骤

每个步骤都有一个小的圆形 **端口**：顶部一个（输入），底部一个或多个（输出）。要连接两个步骤，请从一个步骤的底部端口拖拽到另一个步骤的顶部端口 —— 会出现一条曲线将它们连接起来。

**分支** 步骤有两个输出端口而不是一个：绿色的 **是** 和红色的 **否**。将每个端口连接到该路径应去的位置 —— 它们可以在稍后的同一步骤处重新汇合（如上图示例所示，两条路径都回到同一个 **退出**），也可以完全走向不同的方向。

要重新排列布局，请通过拖动步骤的主体来重新定位它 —— 连接线会自动跟随。拖动画布背景的空闲区域以平移视图，并使用滚轮进行放大或缩小。如果您迷失了流程方向，请点击工具栏中的 **适应** 以重新居中并缩放以在屏幕上显示所有内容。

## 配置步骤

点击任意步骤以在右侧面板中打开其设置：

| 步骤 | 设置 |
|------|---------|
| **发送邮件** | 从您的营销活动下拉列表中选择一个**要发送的邮件**。 |
| **等待** | 设置**等待时间** — 一个数字加上**小时**或**天**。 |
| **分支** | 选择**如果订阅者属于细分** — 决定“是”或“否”的细分。 |
| **退出** | 无设置 — 它只是一个端点。 |

![右侧面板配置分支步骤，画布在背景中变暗](/static/core/admin/img/help/journey-builder/journey-builder-branch-config.webp)

一旦您选择一个值，更改会自动保存 — 画布上没有单独的**保存**按钮。除了**入口**之外的每个步骤，在其设置面板底部都有一个**删除步骤**按钮。

您为**发送邮件**步骤选择的邮件是您在 Campaign Studio 的常规可视化构建器中设计的普通营销活动 — 主题行、内容块，所有的一切。将它们保持为**草稿**状态，并在此处从下拉列表中选择即可；旅程会为您发送它们，您自己永远不会点击发送。

## 从模板开始

从空白画布构建流程并不总是必要的 — 点击工具栏中的**模板**（或在空白画布上点击**浏览模板**）以打开一个包含八个现成起始模板的选择器：

| 模板 | 构建内容 |
|----------|-----------------|
| **欢迎系列** | 向新订阅者致意，介绍品牌理念，然后发送首单提醒。 |
| **首单引导** | 通过温和的引导流程，将首次购买的客户转化为回头客。 |
| **购后与评价** | 在任何订单完成后表达感谢，并在商品送达后请求评价。 |
| **VIP 与标准优惠** | 订单完成后，根据 VIP 细分群体分支，向每组发送相应的后续优惠。 |
| **弃购挽回** | 提醒将商品遗留在购物车中的顾客，并在一天后发送后续提醒。 |
| **流失客户召回** | 通过提供回归理由，重新激活一段时间未购买的客户。 |
| **送达后评价请求** | 在订单状态标记为“已送达”几天后请求评价。 |
| **补货提醒** | 在顾客想要的商品重新有货的那一刻通知等待中的顾客。 |

每个模板都预先配置了相应的触发器——例如，将**流失客户召回**应用于新旅程时，也要求该旅程的**触发器**为**客户流失（召回）**。请参阅[触发式旅程](/help/triggered-journeys)，了解哪些事件会触发这些触发器，以及以挽回为重点的触发器如何运作（空闲窗口、访客结账、每单一次的评价请求，以及补货旅程如何取代普通的一次性提醒）。

![显示现成起步旅程的模板选择器](/static/core/admin/img/help/journey-builder/journey-builder-templates.webp)

应用模板会**替换画布上的当前流程**，因此请在设计旅程的初期使用它，而不是中途使用。Spwig 会将每个步骤重新链接到真实的电子邮件或细分群体（只要名称与您已有的内容匹配）；在无法找到匹配项的地方，页眉会报告仍有多少步骤需要选择电子邮件或细分群体，以便您确切知道在上线前需要完成哪些工作。

## 共享旅程

两个工具栏按钮允许您在步骤之间或店铺之间移动旅程的设计：

- **导出** 将旅程下载为 `.journey.json` 文件——这是流程结构（其步骤、等待、分支以及“是/否”路径）的可移植描述，外加每个步骤使用的邮件和细分的*名称*。它不包含邮件设计本身或任何订阅者数据。
- **导入** 将 `.journey.json` 文件加载到当前旅程中，替换画布上的内容。

这对于备份您引以为傲的流程、将经过验证的欢迎系列交给另一个 Spwig 店铺，或在将店铺克隆到新安装后重建旅程时非常有用。与模板一样，Spwig 会在目标店铺存在匹配项时按名称重新链接邮件和细分，并标记任何无法匹配的内容，以便您完成设置。

## 激活您的旅程

当流程准备就绪时，使用构建器右上角的状态控件。一个药丸状标签显示旅程的当前状态——**草稿**、**激活** 或 **暂停**——旁边是一个 **激活** 按钮。

点击 **激活** 会**先检查流程**。如果有任何问题会阻止其运行，激活将被阻止，横幅中会列出问题——例如，未选择邮件的 **发送邮件** 步骤、没有细分或没有“是/否”路径的 **分支**、已被删除的邮件或细分，或会无限运行的循环。每个问题都是可点击的：选择它会跳转到有问题的步骤，该步骤会以红色轮廓显示，直到您修复它。警告（例如无法到达的步骤或未设置延迟的 **等待**）也会列出，但不会阻止激活。

![激活被阻止，问题在横幅中列出，有问题的步骤以红色轮廓显示](/static/core/admin/img/help/journey-builder/journey-builder-activate-blocked.webp)

一旦流程通过，药丸状标签会切换为 **激活**，旅程将在其触发器触发时开始注册订阅者。

按钮变为 **暂停**，这会停止新的订阅加入——已经进行到一半的订阅者将继续接收剩余的步骤。

有关订阅加入、冷却期和状态如何交互，请参阅 [触发的旅程](/help/triggered-journeys)。

## 查看谁在旅程中

一旦旅程上线，每个步骤的角落都会显示一个小的 **计数徽章**：即当前停留在该步骤的订阅者数量。这是一种快速查看人员流动和堆积位置的方法——**等待** 步骤上的大数字是预期之内的，而特定邮件前的堆积可能值得查看。当您返回构建器选项卡时，计数会刷新。

![画布上步骤带有实时计数徽章，工具栏中有激活按钮](/static/core/admin/img/help/journey-builder/journey-builder-live-counts.webp)

## 提示

- 在旅程仍为 **草稿** 时设计流程——在您 **激活** 它之前，不会有任何人加入。从构建器激活会先运行快速检查，不会让损坏的流程上线，因此没有半成品的旅程订阅者的风险。
- 即使您计划大量自定义，也从 **模板** 开始——编辑现有流程比逐个节点构建更快，并且如果您之前没有使用过分支模式，它展示了分支模式。
- 应用模板或导入文件后，检查标题中是否有未匹配步骤的说明，并在激活之前填写它无法匹配的任何 **发送邮件** 或 **分支** 步骤。
- 当流程变宽时（尤其是分支），点击 **适应**——这是在缩放或平移后再次查看整体形状的最快方法。
- 通过将每个 **等待** 步骤紧挨在其延迟的邮件之前，而不是将多个等待聚集在一起，保持步骤名称易于浏览。
- 在对旅程进行重大更改之前 **导出** 一个可用的旅程——这是一种快速保留回退副本的方法，如果您不喜欢结果，可以重新导入。
