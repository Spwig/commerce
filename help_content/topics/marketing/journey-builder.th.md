**Journey Builder** คือพื้นที่ทำงานแบบลากและวาง (drag-and-drop) ที่ให้คุณออกแบบว่า [Journey](/help/triggered-journeys) จะทำงานอย่างไร — อีเมลใดจะถูกส่งออกไป ต้องรอระหว่างอีเมลนานเท่าใด และผู้สมัครรับข้อมูลกลุ่มต่าง ๆ ควรติดตามเส้นทางที่แตกต่างกันหรือไม่ แทนที่จะกรอกแบบฟอร์ม คุณสร้างโฟลว์เป็นแผนผัง (flowchart): กล่องที่เชื่อมต่อกันบนแคนวาส ซึ่งคุณสามารถจัดเรียง แยกสาขา และดูตัวอย่างได้ทันที

## การเปิด Journey Builder

แต่ละ Journey มีแคนวาสของตัวเอง คุณสามารถเข้าถึงได้สองวิธี:

- การสร้าง Journey ใหม่ — กรอก **ชื่อ (Name)**, **ตัวกระตุ้น (Trigger)** และกลุ่มเป้าหมายในหน้าการตั้งค่า แล้วคลิก **บันทึก (Save)** — จะพาคุณเข้าสู่ Journey Builder ทันทีเพื่อให้คุณเริ่มออกแบบได้ทันที
- เปิดหน้าการตั้งค่าของ Journey ที่มีอยู่แล้ว และคลิก **ออกแบบ Journey (Design journey)** ด้านบน

Journey Builder เป็นพื้นที่ทำงานแบบเต็มหน้าจอที่มีสามส่วน: **พาเลต (palette)** ของประเภทขั้นตอนทางด้านซ้าย **แคนวาส (canvas)** ตรงกลาง และแผง **การตั้งค่าขั้นตอน (step settings)** ทางด้านขวา ซึ่งจะปรากฏขึ้นเมื่อคุณเลือกสิ่งใดสิ่งหนึ่ง

![แคนวาสของ Journey Builder แสดงซีรีส์ต้อนรับพร้อมสาขาใช่/ไม่ใช่](/static/core/admin/img/help/journey-builder/journey-builder-canvas.webp)

ด้านบนของแคนวาส ส่วนหัวจะแสดง **ตัวกระตุ้น (Trigger)** และ **กลุ่มเป้าหมาย (audience)** ของ Journey (หรือ "ผู้สมัครรับข้อมูลทั้งหมด" หากไม่ได้ตั้งค่าเซกเมนต์) เพื่อให้คุณทราบเสมอว่าคุณกำลังออกแบบสำหรับใครโดยไม่ต้องออกจาก Journey Builder

ใช้ปุ่ม **ย้อนกลับ** เพื่อกลับไปยังหน้าการตั้งค่าของ旅程

## ประเภทของขั้นตอน

ลากขั้นตอนจากพาเลตด้านซ้ายไปยังแคนวาส หรือคลิกที่รายการในพาเลตเพื่อวางอัตโนมัติ มีประเภทขั้นตอนให้เลือก 4 ประเภท:

| ขั้นตอน | ทำอะไร |
|------|--------------|
| **ส่งอีเมล** | ส่งแคมเปญของคุณไปยังผู้สมัครรับข้อมูล |
| **รอ** | หยุดพักเป็นจำนวนชั่วโมงหรือวันที่กำหนดก่อนดำเนินการต่อ |
| **แยกเส้นทาง** | แบ่งเส้นทางออกเป็นสองทาง — **ใช่** หรือ **ไม่** — ขึ้นอยู่กับว่าผู้สมัครรับข้อมูลอยู่ในเซกเมนต์ที่คุณเลือกหรือไม่ |
| **ออก** | สิ้นสุด旅程สำหรับผู้สมัครรับข้อมูล |

ทุก旅程เริ่มต้นด้วยขั้นตอน **เข้าสู่ระบบ** เพียงขั้นตอนเดียว ซึ่งสร้างอัตโนมัติเมื่อคุณเปิดบิลเดอร์เป็นครั้งแรก ขั้นตอนนี้จะแสดงตัวกระตุ้นของ旅程และไม่สามารถลบได้ — เป็นเพียงจุดที่ผู้สมัครรับข้อมูลเข้าสู่โฟลว์

## การเชื่อมต่อขั้นตอน

แต่ละขั้นตอนมี **พอร์ต** ขนาดเล็กเป็นวงกลม: หนึ่งพอร์ตด้านบน (อินพุต) และหนึ่งพอร์ตหรือมากกว่าด้านล่าง (เอาต์พุต) เพื่อเชื่อมต่อสองขั้นตอน ให้ลากจากพอร์ตด้านล่างของขั้นตอนหนึ่งไปยังพอร์ตด้านบนของอีกขั้นตอน — เส้นโค้งจะปรากฏขึ้นเพื่อเชื่อมโยงทั้งสอง

ขั้นตอน **แยกเส้นทาง** มีพอร์ตเอาต์พุตสองพอร์ตแทนที่จะเป็นหนึ่ง: **ใช่** สีเขียว และ **ไม่** สีแดง เชื่อมต่อแต่ละพอร์ตไปยังจุดที่เส้นทางนั้นควรนำไป — สามารถรวมกันอีกครั้งที่ขั้นตอนเดียวกัน (เช่น ในตัวอย่างด้านบน ซึ่งทั้งสองเส้นทางกลับไปยัง **ออก** เดียวกัน) หรือแยกไปคนละทางโดยสิ้นเชิง

เพื่อจัดเรียงเลย์เอาต์ ให้ลากขั้นตอนด้วยตัวขั้นตอนเพื่อปรับตำแหน่ง — เส้นที่เชื่อมต่อจะติดตามไปโดยอัตโนมัติ ลากส่วนว่างของพื้นหลังแคนวาสเพื่อเลื่อนดู และใช้ล้อเลื่อนเพื่อซูมเข้าหรือออก หากคุณหลงทางในโฟลว์ ให้คลิก **จัดพอดี** ในแถบเครื่องมือเพื่อจัดกึ่งกลางและซูมให้พอดีกับทุกอย่างบนหน้าจอ

## การกำหนดค่าขั้นตอน

คลิกที่ขั้นตอนใดก็ได้เพื่อเปิดการตั้งค่าในแผงด้านขวา:

| ขั้นตอน | การตั้งค่า |
|------|---------|
| **ส่งอีเมล** | เลือก **อีเมลที่จะส่ง** จากเมนูแบบเลื่อนลงของแคมเปญของคุณ |
| **รอ** | ตั้งค่า **รอ** — จำนวนตัวเลขพร้อม **ชั่วโมง** หรือ **วัน** |
| **แยกเส้นทาง** | เลือก **หากผู้สมัครอยู่ในเซกเมนต์** — เซกเมนต์ที่กำหนดว่าใช่หรือไม่ |
| **สิ้นสุด** | ไม่มีค่าที่ตั้งค่า — เป็นเพียงจุดสิ้นสุด |

![แผงด้านขวาที่ตั้งค่าขั้นตอนแยกเส้นทาง โดยมีแคนวาสมืดลงอยู่เบื้องหลัง](/static/core/admin/img/help/journey-builder/journey-builder-branch-config.webp)

การเปลี่ยนแปลงจะถูกบันทึกโดยอัตโนมัติทันทีที่คุณเลือกค่า — ไม่มีปุ่ม **บันทึก** แยกต่างหากบนแคนวาส ทุกขั้นตอนยกเว้น **จุดเริ่มต้น** มีปุ่ม **ลบขั้นตอน** ที่ด้านล่างของแผงตั้งค่า

อีเมลที่คุณเลือกสำหรับขั้นตอน **ส่งอีเมล** เป็นแคมเปญทั่วไปที่คุณออกแบบในบิลเดอร์ภาพแบบปกติของ Campaign Studio — หัวข้อ เนื้อหา บล็อก และอื่น ๆ ทั้งหมด ปล่อยให้เป็น **ร่าง** และเลือกจากเมนูแบบเลื่อนลงที่นี่; จัรณะจะส่งให้แทน คุณไม่ต้องกดส่งด้วยตนเอง

## เริ่มต้นจากเทมเพลต

การสร้างโฟลว์จากแคนวาสว่างเปล่าไม่ได้จำเป็นเสมอไป — คลิก **เทมเพลต** ในแถบเครื่องมือ (หรือ **ดูเทมเพลต** บนแคนวาสว่างเปล่า) เพื่อเปิดตัวเลือกที่มีตัวเริ่มต้นพร้อมใช้งานแปดแบบ:

| เทมเพลต | สร้างอะไร |
|----------|-----------------|
| **ชุดข้อความต้อนรับ** | ทักทายผู้สมัครใหม่ บอกเล่าเกี่ยวกับธุรกิจของคุณ แล้วกระตุ้นให้สั่งซื้อครั้งแรก |
| **การเริ่มต้นใช้งานสำหรับคำสั่งซื้อแรก** | เปลี่ยนผู้ซื้อครั้งแรกให้กลายเป็นลูกค้าประจำด้วยลำดับขั้นตอนการเริ่มต้นใช้งานที่นุ่มนวล |
| **หลังการซื้อและรีวิว** | กล่าวขอบคุณหลังคำสั่งซื้อใดๆ แล้วขอรีวิวเมื่อสินค้าถึงมือแล้ว |
| **ข้อเสนอ VIP เทียบกับมาตรฐาน** | หลังคำสั่งซื้อ จะแยกตามกลุ่ม VIP ของคุณเพื่อส่งข้อเสนอติดตามที่เหมาะสมไปยังแต่ละกลุ่ม |
| **กู้คืนรถเข็นที่ละทิ้ง** | เตือนนักช้อปที่ทิ้งสินค้าไว้ แล้วส่งข้อความกระตุ้นติดตามอีกวันถัดไป |
| **ดึงลูกค้าที่หายไปกลับมา** | สร้างการมีส่วนร่วมใหม่กับลูกค้าที่ไม่ได้ซื้อมาสักระยะด้วยเหตุผลให้กลับมา |
| **คำขอรีวิวหลังการจัดส่ง** | ขอรีวิวไม่กี่วันหลังคำสั่งซื้อถูกทำเครื่องหมายว่าจัดส่งแล้ว |
| **การแจ้งเตือนสินค้าพร้อมจำหน่าย** | บอกนักช้อปที่กำลังรอทันทีเมื่อสินค้าที่ต้องการพร้อมจำหน่ายอีกครั้ง |

แต่ละเทมเพลตถูกตั้งค่าให้ตรงกับตัวกระตุ้นที่เกี่ยวข้อง — ตัวอย่างเช่น การนำ **ดึงลูกค้าที่หายไปกลับมา** ไปใช้กับเส้นทางใหม่ยังคาดหวังว่า **ตัวกระตุ้น** ของเส้นทางนั้นจะเป็น **ลูกค้าหายไป (ดึงกลับ)** ดู [เส้นทางที่ทำงานด้วยตัวกระตุ้น](/help/triggered-journeys) เพื่อเรียนรู้ว่าอะไรเป็นตัวจุดชนวนเหตุการณ์ตัวกระตุ้นเหล่านี้ และวิธีการทำงานของตัวที่เน้นการกู้คืน (ช่วงเวลาที่ไม่มีกิจกรรม การชำระเงินแบบแขกรับเชิญ คำขอรีวิวต่อคำสั่งซื้อครั้งเดียว และวิธีการที่เส้นทางสินค้าพร้อมจำหน่ายจะเข้ามาแทนที่การแจ้งเตือนแบบครั้งเดียวธรรมดา)

![ตัวเลือกเทมเพลตที่แสดงเส้นทางเริ่มต้นที่พร้อมใช้งาน](/static/core/admin/img/help/journey-builder/journey-builder-templates.webp)

การนำเทมเพลตไปใช้จะ **แทนที่การไหลปัจจุบัน** บนแคนวาส ดังนั้นจึงควรใช้ในช่วงเริ่มต้นของการออกแบบเส้นทางมากกว่าใช้กลางทาง Spwig จะเชื่อมโยงแต่ละขั้นตอนไปยังอีเมลหรือกลุ่มจริงในกรณีที่ชื่อตรงกับสิ่งที่คุณมีอยู่แล้ว ในทุกจุดที่หาการจับคู่ไม่ได้ ส่วนหัวจะรายงานว่ามีขั้นตอนกี่ขั้นตอนที่ยังต้องเลือกอีเมลหรือกลุ่ม เพื่อให้คุณทราบอย่างชัดเจนว่าต้องเสร็จสิ้นอะไรก่อนเปิดใช้งาน

## การแชร์เส้นทาง

ปุ่มเครื่องมือสองปุ่มช่วยให้คุณย้ายการออกแบบ Journey ระหว่างขั้นตอนหรือระหว่างร้านค้า:

- **Export** ดาวน์โหลด Journey เป็นไฟล์ `.journey.json` — คำอธิบายแบบพกพาของโครงสร้าง Flow (ขั้นตอน, การรอ, การแยกสาขา, และเส้นทาง Yes/No) รวมถึง *ชื่อ* ของอีเมลและ Segment ที่แต่ละขั้นตอนใช้ ไม่รวมถึงการออกแบบอีเมลเองหรือข้อมูลผู้สมัครรับข้อมูล
- **Import** โหลดไฟล์ `.journey.json` เข้าไปยัง Journey ปัจจุบัน โดยแทนที่สิ่งที่อยู่บน Canvas

สิ่งนี้มีประโยชน์สำหรับการสำรองข้อมูล Flow ที่คุณภูมิใจ การส่งมอบชุด Welcome Series ที่พิสูจน์แล้วไปยังร้านค้า Spwig อื่น หรือการสร้าง Journey ใหม่หลังจาก Clone ร้านค้าไปยังการติดตั้งใหม่ เช่นเดียวกับเทมเพลต Spwig จะเชื่อมโยงอีเมลและ Segment ใหม่ตามชื่อหากมีชื่อที่ตรงกันบนร้านค้าปลายทาง และทำเครื่องหมายสิ่งที่จับคู่ไม่ได้เพื่อให้คุณดำเนินการตั้งค่าให้เสร็จสิ้น

## การเปิดใช้งาน Journey ของคุณ

เมื่อ Flow พร้อมแล้ว ให้ใช้ตัวควบคุมสถานะที่มุมขวาบนของ Builder ปุ่มวงรีจะแสดงสถานะปัจจุบันของ Journey — **Draft**, **Active**, หรือ **Paused** — อยู่ข้างปุ่ม **Activate**

การคลิก **Activate** จะ **ตรวจสอบ Flow ก่อน** หากมีสิ่งใดที่อาจขัดขวางการทำงาน การเปิดใช้งานจะถูกบล็อกและแถบข้อความจะแสดงรายการปัญหา — ตัวอย่างเช่น ขั้นตอน **Send email** ที่ไม่ได้เลือกอีเมล, **Branch** ที่ไม่มี Segment หรือไม่มีเส้นทาง Yes/No, อีเมลหรือ Segment ที่ถูกลบไปแล้ว หรือลูปที่จะทำงานไปเรื่อยๆ ตลอดไป แต่ละปัญหามีให้คลิก: การเลือกปัญหานั้นจะกระโดดไปยังขั้นตอนที่มีปัญหา ซึ่งจะถูกทำเส้นขอบสีแดงจนกว่าคุณจะแก้ไข ข้อความเตือน (เช่น ขั้นตอนที่ไม่สามารถเข้าถึงได้ หรือ **Wait** ที่ไม่ได้ตั้งค่าการหน่วงเวลา) จะถูกระบุไว้เช่นกันแต่จะไม่บล็อกการเปิดใช้งาน

![การเปิดใช้งานถูกบล็อก พร้อมรายการปัญหาในแถบข้อความและขั้นตอนที่มีปัญหาถูกทำเส้นขอบสีแดง](/static/core/admin/img/help/journey-builder/journey-builder-activate-blocked.webp)

เมื่อ Flow ผ่านการตรวจสอบ ปุ่มวงรีจะเปลี่ยนเป็น **Active** และ Journey จะเริ่มลงทะเบียนผู้สมัครรับข้อมูลเมื่อใดก็ตามที่ Trigger ทำงาน

ปุ่มจะเปลี่ยนเป็น **Pause** ซึ่งหยุดการลงทะเบียนใหม่ — ผู้สมัครที่ดำเนินการอยู่ระหว่างทางจะยังคงได้รับขั้นตอนที่เหลือต่อไป

ดู [Triggered journeys](/help/triggered-journeys) เพื่อทำความเข้าใจว่าการลงทะเบียน ระยะเวลาพัก และสถานะทำงานร่วมกันอย่างไร

## การดูว่ามีใครอยู่ใน journey

เมื่อ journey ทำงานแล้ว แต่ละขั้นตอนจะแสดง **count badge** ขนาดเล็กที่มุม: จำนวนผู้สมัครที่กำลังอยู่ในขั้นตอนนั้น ณ ขณะนี้ เป็นวิธีที่รวดเร็วในการดูว่าผู้คนกำลังไหลไปทางไหนและกำลังสะสมอยู่ที่ไหน — จำนวนมากในขั้นตอน **Wait** เป็นเรื่องปกติ แต่การสะสมก่อนอีเมลฉบับใดฉบับหนึ่งอาจน่าจับตามอง ตัวเลขจะอัปเดตทุกครั้งที่คุณกลับไปที่แท็บ builder

## เคล็ดลับ

- ออกแบบ flow ในขณะที่ยังเป็น **Draft** — ไม่มีอะไรลงทะเบียนใครจนกว่าคุณจะ **Activate** การ Activate จาก builder จะทำการตรวจสอบอย่างรวดเร็วก่อน และจะไม่ให้ flow ที่เสียหายทำงานได้ ดังนั้นจึงไม่มีโอกาสที่ journey ที่สร้างไม่เสร็จจะลงทะเบียนผู้สมัคร
- เริ่มต้นจาก **Template** แม้ว่าคุณจะวางแผนจะปรับแต่งอย่างมาก — การแก้ไข flow ที่มีอยู่แล้วเร็วกว่าการสร้างทีละ node และมันแสดงรูปแบบ branch หากคุณไม่เคยใช้มาก่อน
- หลังจากใช้ template หรือนำเข้าไฟล์ ตรวจสอบส่วนหัวสำหรับบันทึกขั้นตอนที่ไม่ตรงกัน และเติมขั้นตอน **Send email** หรือ **Branch** ที่ไม่สามารถจับคู่ได้ก่อน activate
- คลิก **Fit** ทุกครั้งเมื่อ flow กว้าง (โดยเฉพาะ branches) — เป็นวิธีที่เร็วที่สุดในการเห็นรูปร่างทั้งหมดอีกครั้งหลังจากซูมหรือเลื่อน
- ให้อาหารชื่อขั้นตอนง่ายต่อการอ่านโดยให้แต่ละขั้นตอน **Wait** อยู่ก่อนอีเมลที่มันหน่วงทันที แทนที่จะรวม waits หลายตัวไว้ด้วยกัน
- **Export** journey ที่ทำงานได้ดีก่อนทำการเปลี่ยนแปลงครั้งใหญ่ — เป็นวิธีที่รวดเร็วในการเก็บสำเนาสำรองที่คุณสามารถนำเข้าใหม่ได้หากคุณไม่ชอบผลลัพธ์
