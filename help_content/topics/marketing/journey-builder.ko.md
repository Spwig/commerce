**여행 생성기**는 [여행](/help/triggered-journeys)이 실제로 무엇을 하는지 디자인하는 시각적 드래그 앤 드롭 캔버스입니다. 이메일이 언제 발송되는지, 얼마나 기다려야 하는지, 그리고 다른 구독자가 서로 다른 경로를 따라야 하는지 결정합니다. 양식을 채우는 대신 흐름도로 흐름을 만듭니다. 캔버스에 연결된 상자들이 있으며, 이들을 이동, 분기, 미리 보기할 수 있습니다.

## 생성기 열기

모든 여행에는 자체 생성기 캔버스가 있습니다. 두 가지 방법으로 접근할 수 있습니다.

- 새 여행 생성 — 설정 페이지에서 **이름**, **트리거**, 및 대상 구독자 설정을 입력하고 **저장**을 클릭합니다. 즉시 생성기로 이동하여 바로 디자인을 시작할 수 있습니다.
- 기존 여행의 설정 페이지를 열고 상단의 **여행 디자인**을 클릭합니다.

생성기는 왼쪽에 단계 유형의 **패レ트**, 중앙에 **캔버스**, 그리고 선택 시 나타나는 **단계 설정** 패널이 있는 전체 화면 작업 공간입니다.

![웰컴 시리즈가 있는 여행 생성기 캔버스](/static/core/admin/img/help/journey-builder/journey-builder-canvas.webp)

캔버스 상단에는 여행의 **트리거**와 **대상 구독자**(세그먼트가 설정되지 않은 경우 "모든 구독자")가 반복되어 생성기를 떠나지 않고도 누구를 위한 디자인인지 항상 알 수 있습니다.

여행 설정 페이지로 돌아가기 위해 **뒤로** 버튼을 사용하십시오.

## 단계 유형들

왼쪽 팔레트에서 단계를 끌어다 캔버스에 놓거나, 팔레트 항목을 클릭하여 자동으로 놓을 수 있습니다. 4가지 유형의 단계가 사용 가능합니다.

| 단계 | 무엇을 하나요? |
|------|--------------|
| **이메일 전송** | 구독자에게 캠페인 중 하나를 보냅니다. |
| **대기** | 지정된 시간(시간 또는 일) 동안 중지하고 계속합니다. |
| **분기** | 선택한 세그먼트에 속하는 구독자인지에 따라 두 가지 경로로 나눕니다. **예** 또는 **아니요**. |
| **종료** | 구독자의 여행을 종료합니다. |

모든 여행은 첫 번째로 **입장** 단계가 생성되는 시작 단계입니다. 처음으로 빌더를 여는 경우 자동으로 생성됩니다. 여행의 트리거를 보여주며, 삭제할 수 없습니다. 구독자가 흐름에 들어가는 시작점입니다.

## 단계 연결

각 단계에는 작은 원형 **포트**가 있습니다. 상단에 하나(입력)와 하단에 하나 이상(출력)이 있습니다. 두 단계를 연결하려면, 하나의 단계 하단 포트에서 다른 단계 상단 포트로 끌어다 놓습니다. 연결되는 곡선선이 나타납니다.

**분기** 단계는 일반적인 단계와 달리 두 개의 출력 포트를 가지고 있습니다: 초록색 **예**와 빨간색 **아니요**. 각각을 해당 경로가 이어질 곳에 연결합니다. 예를 들어, 위 예제에서 두 경로가 모두 같은 **종료**로 돌아가도록 할 수 있습니다. 또는 완전히 다른 방향으로 나아갈 수도 있습니다.

레이아웃을 재배열하려면 단계의 본문을 끌어다 이동합니다. 연결된 라인이 자동으로 따라갑니다. 캔버스 뒷면의 빈 부분을 끌어다 움직이면, 스크롤 휠을 사용하여 줌 인 또는 줌 아웃할 수 있습니다. 흐름을 잃은 경우, 도구 모음의 **적응**을 클릭하여 화면에 모든 것을 중심으로 재설정하고 줌 인합니다.

## 단계 구성

어떤 단계든 클릭하여 오른쪽 패널에 설정을 엽니다.

| 단계 | 설정 |
|------|---------|
| **이메일 보내기** | 캠페인 목록에서 **보낼 이메일**을 선택합니다. |
| **대기** | **대기 시간**을 설정합니다 — 숫자와 **시간** 또는 **일**을 지정합니다. |
| **분기** | **구독자가 세그먼트에 속하는 경우**를 선택합니다 — 예/아니오를 결정하는 세그먼트입니다. |
| **종료** | 설정 없음 — 단순히 종점입니다. |

![분기 단계 설정을 위한 우측 패널, 배경 캔버스가 흐리게 표시됨](/static/core/admin/img/help/journey-builder/journey-builder-branch-config.webp)

값을 선택하는 즉시 변경 사항이 자동으로 저장됩니다 — 캔버스에는 별도의 **저장** 버튼이 없습니다. **입력** 단계를 제외한 모든 단계에는 설정 패널 하단에 **단계 삭제** 버튼이 있습니다.

**이메일 보내기** 단계에서 선택하는 이메일은 캠페인 스튜디오의 일반 시각적 빌더에서 설계하는 일반 캠페인입니다 — 제목, 콘텐츠 블록, 모든 것이 포함됩니다. **초안** 상태로 두면 여기서 드롭다운에서 선택하기만 하면 됩니다; 여정이 대신 보내므로 직접 전송 버튼을 클릭할 필요가 없습니다.

## 템플릿에서 시작하기

빈 캔버스에서 플로우를 구축하는 것이 항상 필요한 것은 아닙니다 — 툴바에서 **템플릿**을 클릭하거나(빈 캔버스에서는 **템플릿 탐색**) 8개의 준비된 시작 템플릿이 포함된 선택기를 엽니다:

| 템플릿 | 구성 내용 |
|----------|-----------------|
| **환영 시리즈** | 신규 구독자를 환영하고, 브랜드 소개를 공유한 후 첫 주문을 유도합니다. |
| **첫 주문 온보딩** | 온보딩 시퀀스를 통해 첫 구매 고객을 재구매 고객으로 전환합니다. |
| **구매 후 및 리뷰** | 주문 완료 후 감사 인사를 전하고, 상품 수령 후 리뷰를 요청합니다. |
| **VIP 및 일반 고객 대상 제안** | 주문 후 VIP 세그먼트에 따라 각 그룹에 적합한 후속 제안을 전송합니다. |
| **장바구니 포기 복구** | 장바구니에 상품을 남기고 떠난 쇼핑객에게 알림을 보내고, 하루 후 후속 안내를 전송합니다. |
| **휴면 고객 재유입** | 오랫동안 구매하지 않은 고객에게 돌아올 이유를 제시하여 재참여를 유도합니다. |
| **배송 완료 후 리뷰 요청** | 주문 상태가 '배송 완료'로 표시된 후 며칠이 지나면 리뷰를 요청합니다. |
| **재입고 알림** | 원하는 상품이 다시 재고로 들어오는 즉시 대기 중인 쇼핑객에게 알려줍니다. |

각 템플릿은 해당 트리거에 사전 연결되어 있습니다. 예를 들어, **휴면 고객 재유입** 템플릿을 새 여정에 적용하면 해당 여정의 **트리거**가 **고객 휴면 (재유입)**이어야 합니다. 각 트리거 이벤트가 발생하는 조건과 복구 중심 트리거의 동작 방식(유휴 기간, 게스트 체크아웃, 주문당 1회 리뷰 요청, 재입고 여정이 일반 일회성 알림을 대체하는 방식)은 [트리거 기반 여정](/help/triggered-journeys)을 참고하세요.

![준비된 시작용 여정을 보여주는 템플릿 선택기](/static/core/admin/img/help/journey-builder/journey-builder-templates.webp)

템플릿을 적용하면 캔버스에 있는 **현재 플로우가 대체**되므로, 여정 설계의 초기 단계에서 사용해야 합니다. Spwig는 기존에 보유한 이메일 또는 세그먼트와 이름이 일치하는 경우 각 단계를 실제 이메일이나 세그먼트에 다시 연결합니다. 매칭이 불가능한 경우 헤더에 이메일 또는 세그먼트 선택이 필요한 단계 수를 보고하여 라이브 전환 전에 완료해야 할 사항을 정확히 파악할 수 있도록 합니다.

## 여정 공유

두 개의 툴바 버튼으로 여정의 설계를 단계 간 또는 스토어 간으로 이동할 수 있습니다:

- **Export**는 여정을 `.journey.json` 파일로 다운로드합니다 — 플로우의 구조(단계, 대기, 분기, Yes/No 경로)에 대한 휴대용 설명과 각 단계에서 사용하는 이메일 및 세그먼트의 *이름*을 포함합니다. 이메일 디자인 자체나 구독자 데이터는 포함되지 않습니다.
- **Import**는 `.journey.json` 파일을 현재 여정에 로드하여 캔버스에 있는 내용을 대체합니다.

이 기능은 자랑스러워하는 플로우를 백업하거나, 검증된 웰컴 시리즈를 다른 Spwig 스토어로 전달하거나, 스토어를 새 설치 환경으로 복제한 후 여정을 재구성하는 데 유용합니다. 템플릿과 마찬가지로, Spwig는 대상 스토어에 일치하는 항목이 있는 경우 이메일과 세그먼트를 이름으로 다시 연결하고, 일치하지 않은 항목은 표시하여 설정을 완료할 수 있도록 합니다.

## 여정 활성화

플로우가 준비되면 빌더의 오른쪽 상단에 있는 상태 컨트롤을 사용하세요. 여정의 현재 상태 — **Draft**, **Active**, 또는 **Paused** — 를 표시하는 필이 **Activate** 버튼 옆에 표시됩니다.

**Activate**를 클릭하면 **플로우가 먼저 확인됩니다**. 작동이 중단될 수 있는 문제가 있으면 활성화가 차단되고 배너에 문제가 나열됩니다 — 예를 들어 이메일이 선택되지 않은 **Send email** 단계, 세그먼트나 Yes/No 경로가 없는 **Branch**, 이후 삭제된 이메일 또는 세그먼트, 또는 무한대로 실행되는 루프 등. 각 문제는 클릭 가능합니다: 선택하면 해당 단계로 이동하며, 수정할 때까지 해당 단계가 빨간색으로 강조 표시됩니다. 경고(도달할 수 없는 단계나 지연이 설정되지 않은 **Wait** 등)도 나열되지만 활성화는 차단하지 않습니다.

![활성화가 차단된 상태로, 배너에 문제가 나열되고 해당 단계가 빨간색으로 강조 표시됨](/static/core/admin/img/help/journey-builder/journey-builder-activate-blocked.webp)

플로우가 통과하면 필이 **Active**로 전환되고, 트리거가 발화될 때마다 구독자가 여정에 등록되기 시작합니다.

버튼이 **일시 정지**로 변경되며, 새로운 가입을 중단합니다 — 이미 진행 중인 구독자는 나머지 단계를 계속 수신합니다.

가입, 쿨다운 및 상태가 상호 작용하는 방식은 [트리거된 여정](/help/triggered-journeys)을 참고하세요.

## 여정에 참여 중인 사용자 확인

여정이 라이브 상태가 되면, 각 단계의 모서리에 작은 **카운트 배지**가 표시됩니다: 현재 해당 단계에 머무르고 있는 구독자의 수입니다. 이는 사람들이 어디로 흐르고 어디에 쌓이는지 빠르게 파악하는 방법입니다. **대기** 단계에 큰 숫자가 표시되는 것은 예상되는 반면, 특정 이메일 바로 전에 쌓이는 현상은 확인해 볼 가치가 있을 수 있습니다. 카운트는 빌더 탭으로 돌아올 때마다 새로고침됩니다.

![도구 모음의 활성화 버튼과 단계에 실시간 카운트 배지가 있는 캔버스](/static/core/admin/img/help/journey-builder/journey-builder-live-counts.webp)

## 팁

- **초안** 상태일 때 플로우를 설계하세요 — **활성화**할 때까지 아무도 가입되지 않습니다. 빌더에서 활성화하면 먼저 빠른 검사를 수행하며, 손상된 플로우가 라이브로 전환되는 것을 방지하므로, 완성되지 않은 여정에 구독자가 가입될 위험이 없습니다.
- 대폭 커스터마이징할 계획이 있더라도 **템플릿**에서 시작하세요 — 노드별로 하나씩 만드는 것보다 기존 플로우를 수정하는 것이 더 빠르며, 이전에 사용해보지 않았다면 분기 패턴을 보여줍니다.
- 템플릿을 적용하거나 파일을 가져온 후, 헤더에서 일치하지 않는 단계에 대한 주석을 확인하고 활성화하기 전에 일치하지 않은 **이메일 보내기** 또는 **분기** 단계를 채우세요.
- 플로우가 넓어질 때(특히 분기인 경우) **맞춤**을 클릭하세요 — 줌이나 팬 후 전체 모양을 다시 확인하는 가장 빠른 방법입니다.
- 여러 대기를 한데 모으는 대신, 지연시키는 이메일 바로 앞에 각 **대기** 단계를 배치하여 단계 이름을 쉽게 스캔할 수 있도록 유지하세요.
- 주요 변경 사항을 수행하기 전에 작동 중인 여정을 **내보내기**하세요 — 결과가 마음에 들지 않을 경우 다시 가져올 수 있는 폴백 사본을 빠르게 유지하는 방법입니다.
