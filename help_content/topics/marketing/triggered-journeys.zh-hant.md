Campaign Studio 的 **Journeys** 是自動化的多步驟電子郵件序列，當客戶執行特定動作時會自動觸發 —— 註冊、下訂單、將商品留在購物車中、一陣子沒有活躍，或訂單已送達。您無需記住手動傳送歡迎電子郵件、購物車回復提示或評論請求，只需建立一次序列，Spwig 會為所有符合條件的客戶執行該序列，只要旅程保持活躍狀態。

## 三種發送電子郵件的方式

Campaign Studio 現在涵蓋三種不同的發送模式：

| 類型 | 行為 |
|------|-----------|
| **廣播** | 僅發送一次 —— 立即發送或在單一排定日期和時間。用於一次性公告或促銷。 |
| **重複** | 一個在重複時間表上發送的範本（參見 [重複活動](/help/recurring-campaigns)）。 |
| **旅程** | 一個多步驟序列，當客戶生命周期事件發生時自動觸發，然後在數小時或數天內逐步發送。 |

旅程沒有自己的「發送」按鈕，也沒有要設定的排程 —— 它是根據事件來觸發，而不是根據時間。

## 觸發條件

每段旅程只會監聽一個特定事件，作為旅程的 **觸發條件**：

| 觸發條件 | 觸發時機 |
|---------|-----------|
| **客戶註冊** | 建立新的客戶帳戶時。 |
| **訂單已下** | 任何訂單被下單時，無論是新客戶或回購客戶。 |
| **首筆訂單已下** | 特指客戶的第一筆訂單。 |
| **購物車遺棄** | 購物者將商品加入購物車後，未結帳即處於閒置狀態。 |
| **客戶流失（挽回）** | 客戶已有一段時間未下單。 |
| **訂單已送達** | 訂單狀態變更為「已送達」時。 |
| **商品補貨** | 客戶曾要求通知的商品重新可供購買時。 |

## 詳細說明：挽回與重新參與的觸發條件

**訂單已送達** 與 **商品補貨** 會立即觸發，方式與 **訂單已下** 相同。**購物車遺棄** 與 **客戶流失（挽回）** 的運作方式不同：Spwig 不會對單一時刻做出反應，而是定期檢查符合條件的購物者與客戶，因此從購物車閒置（或客戶流失）到正式納入旅程之間，可能會有短暫的延遲。

**購物車遺棄** — 納入那些將商品加入購物車後，未完成結帳即處於閒置狀態的購物者。預設情況下，這發生在約一小時的無活動之後；精確的閒置時間窗口（以及 Spwig 會回溯多久）是您的主機可為您的商店調整的閾值。此功能適用於已登入的購物者與訪客——對於訪客，Spwig 會使用結帳時捕獲的電子郵件地址。如果購物者回來並完成訂單，他們將自動從旅程中移除，因此已完成的購買不會收到「您是否遺忘了什麼？」的電子郵件。在挽回電子郵件中加入 **遺棄購物車** 內容區塊，以顯示遺留的具體商品，包含即時價格、圖片以及返回購物車連結——或使用 **精選商品** 區塊來突出單一商品。

**客戶流失（挽回）** — 納入已有一段時間未下單的客戶，給予他們回訪的理由。

預設為 90 天內無購買（這也是一個可透過主機調整的閾值）。

客戶在該時間窗口內最多只會重新進入一次挽回旅程，因此持續未回購的客戶不會立即被再次納入。

**訂單已送達** — 當訂單狀態變更為 **已送達** 時，將客戶納入旅程，這是在幾天後詢問評價的自然時機。此觸發器在每次訂單進入已送達狀態時觸發一次——對已送達訂單的後續編輯不會再次觸發。請注意，訂單列表中的 **將選取的訂單標記為已送達** 批量操作會直接更新訂單，不會觸發此觸發器（或送達確認郵件）；若要觸發，請逐一更新訂單，或透過 Spwig 行動應用程式更新。

**商品重新補貨** — 當客戶要求通知的商品重新補貨時，Spwig 會檢查您是否有正在監聽此觸發器的活躍旅程。如果有，客戶將被納入該旅程，而非單純的一次性通知——因此您可以加入延遲、顯示補貨商品的 **精選商品** 區塊，或後續電子郵件。如果沒有活躍的補貨旅程，客戶仍會收到與之前完全相同的標準一次性通知郵件，因此為此觸發器啟用旅程完全是可選的。

## 建立旅程

前往 **活動工作室 > 旅程** 並點擊 **新增旅程**。

1.

為旅程設定 **名稱** — 這僅供您參考；客戶永遠不會看到它。
2.

選擇 **觸發器** 事件。
3.

選擇性地將 **僅限於區段** 設定為某個區段 — 設定後，只有屬於該區段的訂閱者才會被納入。

留空則納入所有符合資格的訂閱者。
4.

設定 **每位訂閱者僅一次** 和 **重新納入冷卻期（天）** — 請參閱下方的 [防止過度納入](#guarding-against-over-enrollment)。
5.

將 **狀態** 設定為 **活躍** 以啟用旅程。

在設計階段，請將其保持為 **草稿** 狀態，或將其設為 **暫停** 以停止新的訂閱，同時保留您的設定。
6.

點擊 **儲存** — Spwig 會直接帶您進入 [Journey Builder](/help/journey-builder)，這是在此視覺畫布上設計實際序列的地方：哪些電子郵件會發送、之間等待多久，以及不同的訂閱者是否應遵循不同的路徑。

一個簡單的三步歡迎系列，在畫布上設計完成後，可能看起來像這樣：

| 步驟 | 等待 | 發送 |
|------|-------|-------|
| 1 | 立即 | 歡迎電子郵件 |
| 2 | 3 天後 | 入門技巧 |
| 3 | 再過 7 天 | 首單折扣 |

這些電子郵件本身是您在與廣播相同的視覺建構器中設計的普通活動 — 主旨、內容區塊，一切皆同。您無需自行排程或發送；將其保持為 **草稿** 狀態，並從建構器中該步驟的下拉選單中選擇即可。旅程會為您發送，每位到達該步驟的訂閱者僅發送一次。

請參閱 [Journey Builder](/help/journey-builder) 以獲取在畫布上設計步驟、使用 **是/否** 條件分支旅程，以及從現成模板開始而非空白畫布的完整指南。

## 對步驟進行 A/B 測試

任何 **發送電子郵件** 步驟都可以轉換為 A/B 測試，讓旅程自動發現 — 並繼續使用 — 表現最佳的電子郵件。由於旅程是持續運行的（訂閱者會隨時間陸續加入），Spwig 不會測試固定批次後停止；相反，它**將新加入者均勻分配到各變體中，觀察每個變體的表現，並一旦某個變體成為明確的統計贏家，就將其鎖定為所有未來加入者的版本。** 已經進行到一半的訂閱者將保留他們最初收到的版本。

在 [Journey Builder](/help/journey-builder) 中開啟一個發送電子郵件步驟，並設定 **步驟類型**：

- **單一電子郵件** — 預設行為：每個人都會收到你選擇的那封電子郵件。
- **A/B：不同電子郵件** — 選擇 **兩到四封** 電子郵件（不同的設計、優惠或版面）；每位註冊者會收到其中一封。
- **A/B：不同主旨** — 選擇一封電子郵件並輸入 **兩到四個** 主旨；每位註冊者會收到該電子郵件，但主旨不同。

然後選擇 **根據...選擇勝者** — **開啟率**（通常用於主旨測試）或 **點擊率** — 完成設定。設定流程為 **啟用** 後，註冊者會被分配到各個變體。

此步驟的面板會顯示 **即時比分**，隨著資料的到來 —— 每個變體的收件人數、開啟率和點擊率，以及 Spwig 對領導者（「以 92% 的信心水準領先」）的自信程度。只有當 Spwig 至少有 **95% 的信心** *且資料足夠可信* 時，才會鎖定勝者，因此低流量的流程不會過早下結論。一旦鎖定，此步驟會顯示 **「勝者已鎖定：變體 B」**，每位新註冊者都會收到該變體；在畫布上，卡片會顯示 **「A/B · N 封電子郵件」**（測試中），一旦決定後則顯示 **「A/B 勝者：B」**。

一些需要注意的事項：

- **提供足夠的流量。** 信心水準取決於流量數量 —— 如果只有少數人到達此步驟，可能會一會兒顯示「資料不夠」。A/B 測試在穩定註冊的流程中表現最佳。
- **編輯變體或勝者指標會重新開始測試** —— 之前已鎖定的勝者會被清除，以讓新的設定獲得自己的結果。
- 如果 A/B 步驟中的變體少於兩個，則會 **阻止流程設為啟用**，直到你完成此步驟（或切換回單一電子郵件）。

請參閱 [A/B 測試](ab-testing) 以了解更多關於 Spwig 如何讀取信心水準和顯著性的資訊。

## 當註冊如何運作

當客戶觸發事件時，Spwig 會檢查所有正在監聽該事件的活躍流程，並針對每個客戶符合條件的流程，**註冊** 他們到流程的起始點。

保留所有 markdown 格式、圖片路徑、程式碼區塊和技術術語。

從那裡開始，Spwig 會引導訂閱者按照您在畫布上設計的流程繼續前進——等待每個 **Wait** 步驟、發送每個 **Send email** 步驟的電子郵件，並在每個 **Branch** 處遵循正確的 **Yes**/**No** 路徑——直到他們到達 **Exit** 步驟，此時該訂閱者的旅程會被標記為 **Completed**。

**始終尊重同意狀態。** 未選擇接收行銷電子郵件的訂閱者，或之後已取消訂閱的訂閱者，將被直接跳過——旅程不會為其他訂閱者中斷，而旅程中取消訂閱會自動停止該訂閱者剩餘的發送。您永遠不需要自行根據同意狀態篩選旅程。

## 防止過度報名

旅程上的兩個設定控制訂閱者可以多久通過一次該旅程：

| 設定 | 功能 | 常見用途 |
|---------|--------------|-------------|
| **Once per subscriber** *(預設開啟)* | 無論觸發事件對該訂閱者再次發生多少次，每位訂閱者最多只能報名一次。 | 歡迎系列——客戶應該只收到一次。 |
| **Re-enrollment cooldown (days)** | 當 **Once per subscriber** 關閉時，設定自訂閱者上次報名以來必須經過的最少天數，之後才能再次報名。設為 `0` 表示無冷卻期。 | 訂單觸發的系列，應為新訂單再次執行，但不應在同一週內為每筆訂單重複觸發。 |

對於希望按訂單執行的旅程（例如購買後感謝訊息），請關閉 **Once per subscriber**，並搭配冷卻期，以便在同一天下單兩次的客戶只被報名一次。無論這些設定如何，正在積極進行某旅程的訂閱者永遠不會被報名到同一旅程的第二個重疊執行中。

## 監控旅程

在 **Campaign Studio > Journeys** 列表中，您可以查看每個旅程的 **Trigger**、**Status**、所發送的 **Emails** 數量，以及正在運行的 **Enrolled** / **Completed** 總計，讓您一眼就能看出旅程是否真正觸達了受眾。

![顯示兩個活躍旅程及其註冊與完成數量的旅程列表](/static/core/admin/img/help/triggered-journeys/journey-list.webp)

若要查看個別訂閱者而非總計數據，請在 `/admin/email_marketing/journeyenrollment/` 開啟 **Journey Enrollments** 列表。每一行顯示一位訂閱者在單一旅程中的進度：他們所在的 **Journey**、**Current step**、**Status**（Active、Completed 或 Cancelled），以及 **Next step** 的到期時間。使用篩選器可將範圍縮小至單一旅程或單一狀態——例如，篩選為 **Active** 可顯示目前處於序列中途的所有人。

![顯示訂閱者在兩個旅程中進度的旅程註冊列表](/static/core/admin/img/help/triggered-journeys/journey-enrollments.webp)

## Journey report

每個旅程都有獨立的 **Report** 頁面，可透過點擊 **Campaign Studio > Journeys** 中旅程卡片上的 **Report** 按鈕，或在旅程自身的設定頁面開啟。這是單頁摘要，顯示註冊者在序列中推進的進度，以及（若您的電子郵件包含追蹤連結）該旅程所帶來的營收。

![顯示註冊漏斗、歸因營收卡片及按步驟分類的營收表格的旅程報告頁面](/static/core/admin/img/help/triggered-journeys/journey-report.webp)

### Enrollment funnel

四張卡片顯示註冊者目前的狀態：

| 卡片 | 显示内容 |
|------|---------------|
| **已注册** | 曾经进入此流程的订阅者总数。 |
| **当前活跃** | 正在流程中，等待或处理下一步的注册者。 |
| **已完成** | 达到流程的 **退出** 步骤的注册者。 |
| **已退出** | 在完成流程前被移出流程的注册者 —— 例如，购物者在购物车遗弃流程中完成结账中途，或订阅者取消订阅。 |

如果流程尚无注册者，所有四个卡片显示为零，并会有一条提示信息提醒您，一旦客户开始进入流程，指标就会出现。

### 归因销售额

**归因销售额** 卡片的工作方式与 [广告活动报告](campaign-reports) 相同 —— Spwig 会追踪订单，以追溯到流程电子邮件中的链接点击，与该页面上的 [归因销售额](campaign-reports#attributed-revenue) 中描述的点击通过、受许可限制的归因方式相同。此处也适用相同的注意事项：归因仅基于点击通过（仅打开邮件不会归因销售额），它遵循您商店的活动归因模型和回溯窗口，尊重分析许可，并且不具有回溯性 —— 流程仅显示在您的商店启用归因跟踪之后发送的电子邮件的销售额。

卡片的副标题将总销售额分解为：

- **订单** —— 该流程中每个步骤的电子邮件组合中，归因于该流程的订单数量。
- **AOV** —— 这些订单的平均订单价值。
- **每位注册者销售额** —— 归因销售额除以总 **已注册**。 流程不像广告活动那样有一个单一的“支出” —— 它是持续运行的，而不是一次性支出 —— 所以这里没有 ROAS 数字。 **每位注册者销售额** 是最接近的等效值：一个稳定且可比较的指标，用于衡量流程将注册者转化为销售的效率，您可以随时间跟踪或与其他流程进行比较。

保留所有 markdown 格式、图片路径、代码块和术语。

### 各步驟營收

當旅程至少包含一個**發送電子郵件**步驟時，**各步驟營收**表格會進一步細分總營收，每個步驟佔一行，讓您可以看出序列中哪封電子郵件真正帶來效益：

| 欄位 | 顯示內容 |
|--------|---------------|
| **步驟** | 該步驟的電子郵件，若該步驟正在執行 [A/B 測試](ab-testing)，則會顯示 **A/B** 徽章。 |
| **營收** | 歸因於該步驟電子郵件所追溯訂單的營收。 |
| **訂單數** | 該營收數字背後的訂單數量。 |
| **已發送** | 該步驟電子郵件已發送的次數。 |
| **開啟** / **點擊** | 這些發送中有多少被開啟，以及有多少被點擊。Spwig 會追蹤每個步驟發送的開啟與點擊次數，無論是一般版本還是 A/B 版本。 |

使用此表格來找出看似健康旅程中的弱點——例如，在歡迎系列中，如果第一封電子郵件貢獻了大部分營收，而後續步驟貢獻甚微，那麼該步驟可能適合提供更強力的優惠或重新撰寫內容，而非假設整個序列都需要重新設計。

- 最快的啟動購物車放棄、回頭客、交付後評價或庫存回報旅程的方式是使用起始範本 —— 當您以這些觸發條件之一儲存新旅程時，[Journey Builder](/help/journey-builder) 的 **範本** 選項會提供一個即時可用的流程（**放棄購物車回復**、**回頭客營銷**、**交付後評價請求** 或 **庫存回報通知**），您可以調整，而不是從頭開始建立。
- 在您建立旅程的步驟時，請將每個旅程設為 **草稿**，然後在檢查電子郵件和延遲時間後，將 **狀態** 變更為 **活躍** —— 在它變為活躍之前，不會有任何會員註冊。
- 為任何與一次性里程碑（註冊、首次訂單）相關的內容保持 **每次會員** 選項為啟用，為任何應該重複的內容（例如購買後系列）關閉此選項，並設定合理的冷卻時間。
- 使用 **僅適用於群組** 為特定受眾運行不同的歡迎系列 —— 例如，VIP 群組會收到比其他人都更豐富的序列。
- 如果您希望第一封電子郵件在觸發條件觸發後立即發送，請將第一步的等待時間設為 `0`，而不是等待。
- 在啟動新旅程後，請檢查 **旅程會員註冊** 列表，以確認會員註冊是否實際上被註冊，並按照預期進行步驟。
- 暫停旅程（**狀態：已暫停**）會停止新會員註冊，但不會取消已經進行到一半的會員註冊 —— 他們會繼續收到剩餘的步驟。
