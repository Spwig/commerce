Campaign Studio의 **Journeys**는 고객이 특정 행동을 수행할 때마다 자동으로 시작되는 다단계 이메일 시퀀스입니다. 고객이 가입하거나, 주문을 하거나, 장바구니에 상품을 남기거나, 일정 기간 동안 활동이 없거나, 주문이 배송된 경우 등이 해당됩니다. 환영 이메일, 장바구니 복구 알림, 리뷰 요청 등을 수동으로 보내야 할 필요 없이, 시퀀스를 한 번만 구성하면 Spwig가 해당 조건을 충족하는 모든 고객에게 여정이 활성화된 동안 자동으로 실행합니다.

## 이메일 전송의 세 가지 방식

Campaign Studio는 이제 세 가지 서로 다른 전송 패턴을 지원합니다:

| 유형 | 동작 방식 |
|------|-----------|
| **Broadcast** | 즉시 또는 단일 예약된 날짜와 시간에 한 번만 전송됩니다. 일회성 공지나 세일에 사용하세요. |
| **Recurring** | 반복되는 일정(예: 매일, 매주)에 따라 전송되는 템플릿입니다(자세한 내용은 [Recurring Campaigns](/help/recurring-campaigns) 참조). |
| **Journey** | 라이프사이클 이벤트가 발생하면 해당 고객에게 자동으로 시작되며, 수 시간 또는 수일에 걸쳐 단계별로 전송되는 다단계 시퀀스입니다. |

여정은 자체적인 "전송" 버튼이나 설정할 일정이 없으며, 시계 대신 이벤트에 반응합니다.

## 트리거

모든 여정은 여정의 **Trigger**로 설정된 정확히 하나의 이벤트를 감시합니다:

| 트리거 | 발생 시점 |
|---------|-----------|
| **고객 가입** | 새로운 고객 계정이 생성될 때. |
| **주문 완료** | 신규 또는 기존 고객이 주문을 할 때. |
| **첫 주문 완료** | 고객의 첫 번째 주문이 완료될 때. |
| **장바구니 포기** | 쇼핑객이 장바구니에 상품을 담고 결제 없이 비활성 상태가 될 때. |
| **고객 이탈 (재유입)** | 고객이 장기간 주문을 하지 않았을 때. |
| **주문 배송 완료** | 주문 상태가 '배송 완료'로 변경될 때. |
| **상품 재입고** | 고객이 알림을 요청한 상품이 다시 재고로 들어올 때. |

## 복구 및 재참여 트리거 상세 설명

**주문 배송 완료**와 **상품 재입고**는 **주문 완료**와 동일한 방식으로 즉시 발생합니다. **장바구니 포기**와 **고객 이탈 (재유입)**은 작동 방식이 다릅니다. 단일 순간에 반응하는 대신, Spwig는 조건에 해당하는 쇼핑객과 고객을 주기적으로 확인하므로, 장바구니가 비활성 상태가 되거나(또는 고객이 이탈한 후) 등록까지 짧은 지연이 발생할 수 있습니다.

**장바구니 포기** — 장바구니에 상품을 담고 결제를 완료하지 않은 채 비활성 상태가 된 쇼핑객을 등록합니다. 기본적으로 약 1시간의 비활성 상태 이후에 발생하며, 정확한 비활성 시간(및 Spwig가 과거로 거슬러 올라갈 수 있는 범위)은 호스트가 스토어에 맞게 조정할 수 있는 임계값입니다. 로그인한 쇼핑객과 게스트 모두에게 적용되며, 게스트의 경우 결제 시 수집된 이메일 주소를 사용합니다. 쇼핑객이 돌아와 주문을 완료하면 자동으로 여정에서 제외되므로, 완료된 구매에는 "무언가를 잊으셨나요?" 이메일이 발송되지 않습니다. 복구 이메일에 **포기된 장바구니** 콘텐츠 블록을 추가하여 정확히 무엇을 남겼는지 실시간 가격, 이미지, 장바구니로 돌아가는 링크와 함께 표시할 수 있습니다. 또는 **추천 상품** 블록을 사용하여 특정 상품을 강조할 수도 있습니다.

**고객 이탈 (재유입)** — 장기간 주문을 하지 않은 고객을 등록하여 다시 방문할 이유를 제공합니다.

기본값은 구매가 없는 90일입니다(호스트에서 조정 가능한 임계값이기도 합니다).

고객은 해당 기간 동안 최대 1회만 재입문(재가입)되므로, 이탈 상태가 유지되는 고객은 바로 다시 등록되지 않습니다.

**주문 완료** — 주문 상태가 **배송 완료**로 변경되면 고객을 등록합니다. 이는 며칠 후 리뷰를 요청하기에 자연스러운 시점입니다. 주문당 1회, 배송 완료 상태로 전환될 때만 발화되며 — 이미 배송 완료된 주문에 대한 후속 수정은 다시 발화하지 않습니다. 주문 목록의 **선택한 주문을 배송 완료로 표시** 일괄 작업은 주문을 직접 업데이트하며 이 트리거(또는 배송 확인 이메일)를 발화하지 않습니다. 발화하려면 주문을 하나씩 업데이트하거나 Spwig 모바일 앱을 통해 업데이트하세요.

**제품 재입고** — 고객이 알림을 요청한 제품이 재입고되면, Spwig는 이 트리거를 감시하는 활성 여정이 있는지 확인합니다. 있다면, 고객은 단순한 일회성 알림 대신 해당 여정에 등록됩니다 — 이렇게 하면 지연 시간, 재입고된 제품을 보여주는 **추천 제품** 블록, 또는 후속 이메일을 추가할 수 있습니다. 재입고 여정이 활성 상태가 아니면, 고객은 이전과 동일하게 표준 일회성 알림 이메일을 받습니다. 따라서 이 트리거에 대한 여정을 활성화하는 것은 완전히 선택 사항입니다.

## 여정 만들기

**캠페인 스튜디오 > 여정**으로 이동하고 **여정 추가**를 클릭하세요.

1.

여정에 **이름**을 지정하세요 — 이는 참고용이며, 고객은 절대 볼 수 없습니다.
2.

**트리거** 이벤트를 선택하세요.
3.

선택적으로 **세그먼트에만**을 세그먼트로 설정하세요 — 설정 시, 해당 세그먼트에 속한 구독자만 등록됩니다.

비워 두면 모든 대상 구독자가 등록됩니다.
4.

**구독자당 1회** 및 **재등록 쿨다운(일)**을 설정하세요 — 아래 [과도한 등록 방지](#guarding-against-over-enrollment)를 참조하세요.
5.

**상태**를 **활성**으로 설정하여 여정을 켜세요.

설계 중에는 **초안(Draft)** 상태로 두거나, 설정을 유지하면서 새로운 가입을 중단하려면 **일시중지(Paused)**로 설정하세요.
6.

**저장(Save)**을 클릭하면 Spwig이 [Journey Builder](/help/journey-builder)로 바로 이동합니다. Journey Builder는 실제 시퀀스를 설계하는 시각적 캔버스로, 어떤 이메일을 보내는지, 이메일 사이에 얼마나 기다릴지, 그리고 다른 구독자가 다른 경로를 따라야 하는지를 결정합니다.

캔버스에서 설계한 간단한 3단계 환영 시리즈는 다음과 같이 보일 수 있습니다:

| 단계 | 대기 | 발송 |
|------|-------|-------|
| 1 | 즉시 | 환영 이메일 |
| 2 | 3일 후 | 시작 팁 |
| 3 | 그 후 7일 후 | 첫 주문 할인 |

이메일 자체는 브로드캐스트에 사용하는 것과 동일한 시각적 빌더에서 설계하는 일반적인 캠페인입니다. 주제 줄, 콘텐츠 블록 등 모든 것이 포함됩니다. 직접 일정 잡기나 발송할 필요가 없으며, **초안(Draft)** 상태로 두면 빌더의 단계 드롭다운에서 선택하기만 하면 됩니다. Journey가 해당 단계에 도달한 구독자당 한 번씩 대신 발송합니다.

캔버스에서 단계를 설계하고, **예/아니오(Yes/No)** 조건으로 Journey를 분기하며, 빈 캔버스 대신 준비된 템플릿에서 시작하는 방법에 대한 전체 가이드는 [Journey Builder](/help/journey-builder)를 참조하세요.

## 단계 A/B 테스트

모든 **이메일 발송(Send email)** 단계를 A/B 테스트로 전환할 수 있어, Journey가 자동으로 가장 잘 수행되는 이메일을 발견하고 계속 사용합니다. Journey는 지속적으로 실행되므로(구독자가 시간에 따라 도착함), Spwig은 고정된 배치만 테스트하고 중단하지 않습니다. 대신 **가입자를 변형(variant)에 고르게 분배하고, 각 변형의 성능을 관찰한 후, 한 변형이 명확한 통계적 승자가 되면 모든 향후 가입자에게 해당 변형을 고정합니다.** 이미 진행 중인 구독자는 처음 받은 버전을 유지합니다.

[Journey Builder](/help/journey-builder)에서 이메일 발송 단계를 열고 **단계 유형(Step type)**을 설정하세요:


- **단일 이메일** — 기본 동작: 선택한 하나의 이메일을 모든 수신자에게 발송합니다.
- **A/B: 다른 이메일** — **두 개에서 네 개**의 이메일(디자인, 혜택 또는 레이아웃이 다른)을 선택합니다. 각 가입자에게 하나씩 발송됩니다.
- **A/B: 다른 제목** — 하나의 이메일을 선택하고 **두 개에서 네 개**의 제목을 입력합니다. 각 가입자에게 해당 이메일이 서로 다른 제목과 함께 발송됩니다.

그 다음 **승자 선택 기준**으로 **열람률**(제목 테스트에 일반적으로 가장 적합) 또는 **클릭률**을 선택하면 완료됩니다. 여정을 **활성화**하면 가입자들이 각 변형으로 분배되기 시작합니다.

단계 패널에는 데이터가 들어오는 동안 **실시간 점수판**이 표시됩니다 — 각 변형의 수신자 수, 열람률, 클릭률, 그리고 Spwig가 선두에 대한 확신 수준("92% 확신으로 선두")이 포함됩니다. Spwig가 최소 **95% 확신**에 도달하고 *신뢰할 수 있을 만큼 충분한 데이터*가 있을 때만 승자가 확정되므로, 트래픽이 적은 여정은 결론을 내리지 않습니다. 확정이 되면 단계에는 **"승자 확정: 변형 B"**라고 표시되고, 모든 신규 가입자에게 해당 변형이 발송됩니다. 캔버스에서는 테스트 중에는 카드에 **"A/B · N개 이메일"**이 표시되고, 결정 후에는 **"A/B 승자: B"**로 변경됩니다.

알아둘 점 몇 가지:

- **트래픽을 확보하세요.** 확신은 볼륨에 따라 달라집니다 — 소수의 사람만 도달하는 단계는 "아직 데이터가 부족합니다" 상태로 유지될 수 있습니다. A/B 테스트는 꾸준한 가입이 있는 여정에서 빛을 발합니다.
- **변형이나 승자 기준을 편집하면 새로운 테스트가 시작됩니다** — 이전에 확정된 승자는 초기화되어 새로운 설정이 자체 결과를 얻습니다.
- 변형이 두 개 미만인 A/B 단계는 완료할 때까지(또는 단일 이메일로 되돌릴 때까지) **여정의 활성화를 차단**합니다.

Spwig가 확신과 유의성을 어떻게 읽는지 자세히 알아보려면 [A/B 테스트](ab-testing)를 참조하세요.

## 가입 방식

고객에게 트리거 이벤트가 발생하면, Spwig는 해당 이벤트를 대기 중인 모든 활성 여정을 확인하고, 고객이 자격을 갖춘 각 여정에 대해 플로우의 시작 지점에서 **가입**시킵니다.

그 후 Spwig은 캔버스에서 설계한 흐름에 따라 구독자를 진행시킵니다 — 각 **대기** 단계를 기다리고, 각 **이메일 보내기** 단계의 이메일을 전송하며, **분기**에서 올바른 **예**/**아니오** 경로를 따릅니다 — **종료** 단계에 도달할 때까지, 이때 해당 구독자의 여정은 **완료**로 표시됩니다.

**동의는 항상 존중됩니다.** 마케팅 이메일에 동의하지 않았거나 이후 구독을 해지한 구독자는 단순히 건너뛰어집니다 — 여정은 다른 구독자를 위해 중단되지 않으며, 여정 중 해지 시 해당 구독자의 남은 전송은 자동으로 중단됩니다. 동의 상태에 따라 여정을 직접 필터링할 필요가 없습니다.

## 과도한 등록 방지

여정의 두 가지 설정이 구독자가 여정을 얼마나 자주 진행할 수 있는지를 제어합니다:

| 설정 | 동작 | 일반적인 사용 |
|---------|--------------|-------------|
| **구독자당 1회** *(기본값: 켜짐)* | 트리거 이벤트가 다시 발생하더라도 각 구독자는 평생 최대 1회만 등록됩니다. | 환영 시리즈 — 고객은 이를 한 번만 받아야 합니다. |
| **재등록 쿨다운 (일)** | **구독자당 1회**가 꺼져 있을 때, 구독자가 다시 등록될 수 있기 전에 마지막 등록 이후 경과해야 하는 최소 일수를 설정합니다. 쿨다운이 없도록 `0`으로 설정합니다. | 새 주문 시 다시 실행되어야 하지만, 같은 주에 주문한 모든 주문에 대해 다시 트리거되지 않아야 하는 주문 트리거 시리즈. |

주문별로 실행하려는 여정(예: 구매 후 감사 메시지)의 경우 **구독자당 1회**를 끄고, 쿨다운과 함께 사용하여 같은 날 두 번 주문한 고객이 한 번만 등록되도록 하십시오. 이미 여정을 진행 중인 구독자는 이러한 설정과 관계없이 동일한 여정의 중복 실행에 등록되지 않습니다.

## 여정 모니터링

The **Campaign Studio > Journeys** list shows each journey's **Trigger**, **Status**, the number of **Emails** it sends, and running **Enrolled** / **Completed** totals, so you can see at a glance whether a journey is actually reaching people.

![The Journeys list showing two active journeys with enrollment and completion counts](/static/core/admin/img/help/triggered-journeys/journey-list.webp)

To see individual subscribers rather than totals, open the **Journey Enrollments** list at `/admin/email_marketing/journeyenrollment/`. Each row shows one subscriber's progress through one journey: which **Journey** they're in, their **Current step**, **Status** (Active, Completed, or Cancelled), and when their **Next step** is due. Use the filters to narrow it down to one journey or one status — for example, filtering to **Active** shows everyone currently mid-sequence.

![The Journey Enrollments list showing subscriber progress across two journeys](/static/core/admin/img/help/triggered-journeys/journey-enrollments.webp)

## Journey report

Every journey has its own **Report** page, opened by clicking the **Report** button on the journey's card in **Campaign Studio > Journeys**, or on the journey's own settings page. It's a single-page summary of how far enrollees get through the sequence and, where your emails contain tracked links, how much revenue the journey has driven.

![The Journey report page showing the enrollment funnel, attributed revenue card, and revenue-by-step table](/static/core/admin/img/help/triggered-journeys/journey-report.webp)

### Enrollment funnel

Four cards show where enrollees currently stand:

| 카드 | 표시 내용 |
|------|---------------|
| **가입됨** | 이 여정에 한 번이라도 진입한 구독자의 총 수. |
| **현재 활성** | 시퀀스를 진행 중인 가입자, 다음 단계를 대기 중이거나 진행 중인 상태. |
| **완료됨** | 여정의 **종료** 단계에 도달한 가입자. |
| **탈퇴됨** | 완료 전에 여정에서 제외된 가입자 — 예를 들어, 장바구니 포기 시퀀스 중간에 체크아웃을 완료한 쇼핑객이나 구독을 해지한 구독자. |

여정에 아직 가입자가 없다면, 네 개의 카드 모두 0으로 표시되며, 고객이 여정에 진입하기 시작하면 지표가 표시된다는 안내 메시지가 표시됩니다.

### 귀속 매출

**귀속 매출** 카드는 [캠페인 보고서](campaign-reports)와 동일한 방식으로 작동합니다 — Spwig은 여정 이메일 내 링크 클릭으로 주문을 추적하며, 해당 페이지의 [귀속 매출](campaign-reports#attributed-revenue)에서 설명된 것과 동일한 클릭 기반, 동의 기반 귀속 방식을 따릅니다. 동일한 주의 사항이 여기에 적용됩니다: 귀속은 클릭 기반만 해당되며(단순 열람만으로는 매출이 귀속되지 않음), 스토어의 활성 귀속 모델과 회귀 기간을 따르며, 분석 동의를 준수하고, 소급 적용되지 않습니다 — 스토어에서 귀속 추적이 활성화된 이후에 전송된 이메일에 대한 매출만 여정에 표시됩니다.

카드의 하위 줄은 총액을 다음과 같이 세분화합니다:

- **주문** — 이 여정에 귀속된 주문 수, 모든 단계의 이메일을 합산한 값.
- **AOV** — 해당 주문들의 평균 주문 금액.
- **가입자당 매출** — 귀속 매출을 총 **가입됨** 수로 나눈 값. 캠페인과 달리 여정은 단일 "지출"이 없으며 — 일회성 비용이 아니라 지속적으로 실행되므로 — 여기에는 ROAS 수치가 없습니다. **가입자당 매출**은 가장 유사한 지표로, 여정이 가입을 판매로 전환하는 효율성을 시간에 따라 추적하거나 다른 여정과 비교할 수 있는 안정적이고 비교 가능한 측정치입니다.

### 단계별 수익

여정이 최소 한 개의 **이메일 전송** 단계를 포함하는 경우, **단계별 수익** 테이블은 총 수익을 단계별로 한 줄씩 나누어 보여 주므로, 시퀀스에서 어떤 이메일이 실제로 성과를 내고 있는지 확인할 수 있습니다:

| 열 | 표시 내용 |
|--------|---------------|
| **단계** | 해당 단계의 이메일이며, 해당 단계에서 [A/B 테스트](ab-testing)가 실행 중이면 **A/B** 배지가 표시됩니다. |
| **수익** | 해당 단계의 이메일로 추적된 주문에서 귀속된 수익입니다. |
| **주문** | 해당 수익 수치에 해당하는 주문 수입니다. |
| **전송** | 해당 단계의 이메일이 전송된 횟수입니다. |
| **열림** / **클릭** | 해당 전송 중 열림 수와 클릭 수입니다. Spwig은 일반 및 A/B 테스트를 포함한 모든 단계의 전송에 대해 열림과 클릭을 추적합니다. |

이 테이블을 사용하여 전반적으로 건강한 여정에서 약한 고리를 찾아낼 수 있습니다. 예를 들어, 첫 번째 이메일이 대부분의 수익을 창출하고 후속 단계의 기여도가 낮은 웰컴 시리즈의 경우, 전체 시퀀스를 재설계해야 한다고 가정하기보다는 더 강력한 제안이나 재작성을 고려해 볼 수 있습니다.

## 팁

- 장바구니 포기, 재유입, 배송 후 리뷰 요청, 재입고 알림 여정을 시작하는 가장 빠른 방법은 스타터 템플릿입니다 — 이러한 트리거 중 하나로 새 여정을 저장하면 [Journey Builder](/help/journey-builder)의 **Templates** 선택기에 **Abandoned cart recovery**, **Win-back lapsed customers**, **Post-delivery review request**, 또는 **Back-in-stock alert**와 같이 바로 사용할 수 있는 플로우가 제공되며, 처음부터 만들지 않고 조정할 수 있습니다.
- 여정을 만들면서 모든 여정을 **Draft** 상태로 시작하고, 이메일과 지연 시간을 확인한 후 **Status**를 **Active**로 전환하세요 — Active 상태가 될 때까지 아무도 등록되지 않습니다.
- 일회성 마일스톤(가입, 첫 주문)과 관련된 항목에는 **Once per subscriber**를 켜 두세요. 구매 후 시리즈처럼 반복되어야 하는 항목에는 적절한 쿨다운 시간을 설정하고 이 옵션을 끄세요.
- **Only for segment**를 사용하여 특정 대상에게 다른 환영 시리즈를 실행하세요 — 예를 들어 VIP 세그먼트는 다른 모든 사람보다 더 풍부한 시퀀스를 받을 수 있습니다.
- 트리거가 발동된 후 대기하지 않고 즉시 첫 번째 이메일을 보내려면 첫 번째 단계의 대기 시간을 `0`으로 설정하세요.
- 새 여정을 활성화한 후 **Journey Enrollments** 목록을 확인하여 구독자가 실제로 등록되고 예상대로 단계를 진행하는지 확인하세요.
- 여정을 일시 중지(**Status: Paused**)하면 새 등록은 중단되지만 이미 진행 중인 구독자는 취소되지 않습니다 — 그들은 나머지 단계를 계속 수신합니다.
