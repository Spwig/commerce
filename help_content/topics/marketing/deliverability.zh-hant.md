---
title: 電子郵件送達率操作手冊
---

將電子郵件*寄出*很容易。但要讓它進入收件匣而非垃圾郵件資料夾，才是真正的挑戰——Gmail 和 Yahoo 等信箱服務供應商現在會強制執行嚴格的技術要求，才會考慮處理您的郵件。本操作手冊將逐步說明應如何設定、以及設定的順序，確保您的訂單確認信和行銷活動能出現在客戶看得到的地方。

這裡沒有任何一項是一次性的任務。送達率是一種需要隨時間累積建立、且可能迅速喪失的持續性狀態——文末的檢查清單值得在出現任何異常時重新檢視。

## 為什麼這很重要

所有主要收件匣供應商都會在決定是否送達、歸入垃圾郵件資料夾或直接拒絕之前，先對傳入郵件的寄件者聲譽進行評分。自 2024 年起，Gmail 和 Yahoo 已將此機制正式化，針對發送大量郵件的人制定了明確的**大量寄件者要求**：

- **驗證您的網域** — 有效的 SPF、DKIM 和 DMARC 記錄。
- **讓退訂變得容易** — 在每封行銷郵件中提供運作正常且低摩擦的退選機制。
- **保持垃圾郵件投訴率低** — 垃圾郵件投訴率超過約 0.3% 的大量寄件者，其郵件有被拒絕或歸入大量郵件資料夾的風險；最安全的目標是遠低於 0.1%。

若未滿足這些要求，受影響的不僅是行銷活動——受損的網域聲譽也可能導致交易郵件（訂單確認、密碼重設）被歸入垃圾郵件，因為 Gmail 和 Yahoo 越來越傾向於在寄件網域層級而非僅針對單一郵件類型來判斷聲譽。以下是滿足上述三項要求的步驟。

## 步驟 1：驗證您的寄件網域

SPF、DKIM 和 DMARC 是 DNS TXT 記錄，用於向接收郵件伺服器證明，聲稱來自您網域的郵件確實是由您寄出的。設定方式取決於您的商店使用哪種寄件模式——這三項設定均在管理側邊欄的**電子郵件設定**下進行（這會開啟電子郵件帳戶清單；完整的帳戶設定說明請參閱 [電子郵件設定](email-configuration)）。

| 發送模式 | 身分驗證方式 |
|---|---|
| **內建 SMTP** (Spwig 自己的電子郵件伺服器) | Spwig 會自動為您的網域產生 DKIM 金鑰對。新增電子郵件帳戶後，設定精靈的 **步驟 4** 會顯示您的 SPF、DKIM 和 DMARC 狀態以及要新增的正確記錄，並提供複製到剪貼板功能與針對 Cloudflare、GoDaddy、Namecheap 和 AWS Route 53 的提供者特定指示。如果之後需要再次尋找，相同的 DKIM DNS 記錄也會出現在帳戶的管理頁面中，位於 **DKIM 金鑰設定** 下。 |
| **通用 SMTP** (您自備的提供者，如 SendGrid、Mailgun、Amazon SES 或 Google Workspace，透過 SMTP 凭證連線) | 身分驗證會部分在該提供者的管理後台進行。設定精靈的 DNS 步驟包含 Gmail、Outlook、SendGrid、Mailgun 和 Amazon SES 的分頁指示 —— 每個說明在提供者的控制台中要如何設定（例如在 SendGrid 中驗證發送網域）以及要在 DNS 提供者處新增哪些 DNS 記錄。 |
| **Spwig 托管的郵件網關** | 可用於 Spwig 托管方案中作為管理式傳送選項。它會自動使用 DKIM 簽名送出的郵件，預設從 Spwig 自己驗證過的網域的位址傳送，因此可以零設定使用。如果您想透過網關使用自己的網域傳送郵件，請與您的主機服務提供者聯繫以驗證它——這是一個管理式服務，不是自服務 DNS 流程。 |

![電子郵件帳戶設定精靈的步驟 4，顯示 SPF/DKIM/DMARC 驗證、DNS 提供者分頁，以及可複製的擴展 DKIM 記錄](/static/core/admin/img/help/deliverability/wizard-dns-step.webp)

![現有內建 SMTP 電子郵件帳戶的 DKIM 金鑰設定面板，包含 DNS TXT 記錄和 [複製 DNS 記錄] 按鈕](/static/core/admin/img/help/deliverability/dkim-dns-record.webp)

無論您使用哪種模式，**添加DNS記錄本身始終是外部步驟** — 您需要在您的域名註冊商或DNS主機（如Cloudflare、GoDaddy、Namecheap、Route 53，或您域名的名稱伺服器所指向的任何地方）中進行操作，而不是在Spwig內部進行。

Spwig可以告訴您需要添加什麼記錄，並驗證它是否已生效，但它無法進入您的註冊商並為您添加記錄。

在開始之前，有一些事情值得了解：

- **DNS變更並非即時生效。** 由於傳播需要時間，可能需要幾分鐘到48小時。精靈的驗證步驟會顯示記錄失敗或缺失，直到它實際傳播 —— 這是一種預期現象，並不代表有錯誤。
- **每個域名只允許一個SPF記錄。** 如果您已經有一個（例如來自Google Workspace，或其他郵件服務器），請使用 `include:` 將您的新發件人新增到現有記錄中，而不是建立第二個SPF TXT記錄 —— 兩個SPF記錄會導致所有人的驗證失敗。
- **DMARC需要SPF或DKIM已通過。** 請在SPF和DKIM都驗證通過後，最後再設置它。

## 步驟2：使用真實的發件身分

當您完成域名驗證後，請確保收件人實際看到的內容能支持它：

- **發件人地址** — 請使用您自己的驗證域名上的地址（`orders@yourstore.com`），而不是免費郵件服務商的地址（`yourstore@gmail.com`）。免費郵件服務商的發件人地址完全無法被您的SPF/DKIM/DMARC記錄驗證，郵箱服務提供商會將其視為商店的強烈垃圾郵件信號。
- **發件人名稱** — 請使用您商店的可識別名稱，而不是通用標籤如「通知」或「無回覆」。
- **回覆郵件地址** — 設定一個受監控的地址。未受監控的 `noreply@` 地址如果無法接收或自動丟棄回覆，本身會成為一種輕微的聲譽信號，並阻礙客戶告訴您有問題的途徑。

在 **電子郵件設定 >（您的帳號）> 發件人設定** 中設置這三項 —— 請參閱 [電子郵件設定](email-configuration) 以獲得完整的欄位說明。

## 步驟 3：在擴展之前進行暖機

一個沒有發送歷史的域名或 IP 地址還沒有聲譽——無論好壞——郵箱提供商對未知的發送者會比較謹慎。從全新的域名發送大量郵件在統計上與垃圾郵件發送者開始新活動完全相同，即使所有技術指標都符合要求，也可能會被分類到郵件群組中。

- 從小規模開始。首先將您的前幾次活動發送到最活躍、最可能打開郵件的受眾，而不是一次發送到整個名單——請參閱 [受眾](audiences) 以了解如何建立針對性的起始段。
- 在最初的幾週內逐漸增加數量，而不是直接發送到整個名單。
- 如果您正在從其他平台遷移現有的名單，也應將其視為聲譽的首日——您舊平台的發送歷史不會隨著域名一起轉移。

## 步驟 4：保持名單乾淨

每一次投訴或退信都會影響您的聲譽，這兩者在很大程度上取決於您名單中的聯繫人以及他們是如何加入的：

- **僅向同意接收郵件的人發送。** 導入的聯繫人、購買的名單和爬取的地址是導致投訴和硬退信的最快方式。
- **使用雙重確認。** Spwig 的營銷同意流程在發送營銷郵件之前驗證訂閱者的電郵地址——請參閱 [通訊偏好](communication-preferences) 以了解如何進行此設置。
- **讓 Spwig 的自動抑制功能發揮作用。** Spwig 會監控硬退信、投訴和重複的軟退信，並自動停止向這些地址發送郵件，無需任何設置——請參閱 [名單清潔與抑制](list-hygiene) 以了解其運作方式以及什麼時候（很少）需要覆蓋。
- **定期刪除不活躍的訂閱者** 而不是無限期地向同一組不活躍的地址發送郵件——一個打開和點擊次數減少的名單比一個沒有打開和點擊的大型名單更有價值。

## 步驟 5：監控

在客戶告知您郵件未收到之前，投遞問題通常會先反映在數據上。

每次發送後，開啟該活動的[報告](campaign-reports)並密切關注以下指標：

| 指標 | 需關注的事項 |
|---|---|
| **退信率** | 以軟退信為主屬正常現象；若**硬退信**比例上升，表示您的清單中累積了過期或無效的電子郵件地址。 |
| **垃圾郵件投訴** | 每次發送時應維持在接近零的水平。務必將其控制在 Gmail 和 Yahoo 觸發大量發送者強制措施的約 0.3% 門檻以下——即使出現小幅波動，也應立即進行調查。 |
| **開啟率 / 點擊開啟率** | 若針對同一清單的多次發送（而非單一活動）出現突然且無法解釋的下降，這可能是郵件被歸類為垃圾郵件而非進入收件箱的早期跡象，即使退信率或投訴率尚未出現變化。 |

此外，請定期檢查活動工作室儀表板上的**已抑制地址**卡片——持續少量增加屬於正常的清單衰退，但若突然激增，則值得在下次發送前進行調查（請參閱[清單衛生](list-hygiene)）。

![活動工作室儀表板上的已抑制地址統計卡片](/static/core/admin/img/help/deliverability/suppressed-addresses-card.webp)

若出現異常激增：請先暫停並檢查您的 DNS 記錄是否仍然有效（域名續約過期或無意的 DNS 變更可能會悄悄破壞 SPF/DKIM），然後檢查觸發該問題的發送內容或受眾有何變化。

## 步驟 6：內容衛生

身份驗證和清單品質讓您得以進入收件箱；但內容仍會影響您進入後的待遇。

- **避免觸發垃圾郵件過濾器的模式** 於主旨中 — 全大寫、過多標點符號（"!!!"），以及「立即行動」或「免費金錢」等措辭，即使來自已驗證的網域，仍會降低您在垃圾郵件過濾器中的評分。
- **不要發送純圖片郵件。** 一封僅包含單一圖片而無實際文字內容的郵件是典型的垃圾郵件模式；請在圖片旁保留足夠的實際文字內容。
- **發送前先預覽。** 在郵件發送給完整清單之前，請檢查其實際渲染效果 — 包括在行動裝置上的顯示。
- **取消訂閱連結已自動處理。** Spwig 會自動在每封行銷郵件的頁尾加入一個可運作且無需登入的取消訂閱連結 — 您不需要自行添加（有關該流程的詳細說明，請參閱 [通訊偏好設定](communication-preferences)）。

請勿移除或隱藏該連結；無論您的其他指標如何，缺失或損壞的取消訂閱連結本身即違反 Gmail 和 Yahoo 的批量發送者規則。

## 「我的郵件被歸類為垃圾郵件」— 故障排除清單

請依序執行以下步驟：

1. **重新檢查您的 DNS 記錄。** 開啟帳戶設定精靈的 DNS 步驟（或內建 SMTP 帳戶管理頁面上的 DKIM 面板），並確認 SPF、DKIM 和 DMARC 均顯示為通過。

網域續約、DNS 供應商遷移，或對您的區域檔案進行的無關變更，都可能悄悄導致其中一項設定失效。
2. **檢查活動報告中的退信和投訴數量** 針對受影響的發送批次 — 請參閱 [活動報告](campaign-reports)。


任一指標的飆升都指向清單品質或內容問題，而非驗證問題。
3. **檢查抑制清單**（[清單衛生](list-hygiene)）是否有突然的激增——如果您的清單中有大量部分在一段時間內持續失敗，對剩餘部分的送達率也會下降。
4. **確認您的寄件人地址位於已驗證的網域上**，而不是免費供應商地址，或與 SPF/DKIM/DMARC 設定不符的網域。
5. **向您控制的 Gmail 和 Yahoo/Outlook 地址發送測試郵件**，並檢查其實際落入的資料夾，而不僅僅是它是否已到達。
6. **如果您最近大幅更改了發送量或受眾，** 請將其視為新的暖機過程——降低發送量並更緩慢地增加。
7. **如果以上所有檢查均無問題且問題仍然存在，** 這可能是供應商特定的節流，而非您的設定故障——一旦根本原因（通常是投訴或退信）得到解決，這可能需要一些時間才能自行恢復。

## 提示

- 在修復其他任何問題之前，先修復 DNS 驗證——如果 SPF/DKIM/DMARC 未通過，其他所有送達率因素（內容、清單衛生、暖機）的重要性都較低。
- 將設定嚮導的 DNS 驗證視為即時檢查，而非一次性操作——每次遷移 DNS 供應商或通過不同的註冊商續期網域時，請重新執行。
- 一個會開啟和點擊的乾淨清單，永遠會優於一個不會這樣做的大清單——抵制導入舊的、未驗證清單的衝動，「以防萬一」。
- 關注您的數字相對於您過去發送記錄的表現，而不是通用的行業基準——您自己的歷史記錄是真實問題最可靠的信號。
- 如果您使用的是 Spwig 託管方案，託管郵件閘道的 DKIM 簽名和聲譽管理已為您處理——您剩餘的責任是清單品質和內容，而不是 DNS。
