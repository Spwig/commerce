---
title: ターゲット層
---

「セグメント」とは、キャンペーン、ジャーニー、またはA/Bテストに設定できる保存済みのターゲット層です。キャンペーンスタジオの独自のセグメント一覧では「ターゲット層」と呼ばれており、このガイドでは同じものを表すために両方の言葉を使用しています。すべてのセグメントは、Spwigが常に再評価するルールによって定義される「ダイナミック」または「スタティック」として分類されます。スタティックは、手作業で選ぶ購読者リストです。

このガイドでは、ダイナミックセグメントのルールの構築について説明します。これは、ストア独自のカスタマーバケット、ロイヤリープログラム、提携会社をターゲットにする新しいフィールドも含んでいます。また、ストアにすでに存在するデータから準備済みのセグメントのセットを構築する「Add starter audiences（スターター層の追加）」ボタンも紹介します。

## ダイナミックセグメントとスタティックセグメント

| タイプ | 動作 | 向いているもの |
|---|---|---|
| **ダイナミック（ルール）** | あなたが条件を定義します。たとえば「総支出が500ドル以上」など。Spwigはセグメントが使用されるたびに再計算し、購読者が変更になるたびにメンバーが自動的に変化します。 | 常に最新の状態にしておく必要がある継続的なターゲット層、たとえば「VIPカスタマー」や「90日間注文していない」など。 |
| **スタティック（固定リスト）** | 手作業で追加または削除する購読者リストです。メンバーは変更されません。 | 1回限りのリスト、たとえば特定のイベントの参加者全員、または1回限りの送信用に手で選んだグループなど。 |

セグメントを作成する際には、**種類**フィールドでどちらの種類を選ぶかを指定してください。このガイドの残りの部分ではダイナミックセグメントについて説明します。スタティックセグメントはルールがなく、単なるメンバー一覧です。

## ダイナミックセグメントの構築

**キャンペーンスタジオ > セグメント** を開き、**+ 新しいセグメント** をクリックしてください（または既存のダイナミックセグメントを開きます）。**ターゲットルール**ビルダーにアクセスします。**+ 条件を追加** をクリックしてルールを追加し、チェックする内容とその方法を選択し、購読者が**すべて**または**いずれか**の条件を満たす必要があるかを設定します。変更するたびに上部右隅のリアルタイムカウント（例: 「8人の該当する購読者」）が更新されるため、保存する前に誰が該当するかを正確に確認できます。

![The Audience rules builder with Customer segment, Loyalty tier, Lifetime value, and Affiliate conditions set, and a live matching-subscriber count](/static/core/admin/img/help/audiences/rule-builder-new-fields.webp)

**固定された** ``is true`` スタイルのチェックを持つ条件 - ``Has ordered``、``Opted into marketing``、``Loyalty member``、``Affiliate`` - は、フィールドそのものを選ぶだけでよく、オペレーターや値を設定する必要はありません。

## あなたがターゲットにできるもの

| フィールド | チェックする内容 |
|---|---|
| **Total spent** | ライフタイムの注文合計。 |
| **Number of orders** | 完了した注文数。 |
| **Lifetime value** | カスタマーの計算されたライフタイムバリュー。 |
| **Average order value** | 完了した注文あたりの平均金額。 |
| **Days since last order** | カスタマーの最新の注文からどれだけの時間が経ったか - リテンション向けに90日以上をターゲットに。 |
| **Has ordered** | カスタマーが少なくとも1件の完了した注文を持っているかどうか。 |
| **Opted into marketing** | トランスアクションメールへの同意をしているかどうか。 |
| **Language** | トランスアクションの保存された言語。 |
| **Source** | トランスアクションが登録された方法 - Storefront signup、Import、Order、手動で追加、またはAPI。 |
| **Joined after** | 選択した日付以降に登録したトランスアクション。 |
| **Has tag** | 作成した[タグ](/help/subscriber-tags)を持っているかどうか。 |
| **Customer segment** | お店の名前がつけられた[カスタマーセグメント](/help/customer-segments)のいずれかに該当するかどうか - ゲストカスタマー、新規カスタマー、レギュラーカスタマー、頻繁な購入者、高価値、VIPカスタマー、安物狙い、リスクあり、または非アクティブ。 |
| **Loyalty member** | お店のロイヤルティプログラムのアクティブな会員かどうか。 |
| **Loyalty points** | 会員の現在の利用可能ポイント残高。 |
| **Loyalty tier** | 会員が現在保持しているロイヤルティティア。 |
| **Affiliate** | お店のアクティブなアフィリエイトパートナーかどうか。 |

**カスタマーセグメント**, 2つの **ロイヤルティ**の値フィールド, **ロイヤルティティア**, **アフィリエイト**は新しい追加であり、それぞれの条件ピッカーに表示されるのは、店舗にその種のデータが実際に存在する場合のみです。ロイヤルティフィールドはロイヤルティプログラムにメンバーがいて、少なくとも1つのアクティブなティアがある場合に表示され、**アフィリエイト**は少なくとも1つのアフィリエイトが存在する場合に表示され、**カスタマーセグメント**は少なくとも1つのアクティブなカスタマーセグメントが構成されている場合に表示されます。

新しい店舗では誰にも該当しないオプションは表示されません。

知っておくべき現在の制限点: 任意の条件で選択肢のドロップダウンがある場合 - **言語**, **ソース**, **タグあり**, **カスタマーセグメント**, **ロイヤルティティア** - には、**どれか**オペレータがまだ1回に1つの値しか選べません。いくつかの値をマッチさせたい場合は（例: VIPまたはハイボリュームセグメントに所属するカスタマー）、1つの値につき1つの条件を追加し、**マッチ**を**任意**に設定してください。

## スターターのオーディエンスを追加

Spwigがすでに誰が該当するかを把握しているため、明らかにオーディエンスを作成するには面倒な作業になります。セグメント一覧で、**スターターのオーディエンスを追加**をクリックすると、Spwigが既存のカスタマー、ロイヤルティ、アフィリエイトデータから、準備ができている編集可能なダイナミックセグメントを生成します。

![セグメント一覧に表示される[新しいセグメント]ボタンと[スターターのオーディエンスを追加]ボタン](/static/core/admin/img/help/audiences/segments-changelist.webp)

| スターター | ターゲット | 必要条件 |
|---|---|---|
| **VIPカスタマー** | あなたのVIPカスタマー層 | 有効なVIPカスタマー層 |
| **ハイボリュームカスタマー** | あなたのVIPおよびハイボリュームカスタマー層 | 有効なVIPまたはハイボリュームカスタマー層 |
| **繰り返し購入者** | あなたの頻繁な購入者および定期的なカスタマー層 | 有効な頻繁な購入者または定期的なカスタマー層 |
| **新規カスタマー** | あなたの新規カスタマー層 | 有効な新規カスタマー層 |
| **離脱したカスタマー** | 以前に注文をしたが、最後の90日以内に注文していないカスタマー | 任意のカスタマー注文履歴 |
| **ロイヤルティ会員** | あなたのロイヤルティプログラムに参加しているすべての人 | 会員を持つ有効なロイヤルティプログラム |
| **トップロイヤルティティア** | あなたの最高ランクのロイヤルティティアに所属する会員 | 有効なロイヤルティティアが1つ以上ある |
| **アフィリエイト** | あなたのアクティブなアフィリエイトパートナー | アフィリエイトが1つ以上ある |

Spwigは実際にデータを持っているスターターのみを作成します。まだロイヤルティプログラムを持っていない場合、**ロイヤルティ会員**のスターターは作成されず、誰にも一致しない空のスターターになるわけではありません。Spwigは追加したものを正確に確認し、例えば次のように表示します: "7つのスターターのオーディエンスを追加しました: ハイボリュームカスタマー、繰り返し購入者、新規カスタマー、離脱したカスタマー、ロイヤルティ会員、トップロイヤルティティア、アフィリエイト。"

![スターターのオーディエンスが正常に追加されたことを確認するメッセージ](/static/core/admin/img/help/audiences/starter-audiences-added.webp)

[スターターのオーディエンスを追加]ボタンを複数回クリックしても問題ありません。Spwigはすでに存在するスターターを重複して作成することはないので、たとえば最初にロイヤルティプログラムを設定した後でボタンをもう一度クリックしても、すでに設定されているものは追加されず、新たに利用可能なものが追加されます。すべての設定が完了している場合は、その旨が表示されます。

![すべてのスターターのオーディエンスがすでに存在していることを示す情報メッセージ](/static/core/admin/img/help/audiences/starter-audiences-already-set-up.webp)

不要なスターターを削除した場合、**スターターオーディエンスの追加**をもう一度クリックしても復元されません。Spwig は、意図的に削除されたセグメントとして扱い、再作成する対象とはみなしません。

シードされた後、スターターは通常の動的セグメントとなります。リストから開いてルールを確認または調整し、名前を変更したり、削除したりできます。自分で作成したセグメントと同様に扱えます。

## これらのオーディエンスが実際に到達する対象

上記の顧客、ロイヤルティ、アフィリエイトの条件は、顧客アカウントに紐付けられたメールアドレスを持つサブスクライバーのみが一致します。匿名のニュースレター登録者は、**ロイヤルティメンバー**や**VIP**の条件に一致しません。これは正しい動作であり、Spwig にはそれらを照合するための注文履歴やロイヤルティ履歴がないためです。多くの顧客がアカウントを持っているがまだ登録していない場合は、Spwig インストールを管理している担当者にサブスクライバー同期の実行を依頼してください。これにより、既存のすべての顧客アカウントに対して 1 ステップで Subscriber レコードが作成され、これらのオーディエンスが一致する実際の対象者が存在するようになります。

セグメントが何人のサブスクライバーをカウントしているかに関わらず、その数値はキャンペーンを*受け取れる*対象者を示すものであり、実際に受け取る対象者を示すものではありません。すべての送信では、まず各サブスクライバー自身のマーケティング同意を確認するため、セグメントはそれを回避する手段にはなりません。

## ヒント

- 同じルールを手動で構築するのではなく、スターターオーディエンスから開始して調整してください。作成された後、スターターは自分で構築したセグメントと変わりありません。
- **ロイヤルティメンバー**、**アフィリエイト**、**注文あり**などのブール条件は、演算子や値を必要としません。条件を追加するだけで完了です。
- より精密なターゲティングのために、新しいフィールドと元のフィールドを組み合わせます。例えば、**ロイヤルティメンバー**に**マーケティングへのオプトイン**を追加する、といった具合です。単一の条件だけに頼るのではなく、組み合わせを検討してください。
- セグメントのルールが、その後削除されたものを参照している場合（削除された顧客セグメント、空になったタグなど）、Spwig は誰も一致しないとして扱い、サブスクライバー全体のリストにフォールバックすることはありません。

誤ったターゲティングによる送信は避け、誰かを間違って全員に送信することはありません。
- もしセグメントのメンバー数が古くなっているように感じたら、再度開いて保存するか、セグメント一覧から**メンバー数の再構築**の一括操作を使用して、すぐに再計算してください。
- ルールを作成中に「一致する購読者数」のリアルタイムカウントを確認してください。これは、保存する前に意図した範囲よりも狭い（または広い）条件に気付くための最も速い方法です。
