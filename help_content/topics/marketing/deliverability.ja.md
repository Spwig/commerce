メールを*送信*することは簡単です。しかし、スパムフォルダではなく受信トレイに届けることが本当の課題であり、Gmail や Yahoo などのメールボックスプロバイダーは、メールを検討する前に厳格な技術要件を課しています。このランブックでは、注文確認メールやキャンペーンメールが顧客に見える場所に届くよう、何をどの順序で設定すべきかを説明します。

ここにある内容は、一度きりのタスクではありません。配信率は時間をかけて構築する継続的な取り組みであり、すぐに失う可能性があります。何か異変を感じたときは、末尾のチェックリストを再確認する価値があります。

## 重要性

すべての主要な受信トレイプロバイダーは、メールを配信するか、スパムフォルダに移動するか、それとも完全に拒否するかを決定する前に、送信者の評判に基づいて受信メールを評価します。2024年以降、Gmail と Yahoo は、一定の量を送信するすべての人に対して、明示的な**大量送信者要件**を正式に定めています：

- **ドメインの認証を行う** — 有効な SPF、DKIM、DMARC レコード。
- **解除を簡単にする** — すべてのマーケティングメールに、機能しており手間のかからないオプトアウト手段を提供する。
- **スパム苦情を低く抑える** — 約 0.3% を超える苦情率の大量送信者は、メールが拒否されたり、一括でスパムフォルダに振り分けられたりするリスクがあります。最も安全な目標は 0.1% を大きく下回ることです。

これらを満たさない場合、影響を受けるのはマーケティングキャンペーンだけではありません。Gmail や Yahoo は、メッセージの種類ごとにではなく、送信ドメインレベルで評判を判断する傾向が強まっているため、損傷したドメインの評判は、取引メール（注文確認、パスワードリセット）もスパムに巻き込む可能性があります。以下の手順は、これら 3 つの要件をすべて満たす方法です。

## ステップ 1: 送信ドメインの認証

SPF、DKIM、DMARC は、受信メールサーバーに対して、あなたのドメインからのメールであると主張しているメールが、実際にあなたによって送信されたものであることを証明する DNS TXT レコードです。設定方法は、ストアが使用する送信モードによって異なります。これら 3 つはすべて、管理サイドバーの **Email Configuration** 下で設定されます（これにより Email Accounts リストが開かれます。アカウント設定の詳細については [Email Configuration](email-configuration) を参照してください）。

| 送信モード | 認証の仕組み |
|---|---|
| **組み込み SMTP**（Spwig 独自のメールサーバー） | Spwig はドメイン用に DKIM キーペアを自動的に生成します。メールアカウントを追加すると、セットアップウィザードの **ステップ 4** に SPF、DKIM、DMARC のステータスと、追加すべき正確なレコードが表示されます。コピー機能と、Cloudflare、GoDaddy、Namecheap、AWS Route 53 向けのプロバイダー固有の手順も含まれています。必要に応じて再度確認する場合、アカウントの管理ページ内、**設定済みの DKIM キー** セクションにも同じ DKIM DNS レコードが表示されます。 |
| **汎用 SMTP**（SendGrid、Mailgun、Amazon SES、Google Workspace などの BYO プロバイダーを SMTP 認証情報で接続） | 認証の一部は、そのプロバイダー独自のダッシュボードで行われます。セットアップウィザードの DNS ステップには、Gmail、Outlook、SendGrid、Mailgun、Amazon SES 向けのタブ付き手順が含まれており、それぞれプロバイダーのコンソールで何を設定するか（例：SendGrid での送信ドメインの検証）と、DNS ホストに追加すべき結果として得られる DNS レコードを説明しています。 |
| **Spwig 提供のメールゲートウェイ** | Spwig 提供プランでは、管理された送信オプションとして利用可能です。送信メールに DKIM を自動的に署名し、デフォルトでは Spwig 自身の検証済みドメイン上のアドレスから送信するため、セットアップなしで動作します。ゲートウェイ経由で独自のドメインから送信したい場合は、ホスティングプロバイダーに検証について相談してください。これはセルフサービス型の DNS フローではなく、管理サービスです。 |

使用するモードに関わらず、**DNS レコードの追加自体は常に外部の手順です** — ドメインレジストラまたは DNS ホスト（Cloudflare、GoDaddy、Namecheap、Route 53、またはドメインのネームサーバーが指す場所）で行い、Spwig 内では行いません。Spwig は追加すべき内容を正確に伝え、それが有効であることを検証できますが、レジストラにアクセスして代わりに追加することはできません。

開始前に知っておくべきいくつかのポイント：

- **DNS の変更は即座には反映されません。** 伝播には数分から 48 時間かかる場合があります。

ウィザードの検証ステップでは、実際に伝播するまでレコードが失敗または不足しているように表示されます。これは不具合を示すものではなく、あらかじめ予期されたものです。
- **ドメイン1つにつき1つのSPFレコードのみが許可されています。** すでに1つ保有している場合（Google Workspaceや他のメール配信サービスなど）、新しい送信者を既存のレコードに`include:`で追加するか、2番目のSPF TXTレコードを作成しないでください。2つのSPFレコードがあると、すべての認証が破綻します。
- **DMARCはSPFまたはDKIMがすでに成功している必要があります。** 両方のSPFとDKIMが検証された後で、最後に設定してください。

## ステップ2: 実際の送信元の識別を使用する

ドメインが認証されたら、受信者が実際に表示するものが裏付けになっているか確認してください。
- **送信元アドレス** — 自分の認証ドメイン上のアドレス（`orders@yourstore.com`）を使用してください。無料のプロバイダーのアドレス（`yourstore@gmail.com`）は使用しないでください。無料プロバイダーの送信元アドレスは、SPF/DKIM/DMARCレコードによって一切認証されず、受信ボックスのプロバイダーはそのアドレスをストアからの強いスパムシグナルとして扱います。
- **送信元名** — 一般的なラベル（「通知」や「無視」など）ではなく、店舗の認識できる名前を使用してください。
- **返信先** — 監視されたアドレスを設定してください。監視されていない`noreply@`アドレスは、届かないまたは無視される返信をブロックするため、自身でやや低い評判シグナルとなり、顧客が何か問題があったことを伝えるためのチャネルをブロックします。

3つの設定を**メール設定 > (あなたのアカウント) > 送信者設定**で行い、[メール設定](email-configuration)で全フィールドの説明を参照してください。

## ステップ3: スケールする前にウォームアップする

送信履歴のないドメインやIPアドレスにはまだ評判がありません。つまり、良いものでも悪いものでもなく、受信ボックスのプロバイダーは未知のものに対して慎重になります。ブランド新しいドメインから大量のメールを送信すると、スパム業者が新しいキャンペーンを開始するのと統計的に同じように見え、すべての技術的なチェックが完了しても一括フォルダーに振り分けられることがあります。
- 小さな段階から始めましょう。

最初のキャンペーンのいくつかを、メールを開封する可能性が最も高いオーディエンスに送信し、一度に全体のリスト全体に送信しないでください。ターゲットを絞ったセグメントの構築については[Audiences](audiences)を参照してください。
- 1〜2週間の間に段階的に送信量を増し、いきなりフルリストの送信に移さないでください。
- 他のプラットフォームからリストを移行している場合、信頼性の観点から見ても、ドメインとともに送信履歴が移行しない点に注意してください。

## ステップ4: リストを整える

クレームやバウンスはすべて、リストに誰が含まれているか、そしてそれがどのようにリストに追加されたかに大きく影響されます:

- **承諾した人だけにメールを送ります。** イmポートされた連絡先、購入したリスト、スクリーニングされたアドレスは、スパムクレームやハードバウンスを急激に増やす最も速い方法です。
- **ダブルオプトインを使用してください。** Spwigのマーケティング同意フローは、マーケティングメールを送る前に購読者の電子メールアドレスを検証します。これの設定方法については[Communication Preferences](communication-preferences)を参照してください。
- **Spwigの自動サプレッションがその役割を果たすようにしてください。** Spwigは、ハードバウンス、スパムクレーム、繰り返しソフトバウンスするアドレスを監視し、設定をすることなく自動的にメールを送信を停止します。これはどのように動作するのか、そして（稀に）オーバーライドするタイミングについて詳しくは[List Hygiene and Suppressions](list-hygiene)を参照してください。
- **定期的に非アクティブな購読者を削除してください。** ずっと同じ非エンゲージメントのあるアドレスにメールを送り続けるのではなく、開封やクリックが行われるリストのサイズが小さくなる方が、開封やクリックが行われない大きなリストよりも信頼性にとって価値があります。

## ステップ5: モニタリングする

配信問題は、顧客がメールが届かないことを伝えてくれるよりも前に数値で現れます。

送信後にキャンペーンの[Report](campaign-reports)を開き、次のように確認してください:

| 指標 | 注目すべき点 |
|---|---|
| **バウンス率** | 主にソフトバウンスであることは正常です。**ハードバウンス**の割合が増加している場合、リストに無効または古いアドレスが蓄積していることを示しています。 |
| **スパム苦情** | 送信のたびにほぼゼロであるべきです。Gmail や Yahoo で大量送信者への強制措置がトリガーされる約 0.3% の閾値を大きく下回すよう維持してください。わずかな増加であっても、直ちに調査する価値があります。 |
| **開封率 / クリック率（開封ベース）** | 同一リストへの送信全体で（単一のキャンペーンだけでなく）突然かつ説明のつかない低下が見られる場合、バウンスや苦情の数値が変動する前に、メールが受信トレイではなくスパムフォルダに届いている初期の兆候である可能性があります。 |

また、キャンペーンスタジオのダッシュボードにある **抑制されたアドレス** カードを定期的に確認してください。緩やかな増加はリストの自然な劣化として正常ですが、突然の急増は次の送信前に調査する価値があります（[リストの衛生管理](list-hygiene) を参照）。

何か急増した場合：まず DNS レコードがまだ有効であるかどうかを停止して確認してください（ドメインの更新期限切れや意図しない DNS 変更により、SPF/DKIM がサイレントに壊れる可能性があります）。その後、トリガーとなった送信の内容や対象オーディエンスについて何が変わったかを調べます。

## ステップ 6: コンテンツの衛生管理

認証とリストの品質は入場券ですが、コンテンツはそこに到達した後の扱いに影響を与え続けます。

- **スパムトリガーとなるパターンを避ける** — 件名内の全大文字、過度な句読点（"!!!"）、および「今すぐ行動」「無料のお金」などのフレーズは、認証済みドメインからの送信であっても、スパムフィルターによって不利に扱われます。
- **画像だけのメールを送信しないこと。** 実質的なテキストが一切なく、単一の画像のみで構成されたメールは典型的なスパムパターンです。画像を添付する場合でも、十分な量の実際のテキストコンテンツを併記してください。
- **送信前にプレビューを確認する。** 全リストへの送信前に、メールが実際にどのように表示されるか（モバイル環境を含む）を確認してください。
- **解除リンクはすでに処理されています。** Spwig は、すべてのマーケティングメールのフッターに、ログイン不要で機能する解除リンクを自動的に追加します。ご自身で追加する必要はありません（そのフローの詳細については [通信設定](communication-preferences) を参照してください）。

これを削除したり非表示にしたりしないでください。Gmail や Yahoo の大量送信者ルールにおいて、解除リンクの欠落や破損は、その他の数値に関わらず、それ自体がポリシー違反となります。

## 「メールがスパムフォルダに入っている」 — トラブルシューティングチェックリスト

これらを順番に確認してください：

1. **DNSレコードを再確認する。** アカウントのセットアップウィザードのDNSステップ（または組み込みSMTPの場合、アカウントの管理ページにあるDKIMパネル）を開き、SPF、DKIM、DMARC がすべて引き続き合格状態であることを確認してください。

ドメインの更新、DNSプロバイダーの移行、またはゾーンファイルへの無関係な変更により、これらのいずれかがサイレントに壊れる可能性があります。
2. **影響を受けた送信のバウンスと苦情の数を確認する** — [キャンペーンレポート](campaign-reports) を参照してください。

いずれかの急増は、認証の問題ではなく、リストの品質やコンテンツの問題を示しています。
3. **抑制リスト**（[リストの衛生管理](list-hygiene)）を確認し、急激な増加がないかチェックしてください — リストの大部分が長期間にわたって失敗している場合、残りのリストへの配信率も低下します。
4. **From アドレスが認証済みドメイン上にあることを確認してください**。無料プロバイダーのアドレスや、SPF/DKIM/DMARC が設定されたものと一致しないドメインを使用しないでください。
5. **Gmail アドレスと、あなたが管理している Yahoo/Outlook アドレスにテストメールを送信し**、届いたかどうかだけでなく、実際にどのフォルダに格納されたかを確認してください。
6. **最近、送信量や対象オーディエンスを大きく変更した場合は**、新しいウォームアップとして扱い、送信量を下げ、より緩やかに段階的に増加させてください。
7. **上記すべてが正常であり、問題が継続する場合は**、設定の故障ではなく、プロバイダー固有のスロットリングである可能性があります — 根本原因（通常は苦情やバウンス）が修正された後、自然に解決するまで時間がかかる場合があります。

## ヒント

- 何よりも先に DNS 認証を修正してください — SPF/DKIM/DMARC がパスしていない場合、他のすべての配信率のレバー（コンテンツ、リストの衛生管理、ウォームアップ）は重要度が低くなります。
- セットアップウィザードの DNS 検証は、一度きりのチェックではなく、時点でのチェックとして扱ってください — DNS プロバイダーを移行したり、別のレジストラでドメインを更新したりするたびに、再実行してください。
- 開封やクリックがあるクリーンなリストは、それらがなくともっと大きなリストよりも常に優れたパフォーマンスを発揮します — 「念のため」という理由で、古い未検証リストをインポートする誘惑に抵抗してください。
- 一般的な業界ベンチマークではなく、ご自身の過去の送信と比較して数値を確認してください — ご自身の履歴は、実際の問題の最も信頼できるシグナルです。
- Spwig ホスティングプランをご利用の場合は、ホストされたメールゲートウェイの DKIM 署名と評判管理は代行されます — 残りの責任は DNS ではなく、リストの品質とコンテンツです。
