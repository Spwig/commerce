---
title: กลุ่มผู้ชม
---

 **Segment** คือกลุ่มผู้ชมที่คุณสามารถกำหนดให้เป็นเป้าหมายของแคมเปญ การเดินทาง หรือการทดสอบ A/B ได้ รายการ Segment ของ Studio การตลาดเรียกกลุ่มดังกล่าวว่า "กลุ่มผู้ชมที่กำหนดเป้าหมาย" และคู่มือนี้ใช้คำทั้งสองคำเพื่อหมายถึงสิ่งเดียวกัน ทุกกลุ่มสามารถเป็น **แบบไดนามิก** ซึ่งถูกกำหนดโดยกฎที่ Spwig ประเมินใหม่ทุกครั้งที่ใช้งาน หรือ **แบบสถิต** ซึ่งเป็นรายการผู้สมัครที่คุณเลือกด้วยมือ

คู่มือนี้กล่าวถึงการสร้างกฎของกลุ่มแบบไดนามิก - รวมถึงฟิลด์ใหม่ที่สามารถกำหนดเป้าหมายไปยังกลุ่มค่าลูกค้าของร้านค้าของคุณ โปรแกรมความภักดี และพันธมิตร - และปุ่ม **Add starter audiences** แบบคลิกเดียวที่สร้างกลุ่มที่กำหนดไว้ล่วงหน้าจากข้อมูลที่ร้านค้าของคุณมีอยู่แล้ว

## กลooมแบบไดนามิกกับกลุ่มแบบสถิต

| ประเภท | วิธีการทำงาน | ใช้สำหรับ | 
|---|---|---| 
| **แบบไดนามิก (กฎ)** | คุณกำหนดเงื่อนไข - เช่น "ยอดใช้จ่ายรวมอย่างน้อย 500 ดอลลาร์" Spwig คำนวณผู้ที่ตรงตามเงื่อนไขใหม่ทุกครั้งที่ใช้กลุ่ม ดังนั้นการเป็นสมาชิกจะเปลี่ยนแปลงโดยอัตโนมัติเมื่อผู้ใช้ของคุณเปลี่ยนแปลง | กลุ่มผู้ชมที่ต่อเนื่องซึ่งควรจะมีข้อมูลล่าสุดเสมอ เช่น "ลูกค้าชั้นนำ" หรือ "ยังไม่สั่งซื้อใน 90 วัน" | 
| **แบบสถิต (รายการคงที่)** | รายการผู้สมัครที่คุณเพิ่มหรือลบด้วยมือ ความเป็นสมาชิกจะไม่มีวันเปลี่ยนแปลงเว้นแต่คุณจะเปลี่ยนแปลง | รายการแบบครั้งเดียว - ทุกคนจากงานเฉพาะ หรือกลุ่มที่คัดเลือกมาเป็นพิเศษสำหรับการส่งครั้งเดียว | 

เลือกประเภทด้วย **Kind** เมื่อคุณสร้างกลุ่ม คู่มือที่เหลือนี้เกี่ยวข้องกับกลุ่มแบบไดนามิก - กลุ่มแบบสถิตคือแค่รายการสมาชิกที่ไม่มีกฎในการตั้งค่า

## การสร้างกลุ่มแบบไดนามิก

เปิด **Campaign Studio > Segments** แล้วคลิก **+ New Segment** (หรือเปิดกลุ่มแบบไดนามิกที่มีอยู่แล้ว) เพื่อเข้าถึง **Audience rules** ผู้สร้างกฎ คลิก **+ Add condition** เพื่อเพิ่มกฎ ระบุสิ่งที่ต้องตรวจสอบและวิธี และตั้งค่าว่าผู้สมัครต้องตรงตาม **ทั้งหมด** หรือ **บางอย่าง** ของเงื่อนไขของคุณ จำนวนผู้ใช้ที่ตรงตามเงื่อนไขในมุมบนขวา - เช่น "มีผู้ใช้ 8 คนที่ตรง" - จะอัปเดตทันทีหลังจากแต่ละการเปลี่ยนแปลง ดังนั้นคุณจึงสามารถดูได้ว่าใครตรงตามเงื่อนไขก่อนที่จะบันทึก

[The Audience rules builder with Customer segment, Loyalty tier, Lifetime value, and Affiliate conditions set, and a live matching-subscriber count](/static/core/admin/img/help/audiences/rule-builder-new-fields.webp)

Condition ที่มีการตรวจสอบแบบ **is true** — **Has ordered**, **Opted into marketing**, **Loyalty member**, **Affiliate** — ไม่จำเป็นต้องตั้งค่าตัวแปรหรือค่าใดๆ เพียงแค่เลือกฟิลด์ที่ต้องการเท่านั้น

## สิ่งที่คุณสามารถกำหนดเป้าหมายได้

| Field | What it checks |
|---|---|
| **Total spent** | จำนวนเงินทั้งหมดที่ใช้ซื้อสินค้าในช่วงเวลาทั้งหมด |
| **Number of orders** | จำนวนคำสั่งซื้อที่สำเร็จแล้ว |
| **Lifetime value** | ค่าคุณค่าตลอดอายุของลูกค้า |
| **Average order value** | จำนวนเงินเฉลี่ยต่อคำสั่งซื้อที่สำเร็จ |
| **Days since last order** | จำนวนวันนับตั้งแต่ลูกค้าสั่งซื้อครั้งลAST — กำหนดเป้าหมาย 90 วันขึ้นไปสำหรับการกลับมาใช้งานซ้ำ |
| **Has ordered** | ว่าลูกค้ามีคำสั่งซื้อสำเร็จอย่างน้อยหนึ่งครั้งหรือไม่ |
| **Opted into marketing** | ว่าผู้สมัครรับข้อมูลมีการยินยอมรับข้อมูลการตลาดหรือไม่ |
| **Language** | ภาษาที่ลูกค้าบันทึกไว้ |
| **Source** | วิธีที่ลูกค้าสมัคร — การลงทะเบียนผ่านร้านค้า, การนำเข้า, การสั่งซื้อ, การเพิ่มโดยตรง, หรือ API |
| **Joined after** | ลูกค้าที่สมัครในวันที่กำหนดหรือหลังจากวันที่กำหนด |
| **Has tag** | ว่าลูกค้ามี [แท็ก](/help/subscriber-tags) ที่คุณสร้างขึ้นแล้ว |
| **Customer segment** | ว่าลูกค้าอยู่ใน [กลุ่มลูกค้า](/help/customer-segments) ที่คุณกำหนดไว้หรือไม่ — ลูกค้าทั่วไป, ลูกค้าใหม่, ลูกค้าประจำ, ลูกค้าที่ซื้อบ่อย, ลูกค้าที่มีมูลค่าสูง, ลูกค้า VIP, ลูกค้าที่ชอบส่วนลด, ลูกค้าที่มีความเสี่ยง, หรือลูกค้าที่ไม่ได้ใช้งาน |
| **Loyalty member** | ว่าลูกค้าเป็นสมาชิกโปรแกรมความภักดีของคุณหรือไม่ |
| **Loyalty points** | จำนวนคะแนนที่ลูกค้าสะสมได้ |
| **Loyalty tier** | ระดับความภักดีที่ลูกค้าอยู่ในปัจจุบัน |
| **Affiliate** | ว่าลูกค้าเป็นพันธมิตรที่มีอยู่หรือไม่ |


**Customer segment**, ค่า **Loyalty** ทั้งสองค่า, **Loyalty tier**, และ **Affiliate** เป็นการเพิ่มเติมที่ใหม่กว่า และแต่ละอันจะปรากฏในตัวเลือกเงื่อนไขเพียงเมื่อร้านค้าของคุณมีข้อมูลประเภทนั้นจริง ๆ: ค่า Loyalty จะปรากฏเมื่อโปรแกรมความภักดีของคุณมีสมาชิกและมีระดับที่ใช้งานอย่างน้อยหนึ่งระดับ, **Affiliate** จะปรากฏเมื่อคุณมี Affiliate อย่างน้อยหนึ่งคน, และ **Customer segment** จะปรากฏเมื่อคุณมีการตั้งค่า Customer segment ที่ใช้งานอย่างน้อยหนึ่งตัว

คุณจะไม่พบตัวเลือกในร้านค้าที่เพิ่งเริ่มต้นขึ้นซึ่งไม่มีทางเลือกที่จะตรงกับใครเลย

ข้อจำกัดปัจจุบันที่ควรทราบ: สำหรับเงื่อนไขใด ๆ ที่มีตัวเลือกใน Dropdown — **Language**, **Source**, **Has tag**, **Customer segment**, **Loyalty tier** — ตัวดำเนินการ **is any of** ยังคงอนุญาตให้เลือกค่าเดียวได้เพียงค่าเดียวเท่านั้น หากคุณต้องการให้ตรงกับหลายค่า (เช่น ลูกค้าในระดับ VIP หรือระดับมูลค่าสูง) ให้เพิ่มเงื่อนไขแต่ละค่าและตั้ง **Match** เป็น **any**

## เพิ่ม Audience เริ่มต้น

การสร้างกฎจากศูนย์สำหรับแต่ละกลุ่มลูกค้าที่ชัดเจน — ลูกค้า VIP ของคุณ, สมาชิกโปรแกรมความภักดี, ทุกคนที่เงียบลง — เป็นเรื่องที่น่าเบื่อเมื่อ Spwig สามารถมองเห็นได้ว่าใครมีคุณสมบัติ บนรายการ Segments ให้คลิก **Add starter audiences** และ Spwig จะสร้าง Segments แบบไดนามิกที่พร้อมใช้งานจากข้อมูลลูกค้า โปรแกรมความภักดี และ Affiliate ที่ร้านค้าของคุณมีอยู่แล้ว

![รายการ Segments พร้อมปุ่ม New Segment และ Add starter audiences](/static/core/admin/img/help/audiences/segments-changelist.webp)

| Starter | Targets | Needs |
|---|---|---|
| **VIP customers** | กลุ่มลูกค้า VIP ของคุณ | กลุ่มลูกค้า VIP ที่ใช้งานอยู่ |
| **High-value customers** | กลุ่มลูกค้า VIP และ High Value ของคุณ | กลุ่มลูกค้า VIP หรือ High Value ที่ใช้งานอยู่ |
| **Repeat buyers** | กลุ่มลูกค้า Frequent Buyer และ Regular ของคุณ | กลุ่มลูกค้า Frequent Buyer หรือ Regular ที่ใช้งานอยู่ |
| **New customers** | กลุ่มลูกค้าใหม่ของคุณ | กลุ่มลูกค้าใหม่ที่ใช้งานอยู่ |
| **Lapsing customers** | ลูกค้าที่เคยสั่งซื้อแต่ไม่ได้สั่งในช่วง 90 วันที่ผ่านมา | ประวัติการสั่งซื้อของลูกค้าใดๆ ก็ตาม |
| **Loyalty members** | ทุกคนที่ใช้งานอยู่ในโปรแกรมความภักดีของคุณ | โปรแกรมความภักดีที่มีสมาชิกใช้งานอยู่ |
| **Top loyalty tier** | สมาชิกในชั้นความภักดีสูงสุดของคุณ | ชั้นความภักดีที่ใช้งานอยู่อย่างน้อยหนึ่งชั้น |
| **Affiliates** | พันธมิตร Affiliate ที่ใช้งานอยู่ของคุณ | Affiliate อย่างน้อยหนึ่งราย |

Spwig จะสร้าง Starter เฉพาะที่มีข้อมูลจริงเท่านั้น — ร้านค้าที่ยังไม่มีโปรแกรมความภักดีจะไม่ได้รับ Starter **Loyalty members** แต่อย่างใด แทนที่จะได้รับ Starter ว่างเปล่าที่ไม่สามารถจับคู่กับใครได้เลย Spwig ยืนยันสิ่งที่เพิ่มเข้าไปอย่างชัดเจน ตัวอย่างเช่น: "Added 7 starter audience(s): High-value customers, Repeat buyers, New customers, Lapsing customers, Loyalty members, Top loyalty tier, Affiliates."

![Success message confirming which starter audiences were just added](/static/core/admin/img/help/audiences/starter-audiences-added.webp)

คุณสามารถคลิก **Add starter audiences** ได้มากกว่าหนึ่งครั้งอย่างปลอดภัย Spwig จะไม่สร้าง Starter ซ้ำซ้อนกับที่มีอยู่แล้ว ดังนั้นการคลิกอีกครั้งหลังจากตั้งค่า (เช่น) โปรแกรมความภักดีเป็นครั้งแรก จะเพิ่มเฉพาะสิ่งที่พร้อมใช้งานใหม่เท่านั้น — หากทุกอย่างตั้งค่าเรียบร้อยแล้ว ระบบจะแจ้งให้ทราบ

![Info message shown when every starter audience already exists](/static/core/admin/img/help/audiences/starter-audiences-already-set-up.webp)

หากคุณลบส่วนเริ่มต้นที่คุณไม่ต้องการ แล้วคลิก **Add starter audiences** อีกครั้ง จะไม่สามารถนำกลับมาได้ — Spwig คิดว่าคุณตั้งใจลบส่วนนั้น ไม่ใช่การลบโดยบังเอิญ จึงไม่จำเป็นต้องสร้างขึ้นซ้ำ

เมื่อส่วนเริ่มต้นถูกสร้างขึ้นแล้ว จะกลายเป็นส่วนที่มีการปรับแต่งแบบไดนามิกทั่วไป: คุณสามารถเปิดส่วนนั้นจากรายการเพื่อตรวจสอบหรือปรับกฎ ตั้งชื่อใหม่ หรือลบมัน ได้เช่นเดียวกับส่วนที่คุณสร้างขึ้นเอง

## ผู้คนที่ส่วนนี้สามารถเข้าถึงได้จริงๆ

เงื่อนไขเกี่ยวกับลูกค้า ความภักดี และพันธมิตรข้างต้นจะตรงกับผู้สมัครที่อีเมลของพวกเขาเชื่อมโยงกับบัญชีลูกค้าเท่านั้น — การสมัครรับข่าวสารแบบไม่ระบุตัวตนจะไม่ตรงกับเงื่อนไข **สมาชิกความภักดี** หรือ **VIP** แม้ว่าจะถูกต้องก็ตาม เนื่องจาก Spwig ไม่มีประวัติการสั่งซื้อหรือประวัติความภักดีในการตรวจสอบ ถ้าลูกค้าจำนวนมากของคุณมีบัญชี แต่ยังไม่ได้สมัครรับข่าวสาร ให้ผู้ที่จัดการการติดตั้ง Spwig ของคุณดำเนินการซิงค์ผู้สมัครรับข่าวสาร — ซึ่งจะสร้างบันทึกผู้สมัครรับข่าวสารให้กับบัญชีลูกค้าทุกคนในครั้งเดียว ทำให้ส่วนนี้มีคนจริงๆ ที่จะเปรียบเทียบได้

ไม่ว่าจำนวนผู้สมัครรับข่าวสารในส่วนนั้นจะมีมากน้อยเพียงใด จำนวนนั้นก็แสดงถึงผู้ที่ *อาจ* ได้รับการส่งข่าวสาร ไม่ใช่ผู้ที่จะได้รับ ทุกครั้งที่ส่งข่าวสาร ระบบจะตรวจสอบสิทธิ์ในการรับข่าวสารของผู้สมัครแต่ละคนก่อนเสมอ ดังนั้น ส่วนนั้นจึงไม่ใช่ทางเลือกในการหลีกเลี่ยงข้อกำหนดนี้

## เคล็ดลับ

- เริ่มจากส่วนเริ่มต้นและปรับเปลี่ยนแทนที่จะสร้างกฎเดียวกันด้วยมือ — เมื่อสร้างแล้ว ส่วนเริ่มต้นก็ไม่ต่างจากส่วนที่คุณสร้างขึ้นเอง
- เงื่อนไขแบบบูลีนเช่น **สมาชิกความภักดี**, **พันธมิตร**, และ **มีการสั่งซื้อ** ไม่จำเป็นต้องมีตัวดำเนินการหรือค่า — เพียงแค่เพิ่มเงื่อนไขและเสร็จสิ้น
- ใช้ฟิลด์ใหม่ๆ ร่วมกับฟิลด์เดิมเพื่อการกำหนดเป้าหมายที่แม่นยำยิ่งขึ้น เช่น **สมาชิกความภักดี** บวกกับ **มีการสมัครรับข่าวสารทางการตลาด** แทนที่จะพึ่งพิงเงื่อนไขเดียว
- หากกฎของส่วนนั้นมีการอ้างอิงสิ่งที่ถูกลบไปแล้ว — เช่น ส่วนลูกค้าที่ถูกลบ หรือแท็กที่ถูกลบออก ฯลฯ — Spwig จะคิดว่าไม่มีใครตรงกับสิ่งนั้น แทนที่จะย้อนกลับไปใช้รายชื่อผู้สมัครทั้งหมด

การส่งข้อมูลที่ไม่ถูกต้อง; ไม่มีการส่งข้อมูลไปยังทุกคนโดยบังเอิญ
- หากจำนวนสมาชิกของเซ็กเมนต์ดูเก่า ให้เปิดเซ็กเมนต์นั้นและบันทึกใหม่ หรือใช้ **การปรับปรุงจำนวนสมาชิก** การกระทำแบบหลายรายการจากรายการเซ็กเมนต์ เพื่อคำนวณใหม่ทันที
- ดูจำนวนผู้สมัครที่ตรงกับเงื่อนไขแบบเรียลไทม์ขณะที่คุณสร้างกฎ มันคือวิธีที่รวดเร็วที่สุดในการตรวจสอบว่าเงื่อนไขที่คุณตั้งใจไว้นั้นกว้าง (หรือแคบ) เกินไปหรือไม่ ก่อนที่จะบันทึก
