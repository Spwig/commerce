**Journey Builder** 是一個視覺化、可拖曳的畫布，讓您可以設計 [Journey](/help/triggered-journeys) 的實際運作方式——包括發送哪些電子郵件、之間的等待時間，以及不同的訂閱者是否應遵循不同的路徑。您無需填寫表單，而是將流程構建為流程圖：在畫布上連接的方塊，您可以重新排列、分支並一覽無遺地預覽。

## 開啟建構器

每個 Journey 都有自己獨立的建構器畫布。您可以透過兩種方式進入：

- 建立新的 Journey——在設定頁面填寫其 **Name**、**Trigger** 和受眾，然後點擊 **Save**——即可直接進入建構器，立即開始設計。
- 開啟現有 Journey 的設定頁面，並點擊頂部的 **Design journey**。

建構器是一個全螢幕工作區，包含三個區域：左側的步驟類型 **palette**、中間的 **canvas**，以及選取項目時出現的右側 **step settings** 面板。

![顯示歡迎系列及 Yes/No 分支的 Journey Builder 畫布](/static/core/admin/img/help/journey-builder/journey-builder-canvas.webp)

在畫布頂部，標頭會重複顯示 Journey 的 **Trigger** 和 **audience**（若未設定區段，則顯示為「All subscribers」），讓您在離開建構器前始終清楚知道設計對象。

使用 **Back** 按鈕返回旅程的設定頁面。

## 步驟類型

從左側面板拖曳一個步驟到畫布上，或點擊面板項目以自動放置。共有四種步驟類型可用：

| 步驟 | 功能說明 |
|------|--------------|
| **Send email** | 向訂閱者發送其中一個行銷活動。 |
| **Wait** | 在繼續之前暫停設定的小時數或天數。 |
| **Branch** | 根據訂閱者是否屬於您選擇的區段，將路徑分為兩支——**Yes** 或 **No**。 |
| **Exit** | 結束該訂閱者的旅程。 |

每個旅程都以單一的 **Entry** 步驟開始，該步驟在您首次開啟編輯器時自動建立。它顯示旅程的觸發條件且無法刪除——它只是訂閱者進入流程的起點。

## 連接步驟

每個步驟都有小型圓形 **port**：頂部一個（輸入）和底部一個或多個（輸出）。要連接兩個步驟，請從一個步驟的底部 port 拖曳到另一個步驟的頂部 port——會出現一條曲線將它們連接起來。

**Branch** 步驟有兩個輸出 port 而非一個：綠色的 **Yes** 和紅色的 **No**。將它們各自連接到該路徑應前往的位置——它們可以在稍後重新匯合到同一個步驟（如上述範例中，兩條路徑都回到同一個 **Exit**），或完全走向不同的方向。

若要重新排列版面，請拖曳步驟的主體以重新定位——連接線會自動跟隨。拖曳畫布背景的空閒區域以平移視圖，並使用滾輪縮放。如果您迷失了流程，請點擊工具列中的 **Fit** 以重新置中並縮放以在螢幕上顯示所有內容。

## 設定步驟

點擊任何步驟以在右側面板中開啟其設定：

| 階段 | 設定 |
|------|---------|
| **發送電子郵件** | 從你的活動清單中選擇 **要發送的電子郵件**。 |
| **等待** | 設定 **等待** — 一個數字加上 **小時** 或 **天**。 |
| **分支** | 選择 **如果訂閱者位於群組中** — 決定是與否的群組。 |
| **退出** | 沒有設定 — 它只是一個終端點。 |

![右側面板配置分支階段，畫布在背後變暗](/static/core/admin/img/help/journey-builder/journey-builder-branch-config.webp)

更改會在你選擇一個值後自動保存 — 画布上沒有單獨的 **保存** 按鈕。除了 **入口** 之外，每個階段在設定面板底部都有 **刪除階段** 按鈕。

你為 **發送電子郵件** 階段選擇的電子郵件是你在 Campaign Studio 的常規視覺化編輯器中設計的普通活動 — 主題行、內容塊，全部都包括在內。將它們保留為 **草稿**，並從這裡的下拉選單中選擇它們；旅程會為你發送它們，你不需要自己點擊 **發送**。

## 從範本開始

有時從空白畫布出發並不是必要的 — 點擊工具列中的 **範本**（或在空白畫布上點擊 **瀏覽範本**）以打開一個包含八個預先設定好的起始範本的選擇器：

| 範本 | 建立內容 |
|----------|-----------------|
| **歡迎系列** | 向新訂閱者問候、介紹品牌理念，並發送首單促銷訊息。 |
| **首單引導** | 透過溫和的引導流程，將首次購買者轉化為回頭客。 |
| **購後與評價** | 在訂單完成後表達感謝，並在商品送達後請求評價。 |
| **VIP 與一般優惠** | 訂單完成後，根據 VIP 分群發送對應的後續優惠給各群組。 |
| **棄購挽回** | 提醒遺留商品的購物者，並在一天後發送後續促銷訊息。 |
| **流失客戶挽回** | 以回歸理由重新接觸已長時間未購買的客戶。 |
| **送達後評價請求** | 在訂單標記為「已送達」數天後請求評價。 |
| **補貨通知** | 在顧客想要的商品重新上架時，立即通知等待中的購物者。 |

每個範本都已預設對應的觸發條件——例如，將 **流失客戶挽回** 套用至新旅程時，也預期該旅程的 **觸發條件** 為 **客戶流失（挽回）**。請參閱 [觸發式旅程](/help/triggered-journeys) 了解哪些事件會觸發這些觸發條件，以及以挽回為主的旅程如何運作（閒置時間窗、訪客結帳、每單一次評價請求，以及補貨旅程如何取代一般一次性通知）。

![顯示預製起始旅程的範本選擇器](/static/core/admin/img/help/journey-builder/journey-builder-templates.webp)

套用範本會 **取代畫布上的目前流程**，因此請在設計旅程的初期使用，而非中途使用。Spwig 會將每個步驟重新連結至實際的電子郵件或分群（當名稱與您已有的項目相符時）；在無法找到匹配的地方，標題會報告仍有幾個步驟需要選擇電子郵件或分群，讓您在正式上線前清楚知道需要完成哪些項目。

## 分享旅程

工具列上的兩個按鈕可讓您在步驟之間或商店之間移動旅程設計：

- **匯出** 會將旅程下載為 `.journey.json` 檔案——這是流程結構的可攜式描述（包含其步驟、等待、分支以及是/否路徑），以及每個步驟所使用的電子郵件和分群的*名稱*。它不包含電子郵件設計本身或任何訂閱者資料。
- **匯入** 會將 `.journey.json` 檔案載入到目前的旅程中，取代畫布上的內容。

這對於備份您滿意的流程、將經過驗證的歡迎系列交給另一個 Spwig 商店，或在將商店複製到新安裝後重建旅程時非常有用。與範本一樣，Spwig 會在目標商店存在匹配時，透過名稱重新連結電子郵件和分群，並標記任何無法匹配的內容，以便您完成設定。

## 啟用您的旅程

當流程準備就緒時，使用建置器右上角的狀態控制項。一個膠囊顯示旅程的目前狀態——**草稿**、**啟用中** 或 **已暫停**——旁邊有一個 **啟用** 按鈕。

點擊 **啟用** 會**先檢查流程**。如果有任何問題會導致其無法運作，啟用將被阻止，並透過橫幅列出問題——例如未選擇電子郵件的 **發送電子郵件** 步驟、沒有分群或沒有是/否路徑的 **分支**、已被刪除的電子郵件或分群，或會無限運行的循環。每個問題都可點擊：選擇它會跳轉到出錯的步驟，該步驟會以紅色輪廓顯示，直到您修復為止。警告（例如無法到達的步驟或未設定延遲的 **等待**）也會列出，但不會阻止啟用。

![啟用被阻止，問題列在橫幅中，出錯的步驟以紅色輪廓顯示](/static/core/admin/img/help/journey-builder/journey-builder-activate-blocked.webp)

一旦流程通過檢查，膠囊會切換為 **啟用中**，旅程會在其觸發條件觸發時開始納入訂閱者。

按鈕會變成 **暫停**，這會停止新的加入 — 已經進行到一半的訂閱者仍會繼續收到剩餘的步驟。

請參閱 [觸發式旅程](/help/triggered-journeys) 以了解加入、冷卻時間和狀態之間的互動方式。

## 查看誰在旅程中

一旦旅程上線，每個步驟的角落都會顯示一個小型 **計數徽章**：目前停留在該步驟的訂閱者人數。這是一種快速查看人們流動位置以及哪裡出現積壓的方式 — **等待** 步驟上出現大量數字是預期的，但在特定電子郵件之前出現積壓可能值得關注。計數會在你返回編輯器標籤時更新。

![畫布上步驟的即時計數徽章和工具列中的啟用按鈕](/static/core/admin/img/help/journey-builder/journey-builder-live-counts.webp)

## 提示

- 在仍為 **草稿** 時設計流程 — 在你 **啟用** 之前，不會有任何人加入。從編輯器啟用會先進行快速檢查，並不會讓損壞的流程上線，因此沒有半完成的旅程加入訂閱者的風險。
- 即使你計劃大幅自訂，也從 **範本** 開始 — 編輯現有流程比逐個節點建立更快，如果你之前沒有使用過分支模式，它也能展示分支模式。
- 套用範本或匯入檔案後，檢查標頭中是否有未匹配步驟的註記，並在啟用之前填寫任何它無法匹配的 **發送電子郵件** 或 **分支** 步驟。
- 當流程變寬時（特別是分支），隨時點擊 **適配** — 這是縮放或平移後再次查看整體形狀的最快方式。
- 透過將每個 **等待** 步驟緊接在其延遲的電子郵件之前，而不是將多個等待聚集在一起，來保持步驟名稱易於掃描。
- 在對正常運作的旅程進行重大更改之前 **匯出** 它 — 這是一種快速保留備份副本的方式，如果你不滿意結果，可以重新匯入。
