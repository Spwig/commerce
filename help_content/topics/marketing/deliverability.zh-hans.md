---
title: 邮件送达率运维手册
---

让邮件*发送*出去很容易。让它进入收件箱而不是垃圾邮件文件夹才是真正的工作——Gmail 和 Yahoo 等邮箱提供商现在会强制执行严格的技术要求，否则他们甚至不会考虑接收。本手册将逐步介绍需要配置的内容以及配置顺序，以确保您的订单确认邮件和营销活动邮件能够送达客户可见的位置。

这里没有任何一项是一次性的任务。送达率是一种需要随时间逐步建立且可能迅速丧失的信誉——文末的检查清单值得在出现任何异常时重新审视。

## 为什么这很重要

所有主要收件箱提供商在决定是投递、折叠到垃圾邮件文件夹还是直接拒收之前，都会根据发件人信誉对传入邮件进行评分。自 2024 年以来，Gmail 和 Yahoo 已将其正式化为针对任何发送大量邮件者的明确**批量发件人要求**：

- **验证您的域名** — 有效的 SPF、DKIM 和 DMARC 记录。
- **让退订变得简单** — 在每封营销邮件中提供有效且低摩擦的退订选项。
- **保持垃圾邮件投诉率低** — 投诉率超过大约 0.3% 的批量发件人面临邮件被拒收或直接归入批量文件夹的风险；最安全的目标是远低于 0.1%。

如果未能满足这些要求，受影响的不仅仅是营销活动——受损的域名信誉甚至可能将事务性邮件（订单确认、密码重置）拖入垃圾邮件，因为 Gmail 和 Yahoo 越来越多地在发件域名层面而非仅按消息类型来判断信誉。以下步骤是满足这三项要求的方法。

## 第 1 步：验证您的发件域名

SPF、DKIM 和 DMARC 是 DNS TXT 记录，用于向接收邮件服务器证明声称来自您域名的邮件确实是由您发送的。如何设置它们取决于您的商店使用的发送模式——这三者均在管理侧边栏的**邮件配置**下进行配置（这将打开邮件账户列表；完整的账户设置指南请参阅[邮件配置](email-configuration)）。

| 发送模式 | 如何进行身份验证 |
|---|---|
| **内置 SMTP**（Spwig 自有的电子邮件服务器） | Spwig 会自动生成您域名的 DKIM 密钥对。添加一个电子邮件账户，设置向导的 **第 4 步** 会显示您的 SPF、DKIM 和 DMARC 状态以及要添加的精确记录，包含复制到剪贴板和针对 Cloudflare、GoDaddy、Namecheap 和 AWS Route 53 的提供商特定说明。如果之后需要再次查找，该 DKIM DNS 记录也会在账户的管理页面的 **DKIM 密钥配置** 下显示。 |
| **通用 SMTP**（您自带的提供商，如 SendGrid、Mailgun、Amazon SES 或 Google Workspace，通过 SMTP 凭证连接） | 身份验证部分在该提供商自己的仪表板中完成。设置向导的 DNS 步骤包括针对 Gmail、Outlook、SendGrid、Mailgun 和 Amazon SES 的选项卡说明——每种说明都会解释在提供商的控制台中要配置什么（例如在 SendGrid 中验证发件域名）以及在您的 DNS 主机上要添加哪些 DNS 记录。 |
| **Spwig 托管的邮件网关** | 仅在 Spwig 托管计划中提供作为托管发送选项。它会自动使用 DKIM 签名传出邮件，并默认从 Spwig 自有验证域名的地址发送，因此无需任何设置即可使用。如果您希望通过网关使用自己的域名发送邮件，请与您的托管提供商联系以验证域名——这是一个托管服务，而不是自助 DNS 流程。 |

![电子邮件账户设置向导的第 4 步，显示 SPF/DKIM/DMARC 验证、DNS 提供商选项卡和已展开的 DKIM 记录以便复制](/static/core/admin/img/help/deliverability/wizard-dns-step.webp)

![现有内置 SMTP 电子邮件账户的 DKIM 密钥配置面板，包含 DNS TXT 记录和“复制 DNS 记录”按钮](/static/core/admin/img/help/deliverability/dkim-dns-record.webp)

无论您使用哪种模式，**添加 DNS 记录本身始终是一个外部步骤** — 您需要在域名注册商或 DNS 托管商（Cloudflare、GoDaddy、Namecheap、Route 53，或您的域名名称服务器指向的任何地方）处进行操作，而不是在 Spwig 内部。

Spwig 可以告诉您确切需要添加什么，并验证其是否已生效，但它无法访问您的注册商为您添加记录。

在开始之前，有几点值得了解：

- **DNS 更改不是即时生效的。** 传播可能需要几分钟到 48 小时不等。在记录实际传播之前，向导的验证步骤会显示该记录为失败或缺失 — 这是预期行为，并非表示出现问题。
- **每个域名只允许一个 SPF 记录。** 如果您已经有一个（来自 Google Workspace、其他邮件服务商等），请使用 `include:` 将新的发件人添加到现有记录中，而不是创建第二个 SPF TXT 记录 — 两个 SPF 记录会导致所有人的身份验证失败。
- **DMARC 需要 SPF 或 DKIM 已经通过。** 请在最后设置，即 SPF 和 DKIM 都已验证之后。

## 步骤 2：使用真实的发件人身份

一旦您的域名经过身份验证，请确保收件人实际看到的内容与之相符：

- **发件人地址** — 使用您自己经过身份验证的域名上的地址（`orders@yourstore.com`），切勿使用免费提供商的地址（`yourstore@gmail.com`）。免费提供商的发件人地址完全无法通过您的 SPF/DKIM/DMARC 记录进行身份验证，收件箱提供商会将其视为来自商店的强烈垃圾邮件信号。
- **发件人名称** — 使用您的商店可识别的名称，而不是像“通知”或“请勿回复”这样的通用标签。
- **回复至** — 设置一个受监控的地址。一个无人监控的 `noreply@` 地址，如果回复被退回或静默丢弃，本身就是一个轻微的名誉信号，并且它阻止了客户告知您出错的唯一渠道。

在 **Email Configuration > (your account) > Sender Configuration** 下设置所有三项 — 有关完整的字段说明，请参阅 [Email Configuration](email-configuration)。

## 第 3 步：在扩大规模前先预热

没有发送历史的域名或 IP 地址尚无信誉记录——无论好坏——收件箱提供商对未知来源通常持谨慎态度。从一个全新域名发送大规模的首批邮件，在统计上与垃圾邮件发送者启动新活动无异，即使所有技术配置均正确，也可能被归入垃圾邮件文件夹。

- 从小规模开始。前几次活动应发送给参与度最高、最可能打开邮件的受众，而非一次性发送给整个列表——请参阅 [受众](audiences) 以了解如何构建目标初始细分。
- 在前几周内逐步增加发送量，而不是直接跳转到全列表发送。
- 如果您正在从其他平台迁移现有列表，在信誉方面也应将其视为第一天——旧平台的发送历史不会随域名转移。

## 第 4 步：保持列表整洁

每一次投诉或退信都会损害您的信誉，而这两者主要取决于列表中的用户及其来源：

- **仅向已同意的用户发送邮件。** 导入的联系人、购买的列表和抓取地址是快速增加垃圾邮件投诉和硬退信的最快途径。
- **使用双重确认（Double Opt-in）。** Spwig 的营销同意流程会在发送营销邮件之前验证订阅者的电子邮件地址——请参阅 [通信偏好](communication-preferences) 了解如何配置此功能。
- **让 Spwig 的自动抑制机制发挥作用。** Spwig 会监控硬退信、垃圾邮件投诉和重复的软退信，并自动停止向这些地址发送邮件，无需任何设置——请参阅 [列表卫生与抑制](list-hygiene) 了解其具体工作原理以及何时（极少情况下）需要手动覆盖。
- **定期清理不活跃订阅者**，而不是无限期地向同一批未参与地址发送邮件——一个规模缩小但打开率和点击率高的列表，比一个规模大但无互动的列表对您的信誉更有价值。

## 第 5 步：监控

可 deliverability 问题在客户告诉您电子邮件未到达之前就会在数字中显现。

在每次发送活动后打开活动的[报告](campaign-reports)，并观察：

| 指标 | 需要关注的内容 |
|---|---|
| **退信率** | 大部分是软性退信是正常的；上升的 **硬性退信** 比例意味着您的列表中积累了过时或无效的地址。 |
| **垃圾邮件投诉** | 每次发送时应接近零。保持在大约 0.3% 的阈值以下，这会触发 Gmail 和 Yahoo 的批量发送者执行措施 —— 即使是小幅度的上升也应立即调查。 |
| **打开率 / 点击率** | 在相同列表的多次发送中突然且无法解释的下降可能是邮件被发送到垃圾邮件而不是收件箱的早期迹象，甚至在退信或投诉数字发生变化之前。 |

还应定期检查 Campaign Studio 仪表板的 **被阻止的地址** 卡片 —— 稳定的少量是正常的列表衰减，但在下一次发送前出现突然的激增应进行调查（参见 [列表清理](list-hygiene)）。

![Campaign Studio 仪表板上的被阻止的地址统计卡片](/static/core/admin/img/help/deliverability/suppressed-addresses-card.webp)

如果某项指标激增：暂停并首先检查您的 DNS 记录是否仍然有效（过期的域名续费或意外的 DNS 变更可能会静默地破坏 SPF/DKIM），然后查看触发该指标的发送内容或受众发生了什么变化。

## 第 6 步：内容清理

认证和列表质量能让你进入大门；内容在你进入后仍会影响你的待遇。

保留所有 markdown 格式、图片路径、代码块和术语。

- **避免触发垃圾邮件过滤的模式**——在主题行中使用全大写字母、过多标点符号（如"!!!"）以及"立即行动"或"免费资金"等短语，即使来自已验证的域名，仍会被垃圾邮件过滤器视为负面信号。
- **不要发送纯图片邮件。** 一封仅包含一张图片而没有实际文本的邮件是典型的垃圾邮件模式；请在图片旁边保留足够多的实际文本内容。
- **发送前预览。** 在邮件发送给完整列表之前，检查其实际渲染效果——包括在移动设备上的显示。
- **退订链接已自动处理。** Spwig 会自动在每封营销邮件的页脚中添加一个可正常工作且无需登录的退订链接——您无需自行添加（有关该流程的具体工作方式，请参阅[通信偏好设置](communication-preferences)）。

不要移除或隐藏该链接；无论您的其他指标如何，缺失或损坏的退订链接本身都违反了 Gmail 和 Yahoo 的批量发件人规则。

## "我的邮件被归入垃圾邮件"——故障排除清单

请按顺序执行以下步骤：

1. **重新检查您的 DNS 记录。** 打开账户设置向导中的 DNS 步骤（或内置 SMTP 账户管理页面上的 DKIM 面板），确认 SPF、DKIM 和 DMARC 均显示为通过。

域名续订、DNS 提供商迁移或对区域文件的无关更改都可能悄悄破坏其中某一项。
2. **检查受影响发送活动的报告中的退信和投诉数量**——请参阅[活动报告](campaign-reports)。


任一指标的激增都指向列表质量或内容问题，而非身份验证问题。
3. **检查抑制列表**（[列表卫生](list-hygiene)）是否有突然的跳升——如果您的列表中有大量部分已经失败了一段时间，那么其余部分的送达率也会下降。
4. **确认您的发件人地址位于经过身份验证的域名上**，而不是免费提供商的地址，或者与 SPF/DKIM/DMARC 设置不匹配的域名。
5. **向您控制的 Gmail 和 Yahoo/Outlook 地址发送测试邮件**，并检查其实际落入的文件夹，而不仅仅是它是否已到达。
6. **如果您最近大幅更改了发送量或受众群体，** 请将其视为一次新的预热——将发送量调低，并更平缓地逐步增加。
7. **如果以上所有检查均正常且问题仍然存在，** 这可能是特定提供商的节流，而不是您配置中的故障——一旦根本原因（通常是投诉或退信）得到解决，这可能需要一些时间才能自行解决。

## 提示

- 在修复其他任何内容之前，先修复 DNS 身份验证——如果 SPF/DKIM/DMARC 未通过，其他所有送达率杠杆（内容、列表卫生、预热）的重要性都会降低。
- 将设置向导中的 DNS 验证视为一个时间点检查，而不是一次性的——每次迁移 DNS 提供商或通过不同的注册商续订域名时，都要重新运行它。
- 一个会打开和点击的干净列表总是比一个不打开的大列表表现更好——抵制导入旧的、未验证的列表的冲动，即使只是为了“以防万一”。
- 关注您相对于自己过去发送情况的数字，而不是通用的行业基准——您自己的历史记录是真实问题最可靠的信号。
- 如果您使用的是 Spwig 托管计划，托管邮件网关的 DKIM 签名和声誉管理将由系统为您处理——您剩余的责任是列表质量和内容，而不是 DNS。
