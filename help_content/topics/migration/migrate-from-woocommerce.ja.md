---
title: WooCommerceからの移行
---

現在、ストアがWooCommerce上で動作している場合、Spwigの移行ウィザードは、WooCommerceのREST APIを通じて製品、顧客、注文、コンテンツを直接インポートできます。このガイドでは、API資格情報を取得し、インポートを実行する方法、および事前に知っておくべき2つのWooCommerce固有の機能について説明します。アフィリエイトデータ用のオプションのMigration Bridgeプラグインと、いくつかの人気のあるWooCommerce拡張機能の組み込みサポートです。

## 開始する前に

移行ウィザードでは、WooCommerceがソースプラットフォームの中で最も広範なサポートを提供しています。以下の項目がクリーンにインポートされます: カテゴリ（階層付き）、製品、画像とバリエーション、顧客と住所、注文、レビュー、クーポン、およびブログ投稿（カテゴリ、タグ、画像を含む）。

アフィリエイトプロファイル、コミッション履歴、支払い履歴もインポートできますが、Spwig Migration Bridgeプラグインをまずインストールする必要があります — 以下を参照してください。これをインストールしない場合、そのデータは単にスキップされます。

また、以下の点にも注意してください:

- 一部のWooCommerce拡張機能（サブスクリプション、バンドル、予約、ギフトカード）から取得した製品は、対応するSpwigの機能に配置されます。ただし、すべての詳細が移行されるわけではありません — 以下を参照してください: **WooCommerce拡張機能のサポート**。
- あなたの製品、顧客、注文に設定されたカスタムフィールドは自動的に検出され、後でマッピングする必要があります。詳しくは [Migration Field Mapping](migration-field-mapping) を参照してください。
- ウィザードの **Import tax settings** および **Import shipping zones and methods** のオプションは、インポートされたデータには適用されません。Spwigでインポート後に税金の設定と配送方法を自分で設定してください — 詳しくは [After Your Migration](after-migration-review) を参照してください。
- 同じステップの **Price adjustment** オプションは、WooCommerceのインポートに対しては効果があります。各製品の基本価格が作成されるたびに変更されます。価格をすべてシフトさせたい場合以外は、**None** に設定してください。

WordPressの管理者ログイン情報を手元に用意し、インポートする製品、顧客、注文の数がだいたいどのくらいか把握しておくと、ウィザードが表示する数値を sanity-check できます。

## REST API 資格情報の取得


# SpwigはWordPressの管理画面から生成されたREST APIキーを使用してWooCommerceに接続します。

このキーには**読み取り**アクセス権のみが必要です — Spwigは移行中にのみストアから読み取りを行い、何も書き戻しません。

1. WordPressで **WooCommerce > Settings > Advanced > REST API** にアクセスしてください
2. **Add key** をクリックしてください
3. 説明を入力してください（例: `Spwig Migration`）そして **Permissions** を **Read** に設定してください
4. **Generate API key** をクリックしてください
5. **Consumer Key** (`ck_...`) と **Consumer Secret** (`cs_...`) を安全な場所にコピーしてください

> **重要:** WooCommerceはConsumer Secretを一度だけ表示します、生成した瞬間にのみ表示されます。コピーする前に画面から離れると、新しいキーを生成する必要があります。

## ストアの接続

Spwigの管理画面で **Data Import & Export > Start New Migration** にアクセスし、ステップ1で **WooCommerce** を選択してください。ステップ2で以下を入力してください:

- **Store URL** — ストアの完全なウェブアドレス、例: `https://mystore.com`
- **Consumer Key** と **Consumer Secret** — 今コピーした値

**Test connection before proceeding** がチェックされている（デフォルトで有効）ようにして、Spwigがストアに接続でき、認証できることを確認してください — これにより、インポートの途中ではなく、すぐにタイプミスや権限の問題を検出できます。成功したら **Next** をクリックしてください。

## データの確認と選択

ステップ3では、ストアからライブカウントを取得します — カテゴリ、商品、顧客、注文、レビュー、クーポン — そして最初の5つの商品のサンプルも取得し、正しいサイトが読み取られているか確認できます。各データタイプのチェックボックスは、そのカウントがゼロより大きい場合に自動的にチェックされ、ゼロの場合は無効になります。

**Import Options:**

- **Skip existing items** (on) — 入力されたレコードをSpwigに既にあるもの（商品のSKU、顧客のメールアドレス）と照合し、重複をスキップします。

空のストアから始める以外は、このオプションを有効にしておく。
- **製品画像のインポート** (有効) — 速度は遅くなるが、価値がある。
- **可能な限り元のIDを保持** (無効) — マジック自体はこれを「推奨されない」とラベル付けしている。WooCommerceの数値IDを保持する特定の技術的な理由がある場合以外は、このオプションを無効にしておく。
- **バッチサイズ** — 10, 25 (デフォルト), 50 または 100 レコードずつ。

小さなバッチは不安定な接続に適しており、大きなバッチは安定した接続ではより早く完了する。

## Spwig マイグレーションブリッジプラグイン

WooCommerceにはアフィリエイトプログラムの概念が組み込まれていないため、WooCommerceのアフィリエイト拡張機能を使ってアフィリエイトプログラムを運営している場合、そのデータは標準のREST APIがアクセスできないテーブルに保存されている。**Spwig マイグレーションブリッジ**は、WordPressサイトにインストールする小さな補助プラグインで、このデータを公開する。

ブリッジプラグインは以下を有効にする。

- **アフィリエイトプロフィール** — アフィリエイトの詳細とリファラルコード
- **コミッション履歴** — 各アフィリエイトに関連するコミッション履歴
- **支払い履歴** — アフィリエイトに支払われた過去の支払い履歴

これは完全にオプションである。アフィリエイトプログラムを運営していない、またはSpwigでその履歴が必要でない場合は、このプラグインをスキップしてもよい。

> **注意:** アフィリエイトデータは、同じマイグレーションで注文と顧客もインポートされている場合にのみインポート可能である。これは、コミッションと支払いが特定の注文と顧客に関連付けられているためである。

インストール方法:

1. ステップ3で、プラグインがすでにサイトに検出されていない場合、**Bridgeプラグインをダウンロード**ボタンとインストール手順が表示される。
2. プラグインのZIPファイルをダウンロードする。
3. WordPressで **プラグイン > 新規追加 > プラグインのアップロード** に移動し、ZIPファイルを選択し、**今すぐインストール** をクリックし、**有効化** をクリックする。
4. Spwigのウィザードに戻り、ページをリフレッシュする — **アフィリエイト** チェックボックスと **アフィリエイトプログラムデータ** ブロックが表示され、見つかった数が表示される。

マイグレーションが完了した後、WordPressからBridgeプラグインを無効化し、削除してもよい。

## WooCommerce拡張機能サポート

ストアが特定の人気のある拡張機能を使用している場合、インポート時にそれらが作成する製品は、通常の製品としてではなく、対応するSpwigの機能にマッピングされます:

| WooCommerce拡張機能 | 対応する場所 |
|---|---|
| Subscriptions | Spwigサブスクリプションプラン |
| Product Add-Ons | Spwig製品追加オプション |
| Product Bundles | Spwig製品バンドル |
| Gift Cards (WooCommerce, YITH and PW variants) | Spwigギフトカード |
| Composite Products | Spwigコンポジット製品 |
| Bookings and Accommodation Bookings | Spwig予約 |

> **注意:** 拡張機能のデータインポートは、基本的な製品の作成を妨げることはありません。製品の拡張機能固有のデータが読み取れなかった場合でも、製品はインポートされます — ただし、サブスクリプション、バンドル、予約、ギフトカードの設定は含まれません。

インポート後、サブスクリプション、バンドル、予約、ギフトカード製品をスポットチェックし、拡張機能固有の設定が正しく転送されたことを確認してください。インポートが成功したからといって、すべての詳細が転送されたとは限りません。

## カスタムフィールド

WooCommerceの製品、顧客、注文にカスタムメタフィールドを追加した場合、Spwigはそれぞれのタイプから約10件のレコードをサンプリングして、存在するフィールドを検出します。これらはステップ4でSpwigのカスタムフィールドスロットまたは一般的なメタデータフィールドにマッピングします。[Migration Field Mapping](migration-field-mapping)を参照して、マッピングの完全な手順を確認してください。これには、将来的なマイグレーション用にマッピングが保存される方法も含まれます。

## インポートの実行

ステップ3を確認し、ステップ4でマッピングを確認した後、インポートを開始してください。これはバックグラウンドで実行されます — ブラウザウィンドウを閉じても、インポートは継続されます。ステップ5では、データタイプごとに1行ずつ（カテゴリ、製品、顧客、注文、レビュー、クーポン、ブログ投稿、Bridgeプラグインを使用した場合のアフィリエイト/コミッション/支払い）ライブ進捗を表示し、拡張可能なアクティビティログも表示されます。

ステップ6では、インポートされた内容、スキップされた内容、または失敗した内容の結果が表示されます。また、インポートされたコンテンツに旧WooCommerceドメインへの内部リンクが含まれている場合、**リンクの書き換え**ツールも表示されます。

結果の概要を慎重に確認した後、[移行後の確認](after-migration-review)にあるチェックリストを順番に実施してください。これは、データの確認、税率と配送の設定（ウィザードでは設定されません）、内部リンクの書き換えをカバーしています。

## APIキーの無効化

移行が成功裏に完了したことを確認したら、WordPressの**WooCommerce > 設定 > 高度 > REST API**にアクセスし、Spwigのために作成したAPIキーを無効化または削除してください。旧ストアでそのAPIキーを必要としなくなった後、アクティブなAPIキーを残しておく理由はありません。

## ヒント

- **必要になる直前にAPIキーを生成してください** — Consumer Secretは一度だけ表示されるため、ステップ2を開始する直前に作成してください。あらかじめ作成しないでください。
- **読み取り専用で十分です** — WriteまたはRead/Writeの権限を決して与えないでください。Spwigは常にWooCommerceストアからデータを読み取るだけです。
- **インポートを開始する前にBridgeプラグインをインストールしてください** — インポートする前に、それを追加し、ウィザードを再読み込みする必要があります。そのため、インポート途中ではなく、事前に確認してください。
- **拡張機能でサポートされている製品をスポットチェックしてください** — サブスクリプション、バンドル、予約、ギフトカードは、インポート後にも手動で確認が必要な可能性が最も高い製品です。
- **部分的なインポートは自動的にクリーンアップされません** — インポートを再試行する前に、[移行のトラブルシューティング](migration-troubleshooting)を参照してください。
- **完了したらAPIキーを無効化してください** — 移行したストアから離れた後、古い統合をアクティブに残さないでください。
