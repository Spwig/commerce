---
title: 從 WooCommerce 移植
---

如果您的商店目前使用 WooCommerce，Spwig 的移植向導可以透過 WooCommerce 的 REST API 直接導入您的產品、客戶、訂單和內容。本指南涵蓋取得 API 權限、執行導入，以及兩個 WooCommerce 特有的功能，建議您事先了解：可選的 Migration Bridge 插件用於導入聯營資料，以及內建支援幾個流行的 WooCommerce 擴充功能。

## 稍後開始前

WooCommerce 是遷移向導中支援最廣的來源平台。以下內容可以整潔地導入：分類（含階層）、產品、圖片和變體、客戶和地址、訂單、評論、優惠券，以及附帶分類、標籤和圖片的部落格文章。

聯營資料、佣金記錄和付款歷史也可以導入，但前提是您先安裝 Spwig Migration Bridge 插件 — 請參閱下方說明。若未安裝，這些資料將被跳過。

請注意以下事項：

- 某些 WooCommerce 擴充功能（訂閱、組合包、預約、禮券）的產品會對應到 Spwig 的對應功能，但並非所有細節都能正確轉換 — 請參閱下方的 **WooCommerce 擴充功能支援**。
- 您產品、客戶和訂單上的自定義欄位會自動被偵測，但需要在後續步驟中進行映射。請參閱 [Migration Field Mapping](migration-field-mapping)。
- 向導中的 **Import tax settings** 和 **Import shipping zones and methods** 選項不會套用到導入的資料。請在 Spwig 中自行設定稅率和運費 — 請參閱 [After Your Migration](after-migration-review)。
- 同一頁面上的 **Price adjustment** 選項 *確實* 會對 WooCommerce 的導入產生影響，會在每個產品建立時更改其基本價格。除非您刻意想要調整所有價格，否則請保留為 **None**。

請準備好您的 WordPress 管理員登入資訊，並大致知道您要導入的產品、客戶和訂單數量，以便與向導顯示的數量進行合理性檢查。

## 獲取 REST API 權限


Spwig 會透過從你的 WordPress 管理員產生的 REST API 金鑰連接到 WooCommerce。

此金鑰只需要 **讀取** 權限 — Spwig 在遷移期間只從你的商店讀取資料，從不寫入任何內容回傳。

1. 在 WordPress 中，前往 **WooCommerce > 設定 > 高階 > REST API**
2. 點擊 **新增金鑰**
3. 為它輸入描述（例如，`Spwig 遷移`），並將 **權限** 設為 **讀取**
4. 點擊 **產生 API 金鑰**
5. 將 **消費者金鑰** (`ck_...`) 和 **消費者密碼** (`cs_...`) 複製到一個安全的地方

> **重要提示：** WooCommerce 只會在你生成時顯示一次消費者密碼。如果你在複製之前離開了這個頁面，你將需要生成一個新的金鑰。

## 連接你的商店

在 Spwig 管理介面中前往 **資料導入與導出 > 開始新遷移**，並在第一步中選擇 **WooCommerce**。在第二步中，輸入：

- **商店 URL** — 你的商店完整網址，例如 `https://mystore.com`
- **消費者金鑰** 和 **消費者密碼** — 你剛剛複製的值

保留 **在繼續之前測試連線** 勾選（預設為啟用），這樣 Spwig 會在你繼續之前確認它能否連接到你的商店並進行驗證 — 這樣可以立即發現拼寫錯誤和權限問題，而不是在導入過程中才發現。一旦測試成功，點擊 **下一步**。

## 檢閱和選擇資料

第三步會從你的商店提取即時數量 — 分類、產品、客戶、訂單、評論和優惠券 — 加上前五個產品的樣本，讓你可以確認它讀取的是正確的網站。當某種資料類型的數量高於零時，其複選框會自動勾選，當數量為零時則會停用。

**導入選項：**

- **跳過現有項目**（啟用）— 將來的記錄與 Spwig 中已有的項目進行比對（產品的 SKU，客戶的電子郵件），並跳過重複項目。

除非你正在從一個空商店開始，否則請保留此選項。
- **導入產品圖片**（開啟）——速度較慢，但值得。
- **盡可能保留原始 ID**（關閉）——該向導本身標記為「不建議」。除非你有特定的技術原因需要保留 WooCommerce 的數字 ID，否則請保持關閉。
- **批次大小** — 10、25（預設）、50 或 100 筆記錄一次。

較小的批次適合連接不穩定的情況；較大的批次在連接穩定時處理速度更快。

## Spwig 迁移桥接插件

WooCommerce 没有内置的附属计划概念，因此如果你通过 WooCommerce 附属插件运行一个附属计划，这些数据存储在标准 REST API 无法访问的表中。**Spwig 迁移桥接插件**是一个小型的配套插件，你可以在 WordPress 网站上安装它以公开这些数据。

桥接插件解锁了以下功能：

- **附属资料** — 你的附属人员的详细信息和推荐码
- **佣金记录** — 与每个附属人员相关的佣金历史记录
- **付款历史** — 发送给附属人员的过往付款记录

这是完全可选的 —— 如果你没有运行附属计划，或者在 Spwig 中不需要这些历史记录，可以跳过它。

> **注意：** 附属数据只能在订单和客户也同时导入的迁移中导入，因为佣金和付款与特定的订单和客户相关联。

安装步骤如下：

1. 在第 3 步，如果插件尚未在您的网站上检测到，您将看到一个 **下载桥接插件** 按钮，并附有安装说明
2. 下载插件 ZIP 文件
3. 在 WordPress 中，进入 **插件 > 添加新 > 上传插件**，选择 ZIP 文件，点击 **立即安装**，然后 **激活**
4. 返回 Spwig 向导并刷新页面 —— 一个 **附属人员** 复选框和一个 **附属计划数据** 块将出现，显示找到的数量

在迁移完成后，你可以停用并从 WordPress 中删除桥接插件。

## WooCommerce 扩展支持

如果您的商店使用了某些流行的擴展功能，這些擴展功能創建的產品在導入時會被識別，並映射到對應的 Spwig 功能，而不是作為普通產品導入：

| WooCommerce 擴展 | 對應到 |
|---|---|
| Subscriptions | Spwig 訂閱方案 |
| Product Add-Ons | Spwig 產品附加功能 |
| Product Bundles | Spwig 產品組合 |
| Gift Cards (WooCommerce, YITH 和 PW 版本) | Spwig 礼品卡 |
| Composite Products | Spwig 組合產品 |
| Bookings and Accommodation Bookings | Spwig 預訂 |

> **注意：** 擴展數據導入從來不會阻止底層產品的創建。如果無法讀取產品的擴展特定數據，產品仍然會導入——只是作為普通產品，沒有其訂閱、組合、預訂或禮品卡配置。

導入後請抽查您的訂閱、組合、預訂和禮品卡產品，確認其擴展特定設置已正確導入，而不是假設成功的導入包含了所有細節。

## 自定義欄位

如果您在 WooCommerce 產品、客戶或訂單中添加了自定義元數據欄位，Spwig 會採樣每種類型約十條記錄以檢測存在哪些欄位。您需要在步驟 4 中將每個欄位映射到 Spwig 的自定義欄位插槽或一般元數據欄位。請參閱 [Migration Field Mapping](migration-field-mapping) 以獲得完整的操作指南，包括映射如何保存以供未來遷移使用。

## 執行導入

在您審核完步驟 3 並確認步驟 4 中的映射後，開始導入。導入在後台運行——您可以關閉瀏覽器窗口，導入仍會繼續。步驟 5 會顯示實時進度，每個數據類型（分類、產品、客戶、訂單、評論、優惠券、博客文章，以及如果使用了 Bridge 插件則包括聯盟/佣金/付款）各佔一行，還有一個可展開的活動日誌。

步驟 6 會顯示您的結果：已導入、跳過或失敗的內容，以及一個 **連結重寫** 工具（如果在導入的內容中發現了指向舊 WooCommerce 域名的內部連結）。

仔細查看摘要，然後按照 [遷移後](after-migration-review) 中的清單進行操作 —— 它涵蓋了驗證數據、設置稅率和運費（向導不會為您配置這些內容），以及重寫內部連結。

## 撤銷您的 API 金鑰

一旦確認遷移成功完成，請返回 WordPress 中的 **WooCommerce > 設定 > 高階 > REST API**，並撤銷或刪除為 Spwig 創建的金鑰。一旦完成遷移，就沒有理由在舊商店上保留一個活動的 API 金鑰。

## 小提示

- **在需要時再生成 API 金鑰** —— 由於消費者密鑰只顯示一次，請在開始步驟 2 前立即創建它，而不是提前創建。
- **只讀權限就足夠了** —— 永遠不要授予寫入或讀寫權限；Spwig 只會從您的 WooCommerce 商店中讀取數據。
- **在開始導入前安裝 Bridge 插件** —— 在導入前需要添加它並刷新向導，因此請提前檢查是否存在，而不是在導入過程中才發現。
- **抽查依賴擴展的產品** —— 訂閱、組合包、預約和禮品卡是最有可能在導入後需要手動檢查的產品。
- **部分導入不會自動清理** —— 在重試失敗的導入之前，請先查看 [遷移問題排除](migration-troubleshooting)。
- **完成後請撤銷 API 金鑰** —— 不要在已遷移離開的商店上保留舊的集成活動。
