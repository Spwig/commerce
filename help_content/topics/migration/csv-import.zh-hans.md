---
title: 从CSV文件导入
---

CSV导入是Spwig无法直接连接的任何商店的后备迁移路径。如果您来自BigCommerce、PrestaShop、Squarespace、Wix、您手动维护的电子表格或Spwig无法理解API的定制系统，这就是您的落脚点——将您的数据导出为CSV文件，并在此处上传，而不是实时连接。

本指南涵盖何时使用CSV而不是API连接，CSV无法迁移的内容，涉及的五个文件，如何准备这些文件，以及列映射的工作原理。

## 何时使用CSV而不是API连接

Spwig可以直接连接到WooCommerce、Shopify和Magento 2/Adobe Commerce——有关这些平台的信息，请参阅[数据迁移概述](migration-overview)。对于任何其他平台，CSV是您唯一的选择；BigCommerce、PrestaShop、Squarespace或Wix没有直接集成。如果您正在从电子表格中整合数据、退役自定义构建的商店，或者希望通过自己整理文件来精确控制导入的内容，这也是正确的选择。

## CSV无法做到的事情

在准备任何内容之前，请了解此方法会遗漏什么——这是使用CSV导入的商户最常见的意外来源：

- **没有产品图片。** 产品导入时不附带图片；请在导入后上传。
- **没有变体。** 每个产品都作为简单产品创建。在导入后在Spwig中重新构建尺寸/颜色/风格结构。
- **没有优惠券。** 折扣码和促销活动不属于CSV格式。
- **没有博客内容。** 没有用于文章或帖子的CSV文件。

这些都不会阻止导入——只是意味着产品在导入到Spwig后需要后续工作。请参阅[迁移后](after-migration-review)以获取完整的导入后检查清单。

## 五个文件

向导的CSV步骤提供五个文件输入，每个都有一个**下载模板**按钮。请从这些模板开始，而不是从头构建文件——它们可以确保正确的列名，并让第4步的自动检测完成更多工作。

| 文件 | 是否必需 |
|---|---|
| 产品 | **必需** |
| 分类 | 可选 |
| 客户 | 可选 |
| 订单 | 可选 |
| 评论 | 可选 |

Spwig 唯一强制要求的文件是 产品 —— 如果您暂时没有其他数据，其余文件可以留空。

### 产品 (必需)

| 列 | 描述 |
|---|---|
| `id` | 您源数据中的唯一标识符；不会显示给客户。 |
| `name` | 产品的标题。**必需。** |
| `slug` | 名称的 URL 友好版本；如果留空，将从 `name` 自动生成。 |
| `description` | 在商店前端显示的描述。 |
| `price` | 产品的常规价格。**必需。** |
| `sku` | 库存单位 —— 当启用 **跳过现有商品** 时用于匹配。 |
| `stock_quantity` | 当前库存数量。 |
| `category` | 该产品所属的分类名称。必须与您分类文件中的 `name` 匹配。 |

### 分类

| 列 | 描述 |
|---|---|
| `id` | 您源数据中的唯一标识符。 |
| `name` | 分类名称。**必需。** |
| `slug` | 名称的 URL 友好版本；如果留空，将自动生成。 |
| `description` | 分类描述文本。 |
| `parent_id` | 该分类父级的 `id`。留空表示顶级分类。 |

### 客户

| 列 | 描述 |
|---|---|
| `id` | 您源数据中的唯一标识符。 |
| `email` | 客户的电子邮件地址。**必需** —— 将订单和评论链接到正确的客户。 |
| `first_name` | 客户的名字。 |
| `last_name` | 客户的姓氏。 |
| `phone` | 客户的电话号码。 |

### 订单

| 列 | 描述 |
|---|---|
| `id` | 源数据中的唯一标识符。 |
| `customer_email` | 下单客户的电子邮件地址。**必需** — 将订单与客户记录关联。 |
| `order_date` | 下单的日期。 |
| `status` | 订单状态（例如：已完成、处理中）。 |
| `total` | 订单总额。**必需。** |
| `currency` | 订单总额的货币代码。 |

### 评论（可选）

| 列 | 描述 |
|---|---|
| `id` | 源数据中的唯一标识符。 |
| `product_id` | 被评论产品的 `id`，与您的产品文件匹配。**必需** — 将评论与正确的商品关联。 |
| `customer_email` | 评论者的电子邮件地址。 |
| `rating` | 评分星级。 |
| `comment` | 评论内容。 |
| `date` | 评论发布的日期。 |

## 准备文件

- **保存为 UTF-8** 以避免出现带有重音字符的乱码，尤其是来自不同源编码的文件。
- **用引号括起包含逗号的字段** — 将包含逗号的描述或名称用双引号括起来，以免被误认为是列分隔符。
- **包含标题行。** 第一行必须包含您的列名 — 没有标题行的文件将被拒绝。
- **使用 `parent_id` 构建分类层级。** 为每个分类分配一个唯一的 `id`，然后将子分类的 `parent_id` 设置为其父分类的 `id`。留空表示顶级分类。
- **使用 `customer_email` 将订单与客户关联**，与客户文件中的 `email` 列进行匹配（或创建一个访客记录），而不是依赖内部 ID 号，因为这些 ID 号在不同平台之间很少一致。
- **使用 `product_id` 将评论与产品关联**，与产品文件中 `id` 列的值匹配，否则该评论将被跳过。

## 在第 4 步中映射列

第 4 步会显示一个 CSV 列映射面板。

Spwig 会扫描您的表头，并与常见别名列表进行自动匹配 — 例如，`sku` 字段也会匹配 `barcode`、`part_number` 或 `item_number`。

直接从其他平台导出的表头通常可以正确映射，无需任何手动操作。

对于每一列，您可以接受自动检测的猜测，通过选择不同的目标字段来覆盖它，或者选择 "— 跳过此列 —" 以排除它。映射将被保存并在将来的 CSV 迁移中重复使用。有关第 4 步的完整说明，请参阅 [迁移字段映射](migration-field-mapping)，包括自动字段映射、分类映射以及税费/运费选项。

## 常见错误及其含义

| 错误 | 含义 |
|---|---|
| `Products CSV is required.` | 您尝试在未上传产品文件的情况下继续操作。这是 Spwig 唯一需要的文件 — 上传一个以继续。 |
| `{Type} CSV has no headers.` | 命名文件的第一行为空或缺失。添加一个包含列名的标题行并重新上传。 |
| `{Type} CSV could not be read: ...` | Spwig 无法解析命名文件 — 通常是文件损坏、编码错误，或尽管扩展名为 CSV 但实际上不是 CSV 文件。重新导出它，并确认在重新上传前可以干净地打开。 |

## 运行导入

确认映射后，从第 5 步开始迁移。它在后台运行，因此您可以关闭窗口 — 如果在完成前检查回来，可以查看进度和实时日志。有关验证结果的详细信息，请参阅 [迁移后](after-migration-review)。

请记住，CSV 导入特别会将 **产品图片** 和 **变体** 留给你手动完成 —— 无论你的文件多么完整，这两项都不会自动传输。

## 小贴士

- **从每个文件的“下载模板”按钮开始** —— 这可以避免你去查找那些本应通过手动映射来纠正的列名拼写错误。
- **在上传评论前修复 `product_id` 不匹配的问题** —— 如果某个评论的 `product_id` 与任何产品的 `id` 都不匹配，它将没有可以附加的对象，因此会被跳过。
- **不要重命名其他平台导出的列标题** —— 自动识别通常会直接通过别名识别它们，因此可能根本不需要手动映射。
- **在导入后立即为图片和变体预留时间** —— 这是CSV永远无法传输的两个部分，很容易被遗忘，直到客户注意到一个空荡荡的产品页面。
- **使用 `parent_id` 来构建多级分类** —— 将子分类的 `parent_id` 指向其父分类的 `id` 以实现嵌套；顶级分类则留空。
- **在出现“无法读取”错误时重新导出并重新检查** —— 几乎总是源文件的编码或损坏问题，而不是Spwig需要修复的问题。
