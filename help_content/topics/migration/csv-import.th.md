การนำเข้าจากไฟล์ CSV เป็นทางเลือกสำหรับการย้ายข้อมูลสำหรับร้านค้าใด ๆ ที่ Spwig ไม่สามารถเชื่อมต่อโดยตรงได้ หากคุณมาจาก BigCommerce, PrestaShop, Squarespace, Wix, ตารางที่คุณจัดการด้วยตนเอง หรือระบบเฉพาะที่ไม่มี API ที่ Spwig สามารถเข้าใจได้ นี่คือจุดที่คุณจะไปถึง — คุณต้องส่งออกข้อมูลของคุณเป็นไฟล์ CSV และอัปโหลดที่นี่แทนที่จะเชื่อมต่อแบบเรียลไทม์

คู่มือนี้ครอบคลุมถึงกรณีที่ควรใช้ CSV แทนการเชื่อมต่อ API ว่ามันไม่สามารถนำข้อมูลอะไรมาได้ ไฟล์ 5 ไฟล์ที่เกี่ยวข้อง การเตรียมไฟล์เหล่านั้นอย่างไร และการจับคู่คอลัมน์ทำงานอย่างไร

## เมื่อใดควรใช้ CSV แทนการเชื่อมต่อ API

Spwig เชื่อมต่อกับ WooCommerce, Shopify และ Magento 2/Adobe Commerce โดยตรง — ดู [ภาพรวมการย้ายข้อมูล](migration-overview) สำหรับข้อมูลเหล่านั้น หากคุณใช้แพลตฟอร์มอื่น CSV เป็นทางเลือกเดียวเท่านั้น ไม่มีการเชื่อมต่อโดยตรงสำหรับ BigCommerce, PrestaShop, Squarespace หรือ Wix มันยังเป็นทางเลือกที่ถูกต้องหากคุณกำลังรวมข้อมูลจากตาราง กำลังปิดร้านค้าที่สร้างเอง หรือต้องการควบคุมว่าข้อมูลใดถูกนำเข้าโดยการจัดการไฟล์ด้วยตนเอง

## สิ่งที่ CSV ไม่สามารถทำได้

ก่อนที่คุณจะเตรียมไฟล์ใด ๆ ให้ทราบว่าเส้นทางนี้จะไม่สามารถนำข้อมูลอะไรมาได้ — นี่คือแหล่งที่มาของความประหลาดใจที่ใหญ่ที่สุดสำหรับผู้ค้าที่ใช้การนำเข้า CSV:

- **ไม่มีรูปภาพสินค้า** สินค้าจะถูกนำเข้าโดยไม่มีรูปภาพ คุณต้องอัปโหลดรูปภาพหลังจากนั้น
- **ไม่มีตัวเลือกสินค้า** สินค้าทุกตัวจะถูกสร้างเป็นสินค้าแบบธรรมดา คุณต้องสร้างโครงสร้างขนาด/สี/สไตล์ใน Spwig หลังการนำเข้า
- **ไม่มีคูปอง** รหัสส่วนลดและโปรโมชันไม่ได้รวมอยู่ในรูปแบบ CSV
- **ไม่มีเนื้อหาบล็อก** ไม่มีไฟล์ CSV สำหรับโพสต์หรือบทความ

สิ่งเหล่านี้ไม่ได้ขัดขวางการนำเข้า — มันเพียงหมายความว่าสินค้าต้องมีงานต่อเนื่องหลังจากนำเข้าแล้วใน Spwig ดู [รายการตรวจสอบหลังการย้ายข้อมูล](after-migration-review) สำหรับรายการตรวจสอบหลังการนำเข้าทั้งหมด

## ไฟล์ 5 ไฟล์

ขั้นตอน CSV ของวิซาร์ดมีการนำเข้าไฟล์ 5 ไฟล์ แต่ละไฟล์มีปุ่ม **ดาวน์โหลดเทมเพลต** เริ่มต้นจากเทมเพลตเหล่านี้แทนที่จะสร้างไฟล์จากศูนย์ — เทมเพลตเหล่านี้รับประกันว่าชื่อคอลัมน์ถูกต้อง และช่วยให้การตรวจจับอัตโนมัติทำได้มากขึ้นในขั้นตอนที่ 4

| ไฟล์ | จำเป็น? |
|---|---|
| ผลิตภัณฑ์ | **จำเป็น** |
| หมวดหมู่ | ไม่จำเป็น |
| ลูกค้า | ไม่จำเป็น |
| คำสั่งซื้อ | ไม่จำเป็น |
| รีวิว | ไม่จำเป็น |

ผลิตภัณฑ์เป็นไฟล์เดียวที่ Spwig กำหนดไว้ — ไฟล์อื่นสามารถเว้นว่างได้หากคุณยังไม่มีข้อมูลนั้น

### ผลิตภัณฑ์ (จำเป็น)

| คอลัมน์ | คำอธิบาย |
|---|---|
| `id` | ตัวระบุที่เป็นเอกลักษณ์ในข้อมูลแหล่งที่มาของคุณ; ไม่แสดงให้ลูกค้าเห็น |
| `name` | ชื่อของผลิตภัณฑ์ **จำเป็น** |
| `slug` | รูปแบบที่เป็นมิตรกับ URL ของชื่อ; จะสร้างอัตโนมัติจาก `name` หากว่าง |
| `description` | คำอธิบายที่แสดงบนหน้าร้าน |
| `price` | ราคาปกติของผลิตภัณฑ์ **จำเป็น** |
| `sku` | หน่วยสต็อก — ใช้สำหรับการจับคู่เมื่อเปิดใช้งาน **ข้ามรายการที่มีอยู่แล้ว** |
| `stock_quantity` | จำนวนหน่วยที่มีอยู่ในสต็อก |
| `category` | ชื่อหมวดหมู่ที่ผลิตภัณฑ์นี้อยู่ใน; ต้องตรงกับ `name` ในไฟล์หมวดหมู่ของคุณ |

### หมวดหมู่

| คอลัมน์ | คำอธิบาย |
|---|---|
| `id` | ตัวระบุที่เป็นเอกลักษณ์ในข้อมูลแหล่งที่มาของคุณ |
| `name` | ชื่อหมวดหมู่ **จำเป็น** |
| `slug` | รูปแบบที่เป็นมิตรกับ URL ของชื่อ; จะสร้างอัตโนมัติหากว่าง |
| `description` | ข้อความคำอธิบายของหมวดหมู่ |
| `parent_id` | `id` ของหมวดหมู่แม่ของหมวดหมู่นี้; ว่างหมายถึงเป็นระดับบนสุด |

### ลูกค้า

| คอลัมน์ | คำอธิบาย |
|---|---|
| `id` | ตัวระบุที่เป็นเอกลักษณ์ในข้อมูลแหล่งที่มาของคุณ |
| `email` | ที่อยู่อีเมลของลูกค้า **จำเป็น** — เชื่อมโยงคำสั่งซื้อและรีวิวไปยังลูกค้าที่ถูกต้อง |
| `first_name` | ชื่อจริงของลูกค้า |
| `last_name` | นามสกุลของลูกค้า |
| `phone` | หมายเลขโทรศัพท์ของลูกค้า |

### คำสั่งซื้อ

| คอลัมน์ | คำอธิบาย |
|---|---|
| `id` | ตัวระบุที่เป็นเอกลักษณ์ในข้อมูลแหล่งที่มาของคุณ |
| `customer_email` | อีเมลของลูกค้าที่สั่งซื้อ **สำคัญ** — เชื่อมโยงคำสั่งซื้อกับบันทึกลูกค้า |
| `order_date` | วันที่ที่คำสั่งซื้อถูกวาง |
| `status` | สถานะของคำสั่งซื้อ (เช่น สำเร็จ, กำลังดำเนินการ) |
| `total` | ยอดรวมของคำสั่งซื้อ **สำคัญ** |
| `currency` | รหัสสกุลเงินสำหรับยอดรวมคำสั่งซื้อ |

### รีวิว (ไม่จำเป็น)

| คอลัมน์ | คำอธิบาย |
|---|---|
| `id` | ตัวระบุที่เป็นเอกลักษณ์ในข้อมูลแหล่งที่มาของคุณ |
| `product_id` | `id` ของสินค้าที่กำลังรีวิว ตรงกับไฟล์สินค้าของคุณ **สำคัญ** — เชื่อมโยงรีวิวกับสินค้าที่ถูกต้อง |
| `customer_email` | อีเมลของผู้รีวิว |
| `rating` | คะแนนที่ให้ |
| `comment` | ข้อความรีวิว |
| `date` | วันที่รีวิวถูกโพสต์ |

## การเตรียมไฟล์ของคุณ

- **บันทึกเป็น UTF-8** เพื่อหลีกเลี่ยงตัวอักษรที่ผิดเพี้ยน โดยเฉพาะตัวอักษรที่มีเส้นทแยงจากแหล่งที่มาที่มีการเข้ารหัสต่างกัน
- **ใส่เครื่องหมายอัญประกาศสำหรับคอลัมน์ที่มีเครื่องหมายจุลภาค** — ใส่เครื่องหมายอัญประกาศรอบคำอธิบายหรือชื่อที่มีเครื่องหมายจุลภาคเพื่อไม่ให้ถูกอ่านผิดเป็นการแบ่งคอลัมน์
- **ใส่แถวหัวข้อ** แถวแรกต้องมีชื่อคอลัมน์ของคุณ — ไฟล์ที่ไม่มีแถวหัวข้อจะถูกปฏิเสธ
- **สร้างลำดับชั้นของหมวดหมู่ด้วย `parent_id`** ให้แต่ละหมวดหมู่มี `id` ที่เป็นเอกลักษณ์ แล้วตั้งค่า `parent_id` ของหมวดหมู่ย่อยให้ตรงกับ `id` ของหมวดหมู่หลัก ช่องว่างหมายถึงระดับสูงสุด
- **เชื่อมโยงคำสั่งซื้อกับลูกค้าด้วย `customer_email`** ที่ตรงกับคอลัมน์ `email` ในไฟล์ลูกค้าของคุณ (หรือจะสร้างบันทึกผู้ใช้ที่ไม่ได้ลงชื่อเข้าใช้) แทนที่จะพึ่งพาหมายเลข ID ภายใน ซึ่งมักจะไม่ตรงกันระหว่างแพลตฟอร์ม
- **เชื่อมโยงรีวิวกับสินค้าด้วย `product_id`** ที่ตรงกับค่าในคอลัมน์ `id` ของไฟล์สินค้าของคุณ หรือรีวิวนั้นจะถูกข้าม

## การจับคู่คอลัมน์ในขั้นตอนที่ 4

ขั้นตอนที่ 4 แสดงหน้าต่างการจับคู่คอลัมน์ CSV

Spwig ตรวจสอบหัวข้อของคุณและตรวจจับการจับคู่ที่เป็นไปได้โดยอัตโนมัติจากรายการของชื่อเรียกที่พบบ่อย — ตัวอย่างเช่น ฟิลด์ `sku` ยังสามารถจับคู่กับ `barcode`, `part_number`, หรือ `item_number` ได้อีกด้วย

หัวข้อที่ส่งออกโดยตรงจากแพลตฟอร์มอื่นมักจะจับคู่ได้อย่างถูกต้องโดยไม่ต้องมีการปรับแต่งใดๆ ทั้งสิ้น

สำหรับแต่ละคอลัมน์ คุณสามารถยอมรับการคาดการณ์ที่ตรวจจับโดยอัตโนมัติ ปรับเปลี่ยนโดยการเลือกฟิลด์ปลายทางที่ต่างออกไป หรือเลือก "— ข้ามคอลัมน์นี้ —" เพื่อไม่รวมมันไว้ แผนการจับคู่จะถูกบันทึกและใช้ซ้ำในอนาคตเมื่ออัปโหลดไฟล์ CSV ใหม่ ดู [Migration Field Mapping](migration-field-mapping) เพื่อดูภาพรวมของขั้นตอนที่ 4 รวมถึงการจับคู่ฟิลด์อัตโนมัติ การจับคู่หมวดหมู่ และตัวเลือกภาษี/การจัดส่ง

## Common Errors and What They Mean

| Error | Meaning |
|---|---|
| `Products CSV is required.` | คุณพยายามดำเนินการต่อโดยไม่ได้อัปโหลดไฟล์ผลิตภัณฑ์ ไฟล์นี้เป็นไฟล์เดียวที่ Spwig ต้องการ — อัปโหลดไฟล์หนึ่งเพื่อดำเนินการต่อ |
| `{Type} CSV has no headers.` | แถวแรกของไฟล์ที่ระบุว่างเปล่าหรือหายไป โปรดเพิ่มแถวหัวข้อที่มีชื่อคอลัมน์และอัปโหลดใหม่ |
| `{Type} CSV could not be read: ...` | Spwig ไม่สามารถวิเคราะห์ไฟล์ที่ระบุได้ — มักเกิดจากไฟล์เสียหาย ตัวอักษรผิดพลาด หรือไฟล์ที่ไม่ใช่ไฟล์ CSV จริงแม้จะมีนามสกุลไฟล์ที่ถูกต้อง โปรดส่งออกไฟล์ใหม่และตรวจสอบให้แน่ใจว่าไฟล์เปิดได้โดยไม่มีปัญหา ก่อนอัปโหลดอีกครั้ง |

## Running the Import

เมื่อแผนการจับคู่ได้รับการยืนยันแล้ว ให้เริ่มการอัปโหลดจากขั้นตอนที่ 5 มันจะทำงานในพื้นหลัง ดังนั้นคุณสามารถปิดหน้าต่างได้ — คุณสามารถตรวจสอบความคืบหน้าและบันทึกแบบเรียลไทม์ได้หากคุณตรวจสอบกลับก่อนที่มันจะเสร็จสิ้น ดู [After Your Migration](after-migration-review) เพื่อตรวจสอบผลลัพธ์

จำไว้ว่าการนำเข้า CSV โดยเฉพาะอย่างยิ่งจะทิ้ง **รูปภาพสินค้า** และ **ตัวแปร** ให้คุณต้องจัดการด้วยมือ — ทั้งสองอย่างจะไม่ถูกนำเข้าโดยอัตโนมัติ ไม่ว่าไฟล์ของคุณจะสมบูรณ์แค่ไหน

## เคล็ดลับ

- **เริ่มต้นจากปุ่ม Download Template สำหรับไฟล์ทุกไฟล์** — มันช่วยคุณหลีกเลี่ยงการต้องแก้ไขข้อผิดพลาดของชื่อคอลัมน์ที่อาจเกิดขึ้นได้
- **แก้ไขความไม่ตรงกันของ `product_id` ก่อนอัปโหลดรีวิว** — รีวิวที่มี `product_id` ไม่ตรงกับ `id` ของสินค้าใดๆ จะไม่มีสิ่งใดที่จะติดต่อกับมันและจะถูกข้ามไป
- **อย่าเปลี่ยนชื่อหัวข้อจากไฟล์ส่งออกของแพลตฟอร์มอื่น** — การตรวจจับอัตโนมัติมักจะระบุชื่อหัวข้อได้โดยตรงผ่านชื่อเรียกอื่นๆ ดังนั้นการจับคู่อาจไม่จำเป็นต้องใช้การทำงานด้วยมือเลย
- **จัดสรรเวลาสำหรับรูปภาพและตัวแปรทันทีหลังการนำเข้า** — นี่คือสองสิ่งที่ CSV ไม่สามารถนำเข้าได้ และมักถูกลืมจนกว่าลูกค้าจะสังเกตเห็นหน้าสินค้าที่ไม่มีรูปภาพ
- **ใช้ `parent_id` เพื่อสร้างหมวดหมู่หลายระดับ** — กำหนด `parent_id` ของหมวดย่อยให้ชี้ไปยัง `id` ของหมวดหลักเพื่อจัดระเบียบเป็นลำดับชั้น; ปล่อยว่างหากเป็นหมวดหมู่ระดับบนสุด
- **นำออกและตรวจสอบอีกครั้งเมื่อเกิดข้อผิดพลาด "could not be read"** — มันเกิดขึ้นเกือบทั้งหมดจากปัญหาการเข้ารหัสหรือความเสียหายของไฟล์แหล่งที่มา ไม่ใช่สิ่งที่ต้องแก้ไขใน Spwig
