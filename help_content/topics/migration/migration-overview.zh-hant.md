---
title: 資料遷移概述
---

如果您的產品、客戶和訂單目前位於 WooCommerce、Shopify 或 Magento — 或只是幾個 CSV 檔案 — 遷移工具會將這些資料帶入您的新 Spwig 商店，這樣您就不需要手動重新輸入。它處理分類、產品、客戶、訂單、評論和優惠券，對於 WooCommerce，它還可以遷移部落格內容，並透過橋接外掛程式遷移您的聯營計劃。

在管理員側邊欄中找到 **系統儀表板 > 資料導入/導出**（在自托管安裝中對超級用戶可見；如果您看不到它，請詢問管理您安裝的人員）。標題為 **資料導入與導出** 的頁面，會列出您啟動過的所有遷移，並有統計卡片顯示總遷移數、已完成、進行中和失敗的遷移，以及 **開始新遷移**、**查看日誌** 和 **欄位映射** 按鈕。遷移只能透過向導創建。

## 支援的平台

Spwig 可直接連接到三個平台，再加上純 CSV 檔案：

- **WooCommerce** — 最完整的路徑；擴充功能資料（訂閱、組合包、禮品卡、預訂）和您的聯營計劃也可以遷移過來。
- **Shopify** — 透過您在 Shopify 開發者儀表板中創建的自定義應用程式連接。
- **Magento 2** — 透過來自您 Magento 管理員的整合令牌連接。
- **CSV 檔案** — 五個獨立的檔案（產品、分類、客戶、訂單、評論），用於其他平台或手動準備的資料。

> **注意：** BigCommerce、PrestaShop、Squarespace 和 Wix 不支援直接連接。如果您要從這些平台遷移，請將您的目錄和客戶資料匯出為 CSV，並使用 CSV 路徑 — 請參閱 [從 CSV 檔案導入](csv-import)。

| 資料 | WooCommerce | Shopify | Magento 2 | CSV |
|---|---|---|---|---|
| 分類 | 支援，支援階層結構 | 支援，作為集合（扁平） | 支援 | 支援 |
| 產品 | 支援 | 支援 | 支援 | 支援（必填檔案） |
| 產品圖片 | 支援 | 支援 | 支援 | 不支援 |
| 變體 | 支援 | 支援 | 支援 | 不支援 |
| 顧客 + 地址 | 支援 | 支援 | 支援 | 支援 |
| 訂單 | 支援 | 支援，僅限最近 60 天，除非新增了 `read_all_orders` 權限 | 支援 | 支援 |
| 評論 | 支援 | 完全不支援 | 通常不可用 — Magento 社群版沒有針對評論的 REST 端點 | 支援 |
| 優惠券 / 折扣 | 支援 | 支援 | 支援 | 不支援 |
| 部落格 / CMS 內容 | 支援（文章、分類、標籤、圖片） | 支援（文章） | 支援（CMS 頁面） | 不支援 |
| 會員制度、佣金、付款 | 支援，需要 Spwig Migration Bridge 插件 | 不支援 | 不支援 | 不支援 |
| 自定義欄位偵測 | 支援 | 不支援 — Shopify 的 metafields 不會被讀取 | 不支援 | n/a |

Shopify 商家應計畫在導入後手動重新輸入任何 metafield 資料（自定義產品規格、額外顧客欄位），因為它不會被偵測或轉移。對於其他內容，請參閱 [Migration Field Mapping](migration-field-mapping) 了解來源欄位如何對應到 Spwig 欄位。

## 規劃您的遷移

- **在正式上線前進行遷移**，針對尚未處理實際流量的 Spwig 安裝進行，並在將域名的 DNS 指向它之前 — 這樣您可以在客戶看到尚未完成的目錄之前審查並修正問題。
- **在確認 Spwig 的複製正確之前，保持舊商店運行，僅限只讀**。
- **預留時間在遷移後設置稅務和運費** — 雖然向導的設置看起來會導入您的稅率和區域，但實際上並未套用（請參閱 [Migration Field Mapping](migration-field-mapping)）。

請自行配置 **Settings > Tax & Currency** 和 **Settings > Shipping**。
- **進行抽查而非略過** — 擴展資料的導入是盡最大努力進行的；一個無法讀取擴展資料的產品仍會被建立，只是缺少這些資料。

在向客戶宣布任何內容之前，請先查看 [遷移後的步驟](after-migration-review)。

## 前提條件

- **對來源平台的管理員訪問權限**，用於創建 API 凭證 — 在 WooCommerce 中創建 REST API 金鑰，在 Shopify 中創建自定義應用，在 Magento 中創建整合令牌。CSV 不需要。
- **只讀權限** — 在來源平台提供只讀權限的地方 — Spwig 只從您的舊商店讀取資料，從不寫回。
- **時間預算** — 每次運行有嚴格的 4 小時限制。對於大型商店，建議採用分階段的方法（先遷移類別和產品，後遷移訂單），而不是一次性完成。

> **重要提示：** Spwig 不會加密您在向導中輸入的 API 凭證。一旦遷移驗證完成，請在來源平台上撤銷或刪除該憑證。

## 遷移向導，逐步說明

向導共有六個步驟，步驟之間會保存進度：

1. **平台** — 選擇 WooCommerce、Shopify、Magento 或 CSV 導入。
2. **連接** — 輸入憑證，並有選項（預設啟用）先測試連接。平台特定的指南會詳細說明應生成的內容。
3. **預覽** — 來自來源商店的即時數字，前 5 個產品的樣本，以及用於包含哪些數據類型的複選框，以及批次大小等選項。
4. **映射** — 來源欄位如何映射到 Spwig 欄位，任何 WooCommerce 自定義欄位，以及沒有明顯匹配的類別。詳細資訊請見 [遷移欄位映射](migration-field-mapping)。
5. **導入** — 在後台運行；您可以關閉標籤頁，它會繼續運行，並提供即時日誌。
6. **完成** — 結果摘要，一個用於重寫內容中引用舊域名的連結工具，以及 PDF/CSV 報告的下載選項。

## 遷移後

成功的導入並不是終點 — 請查看 [遷移後的步驟](after-migration-review)，以獲得完整的檢查清單，涵蓋數據驗證、修復仍然指向舊域名的內部連結，以及向導無法為您處理的稅務和運輸配置。

## 回滾不是萬能的安全網

在開始之前就應該了解這一點，而不是等到出了問題才後悔。回滾功能確實存在，但它並不像聽起來那樣是一個簡單的「取消」按鈕：

- 如果導入過程部分失敗，不會自動回滾。失敗前導入的內容會保留在您的商店中，而且無法從管理介面回滾失敗的導入——您需要手動審查並清理部分數據。
- 已完成的遷移可以回滾，回滾只會刪除導入本身建立的內容——絕不會更多。一位已遷移的客戶，如果自導入之後下過真實訂單，其帳戶、地址、忠誠度歷史和商店購物金都會被保留，而那筆真實訂單不會被觸動；只有導入建立的訂單才會被刪除。仍被任何訂單、組合包、禮品卡或配置器插槽引用的已遷移產品同樣會被保留，而屬於其他客戶的訂單永遠不會被修改。
- 導入建立的聯盟、佣金和付款會被刪除，導入建立的任何聯盟帳戶也會一併刪除——附屬於原本已存在客戶的聯盟，會保留該客戶的帳戶，只刪除聯盟記錄本身。由商店擴充功能建立的訂閱方案、定價層級或預訂資源仍然不會被刪除——這些需要您手動清理。
- 在您確認之前，Spwig 會顯示一份預覽，準確列出將被刪除和將被保留的內容，依名稱和數量列出，並說明原因——這是根據您的即時資料計算得出的。請在確認之前閱讀它。之後回滾會在後台執行，因此關閉標籤頁是安全的；完成後請查看遷移摘要以取得報告。
- 回滾對它確實刪除的資料列仍然是一項永久且具破壞性的操作，因此請謹慎使用——並手動清理任何 Spwig 保留下來但您實際上不想要的內容。但由於它不再波及導入建立範圍之外的內容，它不再像以前那樣只是一個當天使用的工具。
- 只要任務記錄存在，回滾按鈕就會一直保留在已完成遷移的摘要頁面上，如果一次回滾嘗試本身中途失敗，該按鈕會再次提供，讓您可以重試。記錄不會按照任何排程被移除，因此這不會自行到期。

如果您遇到遷移失敗或卡住的情況，[遷移問題排除](migration-troubleshooting) 將涵蓋重試、取消和查看日誌的方法。

## 小技巧

- **從小範圍的測試運行開始** — 在完整目錄遷移之前，遷移類別加上幾個產品可以確認欄位映射是否正確。
- **先閱讀特定平台的指南** — [從 WooCommerce 迁移](migrate-from-woocommerce)、[從 Shopify 迁移](migrate-from-shopify) 和 [從 Magento 迁移](migrate-from-magento) 說明了您需要的確切憑證和範圍。
- **不要跳過上面的能力矩陣** — 知道 Shopify 審核或 CSV 變體不會傳輸，可以在切換 DNS 後節省驚訝。
- **在另一個標籤頁中保持來源平台的管理介面開啟**，以便在進行過程中生成或複製憑證。
- **字面上對待向導的複選框** — 如果某個設定未在此處說明為可用，請直接在 Spwig 中進行設定，而不是信任向導。
