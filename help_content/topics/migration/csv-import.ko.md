---
title: CSV 파일에서 가져오기
---

CSV 가져오는 것은 Spwig이 직접 연결하지 않는 모든 가게에 대한 대체 마이그레이션 경로입니다. BigCommerce, PrestaShop, Squarespace, Wix, 수작업으로 유지한 스프레드시트, 또는 Spwig이 이해하지 못하는 API가 없는 맞춤형 시스템에서 오셨다면, 이곳이 바로 도착하는 곳입니다 — 라이브 연결 대신 CSV 파일로 데이터를 내보내고 여기에 업로드하세요.

이 가이드는 CSV를 사용해야 하는 경우, CSV가 전달하지 못하는 내용, 관여된 5개의 파일, 어떻게 준비할지, 그리고 열 매핑이 어떻게 작동하는지 다룹니다.

## API 연결 대신 CSV를 사용해야 하는 경우

Spwig은 WooCommerce, Shopify, Magento 2/Adobe Commerce에 직접 연결합니다 — 이에 대한 내용은 [데이터 마이그레이션 개요](migration-overview)를 참조하세요. 다른 플랫폼이라면 CSV가 유일한 선택지입니다; BigCommerce, PrestaShop, Squarespace, 또는 Wix에 대한 직접 통합은 없습니다. 또한 스프레드시트에서 데이터를 통합하고자 하거나, 맞춤형 가게를 폐쇄하거나, 파일을 직접 정리하여 정확히 무엇이 가져와지는지 제어하고 싶다면 CSV가 적절한 선택입니다.

## CSV가 할 수 없는 것

아무것도 준비하기 전에, 이 경로가 남겨두는 것을 알아야 합니다 — 이는 CSV 가져오기를 사용하는 상인들에게 가장 큰 놀라움의 원천입니다:

- **제품 이미지 없음.** 제품은 이미지가 첨부되지 않은 상태로 가져옵니다. 이후에 이미지를 업로드하세요.
- **변형 없음.** 모든 제품은 단순 제품으로 생성됩니다. 가져오기 후 Spwig에서 크기/색상/스타일 구조를 다시 구축해야 합니다.
- **쿠폰 없음.** 할인 코드 및 프로모션은 CSV 형식에 포함되지 않습니다.
- **블로그 콘텐츠 없음.** 게시물이나 기사에 대한 CSV 파일은 없습니다.

이 모든 것이 가져오기를 방해하지는 않지만, 제품이 Spwig에 도달한 후 추가 작업이 필요하다는 의미입니다. 가져오기 후 전체 확인 목록은 [마이그레이션 후](after-migration-review)에서 확인하세요.

## 다섯 개의 파일

마법사의 CSV 단계는 다섯 개의 파일 입력을 제공하며, 각각에 **템플릿 다운로드** 버튼이 있습니다. 파일을 처음부터 만드는 대신 이러한 템플릿에서 시작하세요 — 이는 올바른 열 이름을 보장하고 단계 4에서 자동 감지가 더 많은 작업을 수행할 수 있도록 합니다.

| 파일 | 필수? |
|---|---|
| 제품 | **필수** |
| 카테고리 | 선택 |
| 고객 | 선택 |
| 주문 | 선택 |
| 리뷰 | 선택 |

제품은 Spwig에서 필수로 요구하는 유일한 파일입니다 — 나머지는 아직 해당 데이터가 없으면 비워둘 수 있습니다.

### 제품 (필수)

| 열 | 설명 |
|---|---|
| `id` | 원본 데이터에서의 고유 식별자; 고객에게 표시되지 않습니다. |
| `name` | 제품 제목. **필수입니다.** |
| `slug` | 이름의 URL 친화 버전; 빈 경우 `name`에서 자동 생성됩니다. |
| `description` | 판매처에 표시되는 설명. |
| `price` | 제품의 정상 가격. **필수입니다.** |
| `sku` | 재고 관리 단위 — **기존 항목 건너뛰기**가 활성화된 경우 일치시킬 때 사용됩니다. |
| `stock_quantity` | 현재 재고 수량. |
| `category` | 이 제품이 속한 카테고리 이름. 카테고리 파일의 `name`과 일치해야 합니다. |

### 카테고리

| 열 | 설명 |
|---|---|
| `id` | 원본 데이터에서의 고유 식별자. |
| `name` | 카테고리 이름. **필수입니다.** |
| `slug` | 이름의 URL 친화 버전; 빈 경우 자동 생성됩니다. |
| `description` | 카테고리 설명 텍스트. |
| `parent_id` | 이 카테고리의 부모의 `id`. 빈 경우 최상위 카테고리입니다. |

### 고객

| 열 | 설명 |
|---|---|
| `id` | 원본 데이터에서의 고유 식별자. |
| `email` | 고객의 이메일 주소. **필수** — 주문과 리뷰를 올바른 고객과 연결합니다. |
| `first_name` | 고객의 이름. |
| `last_name` | 고객의 성. |
| `phone` | 고객의 전화 번호. |

### 주문


| 컬럼 | 설명 |
|---|---|
| `id` | 원본 데이터에서의 고유 식별자입니다. |
| `customer_email` | 주문을 한 고객의 이메일입니다. **필수** — 주문을 고객 기록과 연결합니다. |
| `order_date` | 주문이 이루어진 날짜입니다. |
| `status` | 주문 상태 (예: 완료, 처리 중). |
| `total` | 주문 총액입니다. **필수입니다.** |
| `currency` | 주문 총액의 통화 코드입니다. |

### 리뷰 (선택)

| 컬럼 | 설명 |
|---|---|
| `id` | 원본 데이터에서의 고유 식별자입니다. |
| `product_id` | 리뷰 대상 제품의 `id`로, 제품 파일에 있는 값과 일치해야 합니다. **필수** — 리뷰를 올바른 제품과 연결합니다. |
| `customer_email` | 리뷰자의 이메일 주소입니다. |
| `rating` | 제공된 별점입니다. |
| `comment` | 리뷰 텍스트입니다. |
| `date` | 리뷰가 게시된 날짜입니다. |

## 파일 준비

- **UTF-8로 저장**하여, 다른 원본 인코딩에서 특수 문자가 깨지는 것을 방지하세요.
- **콤마가 포함된 필드를 따옴표로 묶으세요** — 설명이나 이름에 콤마가 포함된 경우, 이중 따옴표로 감싸서 열 분리로 오해되지 않도록 하세요.
- **헤더 행을 포함하세요.** 첫 번째 행에는 컬럼 이름이 포함되어야 합니다 — 헤더 행이 없는 파일은 거부됩니다.
- **`parent_id`를 사용하여 카테고리 계층 구조를 생성하세요.** 각 카테고리에 고유한 `id`를 부여하고, 하위 카테고리의 `parent_id`를 상위 카테고리의 `id`로 설정하세요. 공백은 최상위 수준을 의미합니다.
- **`customer_email`을 사용하여 주문을 고객과 연결하세요**, 고객 파일의 `email` 열과 일치시키면 (또는 게스트 기록이 생성됨), 플랫폼 간에 거의 일치하지 않는 내부 ID 번호에 의존하지 마세요.
- **`product_id`를 사용하여 리뷰를 제품과 연결하세요**, 제품 파일의 `id` 열에 있는 값과 일치시키면, 그렇지 않으면 해당 리뷰는 건너뜁니다.

## 단계 4에서 컬럼 매핑

단계 4에서는 CSV 컬럼 매핑 패널을 보여줍니다.

Spwig은 헤더를 스캔하여 일반적인 별칭 목록과 자동으로 일치하는 항목을 감지합니다. 예를 들어, `sku` 필드는 `barcode`, `part_number`, 또는 `item_number`와도 일치할 수 있습니다.

다른 플랫폼에서 직접 내보낸 헤더는 수동 작업 없이도 올바르게 매핑되는 경우가 많습니다.

각 열에 대해 자동 감지된 추측을 수락하거나, 다른 대상 필드를 선택하여 덮어쓸 수 있고, 또는 이 열을 제외하려면 "— 이 열 건너뛰기 —"를 선택할 수도 있습니다. 매핑은 이후 CSV 마이그레이션에서 저장되어 재사용됩니다. 단계 4에 대한 전체적인 내용, 자동 필드 매핑, 카테고리 매핑 및 세금/배송 옵션에 대해 [Migration Field Mapping](migration-field-mapping)을 참조하십시오.

## 일반적인 오류 및 의미

| 오류 | 의미 |
|---|---|
| `Products CSV is required.` | 제품 파일을 업로드하지 않고 진행하려 했습니다. Spwig이 요구하는 유일한 파일은 제품 파일입니다. 하나 업로드하여 계속하십시오. |
| `{Type} CSV has no headers.` | 해당 파일의 첫 번째 행이 비어 있거나 누락되었습니다. 열 이름을 포함한 헤더 행을 추가하고 다시 업로드하십시오. |
| `{Type} CSV could not be read: ...` | Spwig이 해당 파일을 해석할 수 없습니다. 일반적으로 손상된 파일, 잘못된 인코딩, 또는 확장자가 CSV이지만 실제로 CSV가 아닌 파일 때문입니다. 다시 내보내고 업로드하기 전에 파일이 깨끗하게 열리는지 확인하십시오. |

## 임포트 실행

매핑이 확인되면 단계 5에서 마이그레이션을 시작하십시오. 이 작업은 백그라운드에서 실행되므로 창을 닫을 수 있습니다. 완료되기 전에 다시 확인하면 진행 상황과 실시간 로그를 확인할 수 있습니다. 결과를 확인하려면 [After Your Migration](after-migration-review)을 참조하십시오.

CSV 임포트는 특히 **제품 이미지**와 **변형**(variants)을 수작업으로 완료해야 하므로 자동으로 전달되지 않습니다. 파일이 얼마나 완전하든 간에 이 두 항목은 자동으로 처리되지 않습니다.

## 팁

- **파일마다 "다운로드 템플릿" 버튼부터 시작하세요** — 이는 수동 매핑으로 이어질 수 있는 열 이름 오타를 피하게 해줍니다.
- **리뷰 업로드 전에 `product_id` 불일치를 수정하세요** — `product_id`가 어떤 제품의 `id`와도 일치하지 않는 리뷰는 첨부할 수 있는 대상이 없어 스킵됩니다.
- **다른 플랫폼의 내보내기에서 헤더를 이름을 바꾸지 마세요** — 자동 감지 기능은 일반적으로 별도의 별칭을 통해 그대로 인식하므로 수동 매핑이 전혀 필요할 수 있습니다.
- **임포트 직후 이미지와 변형을 위해 시간을 따로 확보하세요** — 이 두 항목은 CSV가 전달하지 않으며, 고객이 제품 페이지가 비어 있는 것을 발견하기 전까지 쉽게 잊혀질 수 있습니다.
- **`parent_id`를 사용하여 다단계 카테고리를 모델링하세요** — 하위 카테고리의 `parent_id`를 상위 카테고리의 `id`로 지정하여 중첩할 수 있습니다. 최상위 카테고리는 `parent_id`를 비워 두세요.
- **"읽을 수 없음" 오류 발생 시 재내보내기 및 재확인을 수행하세요** — 이는 거의 대부분 원본 파일의 인코딩 또는 손상 문제이며, Spwig에서 수정할 필요는 없습니다.
