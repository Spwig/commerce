---
title: Импорт из CSV-файлов
---

Импорт из CSV-файлов является альтернативным способом миграции для любого магазина, к которому Spwig не подключается напрямую. Если вы пришли с BigCommerce, PrestaShop, Squarespace, Wix, вручную поддерживаемой таблицы или собственной системы без API, понятного Spwig, вы попадете сюда — экспортируйте свои данные в CSV-файлы и загрузите их здесь вместо прямого подключения.

Этот руководство охватывает, когда использовать CSV вместо подключения через API, что он не может передать, пять файлов, участвующих в процессе, как их подготовить и как работает сопоставление столбцов.

## Когда использовать CSV вместо подключения через API

Spwig напрямую подключается к WooCommerce, Shopify и Magento 2/Adobe Commerce — см. [Обзор миграции данных](migration-overview) для этих платформ. Для любой другой платформы CSV — ваш единственный вариант; нет прямого интеграции с BigCommerce, PrestaShop, Squarespace или Wix. Это также правильный выбор, если вы объединяете данные из таблицы, выводите пользовательский магазин или хотите контролировать, что именно будет импортировано, самостоятельно курируя файлы.

## Что CSV не может сделать

Перед подготовкой чего-либо узнайте, что этот способ оставляет позади — это самый большой источник неожиданностей для продавцов, использующих импорт через CSV:

- **Нет изображений товаров.** Товары импортируются без прикрепленных изображений; загрузите их позже.
- **Нет вариантов.** Каждый товар создается как простой товар. Перестройте структуры размера/цвета/стиля в Spwig после импорта.
- **Нет купонов.** Коды скидок и акции не являются частью формата CSV.
- **Нет контента блога.** Нет CSV-файла для постов или статей.

Ничто из этого не блокирует импорт — это просто означает, что товары потребуют дополнительной работы после их загрузки в Spwig. См. [После миграции](after-migration-review) для полного списка проверок после импорта.

## Пять файлов

Шаг CSV-файла мастера предлагает пять полей ввода файлов, каждый с кнопкой **Скачать шаблон**. Начните с этих шаблонов вместо создания файлов с нуля — они гарантируют правильные названия столбцов и позволяют автоматическому обнаружению сделать больше работы на шаге 4.

| Файл | Обязательно? |
|---|---|
| Товары | **Обязательно** |
| Категории | Необязательно |
| Клиенты | Необязательно |
| Заказы | Необязательно |
| Отзывы | Необязательно |

Только файл **Товары** является обязательным для Spwig — остальные можно оставить пустыми, если у вас еще нет этой информации.

### Товары (Обязательно)

| Столбец | Описание |
|---|---|
| `id` | Уникальный идентификатор в вашем исходных данных; не отображается клиентам. |
| `name` | Название товара. **Обязательно.** |
| `slug` | URL-дружественная версия названия; автоматически генерируется из `name`, если оно пустое. |
| `description` | Описание, отображаемое на сайте. |
| `price` | Регулярная цена товара. **Обязательно.** |
| `sku` | Учетная единица запаса — используется для сопоставления, когда включено **Пропустить существующие товары**. |
| `stock_quantity` | Единицы товара, доступные на складе. |
| `category` | Название категории, к которой относится товар. Должно совпадать с `name` в вашем файле категорий. |

### Категории

| Столбец | Описание |
|---|---|
| `id` | Уникальный идентификатор в вашем исходных данных. |
| `name` | Название категории. **Обязательно.** |
| `slug` | URL-дружественная версия названия; автоматически генерируется, если оно пустое. |
| `description` | Текст описания категории. |
| `parent_id` | `id` родительской категории. Пустое значение означает, что это категория верхнего уровня. |

### Клиенты

| Столбец | Описание |
|---|---|
| `id` | Уникальный идентификатор в вашем исходных данных. |
| `email` | Электронная почта клиента. **Обязательно** — связывает заказы и отзывы с правильным клиентом. |
| `first_name` | Имя клиента. |
| `last_name` | Фамилия клиента. |
| `phone` | Номер телефона клиента. |

### Заказы

Сохраните все форматирование markdown, пути к изображениям, блоки кода и технические термины.

| Column | Description |
|---|---|
| `id` | Уникальный идентификатор в вашем исходных данных. |
| `customer_email` | Электронная почта клиента, который сделал заказ. **Обязательно** — связывает заказ с записью клиента. |
| `order_date` | Дата, когда был сделан заказ. |
| `status` | Статус заказа (например, завершен, обработка). |
| `total` | Общая сумма заказа. **Обязательно.** |
| `currency` | Код валюты для общей суммы заказа. |

### Отзывы (Необязательно)

| Column | Description |
|---|---|
| `id` | Уникальный идентификатор в вашем исходных данных. |
| `product_id` | `id` продукта, который оценивается, совпадающий с вашим файлом продуктов. **Обязательно** — связывает отзыв с правильным продуктом. |
| `customer_email` | Электронная почта автора отзыва. |
| `rating` | Оценка в виде звезд. |
| `comment` | Текст отзыва. |
| `date` | Дата публикации отзыва. |

## Подготовка файлов

- **Сохраните как UTF-8**, чтобы избежать искаженных символов с ударением, особенно если данные были в другом кодировке.
- **Заключите в кавычки поля, содержащие запятые** — оберните описание или имя, содержащее запятую, в двойные кавычки, чтобы оно не было неправильно интерпретировано как разделение столбцов.
- **Включите строку заголовка.** Первая строка должна содержать названия ваших столбцов — файл без строки заголовка будет отклонен.
- **Постройте иерархию категорий с помощью `parent_id`.** Назначьте каждому категория уникальный `id`, а затем установите `parent_id` подкатегории как `id` ее родительской категории. Пустое значение означает верхний уровень.
- **Свяжите заказы с клиентами через `customer_email`**, сопоставляя его с колонкой `email` в вашем файле клиентов (или будет создан гостевой аккаунт), вместо того чтобы полагаться на внутренние идентификаторы, которые редко совпадают между платформами.
- **Свяжите отзывы с продуктами через `product_id`**, сопоставляя его со значением в колонке `id` вашего файла продуктов, иначе отзыв будет пропущен.

## Сопоставление столбцов на шаге 4

Шаг 4 показывает панель сопоставления столбцов CSV. Spwig сканирует ваши заголовки и автоматически определяет вероятные совпадения из списка распространенных псевдонимов — например, поле `sku` также соответствует `barcode`, `part_number` или `item_number`. Заголовки, экспортированные напрямую с другой платформы, часто сопоставляются правильно без вмешательства.

Для каждого столбца вы можете принять автоматически обнаруженное предположение, изменить его, выбрав другое поле назначения, или выбрать «— Пропустить этот столбец —», чтобы исключить его. Сопоставления сохраняются и повторно используются при будущих CSV-миграциях. См. [Сопоставление полей миграции](migration-field-mapping), чтобы получить полное представление о шаге 4, включая автоматическое сопоставление полей, сопоставление категорий и настройки налогов/доставки.

## Распространенные ошибки и что они означают

| Ошибка | Значение |
|---|---|
| `Products CSV is required.` | Вы попытались продолжить без загрузки файла продуктов. Это единственный файл, который требует Spwig — загрузите его, чтобы продолжить. |
| `{Type} CSV has no headers.` | Первая строка указанного файла пуста или отсутствует. Добавьте строку заголовка с названиями столбцов и загрузите файл заново. |
| `{Type} CSV could not be read: ...` | Spwig не смог распарсить указанный файл — обычно поврежденный файл, неправильная кодировка или файл, который на самом деле не является CSV, несмотря на расширение. Пересоздайте его и убедитесь, что он открывается без ошибок, прежде чем загружать снова. |

## Запуск импорта

После подтверждения сопоставления запустите миграцию со шага 5. Она выполняется в фоновом режиме, поэтому вы можете закрыть окно — прогресс и живой журнал доступны, если вы вернетесь до завершения. См. [После вашей миграции](after-migration-review), чтобы проверить результаты.

Помните, что импорт CSV специально оставляет **изображения продуктов** и **варианты** для вас, чтобы завершить вручную — ни одно из них не передается автоматически, независимо от того, насколько полными были ваши файлы.

## Советы

Сохраните всю разметку Markdown, пути к изображениям, блоки кода и технические термины.

- **Начните с кнопки "Скачать шаблон" для каждого файла** — это избавит вас от поиска опечаток в названиях столбцов, которые в противном случае пройдут мимо и потребуют ручного сопоставления.
- **Исправьте несоответствия `product_id` перед загрузкой отзывов** — отзыв, у которого `product_id` не совпадает с `id` любого продукта, не имеет к чему привязаться и будет пропущен.
- **Не переименовывайте заголовки из экспорта другого платформы** — автоматическое распознавание часто определяет их такими, какие они есть, через псевдонимы, поэтому сопоставление может вообще не требовать ручной работы.
- **Отведите время для изображений и вариантов сразу после импорта** — эти два элемента никогда не передаются через CSV, и их легко забыть, пока клиент не заметит пустую страницу продукта.
- **Используйте `parent_id`, чтобы моделировать многоуровневые категории** — укажите `parent_id` подкатегории на `id` её родительской категории, чтобы вложить её; оставьте это поле пустым для категорий верхнего уровня.
- **Снова экспортируйте и проверьте при ошибке "could not be read"** — это почти всегда связано с кодировкой или повреждением исходного файла, а не с чем-то, что нужно исправлять в Spwig.
