Spwig POS 是一個進步式網頁應用程式 (PWA)。它完全在瀏覽器中運行，可以像原生應用程式一樣安裝到設備的首頁。由於應用程式、您的產品目錄和最近的訂單歷史會在設備上本地緩存，因此即使在網路中斷或連線速度較慢的情況下，您的收銀機仍能繼續運作。

本主題將說明當連線中斷時哪些功能仍然可用，連線恢復後如何處理已排隊的銷售，如何將 POS 安裝到設備的首頁，以及更新如何傳送到已安裝的設備。

## 離線模式的工作方式

當您在設備上首次開啟 POS 時，瀏覽器會下載並緩存整個應用程式 — 其介面、圖片和所有支援程式碼。一個稱為 Service Worker 的背景組件會管理這個緩存。從此之後，即使伺服器無法連線，應用程式也會從本地緩存載入。

除了應用程式緩存之外，POS 會在設備上維護一個本地資料庫（使用瀏覽器內建的 IndexedDB 儲存）。這個資料庫包含：

- **產品和變體** — 從您的目錄同步，並在線時每五分鐘更新一次
- **分類** — 啟動時同步，並與產品一起更新
- **庫存數量** — 在線時每兩分鐘同步一次（使用一種網路優先策略，如果伺服器在三秒內沒有回應，則會回退到緩存的數據）
- **客戶記錄** — 最多1,000位最近的客戶
- **訂單歷史** — 可設定數量的最近POS訂單（預設：14天內500筆訂單；可在 **POS > POS終端機** 中按終端機設定）
- **產品圖片** — 最多緩存本地24小時

當POS檢測到設備已離線時，螢幕頂部會出現一個橫幅：**"離線模式 - 連線恢復後銷售將會同步。"** 收銀機將繼續使用本地緩存的數據進行操作。

## 什麼功能可以在離線時使用

| 功能 | 离线可用性 |
|---------|---------------------|
| 产品搜索和浏览 | 可用 — 使用本地缓存的目录 |
| 条形码扫描 | 可用 — 扫描会在本地缓存中查找产品 |
| 将商品添加到购物车 | 可用 |
| 应用手动折扣 | 可用 |
| 应用优惠码 | 不可用 — 余额检查需要实时连接 |
| 现金支付 | 可用 — 本地记录并排队等待同步 |
| 卡支付（手动输入） | 可用 — 收银员在独立终端上处理并输入参考信息；本地记录并排队等待同步 |
| 卡支付（集成读卡器 — Stripe Terminal 等） | 不可用 — 集成的卡读卡器会实时与支付网络通信 |
| 礼品卡支付 | 不可用 — 余额查询需要实时连接 |
| 组合现金和手动卡的分账支付 | 可用 |
| 打印到网络打印机的收据 | 如果打印机与设备在同一本地网络中则可用 — 打印不需要互联网访问，只需本地网络连接 |
| 数字收据（电子邮件/SMS/WhatsApp） | 不可用 — 发送需要实时连接 |
| 浏览订单历史 | 可用 — 显示缓存的订单，并带有横幅提示您正在查看离线数据 |
| 退款和作废 | 不可用 — 这些操作需要实时连接 |
| 客户忠诚度积分查询 | 不可用 |
| 开启和关闭班次 | 可用 — 班次状态存储在本地 |

## 当连接恢复时的排队销售和同步

离线销售不会丢失。当收银机无法连接到服务器时，每笔完成的销售都会写入本地队列（设备本地数据库中的 `pendingTransactions` 存储）。销售包括所有购物车商品、数量、价格、支付方式以及完成时间。

当网络恢复时，POS 会自动：

1.

检测到通过浏览器的 `online` 事件重新连接
2.

保留所有Markdown格式、图片路径、代码块和专业术语。

顯示橫幅：**"正在同步 N 個待處理交易..."**
3.

按順序將排隊的銷售資料傳送至後端，如果首次嘗試失敗，將使用指數退避重試機制（最多每嘗試一次最多五分鐘，總共重試 10 次）
4.

一旦後端確認銷售資料，就會將每個銷售標記為已同步

**重複銷售保護** — 每個排隊的銷售資料在離開設備前都會被分配一個唯一的本地 ID。後端在創建訂單前會檢查這個 ID。如果相同的銷售資料被提交兩次（例如，因為重試與首次成功嘗試重疊），後端會忽略重複的資料。您永遠不會出現重複計數的銷售資料。

**衝突檢測** — 在極少數情況下，後端可能會將排隊的銷售資料標記為衝突（例如，設備離線時伺服器端刪除了產品）。衝突的銷售資料會出現在 **POS > 設定 > 待處理交易** 中，您可以手動審查並解決它們。

**離線庫存調整** 以相同方式處理：在離線時進行的庫存更改會被排隊，並在連線恢復時重播。設備上的本地庫存數字會立即更新，因此收銀員可以看到準確（估計）的數量。

## 將 POS 安裝到設備主畫面

將 POS 安裝到主畫面可以讓您獲得全螢幕體驗，沒有瀏覽器地址列，設備上會有捷徑圖示，並能更快啟動。

### iPad (Safari)

1. 打開 Safari 並導覽到您商店的 POS URL：`https://yourstore.com/pos/`
2. 登入並完成初始配對（如果是新設備）。
3. 點擊 Safari 工具列中的 **分享** 按鈕（帶有向上的箭頭方塊）。
4. 在分享面板中向下滾動並點擊 **加入主畫面**。
5. 如果您喜歡，可以編輯名稱（預設為 "Spwig POS"），然後點擊 **加入**。

POS 圖示現在會出現在您的 iPad 主畫面上。點擊它會以全螢幕模式打開應用程式，而無需 Safari 的瀏覽器介面。

> **注意：** 需要使用 iPad 上的 Safari 瀏覽器才能使用「加入主畫面」選項。

iOS 上的第三方瀏覽器（如 Chrome、Firefox）截至 2025 年中仍不支援 PWA 安裝。

### Android（Chrome）

1. 打開 Chrome，並導覽至您商店的 POS 網址：`https://yourstore.com/pos/`
2. 登入並在需要時完成配對。
3. 點擊右上角的 **三個點選單**，然後點擊 **安裝應用程式**（或較舊版本 Chrome 的 **加入主畫面**）。
4. 點擊 **安裝** 以確認。

POS 圖示會出現在主畫面和應用程式抽屜中。從圖示啟動會以獨立模式開啟應用程式。

### 桌面（Chrome 或 Edge）

1. 在 Chrome 或 Edge 中導覽至您商店的 POS 網址。
2. 在瀏覽器的地址列中尋找 **安裝圖示**（根據版本，可能是顯示電腦螢幕與向下箭頭的圖示，或是一個「+」圖示）。
3. 或者，打開 **三個點選單**，並選擇 **安裝 Spwig POS**（Chrome）或 **應用程式 > 將此網站安裝為應用程式**（Edge）。
4. 確認安裝。

POS 會以獨立視窗開啟，不帶瀏覽器標籤或地址列。它會出現在您系統的應用程式清單中，並可以固定在工作列上。

## 應用程式如何更新

POS 透過 Service Worker 管理自己的更新。您不需要訪問應用程式商店或手動下載任何東西。

**更新週期：**

1. 每次您開啟 POS（或標籤頁在背景中被啟動後），Service Worker 會檢查伺服器是否有新版本。
2. 如果有新版本可用，Service Worker 會在背景中下載它，而您繼續工作時不會中斷目前的會話。
3. 更新會在您下次開啟 POS 時生效。如果應用程式已經開啟且有待同步的資料，POS 會等到佇列清空後才通知您可以重新載入，以避免在尚未同步的銷售資料中中斷當前的班次。

**當銷售處於待處理狀態時，"重新載入" 的含義** — 如果看到提示需要重新載入以更新，且您有待處理的離線銷售，請在重新載入前先正確結束當前班次（或等待同步橫幅消失）。

在銷售處於隊列狀態時重新載入不會刪除它們 — 它們仍會保留在本地資料庫中 — 但先進行同步會更安全，以確認它們已成功接收。

**檢查已安裝的版本** — 打開 POS，點擊 **菜單圖示**（三條水平線），然後前往 **設定**。目前的構建版本會顯示在設定面板的底部。

## 儲存空間與清除安裝

POS 會在本地儲存幾種類型的資料：

| 什麼 | 典型大小 |
|------|-------------|
| 應用程式殼層（HTML、CSS、JS、圖示） | ~3–5 MB |
| 產品目錄（文字和元資料） | 依目錄大小而定，1–10 MB |
| 產品圖片（快取） | 依目錄大小而定，5–50 MB |
| 訂單歷史 | 1–5 MB（500 個訂單） |
| 顧客記錄 | 1–3 MB（1,000 位顧客） |
| 待處理交易佇列 | 最小；同步時清除 |

**如果設備儲存空間不足** — 當設備儲存空間滿時，瀏覽器會對快取儲存施加壓力。POS 會在瀏覽器允許的情況下將其快取設為持久化，但在設備非常滿的情況下，瀏覽器可能會先清除產品圖片。如果圖片停止加載，POS 會在下次同步時重新快取它們。已同步的銷售和應用程式殼層不會受到影響。

**重置安裝** — 如果 POS 的行為異常（卡在舊版本、目錄未更新、同步永久卡住），您可以執行清潔重置：

1. **卸載應用程式** — 在行動裝置上，長按 POS 圖示並選擇 **移除** 或 **卸載**。

在桌面端，右鍵點擊應用程式視窗的標題列，並選擇 **卸載**。
2.

直接在瀏覽器中打開 POS URL 並重新登入。
3.

設備會再次要求輸入終端機的 8 個字元配對碼。


你可以在管理后台的 **POS > POS 端點** 中找到或重新生成此代碼 — 打開終端機並點擊 **重新生成配對碼**。
4.

一個新的配對會強制重新同步所有緩存的數據。

> **重置後**：任何在重置前已排隊但尚未同步的離線銷售將會遺失，因為本地數據庫已被清除。在重置安裝之前，請確保連接已恢復且同步橫幅已清除。

## 故障排除

### POS 無法更新到最新版本

服務工作人員可能尚未激活新版本。請嘗試關閉所有打開 POS 的瀏覽器標籤，然後重新打開 POS。如果問題仍然存在，請按照上述說明重置安裝。

### "無連線" 標語無法清除

請確認設備在 POS 之外有互聯網連接（嘗試加載另一個網站）。如果設備在線但標語仍然存在：

- POS 服務器可能臨時無法連接 — 等待一分鐘，POS 會自動重試。
- 如果你處於需要登錄頁面的網絡（ captive portal），請打開一個新的瀏覽器標籤，完成登錄，然後返回 POS。

### POS 中缺少了管理后台中存在的產品

POS 在線時每五分鐘同步一次產品。如果你剛在管理后台添加了一個產品，請點擊 **菜單圖標**，前往 **設定 > 立即同步** 以觸發即時同步。如果產品仍然沒有出現，請確認它已被標記為 **啟用**，且在產品設置中未被排除在 POS 可用性之外。

### 挂起的交易卡在 "衝突" 狀態

前往 **POS > 設定**（在 POS 應用程式本身中），並查看 **掛起交易** 面板。衝突交易通常是由於在離線銷售和同步之間產品或價格發生了變化所導致。你可以查看銷售詳情，如果銷售已正確接收，可以標記為已審核。

## 小技巧

保留所有 markdown 格式、圖片路徑、程式碼區塊和技術術語。

- 在專用設備上執行 POS，該設備需持續連接到本地 Wi-Fi。

短暫的 Wi-Fi 中斷會自動處理，但若設備長時間處於離線狀態，則在重新連接後需要更多時間來重新同步。
- 同步間隔是按設備設定的。

如果您有多個終端機，每個終端機都會獨立同步。

在一個終端機上完成的銷售會在同步後立即出現在管理介面中，但其他終端機的本地訂單緩存只會在其自己的同步週期中更新。
- 在計劃中的網路中斷（例如，移動到沒有 Wi-Fi 的活動場地）之前，請在仍連接網路時打開 POS，以確保目錄和庫存資料完全更新。

現金交易會可靠地排隊；只需在重新上線之前避免使用整合式信用卡支付。
- 如果您在活動中只需要現金交易，手動信用卡支付方式（ cashier 在獨立終端機上處理並輸入參考編號）也可以在離線狀態下進行信用卡交易。
- 在長時間的工作班次中，請保持設備連接電源 — 本地資料庫和同步過程與螢幕相比對電池的影響不大，但充滿電的設備在交易時總是更安全。
