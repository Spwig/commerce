Spwig POS 是一个渐进式网络应用（PWA）。它完全在浏览器中运行，并可以像原生应用一样安装到设备的主屏幕。由于应用、您的产品目录和最近的订单历史记录在设备上本地缓存，因此即使在网络中断或连接速度较慢的情况下，您的收银机仍可继续工作。

本主题将详细说明当连接中断时哪些功能仍然可用，连接恢复后如何处理已排队的销售，如何将 POS 安装到设备的主屏幕，以及更新如何传达给已安装的设备。

## 离线模式的工作原理

当您第一次在设备上打开 POS 时，浏览器会下载并缓存整个应用 —— 其界面、图片和所有支持代码。一个名为 Service Worker 的后台组件管理此缓存。从那时起，即使服务器无法访问，应用也会从本地缓存加载。

除了应用缓存之外，POS 还在设备上维护一个本地数据库（使用浏览器内置的 IndexedDB 存储）。此数据库包含：

- **产品和变体** — 从您的商品目录中同步，并在联网时每五分钟刷新一次
- **分类** — 在启动时同步，并与产品一起刷新
- **库存水平** — 在联网时每两分钟同步（使用一种网络优先的策略，如果服务器在三秒内未响应，则回退到缓存数据）
- **客户记录** — 最多1,000位最近的客户
- **订单历史** — 可配置数量的最近POS订单（默认：14天内500笔订单；在 **POS > POS终端** 中按终端设置）
- **产品图片** — 本地缓存最多24小时

当POS检测到设备已离线时，屏幕顶部会出现一条横幅：**"离线模式 - 连接恢复后销售记录将被同步。"** 收银机将继续使用本地缓存的数据进行操作。

## 离线时可使用的功能

| 功能 | 离线可用性 |
|---------|---------------------|
| 产品搜索和浏览 | 可用 — 使用本地缓存的目录 |
| 条形码扫描 | 可用 — 扫描会在本地缓存中查找产品 |
| 将商品添加到购物车 | 可用 |
| 应用手动折扣 | 可用 |
| 应用优惠码 | 不可用 — 余额检查需要实时连接 |
| 现金支付 | 可用 — 本地记录并排队等待同步 |
| 卡支付（手动输入） | 可用 — 收银员在独立终端上处理并输入参考信息；本地记录并排队等待同步 |
| 卡支付（集成读卡器 — Stripe Terminal 等） | 不可用 — 集成的卡读卡器会实时与支付网络通信 |
| 礼品卡支付 | 不可用 — 余额查询需要实时连接 |
| 组合现金和手动卡的分账支付 | 可用 |
| 打印到网络打印机的收据 | 如果打印机与设备在同一本地网络中则可用 — 打印不需要互联网访问，只需本地网络连接 |
| 数字收据（电子邮件/SMS/WhatsApp） | 不可用 — 发送需要实时连接 |
| 浏览订单历史 | 可用 — 显示缓存的订单，并带有横幅提示您正在查看离线数据 |
| 退款和作废 | 不可用 — 这些操作需要实时连接 |
| 客户忠诚度积分查询 | 不可用 |
| 开启和关闭班次 | 可用 — 班次状态存储在本地 |

## 连接恢复时的排队销售和同步

离线销售不会丢失。当收银机无法连接到服务器时，每笔完成的销售都会写入本地队列（设备本地数据库中的 `pendingTransactions` 存储）。销售包括所有购物车商品、数量、价格、支付方式以及完成时间。

当网络恢复时，POS 会自动：

1.

检测到通过浏览器的 `online` 事件重新连接
2.


显示横幅：**"正在同步 N 个待处理的交易..."**
3.

按顺序将排队的销售发送到后端，如果第一次尝试失败，使用指数退避重试计划（每个尝试最多五分钟，最多重试十次）
4.

一旦后端确认，将每笔销售标记为已同步

**重复销售保护** — 每个排队的销售在离开设备前都会被分配一个唯一的本地 ID。后端在创建订单前会检查这个 ID。如果同一笔销售被提交了两次（例如，因为重试与首次成功尝试重叠），后端会忽略重复的销售。您永远不会出现重复计数的销售。

**冲突检测** — 在罕见的情况下，后端可能会将排队的销售标记为冲突（例如，当设备离线时服务器端删除了产品）。冲突的销售会出现在 **POS > 设置 > 待处理交易** 中，您可以手动查看并解决它们。

**离线库存调整** 以相同的方式处理：在离线期间进行的库存更改会被排队，并在连接恢复时重播。设备上的本地库存数字会立即更新，以便收银员看到准确（预估）的数量。

## 将 POS 安装到设备主屏幕

将 POS 安装到主屏幕可以为您提供全屏体验，没有浏览器地址栏，设备上有一个快捷方式图标，并且启动速度更快。

### iPad (Safari)

1. 打开 Safari 并导航到您的商店 POS URL：`https://yourstore.com/pos/`
2. 登录并完成初始配对（如果是新设备）。
3. 点击 Safari 工具栏中的 **分享** 按钮（带有向上的箭头的方块）。
4. 在分享面板中向下滚动并点击 **添加到主屏幕**。
5. 如果需要，可以编辑名称（默认为 "Spwig POS"），然后点击 **添加**。

POS 图标现在出现在您的 iPad 主屏幕上。点击它即可全屏打开应用，而无需 Safari 的浏览器界面。

> **注意：** 需要使用 iPad 上的 Safari 浏览器才能使用 添加到主屏幕 选项。

截至 2025 年中，iOS 上的第三方浏览器（如 Chrome、Firefox）不支持 PWA 安装。

### Android（Chrome）

1. 打开 Chrome 并访问您的商店 POS URL：`https://yourstore.com/pos/`
2. 登录并根据需要完成配对。
3. 点击右上角的 **三点菜单**，然后点击 **安装应用**（或旧版 Chrome 中的 **添加到主屏幕**）。
4. 点击 **安装** 确认。

POS 图标将显示在主屏幕和应用抽屉中。从图标启动会以独立模式打开应用。

### 桌面（Chrome 或 Edge）

1. 在 Chrome 或 Edge 中访问您的商店 POS URL。
2. 在浏览器地址栏中查找 **安装图标**（一个带有向下箭头的电脑显示器图标，或根据版本不同为“+”图标）。
3. 或者，打开 **三点菜单** 并选择 **安装 Spwig POS**（Chrome）或 **应用 > 将此网站安装为应用**（Edge）。
4. 确认安装。

POS 会以独立窗口打开，不带浏览器标签或地址栏。它会出现在您的系统应用列表中，并可以固定到任务栏。

## 应用如何更新

POS 通过 Service Worker 管理自己的更新。您无需访问应用商店或手动下载任何内容。

**更新周期：**

1. 每次打开 POS（或标签页在后台激活后），Service Worker 会检查服务器是否有新版本。
2. 如果有新版本可用，Service Worker 会在后台下载它，而您继续工作 —— 当前会话不会中断。
3. 更新将在下次打开 POS 时生效。如果应用已经打开且有待同步的内容，POS 会等待队列清空后再通知您可以重新加载，以避免在有未同步销售记录时中断正在进行的班次。

**当销售挂起时"重新加载"的含义** — 如果您看到需要重新加载以更新的提示，并且有挂起的离线销售，请在重新加载前干净地结束当前班次（或等待同步横幅消失）。

在销售排队时重新加载不会删除它们 — 它们仍保留在本地数据库中 — 但先进行同步以确认它们已被接收会更安全。

**检查已安装的版本** — 打开POS，点击 **菜单图标**（三条水平线），然后进入 **设置**。当前构建版本显示在设置面板的底部。

## 存储和清除安装

POS会在本地存储几种类型的数据：

| 什么 | 典型大小 |
|------|-------------|
| 应用外壳（HTML、CSS、JS、图标） | ~3–5 MB |
| 产品目录（文本和元数据） | 根据目录大小为1–10 MB |
| 产品图片（缓存） | 根据目录大小为5–50 MB |
| 订单历史 | 1–5 MB（500个订单） |
| 客户记录 | 1–3 MB（1,000个客户） |
| 挂起的交易队列 | 最小；同步时清除 |

**如果设备存储空间不足** — 当设备存储空间满时，浏览器会对缓存存储施加压力。POS会在浏览器允许的情况下将缓存设置为持久化，但在设备非常满的情况下，浏览器可能会首先清除产品图片。如果图片停止加载，POS将在下次同步时重新缓存它们。已同步的销售和应用外壳不受影响。

**重置安装** — 如果POS行为异常（卡在旧版本、目录未刷新、同步永久卡住），您可以执行干净重置：

1. **卸载应用** — 在移动设备上，长按POS图标并选择 **移除** 或 **卸载**。

在桌面端，右键点击应用窗口标题栏并选择 **卸载**。
2.

直接在浏览器中打开POS URL并重新登录。
3.

设备将再次要求输入终端的8位配对码。


你可以在管理员界面的 **POS > POS终端** 中找到或重新生成此代码 — 打开终端并点击 **重新生成配对代码**。
4.

一个新的配对会强制重新同步所有缓存的数据。

> **重置后**：任何在重置前已排队但尚未同步的离线销售将会丢失，因为本地数据库已被清除。在重置安装之前，请确保连接已恢复并且同步横幅已清除。

## 故障排除

### POS卡在旧版本上

服务工作者可能尚未激活新版本。尝试关闭所有打开POS的浏览器标签，然后重新打开POS。如果问题仍然存在，请按照上述步骤重置安装。

### "无连接"横幅无法清除

检查设备是否在POS之外有互联网访问（尝试加载另一个网站）。如果设备在线但横幅仍然存在：

- POS服务器可能暂时无法访问 — 等待一分钟，POS将自动重试。
- 如果你处于需要登录页面的网络（受限制的门户），打开一个新的浏览器标签，完成登录，然后返回POS。

### POS中缺少了在管理员中存在的一款产品

POS在联网时每五分钟同步一次产品。如果你最近在管理员中添加了一款产品，请点击 **菜单图标**，进入 **设置 > 立即同步** 以触发即时同步。如果产品仍然没有出现，请确认它已被标记为 **启用**，并且在产品设置中未被排除在POS可用性之外。

### 挂起的交易卡在 "冲突" 状态

进入 **POS > 设置**（在POS应用本身中），查看 **挂起交易** 面板。冲突的交易通常是由产品或价格在离线销售时和同步时发生了变化所导致的。你可以查看销售详情，并且如果销售已正确接收，可以将其标记为已审核。

## 小贴士

保留所有Markdown格式、图片路径、代码块和专业术语。

- 在专用设备上运行 POS，该设备始终保持连接到本地 Wi-Fi。

短暂的 Wi-Fi 中断会自动处理，但长时间离线的设备在重新连接时需要更多时间进行重新同步。
- 同步间隔是按设备设置的。

如果您有多个终端，每个终端都会独立同步。

在一个终端上进行的销售会在同步后立即显示在管理后台，但其他终端的本地订单缓存仅在其自身的同步周期中刷新。
- 在计划中的网络中断（例如，前往没有 Wi-Fi 的活动）之前，仍保持连接时打开 POS，以确保商品目录和库存数据完全更新。

现金销售将可靠地排队；只需在重新联网之前避免使用集成的银行卡支付。
- 如果您在活动中只需要现金销售，手动银行卡支付方式（收银员在独立终端上处理并输入参考编号）也可以在离线状态下进行银行卡交易。
- 在长时间的工作班次中，请保持设备充电——本地数据库和同步过程与屏幕相比对电池的影响不大，但充满电的设备在交易时总是更安全。
