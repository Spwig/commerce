- **สินค้าและรูปแบบสินค้า** — ซิงค์จากแคตตาล็อกของคุณและอัปเดตทุก 5 นาทีขณะออนไลน์
- **หมวดหมู่** — ซิงค์เมื่อเริ่มต้นและอัปเดตพร้อมกับสินค้า
- **ระดับสต็อก** — ซิงค์ทุก 2 นาทีขณะออนไลน์ (ใช้กลยุทธ์เครือข่ายก่อนที่จะกลับไปใช้ข้อมูลที่แคชไว้หากเซิร์ฟเวอร์ไม่ตอบสนองภายใน 3 วินาที)
- **บันทึกลูกค้า** — ลูกค้าล่าสุดสูงสุด 1,000 ราย
- **ประวัติการสั่งซื้อ** — จำนวนการสั่งซื้อ POS ล่าสุดที่กำหนดได้ (ค่าเริ่มต้น: 500 รายการใน 14 วัน; ตั้งค่าต่อเทอร์มินัลใน **POS > POS Terminals**)
- **รูปภาพสินค้า** — แคชไว้ในท้องถิ่นได้สูงสุด 24 ชั่วโมง

เมื่อ POS ตรวจพบว่าอุปกรณ์ได้สูญเสียการเชื่อมต่อ เบอร์ริ่งจะปรากฏขึ้นที่ด้านบนของหน้าจอ: **"โหมดออฟไลน์ - การขายจะถูกซิงค์เมื่อการเชื่อมต่อกลับมา"** ตู้ขายสินค้าจะยังคงทำงานต่อไปโดยใช้ข้อมูลที่แคชไว้ในท้องถิ่น

## สิ่งที่ทำงานได้ในโหมดออฟไลน์

| คุณสมบัติ | การใช้งานแบบออฟไลน์ |
|---------|---------------------|
| การค้นหาและเรียกดูสินค้า | ใช้งานได้ — ใช้แคตตาล็อกที่แคชไว้ในท้องถิ่น |
| การสแกนบาร์โค้ด | ใช้งานได้ — สแกนเพื่อค้นหาสินค้าในแคชท้องถิ่น |
| การเพิ่มสินค้าลงในตะกร้า | ใช้งานได้ |
| การใช้ส่วนลดแบบมืออาชีพ | ใช้งานได้ |
| การใช้รหัสคูปอง | ไม่สามารถใช้งานได้ — การตรวจสอบยอดคงเหลือต้องการการเชื่อมต่อแบบเรียลไทม์ |
| การชำระเงินสด | ใช้งานได้ — บันทึกไว้ในท้องถิ่นและเตรียมส่งซิงค์ |
| การชำระเงินด้วยบัตร (การป้อนข้อมูลด้วยมือ) | ใช้งานได้ — พนักงานดำเนินการที่เครื่องปลายทางแยกต่างหากและป้อนอ้างอิง; บันทึกไว้ในท้องถิ่นและเตรียมส่งซิงค์ |
| การชำระเงินด้วยบัตร (อ่านโดยอุปกรณ์ที่ผสาน — เช่น Stripe Terminal) | ไม่สามารถใช้งานได้ — อุปกรณ์อ่านบัตรที่ผสานจะสื่อสารกับเครือข่ายการชำระเงินแบบเรียลไทม์ |
| การชำระเงินด้วยบัตรขวัญถิ่น | ไม่สามารถใช้งานได้ — การตรวจสอบยอดคงเหลือต้องการการเชื่อมต่อแบบเรียลไทม์ |
| การชำระเงินแบบผสมระหว่างเงินสดและบัตรมืออาชีพ | ใช้งานได้ |
| การพิมพ์ใบเสร็จไปยังเครื่องพิมพ์เครือข่าย | ใช้งานได้หากเครื่องพิมพ์อยู่ในเครือข่ายท้องถิ่นเดียวกับอุปกรณ์ — การพิมพ์ไม่ต้องการการเข้าถึงอินเทอร์เน็ต แต่ต้องการการเชื่อมต่อเครือข่ายท้องถิ่นเท่านั้น |
| ใบเสร็จแบบดิจิทัล (อีเมล/เอสเอ็มเอส/วอทสแอป) | ไม่สามารถใช้งานได้ — การส่งต้องการการเชื่อมต่อแบบเรียลไทม์ |
| การเรียกดูประวัติการสั่งซื้อ | ใช้งานได้ — แสดงรายการสั่งซื้อที่แคชไว้พร้อมกับแถบแสดงว่าคุณกำลังดูข้อมูลออฟไลน์ |
| การคืนเงินและยกเลิกการขาย | ไม่สามารถใช้งานได้ — ต้องการการเชื่อมต่อแบบเรียลไทม์ |
| การตรวจสอบคะแนนสะสมลูกค้า | ไม่สามารถใช้งานได้ |
| การเปิดและปิดกะ | ใช้งานได้ — สถานะของกะจะถูกเก็บไว้ในท้องถิ่น |

## การขายที่ถูกคิวและซิงค์เมื่อการเชื่อมต่อกลับมา

การขายแบบออฟไลน์จะไม่สูญหาย เมื่อเครื่องจุดขายไม่สามารถเชื่อมต่อกับเซิร์ฟเวอร์ได้ การขายที่เสร็จสิ้นแต่ละรายการจะถูกเขียนลงในคิวท้องถิ่น (สต็อก `pendingTransactions` ในฐานข้อมูลท้องถิ่นของอุปกรณ์) การขายจะรวมรายการสินค้า จำนวน สินค้า วิธีการชำระเงิน และเวลาที่เสร็จสิ้น

เมื่อการเข้าถึงอินเทอร์เน็ตได้รับการฟื้นฟู POS จะดำเนินการอัตโนมัติ:

1.

ตรวจจับการเชื่อมต่อใหม่ผ่านเหตุการณ์ `online` ของเบราว์เซอร์
2.

รักษาการจัดรูปแบบมาร์กดาวน์ การใช้เส้นทางภาพ บล็อกโค้ด และคำศัพท์ทางเทคนิคไว้

แสดงแถบข้อความ: **"กำลังซิงค์ N รายการธุรกรรมที่ยังไม่ได้ดำเนินการ..."**
3.

ส่งรายการขายที่ค้างไว้ไปยังระบบหลังบ้านตามลำดับ โดยใช้การกำหนดช่วงเวลาที่เพิ่มขึ้นแบบเอ็กซ์โพเนนเชียล (exponential back-off) หากการลองส่งครั้งแรกล้มเหลว (สามารถลองส่งได้สูงสุด 10 ครั้ง ภายในช่วงเวลาสูงสุด 5 นาทีต่อการลองส่ง)
4.

เมื่อระบบหลังบ้านยืนยันการซิงค์แล้ว จะทำเครื่องหมายว่ารายการขายดังกล่าวได้รับการซิงค์แล้ว

**การป้องกันการซื้อซ้ำ** — รายการขายที่ค้างไว้แต่ละรายการจะถูกกำหนดให้มี ID ที่เป็นเอกลักษณ์ภายในอุปกรณ์ก่อนที่จะออกจากอุปกรณ์ ระบบหลังบ้านจะตรวจสอบ ID นี้ก่อนที่จะสร้างคำสั่งซื้อ หากมีการส่งรายการขายเดียวกันสองครั้ง (เช่น เนื่องจากมีการลองส่งทับกับการส่งครั้งแรกที่สำเร็จแล้ว) ระบบหลังบ้านจะเพิกเฉยต่อรายการซ้ำ คุณจะไม่มีรายการขายที่ถูกนับซ้ำแน่นอน

**การตรวจจับความขัดแย้ง** — ในบางกรณี ระบบหลังบ้านอาจระบุรายการขายที่ค้างไว้ว่ามีความขัดแย้ง (เช่น หากสินค้าถูกลบในระบบขณะที่อุปกรณ์อยู่ในโหมดออฟไลน์) รายการขายที่มีความขัดแย้งจะปรากฏใน **POS > Settings > Pending Transactions** เพื่อให้คุณสามารถตรวจสอบและแก้ไขได้ด้วยตนเอง

การปรับปรุงสต็อกในโหมดออฟไลน์จะถูกจัดการในลักษณะเดียวกัน: การเปลี่ยนแปลงสต็อกที่ทำขณะอยู่ในโหมดออฟไลน์จะถูกเก็บไว้ในคิว และจะถูกส่งกลับไปยังระบบเมื่อการเชื่อมต่อกลับมา จำนวนสต็อกที่แสดงในอุปกรณ์จะถูกอัปเดตทันที เพื่อให้พนักงานแคชเชียร์เห็นจำนวนที่ถูกต้อง (ประมาณการ) ได้

## การติดตั้ง POS บนหน้าจอเริ่มต้นของอุปกรณ์

การติดตั้ง POS บนหน้าจอเริ่มต้นของอุปกรณ์จะให้ประสบการณ์แบบเต็มหน้าจอโดยไม่มีแถบแสดงที่อยู่ของเบราว์เซอร์ ไอคอนลัดทางบนอุปกรณ์ และสามารถเปิดใช้งานได้เร็วขึ้น

### iPad (Safari)

1. เปิด Safari และเข้าไปที่ URL POS ของร้านค้าของคุณ: `https://yourstore.com/pos/`
2. ลงชื่อเข้าใช้และดำเนินการคู่กับอุปกรณ์หากนี่คืออุปกรณ์ใหม่
3. แตะปุ่ม **Share** (รูปสี่เหลี่ยมที่มีลูกศรขึ้น) ในแถบเครื่องมือของ Safari
4. เลื่อนลงในหน้าต่าง Share และแตะ **Add to Home Screen**
5. แก้ไขชื่อหากคุณต้องการ (ค่าเริ่มต้นคือ "Spwig POS") และแตะ **Add**

ไอคอน POS ตอนนี้จะปรากฏบนหน้าจอเริ่มต้นของ iPad คุณสามารถแตะเพื่อเปิดแอปแบบเต็มหน้าจอโดยไม่มีส่วนประกอบของเบราว์เซอร์ Safari

> **หมายเหตุ:** ต้องใช้ Safari บน iPad เท่านั้นสำหรับตัวเลือก Add to Home Screen

เบราว์เซอร์ที่สามที่ใช้บน iOS (เช่น Chrome, Firefox) ไม่รองรับการติดตั้ง PWA จนถึงกลางปี 2025

### Android (Chrome)

1. เปิด Chrome และเข้าไปที่ URL POS ของร้านค้าของคุณ: `https://yourstore.com/pos/`
2. เข้าสู่ระบบและทำขั้นตอนการจับคู่หากจำเป็น
3. แตะที่ **เมนูสามจุด** (มุมขวาบน) และแตะ **Install app** (หรือ **Add to Home screen** สำหรับเวอร์ชันเก่าของ Chrome)
4.ยืนยันโดยการแตะ **Install**

ไอคอน POS จะปรากฏบนหน้าจอหลักและใน drawer ของแอป ที่เปิดจากไอคอนจะเปิดแอปในโหมด standalone

### Desktop (Chrome หรือ Edge)

1. เข้าไปที่ URL POS ของร้านค้าของคุณใน Chrome หรือ Edge
2. หา **ไอคอนติดตั้ง** ในแถบแอดเดรสของเบราว์เซอร์ (เป็นหน้าจอคอมพิวเตอร์พร้อมลูกศรลง หรือไอคอน "+" ขึ้นอยู่กับเวอร์ชัน)
3. หรือเปิด **เมนูสามจุด** และเลือก **Install Spwig POS** (Chrome) หรือ **Apps > Install this site as an app** (Edge)
4. ยืนยันการติดตั้ง

POS จะเปิดในหน้าต่าง standalone โดยไม่มีแท็บเบราว์เซอร์หรือแถบแอดเดรส มันจะปรากฏในรายการแอปของระบบและสามารถยึดติดกับ taskbar ได้

## การอัปเดตแอป

POS จัดการอัปเดตของตัวเองผ่าน Service Worker คุณไม่จำเป็นต้องเข้าไปที่ร้านค้าแอปหรือดาวน์โหลดอะไรด้วยตนเอง

**วงจรการอัปเดต:**

1. ทุกครั้งที่คุณเปิด POS (หรือแท็บเป็น active หลังจากอยู่ในพื้นหลัง) Service Worker จะตรวจสอบเซิร์ฟเวอร์เพื่อหาเวอร์ชันใหม่
2. หากมีเวอร์ชันใหม่ ตัว Service Worker จะดาวน์โหลดในพื้นหลังขณะที่คุณยังทำงานต่อไป — ช่วงเวลาการใช้งานปัจจุบันจะไม่ถูกขัดจังหวะ
3. การอัปเดตจะมีผลเมื่อคุณเปิด POS อีกครั้ง หากแอปเปิดอยู่แล้วและมีการซิงค์ที่ยังไม่เสร็จ แอปจะรอจนกระทั่งคิวว่างก่อนส่งสัญญาณว่าการรีโหลดพร้อมแล้ว เพื่อหลีกเลี่ยงการขัดจังหวะช่วงเวลาการทำงานที่ยังมีการขายที่ยังไม่ซิงค์

**ความหมายของคำว่า "reload" เมื่อการขายยังอยู่ในสถานะค้างอยู่** — หากคุณเห็นคำแนะนำให้รีโหลดเพื่ออัปเดต และคุณมีการขายแบบออฟไลน์ที่ยังค้างอยู่ ให้ปิดการใช้งานชิฟต์ปัจจุบันอย่างถูกต้อง (หรือรอจนกว่าแถบแจ้งเตือนการซิงค์จะหายไป) ก่อนรีโหลด

การรีโหลดขณะมีการขายค้างอยู่จะไม่ลบข้อมูลเหล่านั้น — ข้อมูลยังคงอยู่ในฐานข้อมูลท้องถิ่น — แต่จะปลอดภัยกว่าหากคุณซิงค์ข้อมูลก่อนเพื่อยืนยันว่าได้รับข้อมูลแล้ว

**การตรวจสอบเวอร์ชันที่ติดตั้งไว้** — เปิด POS แล้วแตะที่ **ไอคอนเมนู** (เส้นแนวนอน 3 เส้น) และไปที่ **การตั้งค่า** เวอร์ชันการสร้างปัจจุบันจะแสดงอยู่ด้านล่างของแผงการตั้งค่า

## การจัดเก็บและล้างการติดตั้ง

POS จะจัดเก็บข้อมูลหลายประเภทในท้องถิ่น:

| อะไร | ขนาดโดยทั่วไป |
|------|-------------|
| โครงสร้างของแอป (HTML, CSS, JS, ไอคอน) | ~3–5 MB |
| แคตตาล็อกสินค้า (ข้อความและเมตาดาต้า) | 1–10 MB ขึ้นอยู่กับขนาดของแคตตาล็อก |
| รูปภาพสินค้า (ที่แคชไว้) | 5–50 MB ขึ้นอยู่กับขนาดของแคตตาล็อก |
| ประวัติการสั่งซื้อ | 1–5 MB (500 รายการ) |
| บันทึกลูกค้า | 1–3 MB (1,000 ลูกค้า) |
| คิวการขายที่ค้างอยู่ | ขนาดเล็กมาก; ถูกล้างเมื่อซิงค์ |

**หากอุปกรณ์มีพื้นที่จัดเก็บน้อยเกินไป** — บราวเซอร์จะใช้แรงกดต่อการจัดเก็บแคชเมื่ออุปกรณ์เต็ม แอป POS จะตั้งค่าแคชของตัวเองให้เป็นแบบถาวรเมื่อบราวเซอร์อนุญาต แต่ในอุปกรณ์ที่เต็มมาก บราวเซอร์อาจลบภาพสินค้าก่อน หากภาพหยุดโหลด แอป POS จะแคชภาพอีกครั้งเมื่อซิงค์ครั้งต่อไป การซิงค์การขายและโครงสร้างของแอปจะไม่ได้รับผลกระทบ

**การรีเซ็ตการติดตั้ง** — หาก POS ทำงานผิดปกติ (ติดอยู่กับเวอร์ชันเก่า แคตตาล็อกไม่รีเฟรช หรือซิงค์ติดอยู่ตลอดเวลา) คุณสามารถทำการรีเซ็ตที่สะอาด:

1. **ถอนการติดตั้งแอป** — บนมือถือ ให้กดและถือไอคอน POS แล้วเลือก **ลบ** หรือ **ถอนการติดตั้ง**

บนเดสก์ท็อป ให้คลิกขวาที่แถบชื่อหน้าต่างแอปแล้วเลือก **ถอนการติดตั้ง**
2.

เปิด URL POS โดยตรงในเบราว์เซอร์และเข้าสู่ระบบอีกครั้ง
3.

อุปกรณ์จะถูกถามให้ใส่รหัสคู่กับเทอร์มินัล 8 ตัวอักษรอีกครั้ง


คุณสามารถค้นหาหรือสร้างคีย์การจับคู่ใหม่ได้ในแดชบอร์ดที่ **POS > POS Terminals** — เปิดอุปกรณ์และคลิกที่ **Regenerate pairing code**
4.

การจับคู่ใหม่จะทำให้ข้อมูลที่ถูกแคชทั้งหมดซิงค์กันใหม่ทั้งหมด

> **หลังจากการรีเซ็ต**: การขายที่อยู่ในคิวแต่ยังไม่ได้ซิงค์ก่อนการรีเซ็ตจะสูญหาย เนื่องจากฐานข้อมูลท้องถิ่นถูกลบ โปรดตรวจสอบให้แน่ใจว่าการเชื่อมต่อได้รีสตาร์ทแล้ว และแถบข้อความซิงค์ได้หายไปก่อนที่จะรีเซ็ตการติดตั้ง

## การแก้ไขปัญหา

### POS ติดอยู่กับเวอร์ชันเก่า

Service Worker อาจยังไม่ได้เปิดใช้งานเวอร์ชันใหม่ ลองปิดแท็บเบราว์เซอร์ทั้งหมดที่เปิด POS แล้วเปิดใหม่ หากปัญหายังคงอยู่ ให้รีเซ็ตการติดตั้งตามที่อธิบายไว้ข้างต้น

### แถบข้อความ "No connection" ไม่หายไป

ตรวจสอบว่าอุปกรณ์มีการเชื่อมต่ออินเทอร์เน็ตนอกเหนือจาก POS (ลองเปิดเว็บไซต์อื่น) หากอุปกรณ์ออนไลน์แล้วแต่แถบข้อความยังคงอยู่:

- อาจมีปัญหากับเซิร์ฟเวอร์ POS ชั่วคราว — รอสักพักหนึ่งและ POS จะลองเชื่อมต่ออัตโนมัติ
- หากคุณอยู่ในเครือข่ายที่ต้องการหน้าจอสำหรับการลงชื่อเข้าใช้ (captive portal) ให้เปิดแท็บเบราว์เซอร์ใหม่ ทำขั้นตอนการลงชื่อเข้าใช้ แล้วกลับไปที่ POS

### สินค้าที่มีอยู่ในแดชบอร์ดหายไปจาก POS

POS จะซิงค์สินค้าทุก 5 นาทีขณะออนไลน์ หากคุณเพิ่มสินค้าในแดชบอร์ดเมื่อไม่นานมานี้ ให้แตะที่ **menu icon** และไปที่ **Settings > Sync Now** เพื่อเรียกใช้การซิงค์ทันที หากสินค้ายังไม่ปรากฏ ให้ตรวจสอบว่ามันถูกตั้งค่าเป็น **Active** และไม่ถูกตัดออกจากการใช้งาน POS ในตั้งค่าสินค้า

### การทำธุรกรรมที่ค้างอยู่อยู่ในสถานะ "Conflict"

ไปที่ **POS > Settings** (ภายในแอป POS เอง) และตรวจสอบแผง **Pending Transactions** การทำธุรกรรมที่มีความขัดแย้งมักเกิดขึ้นเมื่อสินค้าหรือราคาเปลี่ยนไประหว่างที่การขายถูกทำออฟไลน์และเมื่อการซิงค์เกิดขึ้น คุณสามารถดูรายละเอียดการขาย และหากการขายได้รับมาอย่างถูกต้อง ให้ทำเครื่องหมายว่าได้ตรวจสอบแล้ว

## เคล็ดลับ

รักษาการจัดรูปแบบมาร์กดาวน์ ค่าเส้นทางรูปภาพ บล็อกโค้ด และคำศัพท์ทางเทคนิคไว้ทั้งหมด

- ให้รัน POS บนอุปกรณ์ที่เฉพาะเจาะจงซึ่งเชื่อมต่อกับ Wi-Fi ของคุณอย่างต่อเนื่อง

การหลุดของ Wi-Fi ชั่วคราวจะถูกจัดการโดยอัตโนมัติ แต่หากอุปกรณ์ใช้เวลาอยู่ออฟไลน์เป็นเวลานาน จะต้องใช้เวลานานขึ้นในการเรียกคืนข้อมูลเมื่อเชื่อมต่ออีกครั้ง
- ช่วงเวลาการซิงค์เป็นต่ออุปกรณ์

หากคุณมีหลายหน้าจอ แต่ละหน้าจอจะซิงค์ด้วยตนเอง

การขายหนึ่งครั้งบนหน้าจอจะปรากฏในแดชบอร์ดทันทีเมื่อซิงค์ แต่แคชคำสั่งซื้อท้องถิ่นของหน้าจออื่นจะอัปเดตเฉพาะในรอบซิงค์ของตนเองเท่านั้น
- ก่อนการสูญเสียการเชื่อมต่ออินเทอร์เน็ตที่วางแผนไว้ (เช่น การย้ายไปที่เหตุการณ์ที่ไม่มี Wi-Fi) ให้เปิด POS ขณะยังเชื่อมต่ออยู่เพื่อให้ข้อมูลแคตตาล็อกและสต็อกสินค้าเป็นปัจจุบันอย่างสมบูรณ์

การขายเงินสดจะถูกคิวได้อย่างน่าเชื่อถือ แต่หลีกเลี่ยงการชำระเงินด้วยบัตรที่ผสานรวมจนกว่าคุณจะกลับมาออนไลน์อีกครั้ง
- หากคุณต้องการขายเงินสดเพียงอย่างเดียวที่เหตุการณ์ วิธีการชำระเงินด้วยบัตรแบบมือถือ (พนักงานแคชเชียร์ดำเนินการบนอุปกรณ์แบบสแตนด์อโลนและป้อนอ้างอิง) จะทำงานได้ในโหมดออฟไลน์สำหรับการทำธุรกรรมบัตรด้วย
- ให้ชาร์จอุปกรณ์ไว้ตลอดช่วงเวลาการทำงานที่ยาวนาน — ฐานข้อมูลท้องถิ่นและกระบวนการซิงค์ไม่ส่งผลต่อแบตเตอรี่อย่างมีนัยสำคัญเมื่อเทียบกับหน้าจอ แต่การชาร์จแบตเตอรี่ไว้เสมอจะปลอดภัยกว่าสำหรับการขาย
