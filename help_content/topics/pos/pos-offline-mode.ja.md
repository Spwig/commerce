Spwig POSはProgressive Web App (PWA) です。これはブラウザ内でのみ動作し、ネイティブアプリのようにデバイスのホーム画面にインストールできます。アプリ、商品カタログ、最近の注文履歴はすべてデバイス上にローカルキャッシュされるため、ネットワークの短時間の障害や遅い接続でもレジは正常に動作し続けます。

このトピックでは、接続が切れたときに何が動作するか、接続が復旧したときにキューイングされた販売がどのように調整されるか、POSをデバイスのホーム画面にインストールする方法、およびアップデートがインストールされたデバイスに届く方法について詳しく説明します。

## オフラインモードの動作方法

デバイスでPOSを初めて開くと、ブラウザはアプリ全体 — インターフェース、画像、およびすべてのサポートコード — をダウンロードしてキャッシュします。このキャッシュを管理する背景コンポーネントはService Workerと呼ばれます。この後、サーバーが利用不可でもアプリはローカルキャッシュから読み込まれます。

アプリのキャッシュに加えて、POSはデバイス上にローカルデータベースを維持します（ブラウザの組み込みIndexedDBストレージを使用）。このデータベースには以下が保存されます:

- **製品とバリエーション** — カタログから同期され、オンライン時に5分ごとに更新されます
- **カテゴリ** — 起動時に同期され、製品とともに更新されます
- **在庫レベル** — オンライン時に2分ごとに同期されます（3秒以内にサーバーが応答しない場合、キャッシュされたデータを使用するネットワークファースト戦略）
- **顧客情報** — 最近の顧客は最大1,000件まで
- **注文履歴** — 最近のPOS注文数（デフォルト: 14日間で500注文; **POS > POS端末** で端末ごとに設定可能）
- **製品画像** — 最大24時間までローカルにキャッシュされます

POSがデバイスがオフラインになったことを検出すると、画面の上部にバナーが表示されます: **"オフラインモード - 接続が復旧すると販売が同期されます。"** レジはローカルにキャッシュされたデータを使用して引き続き操作を続けます。

## オフラインで動作する機能

| フィーチャー | オフラインでの利用可能性 |
|---------|---------------------|
| 商品の検索とブラウジング | 利用可能 — ローカルにキャッシュされたカタログを使用 |
| バーコードスキャン | 利用可能 — ローカルキャッシュから商品を検索 |
| カートへの商品追加 | 利用可能 |
| 手動割引の適用 | 利用可能 |
| チケットコードの適用 | 利用不可 — 残高確認にはライブ接続が必要 |
| 現金支払い | 利用可能 — ローカルに記録され、同期待ち |
| カード支払い（手入力） | 利用可能 — 売り子は別端末で処理し、参照を入力します。ローカルに記録され、同期待ち |
| カード支払い（統合リーダー — Stripe Terminalなど） | 利用不可 — 統合型カードリーダーはリアルタイムで支払いネットワークと通信 |
| ギフトカード支払い | 利用不可 — 残高照会にはライブ接続が必要 |
| 現金と手入力カードを組み合わせた分割支払い | 利用可能 |
| ネットワークプリンタへのレシート印刷 | デバイスと同じローカルネットワークにプリンタがある場合に利用可能 — インターネット接続は不要で、ローカルネットワーク接続のみ必要 |
| デジタルレシート（メール/SMS/WhatsApp） | 利用不可 — 送信にはライブ接続が必要 |
| 注文履歴の閲覧 | 利用可能 — キャッシュされた注文を表示し、オフラインデータを閲覧していることを示すバナーが表示 |
| 返金とキャンセル | 利用不可 — これらにはライブ接続が必要 |
| 顧客のロイヤルティポイント照会 | 利用不可 |
| シフトの開始と終了 | 利用可能 — シフト状態はローカルに保存 |

## 接続が復旧した際のキューイングされた販売と同期

オフライン販売は失われません。レジがサーバーに接続できない場合、完了した各販売はデバイスのローカルデータベース内のローカルキュー（`pendingTransactions` ストア）に記録されます。販売にはカート内のすべての商品、数量、価格、支払い方法、および完了した時間が含まれます。

インターネット接続が復旧した場合、POSは自動的に以下を行います：

1.

ブラウザの `online` イベントを通じて再接続を検出
2.


表示するバナー: **"N件の未同期の取引を同期しています..."**
3.

キューに並んでいる販売をバックエンドに順番に送信し、最初の試行が失敗した場合、指数関数的なバックオフリトライスケジュールを使用して最大5分の最大ウィンドウ内で最大10回リトライします。
4.

バックエンドがその販売を確認した後、各販売を同期済みとしてマークします。

**重複販売の保護** — 各キューイングされた販売は、デバイスから出る前に一意のローカルIDが割り当てられます。バックエンドは、注文を作成する前にこのIDをチェックします。同じ販売が2回送信された場合（例: リトライが最初の成功した試行と重なった場合）、バックエンドは重複を無視します。重複してカウントされる販売は決して発生しません。

**衝突検出** — レアなケースでは、バックエンドがキューイングされた販売を衝突としてマークする可能性があります（例: デバイスがオフラインの間にサーバー側で製品が削除された場合）。衝突した販売は **POS > Settings > Pending Transactions** に表示されるため、手動で確認および解決できます。

**オフラインでの在庫調整** は同じように処理されます: オフライン時に実行された在庫変更はキューイングされ、接続が復帰すると再現されます。デバイス上のローカル在庫数はすぐに更新されるため、レジ係は正確な（推定）数を表示します。

## POSをデバイスのホーム画面にインストールする

POSをホーム画面にインストールすると、ブラウザのアドレスバーがなく、デバイスにショートカットアイコンが表示され、起動が速くなります。

### iPad (Safari)

1. Safariを開き、ストアのPOS URLにアクセスしてください: `https://yourstore.com/pos/`
2. 新しいデバイスの場合、ログインし、初期ペアリングを完了してください。
3. Safariのツールバーにある **Share** ボタン（上向きの矢印が入った四角）をタップします。
4. Shareシートをスクロールし、**Add to Home Screen** をタップします。
5. 名前を編集してから **Add** をタップします（デフォルトは "Spwig POS" です）。

POSのアイコンは今やiPadのホーム画面に表示されます。これをタップすると、Safariのブラウザのchromeなしでアプリをフルスクリーンで開きます。

> **注意:** Add to Home Screen オプションを使用するには、iPad での Safari が必要です。

iOS 用のサードパーティのブラウザ（Chrome、Firefox）は、2025年中盤時点ではPWAのインストールをサポートしていません。

### Android (Chrome)

1. Chromeを開き、店舗のPOS URLにアクセスしてください: `https://yourstore.com/pos/`
2. ログインし、必要に応じてペアリングを完了してください。
3. **3つの点のメニュー**（右上）をタップし、**Install app**（または古いバージョンのChromeでは**Add to Home screen**）をタップしてください。
4. **Install**をタップして確認してください。

POSのアイコンがホーム画面およびアプリドロワーに表示されます。アイコンから起動すると、スタンドアロンモードでアプリが開きます。

### Desktop (Chrome or Edge)

1. ChromeまたはEdgeで、店舗のPOS URLにアクセスしてください。
2. ブラウザのアドレスバーに**インストールアイコン**を確認してください（コンピュータのモニタに下向きの矢印、またはバージョンによっては"+"アイコン）。
3. または、**3つの点のメニュー**を開き、**Install Spwig POS**（Chrome）または**Apps > Install this site as an app**（Edge）を選択してください。
4. インストールを確認してください。

POSはブラウザのタブやアドレスバーなしでスタンドアロンのウィンドウとして開きます。システムのアプリ一覧に表示され、タスクバーにピン留めすることもできます。

## アプリの更新方法

POSはService Workerを通じて自身の更新を管理します。アプリストアにアクセスしたり、手動でダウンロードしたりする必要はありません。

**更新サイクル:**

1. POSを開くたびに（またはバックグラウンドでアクティブになったタブ）、Service Workerがサーバーで新しいバージョンを確認します。
2. 新しいバージョンが利用可能な場合、Service Workerはバックグラウンドでダウンロードします。これにより、現在のセッションが中断されることはありません。
3. 更新は、次回POSを開いたときに反映されます。アプリがすでに開いていて同期が待機している場合、POSはキューが空になるのを待ち、再読み込みが準備できたことを通知します。これにより、未同期の販売データがある場合にアクティブなシフトが中断されることを防ぎます。

**"リロード"の意味（売上保留中時）** — 売上が保留中の場合、更新用のリロードのプロンプトが表示されたら、現在のシフトをクリーンに終了するか（または同期バナーが消えるのを待つ）リロードする前に、現在のシフトをクリーンに終了してください。

保留中の売上がキューイングされている間リロードしても、それらは削除されません — ローカルデータベースに残ります — ただし、まず同期してそれらが受信されたことを確認するのがより安全です。

**インストールされているバージョンの確認** — POSを開き、**メニューのアイコン**（3本の水平線）をタップし、**設定**に移動します。設定パネルの下部に現在のビルドバージョンが表示されます。

## ストレージとインストールのクリア

POSはいくつかのタイプのデータをローカルに保存します：

| 何 | 一般的なサイズ |
|------|-------------|
| アプリシェル（HTML、CSS、JS、アイコン） | ~3–5 MB |
| 商品カタログ（テキストとメタデータ） | カタログのサイズにより1–10 MB |
| 商品画像（キャッシュ済み） | カタログのサイズにより5–50 MB |
| 注文履歴 | 500注文で1–5 MB |
| 顧客記録 | 1,000顧客で1–3 MB |
| 保留中のトランザクションキュー | 最小；同期時にクリア |

**デバイスのストレージが不足している場合** — デバイスがいっぱいになると、ブラウザはキャッシュストレージに圧力をかけます。POSはブラウザが許可する限りキャッシュを永続的に設定しますが、非常に満タンのデバイスではブラウザがまず商品画像を削除することがあります。画像の読み込みが停止した場合、POSは次の同期時に再キャッシュします。同期された売上やアプリシェルは影響を受けません。

**インストールのリセット** — POSが予期せぬ動作を示す場合（古いバージョンに固まっている、カタログが更新されない、同期が永久に停止している）は、クリーンなリセットを実行できます：

1. **アプリをアンインストール** — モバイルでは、POSのアイコンを長押しし、**削除**または**アンインストール**を選択します。

デスクトップでは、アプリのウィンドウのタイトルバーを右クリックし、**アンインストール**を選択します。
2.

ブラウザでPOSのURLを直接開き、再度ログインします。
3.

デバイスに端末の8文字のペアリングコードを再度入力するよう求められます。


このコードは、**POS > POS端末**（admin画面内）で見つけるか再生成できます — 端末を開き、**ペアリングコードの再生成**をクリックしてください。
4.

新しいペアリングは、すべてのキャッシュデータの再同期を強制します。

> **リセット後**: リセット前のオフライン販売でキューイングされたがまだ同期されていないものは、ローカルデータベースがクリアされるため失われます。インストールをリセットする前に、接続が復旧し、同期のバナーが消えることを常に確認してください。

## トラブルシューティング

### POSが古いバージョンにとどまっている

サービスワーカーが新しいバージョンをまだアクティブ化していない可能性があります。POSが開いているすべてのブラウザタブを閉じてから、再度開いてください。問題が解決しない場合は、上記で説明したようにインストールをリセットしてください。

### 「接続なし」のバナーが消えない

POSの外でデバイスがインターネットに接続されているかを確認してください（別のサイトをロードしてみてください）。デバイスがオンラインであるにもかかわらずバナーが消えない場合は:

- POSサーバーが一時的にアクセス不能である可能性があります — 1分ほど待って、POSが自動的に再試行します。
- キャプティブポータル（ログインが必要なネットワーク）に接続している場合、新しいブラウザタブを開き、ログインを完了した後、POSに戻ってください。

### 管理画面に存在する商品がPOSに表示されていない

POSはオンライン時に5分ごとに商品を同期します。管理画面で非常に最近商品を追加した場合、**メニューのアイコン**をタップし、**設定 > 今すぐ同期**に移動して、即時同期をトリガーしてください。それでも商品が表示されない場合は、商品設定で**アクティブ**にマークされていることを確認し、POSでの利用を除外されていないか確認してください。

### 保留中の取引が「コンフリクト」状態で止まっている

POSアプリ自体の**POS > 設定**に移動し、**保留中の取引**パネルを確認してください。コンフリクトが発生している取引は、オフラインで販売されたときと同期されたときの間に商品や価格が変更されたことが原因であることが一般的です。販売の詳細を確認し、販売が正しく受信された場合は、それを確認済みとしてマークできます。

## ヒント

すべてのマークダウンのフォーマット、画像のパス、コードブロック、技術用語は保持してください。

- ローカルのWi-Fiに接続された専用のデバイスでPOSを実行してください。

Wi-Fiの短時間の切断は自動的に処理されますが、長時間オフラインになるデバイスは再接続時により時間がかかる場合があります。
- シンク間隔はデバイスごとに設定されます。

複数の端末をお持ちの場合、それぞれが独立してシンクします。

1つの端末で行われた売上がシンク時に即座に管理画面に表示されますが、他の端末のローカル注文キャッシュは自身のシンクサイクル時にのみ更新されます。
- 予定されたインターネットの停止（例：Wi-Fiがないイベントに移動する場合）の前に、まだ接続されている間にPOSを開いて、カタログと在庫データが最新の状態になっているようにしてください。

現金での販売は信頼性高くキューイングされます。オンラインに戻るまで統合されたカード決済は避けてください。
- イベントで現金での販売のみが必要な場合、マニュアルカード決済方法（カウンターでスタンドアロン端末を使用して参照を入力）は、オフラインでもカード取引に使用できます。
- 長時間のシフト中はデバイスを充電したままにしてください。ローカルデータベースとシンクプロセスは画面と比較してバッテリーを大きく消費しませんが、充電されたデバイスは常に取引に安全です。
