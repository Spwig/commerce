Spwig POS는 프로그레시브 웹 앱(PWA)입니다. 이 앱은 브라우저에서 완전히 실행되며, 네이티브 앱처럼 기기의 홈 화면에 설치할 수 있습니다. 앱, 제품 카탈로그, 최근 주문 내역이 기기의 로컬에 캐시되어 있기 때문에, 네트워크 장애나 느린 연결 상태에서도 계산대가 계속 작동합니다.

이 주제에서는 연결이 끊겼을 때 어떤 기능이 작동하는지, 연결이 다시 되돌아올 때 대기 중인 판매가 어떻게 조정되는지, POS를 기기의 홈 화면에 설치하는 방법, 그리고 업데이트가 설치된 기기로 어떻게 전달되는지 설명합니다.

## 오프라인 모드 작동 방식

기기에서 POS를 처음으로 열면 브라우저는 앱 전체를 다운로드하고 캐시합니다. 인터페이스, 이미지 및 모든 지원 코드가 포함됩니다. 이 캐시를 관리하는 백그라운드 구성 요소는 서비스 워커(Service Worker)입니다. 이후로는 서버에 연결이 되지 않아도 앱이 로컬 캐시에서 로드됩니다.

앱 캐시 위에, POS는 기기에서 로컬 데이터베이스를 유지합니다(브라우저의 내장 IndexedDB 저장소를 사용). 이 데이터베이스는 다음을 포함합니다:

- **제품 및 변형** — 카탈로그에서 동기화되고 온라인 상태일 때 5분마다 새로 고침
- **카테고리** — 시작 시 동기화되고 제품과 함께 새로 고침
- **재고 수준** — 온라인 상태일 때 2분마다 동기화 (3초 이내에 서버 응답이 없는 경우 네트워크 우선 전략을 사용하여 캐시된 데이터로 대체)
- **고객 기록** — 최대 1,000개의 최근 고객
- **주문 내역** — 설정 가능한 최근 POS 주문 수 (기본값: 14일 동안 500개 주문; **POS > POS 단말기**에서 단말기별로 설정)
- **제품 이미지** — 최대 24시간 동안 로컬에 캐시됨

POS가 장치가 오프라인 상태임을 감지하면 화면 상단에 배너가 나타납니다: **"오프라인 모드 - 연결이 복원되면 판매가 동기화됩니다."** 계산대는 로컬에 캐시된 데이터를 사용하여 계속 작동합니다。

| 시프트 열기 및 닫기 | 가능 — 시프트 상태는 로컬에 저장 |

## 연결이 복원될 때 대기 중인 판매 및 동기화

오프라인 판매는 손실되지 않습니다. 레지스터가 서버에 연결할 수 없는 경우, 각 완료된 판매는 장치의 로컬 데이터베이스에 있는 `pendingTransactions` 저장소에 로컬 대기열에 기록됩니다. 판매에는 장바구니 항목, 수량, 가격, 결제 방식, 완료 시간이 포함됩니다.

인터넷 연결이 복원되면 POS 시스템은 자동으로:

1.

브라우저의 `online` 이벤트를 통해 재연결 감지
2.


배너를 표시합니다: **"N개의 대기 중인 거래를 동기화 중..."**
3.

대기 중인 판매를 백엔드에 순서대로 전송하며, 첫 번째 시도가 실패할 경우 지수 백오프 재시도 일정을 사용합니다 (각 시도당 최대 5분의 윈도우 내에서 최대 10회 재시도)
4.

백엔드가 해당 판매를 확인하면 각 판매를 동기화된 상태로 표시합니다

**중복 판매 보호** — 각 대기 중인 판매는 기기에서 나가기 전에 고유한 로컬 ID가 할당됩니다. 백엔드는 주문을 생성하기 전에 이 ID를 확인합니다. 동일한 판매가 두 번 제출되는 경우(예: 재시도가 성공적인 첫 번째 시도와 겹쳤을 때), 백엔드는 중복 항목을 무시합니다. 중복 계산된 판매가 결코 발생하지 않습니다.

**충돌 감지** — 드물게 백엔드가 대기 중인 판매를 충돌로 표시할 수 있습니다(예: 기기가 오프라인 상태일 때 서버에서 제품이 삭제된 경우). 충돌한 판매는 **POS > 설정 > 대기 중인 거래**에 표시되어 수동으로 검토하고 해결할 수 있습니다.

**오프라인 재고 조정**은 동일한 방식으로 처리됩니다: 오프라인 상태에서 이루어진 재고 변경은 대기 목록에 추가되고, 연결이 다시 되돌아올 때 재생됩니다. 기기의 로컬 재고 수치는 즉시 업데이트되어 점원이 정확한(추정치) 수량을 확인할 수 있습니다.

## 기기 홈 화면에 POS 설치

POS를 홈 화면에 설치하면 브라우저 주소 표시줄 없이 전체 화면 경험을 제공하며, 기기의 바로가기 아이콘과 더 빠른 실행 시간을 제공합니다.

### iPad (Safari)

1. Safari를 열고 가게의 POS URL로 이동합니다: `https://yourstore.com/pos/`
2. 새 기기이면 로그인하고 초기 쌍방향 연결을 완료합니다.
3. Safari 도구 모음의 **공유** 버튼(위로 가는 화살표가 있는 정사각형)을 탭합니다.
4. 공유 시트를 아래로 스크롤하고 **홈 화면에 추가**를 탭합니다.
5. 원하시면 이름을 편집할 수 있습니다(기본값은 "Spwig POS") 그리고 **추가**를 탭합니다.

POS 아이콘은 이제 iPad의 홈 화면에 나타납니다. 이를 탭하면 Safari의 브라우저 헤드가 없이 전체 화면으로 앱이 열립니다.

> **참고:** 홈 화면에 추가 옵션을 사용하려면 iPad용 Safari가 필요합니다.

iOS에서 사용하는 제3자 브라우저(크롬, 파이어폭스)는 2025년 중반까지 PWA 설치를 지원하지 않습니다.

### Android (Chrome)

1. Chrome을 열고 가게의 POS URL로 이동합니다: `https://yourstore.com/pos/`
2. 로그인하고 필요 시 쌍방향 연결을 완료합니다.
3. 오른쪽 상단의 **세 개의 점 메뉴**를 탭한 후 **앱 설치**를 탭합니다(구형 Chrome에서는 **홈 화면에 추가**를 선택합니다).
4. **설치**를 탭하여 확인합니다.

POS 아이콘은 홈 화면과 앱 도크에 나타납니다. 아이콘을 통해 앱을 실행하면 스탠드얼론 모드로 열립니다.

### Desktop (Chrome 또는 Edge)

1. Chrome 또는 Edge에서 가게의 POS URL로 이동합니다.
2. 브라우저 주소 표시줄에서 **설치 아이콘**을 찾습니다(컴퓨터 모니터와 아래로 가는 화살표 아이콘 또는 버전에 따라 '+' 아이콘일 수 있습니다).
3. 또는 **세 개의 점 메뉴**를 열고 **Spwig POS 설치**를 선택합니다(Chrome) 또는 **앱 > 이 사이트를 앱으로 설치**를 선택합니다(Edge).
4. 설치를 확인합니다.

POS는 브라우저 탭이나 주소 표시줄 없이 스탠드얼론 창으로 열립니다. 시스템의 앱 목록에 나타나며 작업 표시줄에 고정할 수 있습니다.

## 앱 업데이트 방법

POS는 Service Worker를 통해 자체 업데이트를 관리합니다. 앱 스토어에 방문하거나 수동으로 다운로드할 필요가 없습니다.

**업데이트 주기:**

1. POS를 열거나(또는 백그라운드에서 활성화된 탭이 다시 활성화될 때) Service Worker가 서버에서 새 버전을 확인합니다.
2. 새 버전이 있으면 Service Worker가 백그라운드에서 다운로드합니다. 이 과정에서 현재 세션은 중단되지 않습니다.
3. 다음 번에 POS를 열 때 업데이트가 적용됩니다. 앱이 이미 열려 있고 동기화가 필요한 경우, POS는 대기열이 빈 상태가 되기 전까지 새로고침이 준비되었음을 알리는 것을 지연시켜, 활성화된 시프트 중 동기화되지 않은 판매로 인한 중단을 피합니다.

**판매가 대기 중일 때 "재로드"의 의미** — 업데이트를 위해 재로드하는 메시지가 표시되고 오프라인 판매가 대기 중이라면, 현재 시프트를 깨끗이 종료하거나 동기화 배너가 사라질 때까지 기다린 후 재로드하세요.

판매가 대기 중일 때 재로드하면 그 판매 내역이 삭제되지는 않지만, 로컬 데이터베이스에 남아 있습니다. 하지만 먼저 동기화를 수행하여 수신되었는지 확인하는 것이 더 안전합니다.

**설치된 버전 확인** — POS를 열고 **메뉴 아이콘**(세 개의 수평 라인)을 탭한 후 **설정**으로 이동합니다. 설정 패널 하단에 현재 빌드 버전이 표시됩니다.

## 저장소 및 설치 초기화

POS는 여러 유형의 데이터를 로컬에 저장합니다:

| 무엇 | 일반적인 크기 |
|------|-------------|
| 앱 셀룰라(HTML, CSS, JS, 아이콘) | ~3–5 MB |
| 제품 카탈로그(텍스트 및 메타데이터) | 카탈로그 크기에 따라 1–10 MB |
| 제품 이미지(캐시됨) | 카탈로그 크기에 따라 5–50 MB |
| 주문 내역 | 1–5 MB (500개 주문) |
| 고객 기록 | 1–3 MB (1,000명 고객) |
| 대기 중인 거래 대기열 | 최소; 동기화 시 삭제 |

**장치의 저장 공간이 부족할 경우** — 브라우저는 장치가 가득 차 있을 때 캐시 저장소에 압력을 가합니다. POS는 브라우저가 허용하는 경우 캐시를 지속 가능한 것으로 설정하지만, 매우 가득 차 있는 장치에서는 브라우저가 먼저 제품 이미지를 제거할 수 있습니다. 이미지가 더 이상 로드되지 않으면 POS는 다음 동기화 시 다시 캐시합니다. 동기화된 판매 및 앱 셀룰라에는 영향이 없습니다.

**설치 초기화** — POS가 예상치 못하게 작동할 경우(구형 버전에 머무름, 카탈로그가 새로 고침되지 않음, 동기화가 영원히 멈춤), 깨끗한 초기화를 수행할 수 있습니다:

1. **앱 제거** — 모바일에서는 POS 아이콘을 길게 누르고 **제거** 또는 **설치 해제**를 선택합니다.

데스크탑에서는 앱 창 제목 표시줄을 우클릭하고 **설치 해제**를 선택합니다.
2.

브라우저에서 POS URL을 직접 열고 다시 로그인합니다.
3.

장치는 터미널의 8자리 짝꿍 코드를 다시 요청합니다.

관리자에서 **POS > POS 단말기** 메뉴에서 이 코드를 찾거나 재생성할 수 있습니다 — 단말기를 열고 **페어링 코드 재생성**을 클릭하세요.
4.

새로운 페어링은 모든 캐시된 데이터의 완전한 재동기화를 강제합니다.

> **재설정 후**: 재설정 전에 대기 중이지만 아직 동기화되지 않은 오프라인 판매는 로컬 데이터베이스가 삭제되기 때문에 손실됩니다. 설치를 재설정하기 전에 연결이 복원되고 동기화 배너가 사라졌는지 항상 확인하세요.

## 문제 해결

### POS가 오래된 버전에 멈춰 있습니다

서비스 워커가 새 버전을 활성화하지 않았을 수 있습니다. POS가 열린 모든 브라우저 탭을 닫고 다시 열어보세요. 문제가 지속되면 위에서 설명한 대로 설치를 재설정하세요.

### "연결 없음" 배너가 사라지지 않습니다

POS 외부에서 장치가 인터넷에 연결되어 있는지 확인하세요(다른 사이트를 로드해 보세요). 장치가 온라인 상태이지만 배너가 계속 나타난다면:

- POS 서버가 일시적으로 접근 불가능할 수 있습니다 — 1분 정도 기다리면 POS가 자동으로 재시도합니다.
- 네트워크가 로그인 페이지(캡티브 포털)가 필요한 경우, 새 브라우저 탭을 열고 로그인을 완료한 후 POS로 돌아가세요.

### 관리자에 있는 제품이 POS에 누락되었습니다

POS는 온라인 상태일 때 5분마다 제품을 동기화합니다. 관리자에서 제품을 최근에 추가했다면 **메뉴 아이콘**을 탭하고 **설정 > 즉시 동기화**로 이동하여 즉시 동기화를 트리거하세요. 제품이 여전히 나타나지 않는다면 제품 설정에서 제품이 **활성화**되어 있고 POS 사용 가능에서 제외되지 않았는지 확인하세요.

### 대기 중인 거래가 "충돌" 상태에 멈춰 있습니다

POS 앱 자체에서 **POS > 설정**으로 이동하여 **대기 중인 거래** 패널을 확인하세요. 충돌된 거래는 일반적으로 오프라인으로 판매가 이루어진 후 동기화될 때 제품이나 가격이 변경되었기 때문에 발생합니다. 판매 세부 정보를 확인하고, 판매가 올바르게 수신되었다면 검토 완료로 표시할 수 있습니다.

## 팁

모든 마크다운 형식, 이미지 경로, 코드 블록 및 기술 용어를 유지하세요.

- 로컬 Wi-Fi에 연결된 전용 장치에서 POS를 실행하세요.

간헐적인 Wi-Fi 중단은 자동으로 처리되지만, 오랜 시간 오프라인 상태인 장치는 다시 연결될 때 더 오랜 시간 동안 동기화를 다시 시작해야 합니다.
- 동기화 간격은 장치별로 설정됩니다.

여러 개의 터미널이 있는 경우 각 터미널은 독립적으로 동기화됩니다.

한 터미널에서의 판매는 동기화 시 즉시 관리자 화면에 나타나지만, 다른 터미널의 로컬 주문 캐시는 자신의 동기화 주기에서만 새로 고정됩니다.
- 계획된 인터넷 장애(예: Wi-Fi가 없는 행사로 이동하는 경우)가 있을 경우, 여전히 연결되어 있는 상태에서 POS를 열어 카탈로그와 재고 데이터가 완전히 최신 상태인지 확인하세요.

현금 판매는 신뢰성 있게 대기열에 추가되지만, 온라인으로 돌아올 때까지 통합 카드 결제는 피하는 것이 좋습니다.
- 행사에서 오직 현금 판매만 필요하다면, 수동 카드 결제 방법(직원이 독립 터미널에서 결제를 처리하고 참조를 입력함)은 카드 거래에도 오프라인 상태에서 작동합니다.
- 긴 근무 시간 동안 장치를 충전 중으로 유지하세요. 로컬 데이터베이스와 동기화 과정은 화면만큼 배터리에 큰 영향을 주지 않지만, 충전된 장치는 항상 거래에 더 안전합니다.
