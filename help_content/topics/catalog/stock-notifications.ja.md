---
title: 在庫通知
---

在庫通知は、在庫切れの製品が再び入手可能になると電子メールで通知されるように顧客が登録できる機能です。在庫表示設定は、製品ページで顧客が見る内容を制御するものです。例えば、在庫状態ラベル、在庫切れの警告、製品が在庫切れになると何が起こるかなどが該当します。

## 在庫表示設定

在庫表示設定は、カテゴリーや製品レベルで上書きされるまで、すべての製品に適用される店舗全体のデフォルトです。

これらのオプションを構成するには、**カタログ > 在庫表示設定**に移動してください。あなたのストア用に1つの設定レコードがあります。編集するにはそれをクリックしてください。

### 在庫状態の表示

| セットアップ | 説明 |
|---------|-------------|
| **在庫状態を表示** | 製品ページに「在庫あり」または「在庫切れ」ラベルを表示します |
| **在庫切れの警告を表示** | 在庫が少なくなっているときに「X個しかありません」と表示されます |
| **ロウストックスレッショルド** | 在庫切れの警告が表示される数量（デフォルト: 5） |
| **正確な在庫数を表示** | 一般的な警告ではなく、正確な在庫数を表示します（例: 「3個しかありません！」） |

### 在庫切れ時の動作

**在庫切れアクション**の設定は、製品に在庫がなければ顧客が見る内容を決定します:

| アクション | 顧客が見る内容 |
|--------|-------------------|
| **一覧から非表示** | 製品がカテゴリーページや検索結果から削除されます |
| **非利用可能として表示** | 製品は表示されますが、カートに追加することはできません |
| **「私に通知する」ボタンを表示** | 顧客は電子メールを登録して在庫が戻るのを通知してもらうことができます |
| **バックオーダーを許可** | 在庫がゼロでも製品を購入できます |

製品が利用できないときに表示されるテキストをカスタマイズするには、**在庫切れメッセージ**を設定してください（デフォルト: `在庫切れ`）。

バックオーダー可能な製品の表示されるテキストをカスタマイズするには、**バックオーダーメッセージ**を設定してください（デフォルト: `バックオーダー可能`）。

### 配送および配達表示

Markdownフォーマット、画像パス、コードブロック、技術用語をすべて保持してください。

| Setting | Description |
|---------|-------------|
| **"Ships From" ロケーションを表示** | 製品ページに在庫場所名を表示します |
| **推定配達日を表示** | 在庫場所に基づいて計算された推定配達日を表示します |

### バックオーダーを許可する (サイト全体) |

**バックオーダーを許可する** をチェックして、通常、在庫切れの製品をカスタマーが購入できるようにします。個々の製品やカテゴリはこの設定を上書きできます。

## 在庫切れ通知

在庫切れ時のアクションを **"Notify Me" ボタンを表示** に設定すると、カスタマーは製品ページで電子メールアドレスを入力して、製品が再入荷したときに電子メールを受け取ることができます。

### 通知リクエストの表示

すべてのカスタマーリクエストを確認するには、**カタログ > 在庫通知** に移動してください。各レコードには、次の情報が表示されます:
- カスタマーの電子メールアドレス
- 製品とバージョン (該当する場合)
- カスタマーが地域的な選好を指定した場合の希望する在庫場所
- リクエストが作成された日時
- 通知が送信された日時 (まだ送信されていない場合は空)

### 通知が送信されるタイミング

Spwigは、製品の在庫数がゼロより多くなると、自動的に在庫復活メールを送信します。**Notified At** フィールドには、メールが送信された日時が記録されます。

カスタマーは1回の通知メールを受け取ります。通知を受けた後、製品が再び在庫切れになった場合、再度サインアップする必要があります。

1回のプレーンなアラートだけでなく、たとえば **Featured Product** コンテンツブロックを使って再入荷した製品を表示する、または1日後にフォローアップするなど、より多くの情報を提供したい場合は、**Campaign Studio > Journeys** で **製品が在庫復活した** ジャーニーを作成し、それを **有効** にしてください。そのジャーニーが存在する場合、待機中のカスタマーはプレーンな1回限りのメールではなく、そのジャーニーに登録されます。アクティブなジャーニーがない場合、この1回限りのメールは上記のように正確に送信されます。トリガーの動作については [トリガー付きジャーニー](/help/triggered-journeys) を参照してください。

### 通知リクエストのフィルタリング

すべてのマークダウンフォーマット、画像パス、コードブロック、技術用語を保持してください。

次のフィルターを使用して検索してください：
- 特定の製品に関するリクエスト
- すでに通知済みのリクエスト（誰が連絡済みか確認するため）
- まだ保留中のリクエスト（在庫復帰を待っている顧客）

## 製品レベルのオーバーライド

サイト全体の在庫表示設定は、製品やカテゴリごとにオーバーライドできます。製品編集フォームで、**在庫**セクションを確認してください。このセクションで、グローバルデフォルトとは異なる製品固有の**在庫切れ時のアクション**を設定できます。

これは、ほとんどの製品でバックオーダーを許可したいが、いくつかの製品だけは「在庫復帰通知」に設定したい、または特定の製品を在庫切れ時に非表示にしたいためのものです。

## トipp

- **在庫切れのしきい値**を、通常使用する再注文ポイントに設定してください。これにより、在庫が完全に切れる前に製品の在庫が限られていることが顧客に通知されます。
- 在庫切れ製品を非表示にする代わりに、**「在庫復帰通知」ボタンを表示**するオプションを使用してください。登録した顧客は実際の需要を示しており、在庫復帰注文を正当化するためのものです。
- **正確な在庫数を表示**するオプションは、必要に応じてのみ有効にしてください。多くの場合、「あと3点のみ」と表示する方が「正確な数値を表示」するよりも、緊急性を高めるために効果的です。これは、在庫の完全な把握を明らかにすることなく、緊急性を生み出します。
- 新しい注文を出す前に、在庫通知リストを確認してください。保留中の通知リクエストの数から、その製品に対する需要の大きさがわかります。
- バックオーダーを使用している場合、**バックオーダーメッセージ**を更新して、正確な期待値を設定してください（例：「2〜3週間で発送します。今すぐ注文してあなたの場所を予約してください」）。
- 在庫切れ通知を電子メールマーケティングと組み合わせて使用してください。人気のある製品の在庫が復活したとき、自動通知メールだけでなく、登録者全員にキャンペーンを送信してください。
