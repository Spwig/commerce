---
title: 批量庫存操作
---

除了單獨調整之外，Spwig 給予您在 **庫存項目** 列表上三個批量操作功能，用於處理同時針對多個產品的庫存工作：在倉庫之間轉移庫存、註銷損壞或遺失的單位，以及在實地盤點後進行庫存核對。這三個操作都來自相同的 **操作** 下拉選單，會套用相同的數量到您所選擇的每個庫存項目，並完整記錄在庫存變動的審計追蹤中。

導覽至 **產品 > 庫存項目** 來使用它們。

## 執行批量庫存操作

1. 在 **庫存項目** 列表中，使用過激索或搜尋來找到您想要更新的項目
2. 勾選每個庫存項目的方框以包含（或使用首欄方框來選擇頁面上的所有項目）
3. 從 **操作** 下拉選單中選擇其中一個操作：
   - **將庫存轉移到倉庫**
   - **註銷損壞/遺失的庫存**
   - **重新盤點庫存（實地盤點）**
4. 點擊 **執行**
5. 审閱確認頁面 —— 它會列出每個所選庫存項目及其當前 **庫存**, **已分配**, 和 **可用** 數量，讓您可以再次確認您選擇了正確的項目
6. 填寫操作的欄位（見下文）並點擊提交按鈕以套用

![庫存項目列表，批量操作下拉選單開啟，顯示將庫存轉移到倉庫、註銷損壞/遺失的庫存和重新盤點庫存（實地盤點）以及其餘操作](/static/core/admin/img/help/stock-bulk-actions/stock-items-actions-dropdown.webp)

您輸入的相同數量會套用到 **每個** 選擇的項目 —— 這設計用於同時在多個 SKU 上移動、註銷或重新盤點相同數量的單位（例如，將數種產品的 10 個單位轉移到新店舖地點）。對於單一項目有不同數量的情況，請再次執行此操作並僅選擇該項目，或改用 **調整庫存水準**。

## 將庫存轉移到倉庫

使用此功能將每個已選商品倉庫中的庫存移動到另一個倉庫 — 例如，從主要倉庫補貨新零售店，或在地區履行中心之間重新平衡庫存。

在確認頁面中，填寫：

| 欄位 | 說明 |
|-------|-------------|
| **目標倉庫** | 庫存應移動到的倉庫。此清單中只會顯示活躍的倉庫。 |
| **每項數量** | 從每個已選商品當前倉庫中移出的單位數量。 |
| **原因** | 選擇性備註，例如「補貨新的奧克蘭店」。 |

點擊 **轉移庫存** 來套用。

![轉移庫存確認頁面：一個已選庫存項目卡片列出三個項目及其現有/已分配/可用數字，以及一個填寫了目標倉庫、數量和原因的轉移明細表單](/static/core/admin/img/help/stock-bulk-actions/transfer-stock-confirmation.webp)

**只有未保留的庫存可以轉移。** Spwig 從 *可用* 庫存（現有庫存減去已分配給開放訂單的單位）中轉移 — 已承諾給客戶訂單的單位仍留在來源倉庫，以便該訂單仍可履行。如果某個已選商品的可用庫存不夠覆蓋您輸入的數量，則會跳過該商品，並顯示錯誤訊息說明原因；其餘選項仍會進行轉移。

如果某個已選商品已經存放在您選擇的目標倉庫中，則會自動跳過（沒有東西可以轉移到自己），您會看到訊息說明有多少個項目因為此原因被跳過。

每次轉移都會在審計追蹤中寫入一組配對的移動記錄 — 來源處的一個負的 **倉庫轉移** 項目和目標處的一個正的對應項目 — 因此完整的追蹤會顯示庫存的來源和去向。

## 記錄損壞/遺失的庫存

Preserve all markdown formatting, image paths, code blocks, and technical terms.

用於註銷損壞、變質或遺失的單元 — 例如，在收到貨物時發現損壞商品或調查差異後。

在確認頁面中，填寫：

| 欄位 | 描述 |
|-------|-------------|
| **要註銷的數量（每種商品）** | 從現有庫存中移除的數量，針對每個選中的商品。 |
| **原因** | 選擇性備註，例如「存儲期間的水損」。 |

點擊 **記錄註銷** 以套用。

**保留庫存無法被註銷。** 現有庫存數量永遠不能低於目前分配給未完成訂單的數量 — Spwig 會阻止任何會吃掉已分配庫存的註銷，因此你無法不小心讓一筆已付款的訂單沒有足夠的庫存來履行。如果發生這種情況，你會看到錯誤訊息指出該商品以及實際可註銷的未保留單位數量。

每個註銷會被記錄為該庫存項目的一筆 **損壞/遺失** 移動，數量為負數。

## 重新計算庫存（實地盤點）

用於在實地盤點後修正現有庫存數量，使其與實際盤點數量一致 — 在倉庫審計或週期盤點後，快速協調許多商品的最快方式。

在確認頁面中，填寫：

| 欄位 | 描述 |
|-------|-------------|
| **盤點的現有庫存數量（每種商品）** | 你實際盤點的數量。現有庫存會被設為此精確數字，針對每個選中的商品 — 不是增加或減少。 |
| **原因** | 選擇性備註，例如「Q3 倉庫庫存盤點」。 |

點擊 **套用重新計算** 以套用。

![重新計算庫存確認頁面：已選庫存項目卡片和重新計算細節表單，其中已填寫盤點的現有庫存數量和原因](/static/core/admin/img/help/stock-bulk-actions/recount-stock-confirmation.webp)

與其他兩個操作不同，重新計算可以讓庫存數量以任何方向變動 — 如果你盤點的數量比系統預期的多，則增加；如果盤點的數量比系統預期的少，則減少。

保留所有 markdown 格式、圖片路徑、程式碼區塊和技術術語。

如果輸入的數量低於當前分配給未完成訂單的數量，Spwig 仍然會套用（數量是一項事實，而不是可以用來爭論的東西），但該商品的 **可用** 數字將在庫存清單中顯示為 `0`，其狀態圖示將變更為缺貨 —— 視此為信號，以檢查受影響的訂單是否仍可履行。

每次重新盤點都會被記錄為 **實盤重新計算** 的變動，數量顯示舊庫存與新庫存之間的修正值（正數或負數）。

## 審視變更內容

每次轉移、核銷和重新盤點的記錄方式與其他庫存變動相同：

- 開啟庫存項目並捲動至 **庫存變動** 部分以查看完整歷程
- 或導覽至 **產品 > 庫存變動** 以瀏覽所有項目中的變動，可按類型過濾

每個條目會記錄變動類型、數量變動、之前的庫存數量和新的庫存數量、變動的使用者，以及您輸入的說明（如果有）——因此，批量轉移或核銷與單獨手動調整一樣可追蹤。

## 小技巧

- 在完成實盤盤點後馬上執行 **重新盤點庫存**，當盤點數字還清晰時進行 —— 在確認頁面中更容易發現輸入錯誤，而不是後來從變動歷程中糾纏。
- 當進行核銷和重新盤點時，始終填寫 **說明**。

半年後，「存儲期間的水損」在審計追蹤中比空白欄位更有用。
- 在轉移庫存前，請檢查確認頁面中的 **可用** 欄位 —— 它已經考慮了已分配的單位數量，因此您馬上就能知道所選項目中是否有數量過高。
- 這些操作會將相同數量套用到每個選中的項目。

保留所有 markdown 格式、圖片路徑、代碼區塊和技術術語。

按需將選取的項目分組，這些項目確實需要移動相同數量、核銷或重新盤點，並一次處理一個異常。
- 如果您在零售場地使用 POS，請記住倉庫的庫存緩衝區不屬於「可用」用於在線訂單 — 但大額轉移和核銷仍然會根據倉庫實際庫存總額進行計算。
