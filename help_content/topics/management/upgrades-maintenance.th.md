---
title: การอัปเกรดและการบำรุงรักษา
---

Spwig ได้รับการอัปเดตเป็นประจำพร้อมกับคุณสมบัติใหม่ ๆ การปรับปรุงประสิทธิภาพ และการแก้ไขความปลอดภัย คู่มือนี้ครอบคลุมวิธีการอัปเกรดการติดตั้งของคุณ การใช้เครื่องมือตรวจสอบ และการจัดการงานบำรุงรักษา

## การอัปเกรด Spwig

### ก่อนที่คุณจะอัปเกรด

1. **สร้างสำเนาสำรอง** — ไปที่ **Management > System Metrics > Create Full Backup** หรือรันสคริปต์สำเนาสำรองจากบรรทัดคำสั่ง นี่คือเครือข่ายความปลอดภัยของคุณหากเกิดข้อผิดพลาดใด ๆ
2. **ตรวจสอบเวอร์ชันปัจจุบัน** — แสดงใน **Management > System Metrics** หรือที่ส่วนล่างของแดชบอร์ดผู้ดูแลระบบ
3. **ตรวจสอบสิ่งที่เปลี่ยนแปลง** — เปิดหน้า **System Upgrade** เพื่ออ่านหมายเหตุการปล่อยตัวฉบับเต็มสำหรับเวอร์ชันใหม่ก่อนที่คุณจะติดตั้ง มีขั้นตอนเพิ่มเติมที่การปล่อยตัวระบุไว้ (ดูด้านล่าง)

### ตรวจสอบสิ่งใหม่ ๆ บนหน้า System Upgrade

เมื่อ Spwig ตรวจพบเวอร์ชันใหม่กว่า **System Dashboard** จะแสดง **Update Available** ที่เป็น quick action คลิกที่นี่ — หรือไปที่ **System Dashboard > Platform Updates** ก่อนเพื่อดู changelog แล้วดำเนินการต่อ — เพื่อเปิดหน้า **System Upgrade**

หน้านี้แสดง:

- **Current Version** และ **Available Version** cards เพื่อให้คุณยืนยันเวอร์ชันที่คุณกำลังเปลี่ยนระหว่างกันอย่างแน่ชัด
- ส่วน **What's New in {version}** — สรุปสั้น ๆ ของการปล่อยตัว ตามด้วยหมายเหตุการปล่อยตัวฉบับเต็มที่จัดรูปแบบด้วยหัวข้อและรายการจุด ตามที่ผู้ดูแลระบบเขียนไว้
- **Pre-Upgrade Checks** — พื้นที่จัดเก็บ ความเชื่อมต่อฐานข้อมูล สำเนาสำรองล่าสุด สิทธิ์ในการเขียน และการเชื่อมต่อกับเซิร์ฟเวอร์อัปเดต Spwig คลิก **Run Pre-flight Checks**; ปุ่ม **Start Upgrade** จะถูกปิดใช้งานจนกว่าทุกการตรวจสอบจะผ่าน
- แถบ **Before You Upgrade** ที่เตือนคุณว่าสำเนาสำรองจะถูกสร้างอัตโนมัติ ร้านค้าของคุณจะเข้าสู่โหมดบำรุงรักษาชั่วคราวระหว่างการอัปเกรด และคุณไมควรปิดหน้าหรือเปลี่ยนไปยังหน้าอื่นขณะที่มันกำลังดำเนินการ

อ่าน **Upgrade notes** ในส่วน What's New อย่างละเอียด — บางการปล่อยตัวระบุขั้นตอนที่คุณต้องดำเนินการเองหลังจากอัปเกรด

ตัวอย่างเช่น การปล่อยอัปเดตที่เพิ่มรูปแบบภาพใหม่อาจขอให้คุณสร้างภาพหัวเรื่องสินค้าของคุณใหม่จาก **Media Library > Image Processing** เพื่อให้ภาพที่อยู่ในไลบรารีของคุณสามารถใช้การปรับปรุงนี้ได้; การอัปโหลดใหม่จะได้รับการปรับปรุงโดยอัตโนมัติ แต่แคตตาล็อกที่มีอยู่ของคุณจำเป็นต้องรีเฟรชด้วยตนเอง

เมื่อการตรวจสอบก่อนอัปเกรดผ่านไปแล้ว ให้คลิก **Start Upgrade** เพื่อเริ่มต้นจากเบราว์เซอร์ แถบความคืบหน้าจะติดตามแต่ละขั้นตอน และหน้าเว็บจะโหลดใหม่โดยอัตโนมัติเมื่ออัปเกรดเสร็จสิ้น นี่คือเส้นทางที่แนะนำสำหรับผู้ค้าส่วนใหญ่ — ใช้สคริปต์ที่อธิบายไว้ด้านล่างที่ใช้ SSH หากคุณต้องการควบคุมกระบวนการได้โดยตรงมากขึ้น

### การอัปเกรด

เข้าสู่เซิร์ฟเวอร์ผ่าน SSH และไปยังไดเรกทอรีการติดตั้ง Spwig ของคุณ (โดยทั่วไปคือ `/opt/spwig`):

```bash
./upgrade.sh
```

สคริปต์อัปเกรด:

1. **การตรวจสอบก่อนอัปเกรด** — ตรวจสอบพื้นที่จัดเก็บ สถานะของ Docker และสถานะบริการ
2. **การอัปเดตฐานข้อมูลแบบไม่เปลี่ยนแปลง** — ทดสอบว่าการเปลี่ยนแปลงฐานข้อมูลจะถูกประมวลผลได้อย่างถูกต้องโดยไม่เปลี่ยนแปลงอะไรจริงๆ
3. **เข้าสู่โหมดบำรุงรักษา** — ร้านค้าของคุณจะแสดงหน้าบำรุงรักษาให้ผู้เยี่ยมชมระหว่างการอัปเกรด
4. **สร้างสำเนาสำรอง** — สำเนาสำรองความปลอดภัยอัตโนมัติก่อนที่จะทำการเปลี่ยนแปลง
5. **หยุดงานในพื้นหลัง** — รอให้งานที่กำลังดำเนินอยู่ (การส่งอีเมล การแปล) จบลงอย่างเป็นระเบียบ
6. **ดึงรูปภาพใหม่** — ดาวน์โหลดแอปพลิเคชันที่อัปเดตจาก registry ของ Spwig
7. **ประมวลผลการอัปเดตฐานข้อมูล** — อัปเดตโครงสร้างฐานข้อมูลสำหรับเวอร์ชันใหม่
8. **รีสตาร์ทบริการ** — เปิดใช้งานแอปพลิเคชันด้วยเวอร์ชันใหม่
9. **ตรวจสอบสุขภาพ** — ตรวจสอบว่าบริการทั้งหมดทำงานได้อย่างถูกต้อง
10. **ออกจากโหมดบำรุงรักษา** — ร้านค้าของคุณกลับมาออนไลน์อีกครั้ง

หากการตรวจสอบสุขภาพล้มเหลวหลังการอัปเกรด สคริปต์จะ **กลับไปยังเวอร์ชันก่อนหน้าโดยอัตโนมัติ** และกู้คืนสำเนาสำรอง

### ตัวเลือกการอัปเกรด

```bash
./upgrade.sh              # การอัปเกรดมาตรฐานด้วยโหมดบำรุงรักษา
./upgrade.sh --dry-run    # ตรวจสอบว่ามีการเปลี่ยนแปลงอะไรบ้างโดยไม่ได้ดำเนินการ
```

## เครื่องมือวินิจฉัย


Spwig มีเครื่องมือตรวจสอบภายในที่ตรวจสอบการติดตั้งทั้งหมดของคุณเพื่อหาปัญหา:

```bash
./doctor.sh
```

เครื่องมือ doctor ตรวจสอบ:

| Category | What it checks |
|----------|---------------|
| **System** | Disk space, RAM usage, CPU load |
| **Docker** | Docker engine health, container states, image versions |
| **Database** | PostgreSQL connectivity, migration status, connection pool health |
| **Cache** | Redis connectivity, memory usage |
| **Object storage** | MinIO connectivity, bucket accessibility |
| **Network** | DNS resolution, port accessibility, SSL certificate validity |
| **Application** | Service health endpoints, background worker status |

แต่ละการตรวจสอบจะแสดงผลลัพธ์ผ่าน/ไม่ผ่านพร้อมรายละเอียดหากมีปัญหา

### Auto-fix mode

สำหรับปัญหาทั่วไป เครื่องมือ doctor สามารถลองซ่อมแซมอัตโนมัติได้:

```bash
./doctor.sh --fix
```

การซ่อมอัตโนมัติสามารถแก้ไขได้:

- Containers ที่หยุดทำงาน (เริ่มต้นใหม่)
- การเชื่อมต่อฐานข้อมูลที่ล้าสมัย (รีไซเคิล connection pool)
- ใบรับรอง SSL ที่หมดอายุ (เรียกใช้การต่ออายุ)
- ดิสก์เต็มจาก Docker images ที่เก่า (ลบ images ที่ไม่ได้ใช้งาน)

เครื่องมือ doctor จะอธิบายเสมอว่ามันจะแก้ไขอะไรก่อนที่จะดำเนินการ

## Maintenance mode

โหมดบำรุงรักษาจะแสดงหน้า "ร้านค้าชั่วคราวไม่สามารถใช้งานได้" ขณะที่คุณทำการเปลี่ยนแปลง แดชบอร์ดผู้ดูแลยังคงสามารถเข้าถึงได้

### Enabling maintenance mode

จากแดชบอร์ดผู้ดูแล: **Store Settings > Maintenance > Enable Maintenance Mode**

หรือจากบรรทัดคำสั่ง:

```bash
docker exec spwig_shop python manage.py maintenance on
```

### Disabling maintenance mode

จากแดชบอร์ดผู้ดูแล: ปิดสวิตช์โหมดบำรุงรักษา

หรือจากบรรทัดคำสั่ง:

```bash
./go-live.sh
```

### Bypass access during maintenance

ขณะที่โหมดบำรุงรักษาเปิดอยู่ คุณสามารถเข้าถึงร้านค้าได้ตามปกติโดยการเพิ่มพารามิเตอร์ลับใน URL คีย์ลับสำหรับการข้ามสามารถพบได้ในไฟล์กำหนดค่า `.env` ของคุณภายใต้ `MAINTENANCE_SECRET`

## Managing services

### Viewing service status

ตรวจสอบสถานะของบริการ Spwig ทั้งหมด:

```bash
docker compose ps
```

นี่แสดงให้เห็นแต่ละบริการ สถานะ (กำลังทำงาน หยุดทำงาน กำลังเริ่มต้นใหม่) และสถานะสุขภาพ

### การดูบันทึก

ตรวจสอบบันทึกสำหรับบริการเฉพาะ:

```bash
docker logs spwig_shop          # บันทึกแอปพลิเคชัน
docker logs spwig_celery         # บันทึกงานพื้นหลัง
docker logs spwig_nginx          # บันทึกการเข้าถึงเซิร์ฟเวอร์เว็บ
docker logs spwig_db             # บันทึกฐานข้อมูล
```

เพิ่ม `--tail 100` เพื่อดูบรรทัดสุดท้าย 100 บรรทัด หรือ `--follow` เพื่อดูบันทึกแบบเรียลไทม์

### การเริ่มต้นใหม่บริการ

หากต้องการเริ่มต้นใหม่บริการเฉพาะ:

```bash
docker compose restart shop      # เริ่มต้นใหม่แอปพลิเคชัน
docker compose restart celery    # เริ่มต้นใหม่งานพื้นหลัง
docker compose restart nginx     # เริ่มต้นใหม่เซิร์ฟเวอร์เว็บ
```

เพื่อเริ่มต้นใหม่ทั้งหมดบริการ:

```bash
docker compose restart
```

## การอัปเดตส่วนประกอบ

Spwig มีตลาดส่วนประกอบที่คุณสามารถติดตั้งธีม ผู้ให้บริการการชำระเงิน การผสานการจัดส่ง และส่วนขยายอื่น ๆ ได้ ส่วนประกอบอัปเดตได้แยกจากแพลตฟอร์มหลัก

ไปที่ **Management > Component Updates** เพื่อตรวจสอบการอัปเดตส่วนประกอบที่มีอยู่ การอัปเดตจะถูกดาวน์โหลดและนำไปใช้โดยอัตโนมัติเมื่อคุณอนุมัติ

## เคล็ดลับ

- **อัปเกรดเป็นประจำ** — การอยู่ในเวอร์ชันล่าสุดช่วยให้คุณมีการแก้ไขความปลอดภัยและเข้าถึงคุณสมบัติใหม่ ๆ
- **อ่านส่วน What's New ก่อนที่คุณจะคลิก Start Upgrade** — นี่คือวิธีที่เร็วที่สุดในการหาการอัปเกรดฐานข้อมูลที่จำเป็น การแก้ไขความปลอดภัย หรือการแจ้งเตือน **Upgrade notes** ที่คุณต้องดำเนินการหลังจากนั้น
- **สำรองข้อมูลก่อนเสมอ** — แม้ว่าสคริปต์อัปเกรดจะสร้างสำเนาสำรองอัตโนมัติ แต่การสำรองข้อมูลของคุณเองจะเพิ่มความปลอดภัย
- **รัน doctor หลังจากเกิดปัญหา** — หากร้านค้าของคุณทำงานผิดปกติ `./doctor.sh` เป็นวิธีที่เร็วที่สุดในการระบุปัญหา
- **กำหนดเวลาอัปเกรดในช่วงเวลาที่มีการจราจรต่ำ** — โหมดบำรุงรักษาจะขัดขวางการเข้าถึงลูกค้าชั่วคราว ดังนั้นจึงควรอัปเกรดในช่วงเวลาที่เงียบสงบ
- **รักษาพื้นที่ดิสก์ให้พร้อมใช้งาน** — การอัปเกรดต้องการพื้นที่ชั่วคราวสำหรับภาพใหม่และสำเนาสำรอง

รักษาพื้นที่ว่างอย่างน้อย 5 GB

รักษาการจัดรูปแบบ markdown ทั้งหมด ค่าเส้นทางภาพ บล็อกโค้ด และคำศัพท์ทางเทคนิคไว้
