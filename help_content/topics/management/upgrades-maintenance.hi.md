---
title: अपग्रेड एवं रखरखाव
---

Spwig नए फीचर, प्रदर्शन सुधार और सुरक्षा सुधार के साथ नियमित अपडेट प्राप्त करता है। यह प्राचार आपके इंस्टॉलेशन को अपग्रेड करने, डायग्नोस्टिक टूल का उपयोग करने और रखरखाव कार्यों के संचालन के बारे में बताता है।

## Spwig को अपग्रेड करें

### अपग्रेड करने से पहले

1. **बैकअप बनाएं** — **मैनेजमेंट > सिस्टम मीट्रिक्स > फुल बैकअप बनाएं** जाएं या कमांड लाइन से बैकअप स्क्रिप्ट चलाएं। यह आपका सुरक्षा जाल है अगर कुछ गलत हो जाता है।
2. **वर्तमान संस्करण जांचें** — **मैनेजमेंट > सिस्टम मीट्रिक्स** में दिखाई देता है या एडमिन डैशबोर्ड फूटर पर।
3. **जांचें कि क्या बदला गया है** — **सिस्टम अपग्रेड** पेज खोलें और नए संस्करण के लिए पूरे रिलीज नोट्स पढ़ें इससे पहले इस्तेमाल करें, जिसमें रिलीज द्वारा बताए गए कोई अतिरिक्त चरण शामिल हैं (नीचे देखें)।

### सिस्टम अपग्रेड पेज पर नए क्या है जांचें

जब Spwig एक नई संस्करण का पता लगाता है, तो **सिस्टम डैशबोर्ड** में **अपडेट उपलब्ध** एक त्वरित कार्रवाई दिखाई देता है।

इसे क्लिक करें — या पहले **सिस्टम डैशबोर्ड > प्लेटफॉर्म अपडेट** जाएं और चेंजलॉग के पूर्वावलोकन के बाद — ताकि **सिस्टम अपग्रेड** पेज खोल सकें।

इस पृष्ठ में दिखाया गया है:

- **वर्तमान संस्करण** और **उपलब्ध संस्करण** कार्ड, जिससे आप निश्चित रूप से जान सकते हैं कि आप किन संस्करणों के बीच जा रहे हैं
- **{version} में नए क्या हैं** अनुच्छेद — जारी करने के एक छोटा सारांश, बाद में जारी नोट्स के साथ, शीर्षक और बुलेट सूचियों के साथ फॉर्मेट किया गया, ठीक जैसे रखरखावकर्ताओं ने लिखा था
- **अपग्रेड से पहले जांचें** — डिस्क स्थान, डेटाबेस कनेक्शन, एक हालिया बैकअप, लिखने की अनुमति, और Spwig अपडेट सर्वर के लिए एक्सेस। **प्री-फ्लाइट जांच चलाएं** पर क्लिक करें; **अपग्रेड शुरू करें** बटन तब तक अक्षम रहता है जब तक सभी जांच सफल नहीं हो जाती हैं
- **अपग्रेड करने से पहले** बैनर, जो आपको याद दिलाता है कि एक बैकअप स्वचालित रूप से बनाया जाएगा, आपका स्टोर अपग्रेड के दौरान थोड़ी देर के लिए रखरखाव मोड में चला जाएगा, और आप अपग्रेड चलते समय पृष्ठ बंद नहीं करें या दूसरे पृष्ठ पर जाएं

अपग्रेड के नोट्स को What's New अनुभाग में ध्यान से पढ़ें — कुछ रिलीज़ अपग्रेड के बाद आपको खुद करने के लिए कुछ चरणों का उल्लेख करते हैं।

उदाहरण के लिए, एक ऐसा रिलीज़ जो एक नए इमेज फॉर्मेट के साथ आता है, आपसे **Media Library > Image Processing** से अपने उत्पाद थंबनेल को पुनर्जनित करने के लिए कह सकता है ताकि आपकी लाइब्रेरी में पहले से ही उपलब्ध इमेजें सुधार को अपना सकें; नए अपलोड इसे स्वचालित रूप से प्राप्त करते हैं, लेकिन आपके वर्तमान कैटलॉग को मनमाने मोड़ पर ताजा करने की आवश्यकता होती है।

जब प्री-फ्लाइट जांच पास हो जाती हैं, तो अपग्रेड के लिए **Start Upgrade** पर क्लिक करें। प्रगति बार प्रत्येक चरण को ट्रैक करता है, और अपग्रेड पूरा हो जाने के बाद पृष्ठ स्वचालित रूप से रिलोड हो जाता है। यह अधिकांश व्यापारियों के लिए अनुशंसित पथ है — यदि आपको प्रक्रिया के ऊपर अधिक सीधा नियंत्रण चाहिए, तो नीचे दिए गए SSH-आधारित स्क्रिप्ट का उपयोग करें।

### अपग्रेड चलाना

अपने सर्वर में SSH करें और अपने Spwig इंस्टॉलेशन डायरेक्टरी (आमतौर पर `/opt/spwig`) में जाएं:

```bash
./upgrade.sh
```

अपग्रेड स्क्रिप्ट:


1. **प्रारंभिक जांच** — डिस्क स्पेस, डॉकर के स्वास्थ्य और सेवा के स्थिति की जांच करता है
2. **सूखे चलाने के लिए डेटाबेस माइग्रेशन** — डेटाबेस में परिवर्तन लागू करने के बिना यह जांच करता है कि डेटाबेस के परिवर्तन साफ तरीके से लागू होंगे
3. **रखरखाव मोड में प्रवेश** — अपग्रेड के दौरान आपका स्टोर यात्रियों के लिए एक रखरखाव पृष्ठ दिखाता है
4. **एक बैकअप बनाता है** — परिवर्तन करने से पहले सुरक्षा के लिए स्वचालित बैकअप बनाता है
5. **पृष्ठभूमि कार्यकर्ताओं को खाली करता है** — चल रहे कार्यों (ईमेल भेजने, अनुवाद) के लिए धीरे-धीरे रुकने के लिए इंतजार करता है
6. **नए इमेज खींचता है** — Spwig रजिस्ट्री से अपडेटेड एप्लिकेशन को डाउनलोड करता है
7. **डेटाबेस माइग्रेशन लागू करता है** — नए संस्करण के लिए आपके डेटाबेस स्कीमा को अपडेट करता है
8. **सेवाओं को पुनः शुरू करता है** — नए संस्करण के साथ एप्लिकेशन को चलाता है
9. **स्वास्थ्य जांच** — सभी सेवाओं के सही तरीके से चल रहे होने की जांच करता है
10. **रखरखाव मोड से बाहर निकलता है** — आपका स्टोर फिर से ऑनलाइन हो जाता है

अगर अपग्रेड के बाद स्वास्थ्य जांच विफल हो जाता है, तो स्क्रिप्ट पिछले संस्करण में **स्वचालित रूप से वापस जाता है** और बैकअप को पुनर्स्थापित करता है।

### अपग्रेड विकल्प

```bash
./upgrade.sh              # रखरखाव मोड के साथ मानक अपग्रेड
./upgrade.sh --dry-run    # बिना लागू करे देखें कि क्या बदलेगा
```

## डायग्नोस्टिक टूल

Spwig में एक बिल्ट-इन डायग्नोस्टिक टूल शामिल है जो आपकी पूरी इंस्टॉलेशन की जांच करता है:

```bash
./doctor.sh
```

डॉक्टर निम्न चेक करता है:

| श्रेणी | यह क्या जांचता है |
|----------|---------------|
| **सिस्टम** | डिस्क स्पेस, रैम उपयोग, सीपीयू लोड |
| **डॉकर** | डॉकर इंजन के स्वास्थ्य, कंटेनर स्थिति, इमेज संस्करण |
| **डेटाबेस** | पोस्टग्रेस कनेक्टिविटी, माइग्रेशन स्थिति, कनेक्शन पूल स्वास्थ्य |
| **कैश** | रेडिस कनेक्टिविटी, मेमोरी उपयोग |
| **ऑब्जेक्ट स्टोरेज** | मिनिओ कनेक्टिविटी, बकेट पहुंच क्षमता |
| **नेटवर्क** | डीएनएस रिज़ॉल्यूशन, पोर्ट पहुंच क्षमता, एसएसएल सर्टिफिकेट वैधता |
| **एप्लिकेशन** | सेवा स्वास्थ्य एंडपॉइंट, पृष्ठभूमि कार्यकर्ता स्थिति |

प्रत्येक जांच में एक पास/फेल परिणाम होता है और यदि कुछ गलत है तो विवरण दिखाता है।

### ऑटो-फिक्स मोड

सामान्य समस्याओं के लिए, डॉक्टर स्वचालित मरम्मत का प्रयास कर सकता है:

```bash
./doctor.sh --fix
```

स्वचालित मरम्मत निम्नलिखित को हल कर सकता है:

- बंद कंटेनर (उन्हें पुनः शुरू करता है)
- अमूल्य डेटाबेस कनेक्शन (कनेक्शन पूल को फिर से बनाता है)
- अतीत के डॉकर इमेज से पूरा हार्ड डिस्क (अप्रयुक्त इमेज को हटा देता है)

डॉक्टर हमेशा कार्रवाई करने से पहले यह बताता है कि वह क्या मरम्मत करेगा।

## रखरखाव मोड

रखरखाव मोड आप बदलाव करते समय यात्रियों को एक "स्टोर अस्थायी रूप से अवामिल है" पृष्ठ दिखाता है। आपका प्रशासन पैनल अभी भी उपलब्ध रहता है।

### रखरखाव मोड को सक्रिय करें

प्रशासन पैनल से: **स्टोर सेटिंग्स > रखरखाव > रखरखाव मोड को सक्रिय करें**

या कमांड लाइन से:

```bash
docker exec spwig_shop python manage.py maintenance on
```

### रखरखाव मोड को अक्षम करें

प्रशासन पैनल से: रखरखाव मोड के स्विच को बंद करें।

या कमांड लाइन से:

```bash
./go-live.sh
```

### रखरखाव के दौरान पहुंच को बायपास करें

maintenances_mode_active_access_store_normally_adding_secret_parameter_url

महत्वपूर्ण: रखरखाव मोड सक्रिय होने पर, आप URL में एक गुप्त पैरामीटर जोड़कर स्टोर को सामान्य रूप से पहुँच सकते हैं।

बायपास गुप्त कुंजी आपके `.env` विन्यास फ़ाइल में `MAINTENANCE_SECRET` के तहत दिखाई देती है।

## सेवाओं का प्रबंधन

### सेवा के अवस्था की जांच करें

सभी Spwig सेवाओं के अवस्था की जांच करें:

```bash
docker compose ps
```

यह प्रत्येक सेवा, उसकी अवस्था (चल रहा, बंद, पुनः शुरू हो रहा), और उसकी स्वास्थ्य अवस्था दिखाता है।

### लॉग की जांच करें

एक विशिष्ट सेवा के लॉग की जांच करें:

```bash
docker logs spwig_shop          # एप्लिकेशन लॉग

docker logs spwig_celery         # पृष्ठभूमि कार्यकर्ता लॉग

docker logs spwig_nginx          # वेब सर्वर पहुँच लॉग

docker logs spwig_db             # डेटाबेस लॉग
```

`--tail 100` जोड़कर अंतिम 100 पंक्तियों को देखें, या `--follow` वास्तविक समय में लॉग की निगरानी करें।

### एक सेवा को पुनः शुरू करें

यदि एक विशिष्ट सेवा को पुनः शुरू करने की आवश्यकता है:


```bash
docker compose restart shop      # Restart the application
docker compose restart celery    # Restart background workers
docker compose restart nginx     # Restart the web server
```

To restart all services:

```bash
docker compose restart
```

## Component updates

Spwig features a component marketplace where you can install themes, payment providers, shipping integrations, and other extensions. Components update independently from the core platform.

Navigate to **Management > Component Updates** to check for available component updates. Updates are downloaded and applied automatically when you approve them.

## Tips

Preserve all markdown formatting, image paths, code blocks, and technical terms.

- **अपग्रेड करते रहें** — नवीनतम संस्करण पर रहने से आपको सुरक्षा सुधार और नए फीचर्स के लिए एक्सेस मिलता है
- **स्टार्ट अपग्रेड क्लिक करने से पहले What's New अनुच्छेद पढ़ें** — यह आवश्यक डेटाबेस माइग्रेशन, सुरक्षा सुधार या बाद में कार्रवाई के लिए आवश्यक **अपग्रेड नोट्स** को तेजी से पहचानने का सबसे तेज़ तरीका है
- **पहले हमेशा बैकअप बनाएं** — यद्यपि अपग्रेड स्क्रिप्ट एक ऑटोमैटिक बैकअप बनाता है, तो अपना बैकअप अतिरिक्त सुरक्षा प्रदान करता है
- **समस्याओं के बाद डॉक्टर चलाएं** — यदि आपका स्टोर अप्रत्याशित रूप से काम करता है, तो `./doctor.sh` समस्याओं को पहचानने के लिए सबसे तेज़ तरीका है
- **कम ट्रैफिक वाले समय पर अपग्रेड करें** — रखरखाव मोड ग्राहक एक्सेस को अस्थायी रूप से बाधित करता है, इसलिए शांत घंटों में अपग्रेड करें
- **डिस्क स्पेस उपलब्ध रखें** — अपग्रेड के लिए नए इमेज और बैकअप के लिए अस्थायी स्थान की आवश्यकता होती है।
