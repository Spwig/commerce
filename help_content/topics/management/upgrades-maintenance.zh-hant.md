---
title: 升級與維護
---

Spwig 會定期接收包含新功能、效能改進和安全性修復的更新。本指南說明如何升級您的安裝、使用診斷工具以及處理維護任務。

## 升級 Spwig

### 在升級之前

1. **建立備份** — 請前往 **管理 > 系統指標 > 建立完整備份** 或從命令列執行備份腳本。如果發生任何問題，這將是您的安全網。
2. **檢查當前版本** — 可在 **管理 > 系統指標** 或管理員儀表板頁腳中查看。
3. **查看變更內容** — 在 **系統升級** 頁面中開啟，閱讀新版本的完整發行說明，包括發行說明中提到的任何額外步驟（請參閱下文）。

### 在系統升級頁面查看新功能

當 Spwig 檢測到較新版本時，**系統儀表板** 會顯示 **有可用更新** 的快速操作。點擊它 — 或先導航至 **系統儀表板 > 平台更新** 來預覽變更日誌，然後繼續 — 以開啟 **系統升級** 頁面。

該頁面顯示：

- **當前版本** 和 **可用版本** 卡片，讓您確認您正在切換的確切版本
- **{version} 的新功能** 區塊 — 發行的簡短摘要，後面緊接完整的發行說明，以標題和項目清單格式呈現，與維護人員撰寫的方式完全相同
- **升級前檢查** — 磁碟空間、資料庫連線、最近的備份、寫入權限以及與 Spwig 更新伺服器的連線性。點擊 **執行升級前檢查**；在所有檢查通過之前，**開始升級** 按鈕將保持停用狀態
- **升級前** 的橫幅提醒您，備份會自動建立，商店在升級期間會短暫進入維護模式，而且在升級進行時，不應關閉頁面或導航離開

仔細閱讀 **升級說明** 區塊中的內容 — 有些發行版本會指出您在升級後需要自行執行的步驟。

例如，一個新增圖片格式的發行版本可能會要求您從 **媒體庫 > 圖像處理** 重新生成產品縮略圖，這樣已經在您的圖庫中的圖片就能應用這個改進；新上傳的圖片會自動應用，但您現有的目錄需要手動刷新。

一旦預飛行檢查通過，點擊 **開始升級** 從瀏覽器開始升級。進度條會追蹤每個階段，升級完成後頁面會自動重新載入。這對大多數商家來說是推薦的路徑 —— 如果您需要對過程有更直接的控制，請使用下面的基於 SSH 的腳本。

### 執行升級

透過 SSH 登入您的伺服器，並導航到您的 Spwig 安裝目錄（通常為 `/opt/spwig`）：

```bash
./upgrade.sh
```

升級腳本：

1. **預飛行檢查** — 驗證磁碟空間、Docker 健康狀態和服務狀態
2. **乾運行資料庫遷移** — 測試資料庫更改是否能乾淨地應用，而實際上不進行任何更改
3. **進入維護模式** — 在升級期間，您的商店會向訪客顯示維護頁面
4. **建立備份** — 在進行更改之前自動進行安全備份
5. **排空背景工作人員** — 等待進行中的任務（郵件發送、翻譯）順利完成
6. **拉取新圖片** — 從 Spwig 註冊中心下載更新後的應用程式
7. **應用資料庫遷移** — 更新資料庫結構以適應新版本
8. **重新啟動服務** — 使用新版本啟動應用程式
9. **健康檢查** — 驗證所有服務是否正確運行
10. **退出維護模式** — 您的商店重新在線

如果升級後健康檢查失敗，腳本會 **自動回滾** 到上一個版本並恢復備份。

### 升級選項

```bash
./upgrade.sh              # 標準升級，包含維護模式
./upgrade.sh --dry-run    # 檢查會有什麼改變，但不實際應用
```

## 診斷工具

Spwig 內建了一個診斷工具，用來檢查整個安裝是否存在問題：

```bash
./doctor.sh
```

doctor 會檢查以下項目：

| 分類 | 檢查內容 |
|----------|---------------|
| **系統** | 硬碟空間、RAM 使用量、CPU 負載 |
| **Docker** | Docker 引擎狀態、容器狀態、影像版本 |
| **資料庫** | PostgreSQL 連線性、遷移狀態、連線池健康狀態 |
| **快取** | Redis 連線性、記憶體使用量 |
| **物件儲存** | MinIO 連線性、儲存桶可存取性 |
| **網路** | DNS 解析、埠可存取性、SSL 證書有效性 |
| **應用程式** | 服務健康狀態端點、背景工作狀態 |

每個檢查項目都會顯示通過或失敗的結果，如果出現問題，也會顯示詳細資訊。

### 自動修復模式

針對常見問題，doctor 可嘗試自動修復：

```bash
./doctor.sh --fix
```

自動修復可以解決以下問題：

- 停止的容器（重新啟動）
- 過期的資料庫連線（重新建立連線池）
- 過期的 SSL 證書（觸發更新）
- 因舊的 Docker 影像導致硬碟空間滿（清除未使用的影像）

doctor 在採取行動前，始終會說明它將修復的內容。

## 維護模式

維護模式會在您進行更改時，向訪客顯示「商店暫時不可用」頁面。您的管理面板仍然可以存取。

### 啟用維護模式

從管理面板：**商店設定 > 維護 > 啟用維護模式**

或從命令列：

```bash
docker exec spwig_shop python manage.py maintenance on
```

### 停用維護模式

從管理面板：將維護模式開關關閉。

或從命令列：

```bash
./go-live.sh
```

### 維護期間繞過存取

維護模式啟用時，您可以在 URL 中加入一個秘密參數，以正常存取商店。繞過秘密會顯示在您的 `.env` 配置文件中，位於 `MAINTENANCE_SECRET` 下。

## 管理服務

### 查看服務狀態

檢查所有 Spwig 服務的狀態：

```bash
docker compose ps
```

這會顯示每個服務的狀態（運行中、已停止、重新啟動中）及其健康狀態。

### 查看日誌

檢查特定服務的日誌：

```bash
docker logs spwig_shop          # 應用程式日誌
docker logs spwig_celery         # 背景工作程式日誌
docker logs spwig_nginx          # 網站伺服器存取日誌
docker logs spwig_db             # 資料庫日誌
```

加入 `--tail 100` 可查看最後 100 行，或加入 `--follow` 以即時監控日誌。

### 重新啟動服務

如果需要重新啟動特定服務：

```bash
docker compose restart shop      # 重新啟動應用程式
docker compose restart celery    # 重新啟動背景工作程式
docker compose restart nginx     # 重新啟動網站伺服器
```

要重新啟動所有服務：

```bash
docker compose restart
```

## 組件更新

Spwig 提供一個組件市場，您可以在其中安裝主題、付款提供者、運輸整合以及其他擴展。組件的更新與核心平台獨立進行。

導航至 **管理 > 組件更新** 以檢查可用的組件更新。當您批准更新時，更新會自動下載並套用。

## 小技巧

- **定期升級** — 保持最新版本可確保您擁有安全性修復和新功能的存取權
- **在點擊開始升級之前閱讀 What's New 區塊** — 這是最快發現所需資料庫遷移、安全性修復或需要後續處理的 **升級說明** 的方式
- **始終先進行備份** — 雖然升級腳本會建立自動備份，但擁有自己的備份可提供額外的安全性
- **出現問題後執行 doctor 檢查** — 如果您的商店行為異常，`./doctor.sh` 是最快識別問題的方法
- **在低流量時間安排升級** — 維護模式會短暫中斷客戶的存取，因此請在流量較少的時間進行升級
- **保持磁碟空間可用** — 升級需要臨時空間來存放新映像和備份。

保持至少 5 GB 的可用空間。
