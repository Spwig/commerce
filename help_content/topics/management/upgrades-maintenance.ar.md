---
title: التحديثات والصيانة
---

تتلقى Spwig تحديثات منتظمة تحتوي على ميزات جديدة وتحسينات في الأداء وإصلاحات الأمان. يغطي هذا الدليل كيفية ترقية تثبيتك، واستخدام أداة التشخيص، وتنفيذ مهام الصيانة.

## ترقية Spwig

### قبل أن تبدأ الترقية

1. **أنشئ نسخة احتياطية** — انتقل إلى **الإدارة > مؤشرات النظام > إنشاء نسخة احتياطية كاملة** أو قم بتشغيل نسخة احتياطية من خلال سطر الأوامر. هذه هي شبكة الأمان الخاصة بك في حالة حدوث أي شيء غير متوقع.
2. **تحقق من الإصدار الحالي** — يظهر في **الإدارة > مؤشرات النظام** أو في قاعدة بيانات لوحة التحكم.
3. **راجع ما تم تغييره** — افتح صفحة **ترقية النظام** لقراءة ملاحظات الإصدار الكاملة للنسخة الجديدة قبل تثبيتها، بما في ذلك أي خطوات إضافية يشير إليها الإصدار (انظر أدناه).

### مراجعة ما هو جديد في صفحة ترقية النظام

عندما تكتشف Spwig إصدارًا أحدث، تظهر في **لوحة النظام** زر **تحديث متاح** كإجراء سريع. اضغط على هذا الزر — أو انتقل أولاً إلى **لوحة النظام > التحديثات الخاصة بالمنصة** لمراجعة سجل التغييرات، ثم استمر — لفتح صفحة **ترقية النظام**.

تعرض الصفحة:

- بطاقات **الإصدار الحالي** و**الإصدار المتاح**، بحيث يمكنك التأكد من الإصدار الذي تنتقل إليه بالضبط
- قسم **ما الجديد في {الإصدار}** — ملخص قصير للإطلاق، يليه ملاحظات الإصدار الكاملة المنسقة بعناوين وقوائم نقطية، تمامًا كما كتبها المُدارجون
- **التحقق المسبق من الترقية** — مساحة القرص، اتصال قاعدة البيانات، نسخة احتياطية حديثة، صلاحيات الكتابة، واتصال بخادم تحديثات Spwig. اضغط على **تشغيل التحقق المسبق**؛ يظل زر **بدء الترقية** معطلًا حتى يمر كل التحقق
- لافتة **قبل الترقية** تذكيرك بأن نسخة احتياطية تُنشئ تلقائيًا، وستدخل متجرك في وضع الصيانة مؤقتًا أثناء الترقية، ولا يجب أن تغلق الصفحة أو تنتقل إلى مكان آخر أثناء تنفيذها

اقرأ ملاحظات **الترقية** في قسم ما الجديد بعناية — بعض الإصدارات تشير إلى خطوات يجب عليك اتخاذها بنفسك بعد الترقية.

على سبيل المثال، قد يطلب إصدار يضيف تنسيق صورة جديد منك إعادة إنشاء صور منتجاتك المصغرة من **المكتبة الوسيمّة > معالجة الصور** بحيث تتمكن الصور الموجودة في مكتبتك من الاستفادة من التحسين؛ فإن التنزيلات الجديدة تحصل عليها تلقائيًا، لكن دليلك الحالي يحتاج إلى تحديث يدوي.

بعد نجاح فحوصات ما قبل الإطلاق، انقر على **بدء الترقية** لبدء العملية من خلال المتصفح. تتعقب شريط التقدم كل مرحلة، وتقوم الصفحة بإعادة التحميل تلقائيًا بمجرد اكتمال الترقية. هذا هو الطريق الموصى به لمعظم التجار — استخدم النص البرمجي القائم على SSH أدناه إذا كنت بحاجة إلى تحكم مباشر أكثر في العملية.

### تنفيذ ترقية

ابدأ جلسة SSH في خادمك وانتقل إلى دليل تثبيت Spwig (عادة `/opt/spwig`):

```bash
./upgrade.sh
```

نص الترقية:

1. **فحص ما قبل الإطلاق** — يتحقق من مساحة القرص، وصحة Docker، وحالة الخدمة
2. **مهاجرات قاعدة البيانات التجريبية** — تختبر أن التغييرات في قاعدة البيانات ستُطبّق بشكل نظيف دون إجراء أي تغييرات فعليّة
3. **الدخول إلى وضع الصيانة** — يظهر موقع متجرك صفحة صيانة للمستخدمين أثناء الترقية
4. **إنشاء نسخة احتياطية** — نسخة احتياطية آليّة قبل إجراء أي تغييرات
5. **إنهاء العمال الخلفية** — ينتظر المهام الجارية (إرسال البريد الإلكتروني، الترجمات) لإنهائها بشكل لطيف
6. **تنزيل الصور الجديدة** — تنزيل التطبيق المحدث من سجل Spwig
7. **تطبيق مهاجرات قاعدة البيانات** — تحديث هيكل قاعدة البيانات لنسخة جديدة
8. **إعادة تشغيل الخدمات** — تشغيل التطبيق مع النسخة الجديدة
9. **فحص الصحة** — يتحقق من أن جميع الخدمات تعمل بشكل صحيح
10. **الخروج من وضع الصيانة** — يعود متجرك إلى العمل

إذا فشل فحص الصحة بعد الترقية، يقوم النص البرمجي **بإعادة التراجع تلقائيًا** إلى الإصدار السابق ويستعيد النسخة الاحتياطية.

### خيارات الترقية

```bash
./upgrade.sh              # ترقية معيّنة مع وضع الصيانة
./upgrade.sh --dry-run    # فحص ما سيتغير دون تطبيقه
```

## أداة التشخيص


تتضمن Spwig أداة تشخيص مدمجة تتحقق من جميع تثبيتك للتأكد من عدم وجود أي مشاكل:

```bash
./doctor.sh
```

يتحقق الطبيب من:

| الفئة | ما يتحقق منه |
|----------|---------------|
| **النظام** | مساحة القرص، استخدام الذاكرة، حمل المعالج |
| **Docker** | صحة محرك Docker، حالات الحاويات، إصدارات الصور |
| **قاعدة البيانات** | اتصال PostgreSQL، حالة الهجرة، صحة حوض الاتصال |
| **الذاكرة المؤقتة** | اتصال Redis، استخدام الذاكرة |
| **تخزين الكائنات** | اتصال MinIO، توفر الحاوية |
| **الشبكة** | حل DNS، توفر المنفذ، صلاحية شهادة SSL |
| **التطبيق** | نقاط نهاية صحة الخدمة، حالة العامل الخلفي |

يظهر كل فحص نتيجة ناجحة أو فاشلة مع التفاصيل إذا كانت هناك مشكلة.

### الوضع التصحيح التلقائي

للمسائل الشائعة، يمكن للطبيب محاولة إصلاح تلقائي:

```bash
./doctor.sh --fix
```

يمكن للتصحيح التلقائي حل:

- الحاويات المتوقفة (إعادة تشغيلها)
- الاتصالات القديمة بقاعدة البيانات (إعادة تدوير حوض الاتصال)
- الشهادات SSL المنتهية الصلاحية (تشغيل التجديد)
- القرص الكامل من صور Docker القديمة (إزالة الصور غير المستخدمة)

يشرح الطبيب دائمًا ما سيصلحه قبل اتخاذ أي إجراء.

## الوضع الصيانة

يعرض الوضع الصيانة الزوار صفحة "المتجر غير متاح مؤقتًا" أثناء إجراء التغييرات. يظل لوحة التحكم الخاصة بك متاحة.

### تمكين الوضع الصيانة

من لوحة التحكم الإدارية: **إعدادات المتجر > الصيانة > تمكين وضع الصيانة**

أو من سطر الأوامر:

```bash
docker exec spwig_shop python manage.py maintenance on
```

### تعطيل الوضع الصيانة

من لوحة التحكم الإدارية: قم بتoggling مفتاح وضع الصيانة إلى إيقاف.

أو من سطر الأوامر:

```bash
./go-live.sh
```

### تجاوز الوصول أثناء الصيانة

بينما يكون وضع الصيانة نشطًا، يمكنك الوصول إلى المتجر بشكل طبيعي بإضافة معلمة سرية إلى عنوان URL. يتم عرض السر الخاص بالتجاوز في ملف التكوين `.env` الخاص بك تحت `MAINTENANCE_SECRET`.

## إدارة الخدمات

### عرض حالة الخدمة

تحقق من حالة جميع خدمات Spwig:


```bash
docker compose ps
```

هذا يعرض كل خدمة، وحالتها (تشغيل، توقف، إعادة التشغيل)، وحالة صحتها.

### عرض السجلات

تحقق من سجلات خدمة معينة:

```bash
docker logs spwig_shop          # سجلات التطبيق
docker logs spwig_celery         # سجلات العمال الخلفية
docker logs spwig_nginx          # سجلات الوصول إلى خادم الويب
docker logs spwig_db             # سجلات قاعدة البيانات
```

أضف `--tail 100` لعرض آخر 100 سطر، أو `--follow` لمتابعة السجلات في الوقت الفعلي.

### إعادة تشغيل خدمة

إذا كانت هناك حاجة لإعادة تشغيل خدمة معينة:

```bash
docker compose restart shop      # إعادة تشغيل التطبيق
docker compose restart celery    # إعادة تشغيل العمال الخلفية
docker compose restart nginx     # إعادة تشغيل خادم الويب
```

لإعادة تشغيل جميع الخدمات:

```bash
docker compose restart
```

## تحديثات المكونات

تتميز Spwig بسوق للمكونات حيث يمكنك تثبيت قوالب ومزودي الدفع وتكاملات الشحن وتوسعات أخرى. يتم تحديث المكونات بشكل مستقل عن منصة النظام الأساسية.

انتقل إلى **الإدارة > تحديثات المكونات** للتحقق من تحديثات المكونات المتاحة. يتم تنزيل التحديثات وتطبيقها تلقائيًا عندما تصدق عليها.

## نصائح

- **قم بالتحديث بانتظام** - البقاء على أحدث إصدار يضمن لك وجود إصلاحات الأمان ووصولك إلى ميزات جديدة
- **اقرأ قسم "ما الجديد" قبل النقر على "بدء التحديث"** - إنه أسرع طريقة لتحديد تحديث قاعدة بيانات مطلوب أو إصلاح أمني أو ملاحظة تحديث يجب عليك التصرف بشأنها لاحقًا
- **قم دائمًا بإجراء نسخة احتياطية أولًا** - حتى لو أنشأت نسخة احتياطية تلقائية نسخة التحديث، فإن امتلاك نسخة احتياطية الخاصة بك يوفر سلامة إضافية
- **قم بتشغيل "doctor" بعد المشكلات** - إذا تصرف متجرك بشكل غير متوقع، فإن `./doctor.sh` هو أسرع طريقة لتحديد المشكلات
- **جدولة التحديثات في أوقات منخفضة المرور** - وضع الصيانة يقطع الوصول المؤقت للعملاء، لذا قم بالتحديث في أوقات هادئة
- **احتفظ بمساحة القرص متاحة** - يحتاج التحديث إلى مساحة مؤقتة لصور جديدة والنسخ الاحتياطية.

احتفظ بمساحة خالية لا تقل عن 5 جيجابايت.
