---
title: Обновления и техническое обслуживание
---

Spwig получает регулярные обновления с новыми функциями, улучшениями производительности и исправлениями безопасности. Это руководство описывает, как обновить вашу установку, использовать инструмент диагностики и выполнять задачи технического обслуживания.

## Обновление Spwig

### Перед обновлением

1. **Создайте резервную копию** — перейдите в **Управление > Системные метрики > Создать полную резервную копию** или запустите скрипт резервного копирования из командной строки. Это ваша защита, если что-либо пойдет не так.
2. **Проверьте текущую версию** — видна в **Управление > Системные метрики** или в нижней части панели администратора.
3. **Просмотрите изменения** — откройте страницу **Системное обновление**, чтобы прочитать полные заметки о выпуске новой версии перед установкой, включая любые дополнительные шаги, которые указывает выпуск (см. ниже).

### Просмотр изменений на странице Системное обновление

Когда Spwig обнаруживает более новую версию, **Панель управления** показывает быстрое действие **Доступно обновление**. Нажмите на него — или сначала перейдите в **Панель управления > Обновления платформы**, чтобы предварительно просмотреть журнал изменений, а затем продолжить — чтобы открыть страницу **Системное обновление**.

На этой странице отображаются:

- **Текущая версия** и **Доступная версия** — карточки, позволяющие подтвердить, какие именно версии вы переходите
- Раздел **Новое в {версии}** — краткое резюме выпуска, за которым следует полный текст заметок о выпуске, оформленный с заголовками и списками, в точности как его написали разработчики
- **Предварительные проверки перед обновлением** — проверка свободного места на диске, соединения с базой данных, недавней резервной копии, разрешений на запись и подключения к серверу обновлений Spwig. Нажмите **Запустить предварительные проверки**; кнопка **Начать обновление** остается отключенной, пока все проверки не пройдут
- Баннер **Перед обновлением**, напоминающий, что резервная копия создается автоматически, ваш магазин временно переходит в режим технического обслуживания во время обновления, и вы не должны закрывать страницу или уходить с нее, пока обновление не завершится

Внимательно прочитайте примечания об обновлении в разделе **Новое в** — некоторые выпуски требуют выполнения определенных действий после обновления. Например, выпуск, добавляющий новый формат изображения, может попросить вас регенерировать миниатюрные изображения ваших продуктов через **Библиотека медиа > Обработка изображений**, чтобы уже загруженные изображения в вашей библиотеке могли воспользоваться улучшением; новые загрузки автоматически получают это улучшение, но ваш существующий каталог требует ручного обновления.

После успешного прохождения предварительных проверок нажмите **Начать обновление**, чтобы начать с браузера. Строка прогресса отслеживает каждый этап, и страница автоматически перезагружается после завершения обновления. Это рекомендуемый путь для большинства продавцов — используйте скрипт ниже на основе SSH, если вам нужен более прямой контроль над процессом.

### Запуск обновления

SSH-подключение к вашему серверу и переход в директорию установки Spwig (обычно `/opt/spwig`):

```bash
./upgrade.sh
```

Скрипт обновления:

1. **Предварительные проверки** — проверяет свободное место на диске, состояние Docker и статус служб
2. **Тестирование миграций базы данных** — проверяет, будут ли изменения в базе данных применены без ошибок, не применяя никаких изменений
3. **Переход в режим технического обслуживания** — ваш магазин отображает страницу технического обслуживания для посетителей во время обновления
4. **Создание резервной копии** — автоматическая резервная копия перед внесением изменений
5. **Остановка фоновых рабочих процессов** — ждет завершения текущих задач (отправка электронной почты, переводы) вежливым образом
6. **Загрузка новых изображений** — загружает обновленное приложение из реестра Spwig
7. **Применение миграций базы данных** — обновляет схему базы данных для новой версии
8. **Перезапуск служб** — запускает приложение с новой версией
9. **Проверка состояния** — проверяет, что все службы работают корректно
10. **Выход из режима технического обслуживания** — ваш магазин снова онлайн

Если проверка состояния не пройдет после обновления, скрипт **автоматически откатывается** до предыдущей версии и восстанавливает резервную копию.

### Варианты обновления

```bash
./upgrade.sh              # Стандартное обновление с режимом технического обслуживания
./upgrade.sh --dry-run    # Проверьте, что изменится, без применения
```

## Инструмент диагностики

Spwig включает встроенную диагностическую утилиту, которая проверяет всю вашу установку на наличие проблем:

```bash
./doctor.sh
```

Доктор проверяет:

| Категория | Что проверяет |
|----------|---------------|
| **Система** | Доступное дисковое пространство, использование ОЗУ, нагрузка на ЦП |
| **Docker** | Состояние движка Docker, состояние контейнеров, версии образов |
| **База данных** | Подключение к PostgreSQL, статус миграции, состояние пула подключений |
| **Кэш** | Подключение к Redis, использование памяти |
| **Объектное хранилище** | Подключение к MinIO, доступность бакета |
| **Сеть** | Разрешение DNS, доступность портов, действительность сертификата SSL |
| **Приложение** | Точки проверки состояния сервиса, статус фоновых работников |

Каждая проверка показывает результат прохождения/провала с деталями, если что-то не в порядке.

### Режим автоматического исправления

Для распространенных проблем доктор может попытаться автоматически исправить их:

```bash
./doctor.sh --fix
```

Автоматическое исправление может решить:

- Остановленные контейнеры (перезапускает их)
- Устаревшие соединения с базой данных (пересоздает пул подключений)
- Истекшие сертификаты SSL (инициирует обновление)
- Полный диск из-за старых образов Docker (очищает неиспользуемые образы)

Доктор всегда объясняет, что он собирается исправить, прежде чем предпринять действия.

## Режим обслуживания

Режим обслуживания показывает посетителям страницу "магазин временно недоступен", пока вы вносите изменения. Ваш панель администратора остается доступной.

### Включение режима обслуживания

Из панели администратора: **Настройки магазина > Обслуживание > Включить режим обслуживания**

Или из командной строки:

```bash
docker exec spwig_shop python manage.py maintenance on
```

### Отключение режима обслуживания

Из панели администратора: переключите режим обслуживания в положение выкл.

Или из командной строки:

```bash
./go-live.sh
```

### Обход режима обслуживания

Пока режим обслуживания включен, вы можете получить доступ к магазину в обычном режиме, добавив секретный параметр в URL. Секретный ключ обхода отображается в вашем файле конфигурации `.env` под `MAINTENANCE_SECRET`.

## Управление сервисами

### Просмотр статуса сервиса

Проверьте статус всех сервисов Spwig:

```bash
docker compose ps
```

Это показывает каждый сервис, его состояние (работает, остановлен, перезапускается) и его статус здоровья.

### Просмотр логов

Проверьте логи для конкретного сервиса:

```bash
docker logs spwig_shop          # Логи приложения
docker logs spwig_celery         # Логи фоновых работников
docker logs spwig_nginx          # Логи доступа веб-сервера
docker logs spwig_db             # Логи базы данных
```

Добавьте `--tail 100`, чтобы увидеть последние 100 строк, или `--follow`, чтобы наблюдать логи в реальном времени.

### Перезапуск сервиса

Если требуется перезапустить конкретный сервис:

```bash
docker compose restart shop      # Перезапустить приложение
docker compose restart celery    # Перезапустить фоновые работники
docker compose restart nginx     # Перезапустить веб-сервер
```

Чтобы перезапустить все сервисы:

```bash
docker compose restart
```

## Обновления компонентов

Spwig имеет маркетплейс компонентов, где вы можете установить темы, провайдеров оплаты, интеграции доставки и другие расширения. Компоненты обновляются независимо от ядра платформы.

Перейдите в **Управление > Обновления компонентов**, чтобы проверить доступные обновления компонентов. Обновления загружаются и применяются автоматически, когда вы одобряете их.

## Советы

- **Регулярно обновляйтесь** — оставаясь на последней версии вы получаете исправления безопасности и доступ к новым функциям
- **Прочтите раздел "Что нового" перед нажатием "Начать обновление"** — это самый быстрый способ определить необходимую миграцию базы данных, исправление безопасности или **Примечания об обновлении**, на которые вам нужно будет обратить внимание после этого
- **Всегда делайте резервную копию** — даже если скрипт обновления создает автоматическую резервную копию, наличие собственной дает дополнительную защиту
- **Запускайте доктора после проблем** — если ваш магазин ведет себя неожиданно, `./doctor.sh` — самый быстрый способ выявить проблемы
- **Планируйте обновления в часы низкой активности** — режим обслуживания кратковременно прерывает доступ клиентов, поэтому обновляйте в тихие часы
- **Сохраняйте свободное место на диске** — обновления требуют временного места для новых образов и резервных копий. Сохраните как минимум 5 ГБ свободного места.
