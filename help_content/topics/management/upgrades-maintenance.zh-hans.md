title: 升级与维护
---

Spwig 会定期接收包含新功能、性能改进和安全修复的更新。本指南介绍了如何升级您的安装，使用诊断工具以及处理维护任务。

## 升级 Spwig

### 在升级之前

1. **创建备份** — 转到 **管理 > 系统指标 > 创建完整备份** 或从命令行运行备份脚本。如果出现问题，这是您的安全网。
2. **检查当前版本** — 可在 **管理 > 系统指标** 或管理员仪表板页脚中查看。
3. **查看更改内容** — 打开 **系统升级** 页面，阅读新版本的完整发布说明，包括该版本要求的任何额外步骤（见下文）。

### 在系统升级页面上查看新功能

当 Spwig 检测到新版本时，**系统仪表板** 会显示一个 **有可用更新** 的快速操作。点击它 — 或者先导航到 **系统仪表板 > 平台更新** 以预览变更日志，然后继续 — 以打开 **系统升级** 页面。

该页面显示：

- **当前版本** 和 **可用版本** 卡片，以便您确认确切的版本转换
- **{version} 中的新功能** 部分 — 一个简短的发布摘要，后跟完整的发布说明，使用标题和项目符号列表格式，与维护人员编写的方式完全一致
- **升级前检查** — 磁盘空间、数据库连接、最近的备份、写入权限以及与 Spwig 更新服务器的连接性。点击 **运行预检**；在所有检查通过之前，**开始升级** 按钮将保持禁用状态
- **升级前** 通知横幅，提醒您备份会自动创建，商店在升级过程中会短暂进入维护模式，并且在升级过程中不应关闭页面或导航离开

仔细阅读 **升级说明** 部分 — 一些发布版本会指出您在升级后需要自行执行的步骤。

![Spwig upgrade process](/static/core/admin/img/spwig-upgrade-process.png)  

> 注意：升级过程可能需要几分钟，具体取决于您的服务器性能和网络连接速度。

例如，一个添加了新图像格式的版本可能会要求您从 **媒体库 > 图像处理** 重新生成产品缩略图，以便库中已有的图像可以使用此改进；新上传的图像会自动应用此改进，但您现有的产品目录需要手动刷新。

一旦预检通过，点击 **开始升级** 从浏览器开始升级。进度条会跟踪每个阶段，升级完成后页面会自动重新加载。这是大多数商家推荐的路径 —— 如果您需要对过程进行更直接的控制，请使用下面基于 SSH 的脚本。

### 执行升级

通过 SSH 登录到您的服务器，并导航到您的 Spwig 安装目录（通常为 `/opt/spwig`）：

```bash
./upgrade.sh
```

升级脚本：

1. **预检** — 验证磁盘空间、Docker 健康状况和服务状态
2. **数据库迁移预演** — 测试数据库更改是否可以干净地应用，而不会实际更改任何内容
3. **进入维护模式** — 在升级期间，您的商店会向访客显示维护页面
4. **创建备份** — 在进行更改之前自动进行安全备份
5. **排空后台工作进程** — 等待正在进行的任务（电子邮件发送、翻译）优雅地完成
6. **拉取新镜像** — 从 Spwig 注册表下载更新后的应用程序
7. **应用数据库迁移** — 更新数据库模式以适应新版本
8. **重启服务** — 使用新版本启动应用程序
9. **健康检查** — 验证所有服务是否正常运行
10. **退出维护模式** — 您的商店重新上线

如果升级后健康检查失败，脚本会 **自动回滚** 到之前的版本并恢复备份。

### 升级选项

```bash
./upgrade.sh              # 带维护模式的标准升级
./upgrade.sh --dry-run    # 检查会发生哪些更改，但不实际应用
```

## 诊断工具

Spwig 包含一个内置的诊断工具，用于检查整个安装是否存在任何问题：

```bash
./doctor.sh
```

doctor 会检查以下内容：

| 类别 | 检查内容 |
|----------|---------------|
| **系统** | 磁盘空间、RAM 使用情况、CPU 负载 |
| **Docker** | Docker 引擎健康状况、容器状态、镜像版本 |
| **数据库** | PostgreSQL 连接性、迁移状态、连接池健康状况 |
| **缓存** | Redis 连接性、内存使用情况 |
| **对象存储** | MinIO 连接性、存储桶可访问性 |
| **网络** | DNS 解析、端口可访问性、SSL 证书有效性 |
| **应用** | 服务健康检查端点、后台工作进程状态 |

每个检查都会显示通过/失败的结果，并在出现问题时提供详细信息。

### 自动修复模式

对于常见问题，doctor 可以尝试自动修复：

```bash
./doctor.sh --fix
```

自动修复可以解决以下问题：

- 停止的容器（重新启动它们）
- 过时的数据库连接（重新生成连接池）
- 过期的 SSL 证书（触发续订）
- 旧的 Docker 镜像导致磁盘满（清理未使用的镜像）

doctor 在采取行动前总会解释它将修复的内容。

## 维护模式

维护模式会向访客显示“商店暂时不可用”页面，同时您进行更改。您的管理员面板仍然可以访问。

### 启用维护模式

从管理员面板：**商店设置 > 维护 > 启用维护模式**

或从命令行：

```bash
docker exec spwig_shop python manage.py maintenance on
```

### 禁用维护模式

从管理员面板：关闭维护模式开关。

或从命令行：

```bash
./go-live.sh
```

### 维护期间绕过访问

在维护模式激活期间，您可以通过在 URL 中添加一个秘密参数来正常访问商店。绕过秘密显示在您的 `.env` 配置文件中的 `MAINTENANCE_SECRET` 下。

## 管理服务

### 查看服务状态

检查所有 Spwig 服务的状态：

```bash
docker compose ps
```

这会显示每个服务及其状态（运行中、已停止、正在重启）和健康状态。

### 查看日志

检查特定服务的日志：

```bash
docker logs spwig_shop          # 应用程序日志
docker logs spwig_celery         # 后台工作程序日志
docker logs spwig_nginx          # Web 服务器访问日志
docker logs spwig_db             # 数据库日志
```

添加 `--tail 100` 以查看最后 100 行，或添加 `--follow` 以实时查看日志。

### 重启服务

如果需要重启特定服务：

```bash
docker compose restart shop      # 重启应用程序
docker compose restart celery    # 重启后台工作程序
docker compose restart nginx     # 重启 Web 服务器
```

要重启所有服务：

```bash
docker compose restart
```

## 组件更新

Spwig 提供了一个组件市场，您可以在其中安装主题、支付提供商、配送集成和其他扩展。组件的更新与核心平台独立进行。

导航到 **Management > Component Updates** 以检查可用的组件更新。在您批准后，更新将自动下载并应用。

## 小贴士

- **定期升级** —— 保持最新版本可确保您获得安全补丁并使用新功能
- **在点击开始升级前阅读 What's New 部分** —— 这是快速发现所需数据库迁移、安全补丁或需要后续操作的 **升级说明** 的最快方式
- **始终先进行备份** —— 尽管升级脚本会创建自动备份，但拥有自己的备份可以提供额外的安全保障
- **出现问题后运行 doctor** —— 如果您的商店行为异常，`./doctor.sh` 是快速识别问题的最快方式
- **在低流量时段安排升级** —— 维护模式会短暂中断客户访问，因此请在流量较低的时间进行升级
- **保持磁盘空间可用** —— 升级需要临时空间来存储新镜像和备份。

保持至少 5 GB 的可用空间。
