---
title: アップグレードとメンテナンス
---

Spwigは定期的に新機能、パフォーマンスの改善、セキュリティの修正を含むアップデートを受けます。このガイドでは、インストールのアップグレード方法、診断ツールの使用方法、メンテナンスタスクの処理方法について説明します。

## Spwigのアップグレード

### アップグレードする前に

1. **バックアップを作成** — **管理 > システムメトリクス > フルバックアップの作成**にアクセスするか、コマンドラインからバックアップスクリプトを実行してください。何か問題が起きた場合の安全網になります。
2. **現在のバージョンを確認** — **管理 > システムメトリクス**または管理ダッシュボードのフッターに表示されます。
3. **変更内容を確認** — **システムアップグレード**ページを開き、インストール前に新しいバージョンの完全なリリースノートを読み、リリースが特に注意を促す追加手順も含め、確認してください（下記を参照）。

### システムアップグレードページで新機能を確認する

Spwigが新しいバージョンを検出すると、**システムダッシュボード**に**アップデートが利用可能**というクイックアクションが表示されます。クリックするか、まず**システムダッシュボード > プラットフォームアップデート**に移動して変更履歴をプレビューし、その後**システムアップグレード**ページを開いてください。

このページには以下が表示されます：

- **現在のバージョン**と**利用可能なバージョン**のカード — 移動するバージョンを正確に確認できます
- **{version}での新機能**セクション — リリースの簡単な概要に続き、見出しと箇条書きリストでフォーマットされた完全なリリースノートが表示されます。これはメンテナが実際に書いた形式そのままで表示されます
- **アップグレード前のチェック** — ディスク容量、データベース接続、最近のバックアップ、書き込み権限、Spwigアップデートサーバーへの接続性。**事前チェックを実行**をクリックしてください。すべてのチェックがパスするまで、**アップグレードを開始**ボタンは無効のままです
- **アップグレード前の注意事項**のバナー — 自動的にバックアップが作成され、アップグレード中に一時的にストアがメンテナンスモードになります。アップグレードが実行されている間、ページを閉じたり、他のページに移動したりしないでください。

**新機能**セクションの**アップグレードノート**を注意深く読んでください — 一部のリリースでは、アップグレード後に自分で実行する必要がある手順が記載されています。

たとえば、新しい画像形式を追加するリリースでは、**Media Library > Image Processing** から既存の製品サムネイルを再生成するよう求められる場合があります。これにより、ライブラリにすでにアップロードされている画像が改善を反映し、新しいアップロードは自動的に適用されますが、既存のカタログは手動でリフレッシュする必要があります。

プリフライトチェックが通過したら、ブラウザから **Start Upgrade** をクリックしてアップグレードを開始してください。進行状況バーで各段階が追跡され、アップグレードが完了するとページが自動的に再読み込みされます。これは大多数の販売業者にとって推奨される方法です — より直接的な制御が必要な場合は、下記のSSHベースのスクリプトを使用してください。

### アップグレードの実行

サーバーにSSH接続し、Spwigのインストールディレクトリ（通常は `/opt/spwig`）に移動します：

```bash
./upgrade.sh
```

アップグレードスクリプト：

1. **プリフライトチェック** — ディスク容量、Dockerの状態、サービスの状態を確認します
2. **ドライランデータベースマイグレーション** — データベースの変更が実際に何も変更せずにクリーンに適用されることをテストします
3. **メンテナンスモードに入ります** — アップグレード中、店舗は訪問者にメンテナンスページを表示します
4. **バックアップを作成します** — 変更を行う前の自動的な安全バックアップ
5. **バックグラウンドワーカーをドレインします** — 進行中のタスク（メール送信、翻訳）がスムーズに完了するのを待ちます
6. **新しい画像をプルします** — Spwigレジストリから更新されたアプリケーションをダウンロードします
7. **データベースマイグレーションを適用します** — 新しいバージョン用にデータベーススキーマを更新します
8. **サービスを再起動します** — 新しいバージョンでアプリケーションを起動します
9. **ヘルスチェック** — すべてのサービスが正常に動作していることを確認します
10. **メンテナンスモードを終了します** — 店舗はオンラインに戻ります

アップグレード後にヘルスチェックが失敗した場合、スクリプトは**自動的に前のバージョンにロールバック**し、バックアップを復元します。

### アップグレードオプション

```bash
./upgrade.sh              # メンテナンスモード付きの標準アップグレード
./upgrade.sh --dry-run    # 変更内容を確認するだけ、適用はしない
```

## ディアグノスティックツール

Spwigには、インストール全体の問題をチェックする組み込みの診断ツールが含まれています：

```bash
./doctor.sh
```

doctorは次の項目をチェックします：

| カテゴリ | チェック内容 |
|----------|---------------|
| **システム** | ディスク容量、RAM使用量、CPU負荷 |
| **Docker** | Dockerエンジンの状態、コンテナの状態、イメージバージョン |
| **データベース** | PostgreSQLの接続性、マイグレーション状態、接続プールの状態 |
| **キャッシュ** | Redisの接続性、メモリ使用量 |
| **オブジェクトストレージ** | MinIOの接続性、バケットのアクセス可能性 |
| **ネットワーク** | DNS解決、ポートの可アクセス性、SSL証明書の有効性 |
| **アプリケーション** | サービスの健康状態エンドポイント、バックグラウンドワーカーの状態 |

各チェックは、問題がある場合の詳細情報を含めてパス/失敗の結果を表示します。

### 自動修復モード

一般的な問題に対して、doctorは自動的な修復を試みることができます：

```bash
./doctor.sh --fix
```

自動修復は次の問題を解決できます：

- 停止しているコンテナ（再起動）
- 古くなったデータベース接続（接続プールを再生成）
- 期限切れのSSL証明書（更新をトリガー）
- 古いDockerイメージによるディスクのフル（使用していないイメージを削除）

doctorは、アクションを実行する前に何を修復するかを常に説明します。

## 保守モード

保守モードでは、変更を加える間、訪問者に「一時的に店舗が利用不可です」ページを表示します。管理パネルは引き続きアクセス可能です。

### 保守モードの有効化

管理パネルから：**ストア設定 > 保守 > 保守モードを有効にする**

またはコマンドラインから：

```bash
docker exec spwig_shop python manage.py maintenance on
```

### 保守モードの無効化

管理パネルから：保守モードのスイッチをオフにします。

またはコマンドラインから：

```bash
./go-live.sh
```

### 保守モード中のアクセスバイパス

保守モードが有効になっている間、URLにシークレットパラメータを追加することで、通常通り店舗にアクセスできます。バイパスシークレットは、`.env`設定ファイルの`MAINTENANCE_SECRET`の下に表示されます。

## サービスの管理

### サービスの状態の確認

Spwigのすべてのサービスの状態を確認します：

```bash
docker compose ps
```

これは、各サービスの状態（実行中、停止中、再起動中）と健康状態を表示します。

### ログの確認

特定のサービスのログを確認するには:

```bash
docker logs spwig_shop          # アプリケーションログ
docker logs spwig_celery         # バックグラウンドワーカーのログ
docker logs spwig_nginx          # Webサーバーのアクセスログ
docker logs spwig_db             # データベースログ
```

`--tail 100` を追加して最後の100行を表示するか、`--follow` を追加してリアルタイムでログを監視できます。

### サービスの再起動

特定のサービスを再起動する必要がある場合:

```bash
docker compose restart shop      # アプリケーションの再起動
docker compose restart celery    # バックグラウンドワーカーの再起動
docker compose restart nginx     # Webサーバーの再起動
```

すべてのサービスを再起動するには:

```bash
docker compose restart
```

## コンポーネントの更新

Spwig には、テーマ、支払いプロバイダ、配送統合、その他の拡張機能をインストールできるコンポーネントマーケットプレイスが用意されています。コンポーネントはコアプラットフォームとは独立して更新されます。

**管理 > コンポーネントの更新** に移動して、利用可能なコンポーネント更新を確認してください。更新は、承認したときに自動的にダウンロードおよび適用されます。

## ヒント

- **定期的にアップグレードする** — 最新バージョンに保つことで、セキュリティ修正と新しい機能へのアクセスが保証されます
- **アップグレードを開始する前に What's New セクションを確認する** — これにより、必要なデータベースマイグレーション、セキュリティ修正、アップグレード後の **アップグレードノート** の呼び出しを迅速に確認できます
- **常にバックアップを取る** — アップグレードスクリプトは自動バックアップを作成しますが、自分のバックアップがあると追加の安全性が得られます
- **問題が発生した後は doctor を実行する** — ストアの挙動が予期しない場合、`./doctor.sh` は問題の特定に最も迅速な方法です
- **低トラフィック時間にアップグレードをスケジュールする** — メンテナンスモードは一時的に顧客へのアクセスを中断するため、忙しくない時間にアップグレードしてください
- **ディスクスペースを確保する** — アップグレードには、新しいイメージとバックアップ用の一時的なスペースが必要です。

少なくとも5 GBは空き状態を保つこと。
