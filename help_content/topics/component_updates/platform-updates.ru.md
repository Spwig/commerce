---
title: Обновления платформы
---

Ваша установка Spwig состоит из набора компонентов — тем, виджетов, интеграций, элементов конструктора страниц и подключений к поставщикам — каждый из которых имеет свою версию, которую можно обновлять независимо. Регистр компонентов предоставляет централизованный обзор всего установленного, показывает, какие компоненты имеют ожидающие обновления, и позволяет устанавливать или откатывать обновления в любое время.

![Обзор регистра компонентов](/static/core/admin/img/help/platform-updates/component-registry-overview.webp)

## Понимание регистра компонентов

Перейдите в **Системная панель > Обновления компонентов**, чтобы увидеть каждый установленный компонент в вашем магазине. Каждая строка показывает:

- **Название** — отображаемое имя компонента
- **Тип** — какой тип компонента (тема, виджет, интеграция и т.д.)
- **Текущая версия** — версия, которая в настоящее время работает в вашем магазине
- **Состояние обновления** — доступно ли обновление
- **Канал** — какой канал обновления следует компоненту
- **Автоматическое обновление** — обновления устанавливаются автоматически
- **Заблокировано** — компонент заморожен на текущей версии

Панель в верхней части страницы показывает сводные счетчики: общее количество установленных компонентов, сколько из них имеют доступные обновления, и сколько из них актуальны.

### Типы компонентов

| Тип | Что это такое |
|------|------------|
| Тема | Визуальный дизайн вашего магазина |
| Виджет | Повторно используемые блоки конструктора страниц |
| Элемент конструктора страниц | Пользовательские элементы для конструктора страниц |
| Утилита конструктора страниц | Инструменты и утилиты редактора |
| Шаблон заголовка/подвал | Макеты заголовка и подвала |
| Поставщик доставки | Интеграции с перевозчиками (FedEx, UPS и т.д.) |
| Поставщик электронной почты | Сервисы доставки электронной почты |
| Поставщик оплаты | Интеграции с платежными шлюзами |
| Поставщик курса обмена | Источники данных курса обмена |
| Поставщик перевода | Сервисы искусственного интеллекта для перевода |
| Пакет языков | Файлы перевода интерфейса |

## Каналы обновлений

Каждый компонент следует за каналом обновлений, который определяет, какие выпуски он получает. Вы можете назначить каждый компонент разным каналам в зависимости от того, насколько вы готовы к риску.

| Канал | Описание | Лучше всего подходит |
|---------|-------------|----------|
| **Стабильный** | Готовые к производству, тщательно протестированные выпуски | Все компоненты в живых магазинах |
| **Бета-версия** | Предварительные сборки для тестирования новых функций перед их стабилизацией | Некритические компоненты, которые вы хотите предварительно просмотреть |
| **Разработка** | Последние функции, которые могут быть нестабильными | Только для сред тестирования |
| **Безопасность** | Только критические исправления безопасности, доставляемые с самой высокой приоритетностью | Компоненты, где стабильность имеет первостепенное значение |

Чтобы изменить канал компонента, нажмите на его имя, чтобы открыть подробный вид, затем выберите новое значение в поле **Канал обновления** и сохраните.

## Проверка обновлений

Spwig автоматически проверяет обновления с интервалом, настроенным в настройках вашего сервера обновлений (по умолчанию: каждые 24 часа). Чтобы проверить немедленно:

1. Перейдите в **Системная панель > Обновления компонентов**
2. Нажмите кнопку **Проверить обновления** в верхней части страницы
3. Система обращается к серверу обновлений Spwig и обновляет состояние обновления для всех компонентов
4. Компоненты с доступными обновлениями выделяются, и счетчик **Доступны обновления** обновляется

Вы также можете запустить проверку обновления для отдельных компонентов с помощью действия **Проверить обновления** в меню действий списка.

## Установка обновлений

### Обновление одного компонента

1. Перейдите в **Системная панель > Обновления компонентов**
2. Найдите компонент, который вы хотите обновить — компоненты с доступными обновлениями показывают индикатор обновления рядом с их версией
3. Нажмите кнопку **Установить обновление** в строке этого компонента
4. Подтвердите обновление, когда будет предложено
5. Обновление загружается, проверяется и устанавливается — индикатор прогресса показывает каждый этап
6. После завершения версия компонента **Текущая версия** обновляется до нового номера версии

### Обновление нескольких компонентов

1.

Выберите флажки рядом с компонентами, которые вы хотите обновить
2.



Выберите **Установить обновления** в раскрывающемся списке **Действие**
3.

Нажмите **Go**, чтобы продолжить
4.

Обновления устанавливаются в порядке зависимости — компоненты, на которые зависят другие, обновляются первыми

### Что происходит во время обновления

Процесс обновления проходит через следующие этапы:

1. **Проверка** — подтверждает, что обновление доступно, и ваша лицензия действительна
2. **Загрузка** — получает пакет с сервера обновлений Spwig
3. **Проверка целостности** — проверяет целостность пакета с помощью контрольной суммы SHA-256
4. **Распаковка** — распаковывает новые файлы
5. **Развертывание** — активирует новую версию
6. **Проверка состояния** — проверяет, работает ли компонент после обновления

Если на каком-либо этапе возникает сбой, система автоматически попытается восстановить предыдущую версию.

## Обновления на уровне платформы

Помимо отдельных компонентов, Spwig может получать обновления на уровне платформы, которые обновляют сам ядро магазина. Эти обновления проходят более тщательный процесс, включающий миграции базы данных и краткий период обслуживания.

Перейдите в **System Dashboard > Platform Updates**, чтобы просматривать и управлять обновлениями на уровне платформы отдельно от отдельных компонентов.

### Просмотр изменений перед установкой

Нажмите **Check for Updates**, чтобы увидеть, доступна ли новая версия платформы. Когда новая версия найдена, карточка **Update Available** показывает изменение версии (например, `v1.7.0 → v1.7.1`), **Размер пакета**, **Оценочное время**, и **Канал** обновления — а также предварительный просмотр **What's New**, чтобы вы могли увидеть, что изменилось, прежде чем решите установить его:

- Краткая строка с описанием выпуска
- Список основных изменений в этой версии (до пяти, с примечанием, если их больше)

Если обновление изменяет схему вашей базы данных, появляется уведомление **Requires database migration** с оценочным временем. Обновления безопасности отображают значок **Security update**, рекомендующий немедленно установить их. Прочитайте предварительный просмотр What's New перед установкой — это самый быстрый способ понять, нуждается ли релиз в дополнительном внимании, например, в шагах, указанных после завершения обновления.

История обновлений платформы отображается ниже по странице. Каждая запись показывает переход версии (например, `v1.3.2 → v1.3.3`), статус и продолжительность процесса обновления.

Обновления безопасности помечаются отдельно, и если в настройках сервера обновлений включено **Auto Install Security Updates**, они устанавливаются автоматически, без необходимости ручного вмешательства.

## Просмотр истории версий

Чтобы увидеть все ранее установленные версии компонента:

1. Нажмите на имя компонента, чтобы открыть его подробный вид
2. Прокрутите вниз до раздела **Component Versions** в нижней части страницы
3. Каждая запись версии показывает номер версии, когда она была установлена, метод установки и ее состояние здоровья

Система сохраняет последние три установленные версии для отката. Версии, выходящие за этот предел, автоматически удаляются.

## Откат компонента

Если обновление вызывает проблемы, вы можете откатиться к предыдущей версии:

1. Откройте подробный вид компонента
2. Прокрутите вниз до раздела **Rollback**
3. Выберите версию, которую вы хотите восстановить
4. Нажмите **Roll Back to this Version**

Только версии, помеченные как **Rollback Available**, могут быть восстановлены. Запись журнала отката фиксирует, кто инициировал откат и когда это произошло.

## Блокировка компонентов

Блокировка компонента предотвращает установку любых обновлений, включая автоматические. Это полезно, когда у вас есть пользовательские настройки или интеграции, зависящие от определенной версии.

1. Откройте подробный вид компонента
2. Поставьте галочку напротив **Locked** в разделе **Lock & Freeze**
3. Введите причину в **Lock Reason**, чтобы ваша команда понимала, почему компонент заблокирован
4. Сохраните запись

Блокированные компоненты отображаются с индикатором блокировки в списке реестра. Чтобы разблокировать, снимите галочку с **Locked** и сохраните.

## Чтение журналов обновлений

Журнал обновлений фиксирует каждую установку, обновление, откат и проверку состояния:

1.

Откройте подробный вид компонента
2.

**Update Logs** отображаются встроенно в нижней части страницы
3.



Каждая запись показывает: выполненное действие, начальное и конечное время, старую и новую версии, был ли это автоматическое или ручное обновление, а также любые сообщения об ошибках, если операция завершилась неудачно

Записи в журнале с статусом **Failed** включают полное сообщение об ошибке, чтобы помочь в устранении неполадок.

## Включение автоматических обновлений

Вы можете разрешить Spwig автоматически устанавливать обновления, когда они станут доступны:

1. Откройте подробный вид компонента
2. Включите **Auto Update** в разделе **Version & Update Status**
3. Сохраните запись

После включения автоматических обновлений система устанавливает обновления в течение следующего запланированного цикла проверки. Обновления безопасности следуют настройке **Auto Install Security Updates** на глобальном уровне, независимо от настроек отдельных компонентов.

## Советы

- Всегда обновляйте через канал **Stable** для тем и платежных провайдеров — это самые клиентоориентированные компоненты, и стабильность имеет первостепенное значение
- Заблокируйте компонент перед внесением пользовательских изменений в него, и четко запишите причину, чтобы будущие члены команды знали, что не следует обновлять его
- Перед установкой крупного обновления версии проверьте **Release Notes** на странице версии компонента — там отмечаются разрывные изменения
- Перед установкой обновления платформы прочтите предварительный просмотр **What's New** на странице **Platform Updates** — для полного ознакомления с заметками о выпуске, включая любые дополнительные действия, которые вам может понадобиться выполнить, перейдите на страницу **System Upgrade**
- После обновления перейдите в затронутую область вашего магазина, чтобы убедиться, что все выглядит и работает как ожидалось, прежде чем объявить обновление завершенным
- Если автоматическое обновление включено для компонента, периодически проверяйте **Update Logs**, чтобы убедиться, что автоматические обновления успешно завершаются
