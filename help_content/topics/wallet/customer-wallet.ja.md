---
title: 顧客ウォレット
---

顧客ウォレットは、各顧客の残高を追跡するストアクレジットの台帳です。ストアクレジットは、返品、紹介報酬、プロモーションキャンペーン、またはあなたのチームが行った手動の調整の結果として追加されます。

> **ウォレット残高はチェックアウト時に利用可能です。** ストアクレジットを持つサインインした顧客は、支払いステップでそれを表示し、1クリックで適用できます。クレジットは、税金と配達料の後で最終請求書から差し引かれ、残りは通常通りカードで請求されます。クレジットが注文全体をカバーする場合、カードは一切必要ありません。クレジットが適用されると保留され、支払いが確認されるまで実際に差し引かれることはありませんので、チェックアウトが放棄された場合でも顧客に一切の費用は発生しません。

**顧客 > 顧客ウォレット** に移動して、ウォレットを表示および管理してください。

## ウォレット残高の理解

各顧客ウォレットは4つの残高数値を表示します：

| 残高 | 説明 |
|---|---|
| **利用可能残高** | 顧客の現在の、利用可能なクレジット — この機能がリリースされたら、チェックアウト時に利用可能な金額になります |
| **保留残高** | 利用可能残高にまだ含まれていないクレジット — 例えば、確認期間内にある返品 |
| **累計クレジット** | このウォレットにこれまでにクレジットされた合計金額、過去のすべてのクレジットを含む |
| **累計利用額** | このウォレットからこれまでに引き落とされた合計金額 |

利用可能残高は、チェックアウトでの支払いがリリースされた後、重要な数値になります。保留中のクレジットは、保留期間が終了すると利用可能残高に移動します。

## 顧客のウォレットの表示

1. **顧客 > 顧客ウォレット** に移動します
2. 名前またはメールアドレスで顧客を検索するために検索フィールドを使用します
3. ウォレットエントリをクリックして詳細ビューを開きます

詳細ビューは上部に現在の残高を表示し、下部に完全な取引履歴を表示します。**最後にクレジットされた時刻** と **最後に利用された時刻** のタイムスタンプは、ウォレットが最後にアクティブだった時間を示します。

### ウォレットリストのフィルタリング

**アクティブ** フィルタを使用して、アクティブなウォレットと凍結されたウォレットを分離してください。

無効とマークされたウォレットは凍結されます — クレジットやデビットは記録されませんが、残高は保持されます。

## トランザクション履歴の確認

ウォレットの残高に変更が加えられると、それぞれが個別のトランザクションとして記録されます。トランザクション履歴は完全で永久の台帳です — トランザクションは編集または削除されません。エラーを修正する必要がある場合は、代わりに新しい補正トランザクションが追加されます。

各トランザクションには以下が表示されます：

| フィールド | 説明 |
|---|---|
| **タイプ** | クレジット、デビット、リファンド、調整、または逆転 |
| **金額** | このトランザクションの値（常に正の数として表示されます） |
| **トランザクション後の残高** | このトランザクションが適用された後のウォレット残高 |
| **ソース** | クレジットまたはデビットの発生元 |
| **ステータス** | 完了、保留、または逆転 |
| **説明** | トランザクションの簡単な説明 |
| **参照ID** | 元のレコードへのリンク（例：注文番号または報酬ID） |
| **作成日時** | トランザクションが記録された日時 |

### トランザクションタイプの説明

- **クレジット** — ウォレットに資金が追加される（リファンド、プロモーション、または手動調整から）
- **デビット** — ウォレットから資金が引き出される。チェックアウトでの支払いが実装されると、これは「注文に使用された」という意味になります — 今のところ、デビットが発生する唯一の方法は手動調整です
- **リファンド** — 戻りまたはキャンセルされた注文の結果として、ウォレットにクレジットが追加される
- **調整** — あなたのチームによって行われた手動の修正
- **逆転** — 以前のエントリをキャンセルするトランザクション

### トランザクションソースの説明

- **注文リファンド** — 注文がウォレットに戻されたときに発行されたクレジット
- **リファラル報酬** — リファラルプログラムを通じて獲得したクレジット
- **プロモーション** — マーケティングキャンペーンの一環として与えられたクレジット
- **手動調整** — スタッフメンバーによって直接追加または削除されたクレジット
- **注文支払い** — チェックアウトで注文を支払うために使用された資金。まだ使用されていない — ウォレットチェックアウト支払いが実装されたときに予約されます

## 手動のウォレット調整

管理者パネルでは資金の追加や削除はできません — ウォレット取引は、それらを所有するプロセス（注文の返金、ロイヤルティ報酬、リファラル報酬）のみによって作成されます。これは意図的な設計です。すべての動きには、それが起因した原因への参照が含まれており、夜間のチェックで各ウォレットの残高がその履歴と一致していることを確認しています。手入力された行がこの連鎖を破ってしまいます。

善意のクレジット — サービスの苦情、問題の後での贈り物 — については、代わりに手動で**ギフトカード**を発行してください（**ギフトカード**のヘルプトピックを参照してください）。ギフトカードはまさにこの目的に設計されています：あなたが価値を制御し、顧客はメールでコードを受け取り、チェックアウト時に店舗クレジットと同じように使用できます。

## ウォレットの凍結

顧客がウォレットの残高を使用できないようにする必要がある場合 — 例えば、詐欺の調査中に — データを削除したり残高を削除したりすることなく、それを無効化できます。

1. 顧客のウォレット詳細ビューを開きます
2. **Active**（有効）のトグルを外します
3. **Save**（保存）をクリックします

残高は保持され、ウォレットはいつでも再アクティブ化できます。無効な間は、新しいクレジットやデビット（手動を含む）はウォレットに対して記録されません。

## すべての取引の閲覧

すべての顧客のウォレット活動の全体的なビューが必要な場合は、**Customers > Wallet Transactions**（顧客 > ウォレット取引）に移動してください。このリストは、すべての顧客のウォレットのすべての取引を表示し、以下のフィルタが利用可能です：

- **Transaction Type**（取引タイプ） — クレジット、デビット、調整などによるフィルタ
- **Source**（ソース） — 取引の発生元によるフィルタ
- **Status**（ステータス） — 完了、保留、取消によるフィルタ
- **Date**（日付） — 上部の日付階層を使用して特定の日、月、年を詳しく表示

取引リストは読み取り専用です — このビューから取引を編集したり削除したりすることはできません。

## Tips

すべてのマークダウンの書式、画像のパス、コードブロック、技術用語を保持してください。

- **Lifetime Credited** と **Lifetime Used** を確認して、顧客がストアクレジットをどのくらい積極的に使用しているかを把握してください — 大きな未使用残高は、顧客がその存在を忘れている可能性があることを示しています
- 顧客が残高が間違っていると報告した場合、残高が時間とともにどのように変化したかを正確に追跡するために、完全な取引履歴を確認してください — 各項目の **Balance After** 列により、これは簡単になります
- 大きな未使用残高は、顧客に軽く触れることで有効活用される可能性があります — 顧客はアカウントダッシュボードとチェックアウト時の支払いステップでストアクレジットを確認できますが、短いメールでその点を指摘すると、多くの場合、注文に繋がります
- 冻結されたウォレットは、その残高を永久に保持します — 有効期限はありません。ウォレットを一時的に無効にした場合は、問題が解決したときに再び有効にしてください
- 各取引の **Reference ID** は、元のレコードにリンクしており、これにより、他の場所を検索することなく、クレジットまたはデビットが適用された理由を簡単に確認できます
